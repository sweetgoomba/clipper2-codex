# W10 기존 수정·중복 작업 점검 (2026-09-29)

## 확인 시점과 이전 확인 범위

최초 수정 전에 Angular를 fetch한 최신 origin/dev `797782e8f8e1c8488d024d23e6291e91c2b1e30e`에서 격리했고, 6개 증상이 남아 있는 코드와 RED 회귀를 확인했다. W07과의 파일 겹침도 일부 확인했다. 다만 원격 전체 미병합 브랜치의 동일 수정 여부를 사전 전수 대조했다고 말할 근거는 없다. 이번 사용자 질문 이후 아래 보완 점검을 수행했다.

## 조사 방법·결과

- Angular `git fetch origin` 성공. 현재 origin/dev는 최초 기준 SHA와 동일하다. 따라서 이후 dev에 동일 수정이 추가된 상황은 확인되지 않았다. 최초 RED 로그 `/private/tmp/w10-red.log`에서 9 실패/196 성공; 수정 후 전체 5,394 성공은 카드 참조.
- 원격 origin 브랜치 56개(HEAD 제외), 로컬 브랜치 49개의 도달 가능한 커밋을 dev와 비교했다. W10 수정의 제품 파일 13개 및 해당 관련 디렉터리에서 `origin/dev..ref` 변경 이력을 확인했다. 이미 dev에 포함된 커밋은 dev 코드/RED 증거와 대조하고, 미포함 후보는 실제 diff를 읽었다.
- 제품 파일에 미병합 변경이 있는 후보는 이용 권한 계열 `30f4a4db`/`f02bf221`, 밈 프로젝트 지원 `f330d588`, 과거 런타임 통합 `de04dd44`였다. 이들은 다운로드 동의 취소 pending 해제, 빈 실패 결과 액션, 대본 삭제 길이 재계산, 구성 라벨 18% 조건 제거, 안무 다운로드 문구/배치, 로그 chip 상태 단일화의 동일 수정이 아니다.
- `feature/billable-operation-blocking-progress-20260918`의 관련 디렉터리 변경은 유료 처리 중 동작 가드/진행 표시다. 이번 제품 파일 변경은 없으며 W10 동일 수정으로 확인되지 않았다. 별도 기능 디렉터리인 AI video/variation 변경도 이번 경로와 관련 없음.
- 현재 접근 가능한 Angular 작업 공간 7개(W10 제외·원본 포함)의 tracked 미커밋 변경을 점검했다. W07 storyboard-followups에 31개 변경이 있으나 W10 제품 파일 13개와 교집합 없음. 다른 접근 가능한 공간은 tracked clean. 삭제된 임시 worktree 등록은 읽기만 하고 정리하지 않았다.
- 결론: 점검 가능한 origin/local 브랜치 및 현재 작업 공간에서 이번 6개 동일 수정은 발견하지 못했다. 동일 파일의 다른 기능 변경은 존재하므로 향후 통합 시 단순 파일 단위 덮어쓰기가 아닌 변경별 대조가 필요하다.
- 한계: 다른 사람 PC의 미푸시 브랜치·미커밋 작업, origin에 공개되지 않은 fork/다른 remote는 확인할 수 없다. 원격 tip만으로 미래 병합 또는 병행 작업 완료를 보장하지 않는다.

## 버그 원인 설명 근거

- 로그: 원래 `selectedSources`는 빈 Set으로 초기화되고 빈 Set이 전체 선택/전체 로그라는 뜻이었다. 클릭하면 빈 Set에 클릭 소스를 추가하므로 전체에서 해당 소스를 제외하는 동작과 반대였다. 동시에 Material 자체 선택과 `[selected]`/직접 click 토글이 상태를 각각 바꿨다. 수정 전 실제 chip harness에서는 main 클릭 후 다른 3개가 모두 해제되고 로그는 main만 남아 기대와 다르게 실패했다. 사용자가 보고한 모든 설치형 클릭 순서까지 그대로 재연한 것은 아니다.
- 로그 수정: 실제 4개 소스를 초기 Set에 넣고 listbox `value/change`와 개별 chip 고유 value로 상태를 한 경로에서 관리한다. 전체 해제는 빈 로그다. 실제 클릭 시 해당 chip만 전환되며 화면 선택과 로그 목록이 일치하는 회귀가 통과했다.
- 구성 버튼: `cell.widthPercent >= 18 ? cell.label : ''` 조건이 원인. 9/21 `b38dcfa09`에서 들어왔고 현재 dev에도 남아 있다. 전체 대비 18% 미만 길이의 대본은 데이터/tooltip/aria-label은 있어도 버튼 본문이 빈 문자열이었다. `29fe7d0a`의 기존 접근성·마지막 칸 클리핑 수정은 이 조건을 제거하지 않았다.
- 구성 수정: 항상 라벨을 출력하고 라벨 최소 폭, 좁은 막대 내부 가로 스크롤을 적용한다. 1% 칸 및 좁은 화면 6개 칸의 텍스트 실제 bounds/선택 회귀 통과. 짧은 칸의 시각적 비율은 가독성 최소 폭에 의해 보정된다.
