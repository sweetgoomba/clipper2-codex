# AI 숏폼 디렉터 조사 관련성·검색어 라우팅 교정 설계

상태: 사용자 방향 승인 · 구현 전 정본 설계

작성일: 2026-07-29

## 1. 목적

운영 프로필과 선택 키워드에 맞는 최신 자료를 실제 외부 공급자에서 조사하고, 그 과정과
근거를 로컬 JSON artifact로 남기면서도 관련 없는 전국 급상승 검색어가 AI 정리와 영상
후보에 섞이지 않게 한다.

이번 교정은 다음 두 실제 실행에서 확인된 문제를 해결한다.

- `run.director.d5c74426e1c546aeb0ad4f2e43721dcd`
  - 조사는 `부분 완료`됐지만 YouTube 검색 결과가 0개였다.
  - LLM이 만든 첫 번째 네이버 뉴스용 긴 Boolean 검색어가 YouTube 검색에도 사용됐다.
  - 엔터테인먼트·걸그룹 프로필과 무관한 `군대`, `고령화`, `베네수엘라` 같은 Google
    Trends 전국 급상승 항목이 AI 정리 입력에 그대로 포함됐다.
- `run.director.2d7e9e900dbc4cacb8867d60846c9307`
  - 사용자가 `르세라핌`을 추가 범위로 입력한 뒤 `youtube-candidates` 단계에서 실패했다.
  - YouTube 응답의 `nextPageToken`이 로컬 artifact 보안 검사에서 비밀 토큰으로 오인됐다.

## 2. 결정 사항

### 2.1 Google Trends의 역할

Google Trends KR Trending RSS는 계속 수집한다. 이 자료는 특정 운영 프로필만을 위한
검색 결과가 아니라, 현재 한국 전체에서 갑자기 관심이 커진 항목을 발견하는 보조
레이더다.

다만 수집과 활용을 분리한다.

- RSS 원본은 관련성 여부와 무관하게 전부 source artifact에 저장한다.
- 화면에는 `전국 급상승 참고 자료`라고 표시해 운영 프로필에 맞춘 결과로 오해하지 않게
  한다.
- 검색어 계획 LLM은 프로필과 추가 범위를 최우선 기준으로 삼는다.
- LLM이 프로필과 직접 관련 있다고 선택한 Trends 항목만 이후 AI 정리 입력과 영상 후보
  근거에 포함한다.
- 관련 항목이 하나도 없으면 빈 배열을 정상 결과로 인정한다. 억지로 Trends 항목을
  끼워 넣지 않는다.

따라서 원본 조사 기록은 손실하지 않으면서, 관련 없는 전국 이슈가 콘텐츠 주제가 되는
문제를 막는다.

### 2.2 공급자별 검색어

네이버 뉴스, 네이버 DataLab, YouTube는 같은 검색어를 공유하지 않는다. 각 공급자가
잘 처리하는 형태가 다르기 때문이다.

검색어 계획 응답을 `query-plan.v2`로 명확히 나눈다.

```json
{
  "queries": [
    {
      "source": "naver-news",
      "query": "르세라핌 최근 컴백 신곡 뮤직비디오",
      "rationale": "최근 활동과 공식 발표를 확인한다."
    },
    {
      "source": "youtube",
      "query": "르세라핌 최신 안무 직캠 쇼츠",
      "rationale": "최근 영상의 조회 반응과 표현 형식을 확인한다."
    }
  ],
  "datalabKeywords": ["르세라핌"],
  "selectedTrendSignals": [
    {
      "trendSignalId": "trend-03",
      "rationale": "프로필의 걸그룹 활동과 직접 연결되는 급상승 신호다."
    }
  ]
}
```

계약은 다음을 보장한다.

- `queries`에는 `naver-news` 검색어 1~2개와 `youtube` 검색어 정확히 1개가 있어야 한다.
- 네이버 뉴스는 `naver-news` 검색어만 사용한다.
- YouTube는 `youtube` 검색어만 사용한다.
- 추가 범위가 있더라도 단순히 그 단어 하나로 YouTube 검색어를 덮어쓰지 않는다.
- DataLab은 Boolean 문법이나 긴 문장이 아닌 1~3개의 짧은 핵심 키워드만 받는다.
- YouTube 검색어에는 `site:youtube.com`을 넣지 않는다.
- 최신성은 검색어에 무조건 연도를 붙이는 방식보다 각 공급자의 기간·정렬 조건으로
  제어한다.

LLM 응답이 계약을 만족하지 않으면 잘못된 검색어를 여러 공급자에 재사용하지 않는다.
추가 호출 없이 조사 실행을 명확한 계약 오류로 종료한다. 이렇게 해야 사전 승인에 표시된
OpenAI 호출 상한이 실제 실행과 일치한다.

### 2.3 Trends 관련성 선택

검색어 계획 입력의 각 Trends 항목에는 실행 안에서만 쓰는 안정적인
`trendSignalId`를 부여한다.

```json
{
  "trendSignalId": "trend-01",
  "title": "군대",
  "traffic": "10K+",
  "publishedAt": "..."
}
```

LLM은 `selectedTrendSignals`에 직접 관련된 항목 ID와 선택 이유만 반환한다.
의미 관련성 판단은 검색어 계획 호출 한 번 안에서 수행한다. Nest는 다음 구조 조건을
검증한다.

- 반환 ID가 실제 입력에 존재하는가
- 중복이 없는가
- 선택한 Trends 항목이 3개 이하인가
- 선택된 각 ID에 비어 있지 않은 선택 이유가 있는가

Nest가 의미 관련성을 완전히 판정할 수 있다고 가장하지 않는다. 대신 LLM에 프로필,
추가 범위, 각 Trends 항목을 함께 제공하고 직접 관련된 경우만 선택하도록 명시한다.
선택 결과와 이유는 모두 저장해 사용자가 근거 화면에서 판단을 확인할 수 있게 한다.

### 2.4 YouTube 페이지 토큰

현재 discovery는 YouTube 결과의 다음 페이지를 요청하지 않는다. 따라서
`nextPageToken`과 `prevPageToken`은 애플리케이션이 사용하는 조사 데이터가 아니다.

- YouTube API 응답을 내부 DTO로 변환할 때 두 필드를 제거한다.
- 보안 저장소의 `*token` 차단 규칙은 완화하지 않는다.
- API 원문 전체도 저장하지 않는다.
- 실제 영상 ID, 제목, 채널, 게시 시각, 통계, 설명 등 조사에 필요한 필드만 저장한다.

이렇게 하면 페이지 이동용 문자열과 실제 자격 증명을 구분하기 위해 보안 규칙을
느슨하게 만들 필요가 없다.

### 2.5 비용 표시

사전 점검의 `USD 0.00–0.05`는 최솟값 0달러와 승인 상한을 범위처럼 표시해 실제 예상
비용으로 오해하기 쉽다.

- 사전 점검 화면은 `예상 최대 비용: USD 0.05`로 표시한다.
- 기존 승인 계약의 최소·최대 필드는 호환성을 위해 유지하되, 일반 화면에는 승인
  상한만 보여준다.
- 실행이 끝난 뒤 공급자가 반환한 토큰 사용량은 호출 기록에 저장한다.
- 실제 단가와 사용량으로 계산할 수 있을 때만 `실제 사용 비용`을 표시한다.
- 사용량이나 단가가 없으면 비용을 추측하지 않고 `계산 불가`로 표시한다.

이번 discovery 승인에는 Google Trends RSS, 네이버, YouTube, OpenAI 검색어 계획과
정규화 호출만 포함된다. 영상 정밀 분석용 Gemini 호출은 별도 승인 전에는 실행하지
않는다.

## 3. 변경 후 데이터 흐름

### 3.1 사전 점검

1. 활성 운영 프로필과 사용자가 입력한 추가 범위를 읽는다.
2. 필요한 자격 증명의 존재와 버전을 Web API에서 확인한다.
3. 공급자별 최대 호출 수와 승인 비용 상한을 표시한다.
4. 승인 시점의 계약 digest를 저장한다.

### 3.2 Discovery 실행

1. Google Trends KR Trending RSS를 한 번 가져와 전체 원본을 저장한다.
2. 프로필, 추가 범위, Trends 신호를 OpenAI 검색어 계획 입력으로 전달한다.
3. `query-plan.v2` 응답과 파싱된 결과를 저장한다.
4. `naver-news` 검색어로 네이버 뉴스를 조회한다.
5. `datalabKeywords`로 네이버 DataLab을 조회한다.
6. `youtube` 검색어로 YouTube 검색과 영상 상세 정보를 조회한다.
7. 사용하지 않는 YouTube 페이지 토큰을 제거한 뒤 source artifact를 저장한다.
8. 관련성이 선택된 Trends, 네이버 결과, DataLab 결과, YouTube 결과를 AI 정리 입력으로
   전달한다.
9. 정규화 결과와 실제 입력 근거 연결을 저장한다.
10. YouTube 후보가 충분하면 추천 3개를 제시하고 사용자 선택을 기다린다.

### 3.3 정밀 분석과 영상 후보

이번 교정은 정밀 분석 방식 자체를 바꾸지 않는다.

- 사용자가 추천 영상 중 최대 3개를 확정한다.
- 별도 비용 승인 뒤 기존 Clipper Studio STT와 Gemini 영상 이해를 사용해 실제 영상을
  분석한다.
- 훅, 스크롤 스토퍼, 구조, 장면 전환, 화면 문구, 편집 리듬, 재현 가능한 제작 원칙을
  저장한다.
- 영상 후보 생성 LLM에는 프로필, 관련 Trends, 뉴스, DataLab, YouTube 목록 정보와 선택
  영상의 정밀 분석 내용을 ID만이 아니라 실제 구조화된 내용으로 전달한다.

## 4. 화면과 근거 표시

### 조사 실행 카드

- `전국 급상승 참고 자료`: Google Trends 전체 수집 결과
- `이번 조사에 사용한 급상승 항목`: 선택된 항목과 선택 이유
- `공급자별 검색어`
  - 네이버 뉴스 검색어
  - DataLab 핵심 키워드
  - YouTube 검색어
- `YouTube 검색 결과`: 검색된 영상 수, 후보 조건을 통과한 수, 추천된 수
- `AI 정리`: 어떤 source artifact의 어떤 항목을 입력으로 사용했는지 표시

각 섹션은 사람이 읽기 쉬운 요약을 기본으로 보여준다. artifact ID와 원본 JSON은
`JSON 원문 보기`를 펼쳤을 때만 노출한다.

### 부분 완료

YouTube 후보가 부족하면 단순히 `부분 완료`만 표시하지 않는다.

예:

```text
YouTube 영상 후보가 부족해 정밀 분석 선택 단계로 넘어가지 못했습니다.
검색 결과 0개 · 조건 통과 0개 · 추천 0개
```

외부 공급자 실패, 저장 실패, 후보 부족은 서로 다른 상태와 메시지로 구분한다.

## 5. 구성 요소 책임

### Web API

- `query-plan.v2` 프롬프트와 구조화 출력 계약을 소유한다.
- 프로필·추가 범위를 우선하고 Trends는 선택적인 보조 신호로만 쓰도록 지시한다.
- 공급자별 검색어와 짧은 DataLab 키워드를 생성한다.
- 파싱한 필드만 반환하며 원문 응답은 저장 요청에 포함하지 않는다.

### Nest

- 실행 상태, 승인 계약, 로컬 artifact 저장을 소유한다.
- 공급자별 검색어를 보존하고 올바른 클라이언트로 라우팅한다.
- Trends 선택 ID를 입력 목록과 교차 검증한다.
- AI 정리 입력을 관련 근거로만 구성한다.
- YouTube 페이지 토큰을 영속 DTO에서 제거한다.
- 실패 단계와 부분 완료 이유를 구체적으로 기록한다.

### Angular/Electron

- 비용을 범위가 아닌 승인 상한으로 표시한다.
- 조사 원본과 실제 활용 근거를 구분해 보여준다.
- 공급자별 실제 검색어와 결과 수를 사람이 읽기 쉽게 표시한다.
- 원본 JSON은 접힌 상세 영역으로 유지한다.

## 6. 오류 처리

- 공급자 HTTP 오류와 artifact 영속 오류를 같은 `youtube-candidates` 오류로 뭉개지 않는다.
- 로그와 실패 artifact에는 공급자, 작업 종류, 안전한 상태 코드와 trace ID를 남긴다.
- API key, credential 원문, authorization header, 페이지 토큰, 공급자 원문 응답은 남기지
  않는다.
- 네이버 또는 YouTube 검색어 계약이 불완전하면 임의의 다른 공급자 검색어로 대체하지
  않는다.
- 사용자가 재시도하면 새 실행 ID를 만들되 이전 실패 artifact는 감사 기록으로 보존한다.

## 7. 검증 기준

### 자동 테스트

- `query-plan.v2`가 네이버·YouTube 검색어와 DataLab 키워드를 구분한다.
- 추가 범위가 있어도 LLM이 만든 YouTube 검색어를 단어 하나로 덮어쓰지 않는다.
- 네이버 전용 검색어는 YouTube에 전달되지 않고, YouTube 전용 검색어는 네이버에
  전달되지 않는다.
- DataLab에는 긴 Boolean 검색어가 전달되지 않는다.
- 선택되지 않은 Trends 항목은 AI 정리 입력에서 제외된다.
- 선택된 Trends 항목은 원본 artifact와 추적 가능하게 연결된다.
- 존재하지 않는 Trends ID는 거부된다.
- YouTube `nextPageToken`과 `prevPageToken`은 저장 DTO에서 제거된다.
- 실제 credential 관련 필드와 URL은 기존 보안 검사에서 계속 차단된다.
- 사전 점검 화면은 `예상 최대 비용: USD 0.05`처럼 상한만 표시한다.
- 부분 완료 화면은 검색·적합·추천 수량을 설명한다.

### 실제 앱 수용 테스트

1. 엔터테인먼트·걸그룹 프로필로 추가 범위 없이 조사한다.
2. Google Trends 전체 원본은 보이지만 무관한 항목은 AI 정리·영상 후보 근거에 들어가지
   않는지 확인한다.
3. 공급자별 실제 검색어와 YouTube 결과를 근거 화면에서 확인한다.
4. `르세라핌`을 추가 범위로 다시 조사한다.
5. YouTube가 7개 이상의 결과와 `nextPageToken`을 반환해도 502 없이 후보 선택 단계 또는
   설명 가능한 부분 완료 상태에 도달하는지 확인한다.
6. 이 단계에서는 Gemini 정밀 분석 호출이 발생하지 않았는지 확인한다.
