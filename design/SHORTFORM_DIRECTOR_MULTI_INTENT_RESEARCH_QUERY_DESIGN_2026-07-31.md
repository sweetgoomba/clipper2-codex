# AI 숏폼 디렉터 — 다중 목적 운영 프로필의 조사 검색어 분해 설계

작성일: 2026-07-31 KST

상태: 사용자 방향 승인 · 구현 계획 작성 전

## 1. 문제

운영 프로필은 한 채널이 장기적으로 다룰 범위이므로 여러 목적을 포함할 수 있다.
예를 들어 `자취방 구하기 및 인테리어` 프로필에는 다음 두 목적이 함께 존재한다.

- 방 구하기·계약 정보
- 원룸 인테리어·수납 정보

현재 query-plan 계약은 YouTube 검색어를 정확히 하나만 생성한다. 이 제약 때문에
`gpt-5.4-nano`가 두 목적을
`원룸 인테리어 수납 아이디어 자취방 집 구하기 팁`으로 합쳤다. 최근 30일, KR,
한국어, `videoDuration=short` 조건과 함께 실행한 조회수순·관련도순 검색은 모두
정상 HTTP 200이었지만 결과가 0개였다.

이 문제는 운영 프로필이 넓어서 생긴 사용자 입력 오류가 아니다. 넓은 프로필을 하나의
검색어로 압축한 조사 계약의 오류다.

별도로, 아직 레퍼런스 선택 이력이 없는 정상적인
`awaiting_reference_selection` 실행에서 reference-analyses API가 404를 반환하면
Angular 화면이 이를 `대상을 찾을 수 없습니다`로 표시한다. 선택 전에는 분석 목록이
없는 것이 정상 상태이므로 오류로 표시하면 안 된다.

## 2. 고정 결정

### 2.1 운영 프로필과 조사 범위를 분리한다

- **운영 프로필**은 여러 인접 목적을 포함할 수 있는 장기 편집 범위다.
- **조사 범위**는 한 번의 조사 실행에서 검색할 하나의 일관된 관심사다.
- **검색어**는 조사 범위 하나를 provider가 이해할 수 있게 표현한 짧은 문구다.

사용자에게 운영 프로필의 목적을 하나만 적도록 요구하지 않는다.

### 2.2 한 번의 조사에서 최대 두 개의 독립 조사 범위를 사용한다

query-plan은 운영 프로필과 선택적 집중 키워드를 바탕으로 YouTube 조사 범위를
1~2개 생성한다.

- 집중 키워드가 있으면 해당 키워드를 최우선 범위로 사용한다.
- 집중 키워드가 없으면 프로필의 목적을 독립적인 관심사로 분해한다.
- 프로필에서 세 개 이상을 추출할 수 있어도 이번 실행에서는 영상화 가능성과 프로필
  대표성을 기준으로 최대 두 개만 사용한다.
- 선택하지 않은 목적을 하나의 검색어에 다시 합치지 않는다.

예:

| 조사 범위 | YouTube 검색어 |
|---|---|
| 원룸 인테리어·수납 | `원룸 인테리어 수납` |
| 자취방 구하기·계약 | `자취방 구하기 체크리스트` |

### 2.3 각 검색어에 동일한 두 정렬을 적용한다

검색어와 정렬 효과를 섞지 않는다.

- 검색어마다 조회수순 최대 40개
- 같은 검색어마다 관련도순 최대 40개
- 검색어 하나면 최대 2회, 검색어 두 개면 최대 4회의 YouTube `search.list` 호출
- 모든 검색 결과를 합친 뒤 video ID 중복 제거
- 중복 제거된 모든 결과에 Shorts URL 검증 수행
- 확인된 Shorts를 임의의 6개 등으로 잘라내지 않고 모두 후보 화면에 제공

조회수순과 관련도순에 서로 다른 검색어를 배정하는 방식은 사용하지 않는다.

### 2.4 호출량과 근거를 승인 화면 및 로컬 JSON에 그대로 남긴다

조사 preflight에는 실제 최대 범위를 표시한다.

- 생성될 YouTube 조사 범위 최대 개수
- YouTube 검색 최대 호출 수
- 정렬별 최대 결과 수
- 현재 credential ID와 revision
- provider quota 단위

각 source-call JSON에는 기존처럼 실제 `q`, `order`, 기간, 지역, 언어, 길이 조건과
응답 건수를 저장한다. reference-candidates에는 영상별로 발견된 검색어와 정렬 lane을
보존한다. 사람이 보는 근거 화면에서도 다음을 확인할 수 있어야 한다.

- AI가 분해한 조사 범위
- 범위마다 생성한 실제 검색어
- 검색어를 선택한 이유
- 각 검색어·정렬의 반환 건수
- 중복 제거 전후 수량
- Shorts 검증 결과

provider 응답 원문을 별도 `raw` 필드로 저장하지 않는다. 현재의 allowlist projector와
공개 감사 필드만 사용한다.

## 3. 처리 흐름

```text
운영 프로필 + 선택적 집중 키워드 + 관련 Google Trends 신호
  → query-plan LLM
  → 1~2개 독립 YouTube 조사 범위
  → 범위별 짧은 검색어
  → 검색어 A: 조회수순 40 + 관련도순 40
  → 검색어 B(있는 경우): 조회수순 40 + 관련도순 40
  → 전체 video ID 중복 제거
  → 모든 결과 Shorts URL 검증
  → 확인된 Shorts의 videos.list 상세 정보 수집
  → 후보 랭킹 및 전체 후보 표시
```

Google Trends의 광역 급상승 신호가 프로필과 직접 관련되지 않으면 현재처럼 선택하지
않는다. 무관한 트렌드를 검색어에 강제로 넣지 않는다.

Naver 뉴스와 DataLab 조사는 YouTube와 함께 수행하지만, 현재 단계에서는 추가 LLM
호출을 만들어 Naver 결과로 YouTube 검색어를 다시 생성하지 않는다. 이 설계의 목적은
프로필의 복수 목적을 명시적으로 분리하는 것이며, provider 호출과 비용을 필요 이상으로
늘리지 않는다.

## 4. 계약 변경

### 4.1 Web API inference 계약

query-plan 응답은 YouTube 검색어 하나가 아니라 1~2개의 독립 조사 범위를 표현해야 한다.
각 범위는 최소한 다음을 가진다.

- 사람이 읽을 수 있는 범위 이름
- 짧고 일관된 YouTube 검색어
- 운영 프로필 또는 집중 키워드에 연결되는 선택 이유

실행 내 범위 ID는 LLM이 만들지 않고 Desktop Nest projector가 검증된 배열 순서대로
`youtube-scope-1`, `youtube-scope-2`를 부여한다. ID는 해당 query-plan artifact 안에서만
참조하며 전역 ID로 사용하지 않는다.

query-plan prompt는 다음을 명시한다.

- 서로 다른 목적을 한 검색어에 합치지 않는다.
- 각 YouTube 검색어는 하나의 조사 의도만 가진다.
- 검색어는 불필요한 설명 문구와 검색엔진용 Boolean 문법을 포함하지 않는다.
- 운영 프로필에 한 가지 목적만 있으면 억지로 두 범위를 만들지 않는다.

prompt, JSON schema, 수동 validator와 prompt template version을 함께 변경한다.

### 4.2 Desktop Nest 계약

- query-plan projector가 1~2개 YouTube 조사 범위를 엄격하게 검증한다.
- source collector는 각 검색어에 조회수순과 관련도순을 모두 실행한다.
- preflight 승인 스냅샷은 최대 4회의 검색 호출 및 해당 quota를 반영한다.
- candidate collector/ranker는 복수 검색어 lane을 잃지 않는다.
- 존재하는 조사 실행에 아직 reference selection이 없으면 reference-analyses collection은
  404가 아니라 `analyses: []`인 200 응답을 반환한다.
- 기존 단일 검색어 실행 기록은 읽기 호환을 유지하되 새 실행은 새 계약만 생성한다.

### 4.3 Angular 표시

- 아직 reference selection이 없는 실행에서 받은 빈 분석 collection을 정상 상태로
  표시한다.
- 이 경우 `대상을 찾을 수 없습니다`를 표시하지 않는다.
- 실제 실행·artifact 404는 계속 오류로 표시한다.
- 후보 및 근거 화면에서 조사 범위·검색어·정렬 lane을 사람이 이해할 수 있게 표시한다.

## 5. 오류 및 빈 결과 처리

- 검색어 하나가 0개이고 다른 검색어가 결과를 반환하면 남은 결과로 계속한다.
- 모든 검색어가 0개여도 실행을 실패시키지 않고 `insufficient` 후보 snapshot을
  저장한다.
- 모든 검색어가 0개인 경우 화면에 검색어별 반환 건수를 보여 주고, 정밀 분석 없이
  시장 근거로 계속할 수 있게 한다.
- 0개라는 이유로 승인되지 않은 추가 YouTube 검색을 자동 실행하지 않는다.
- 특정 source-call의 provider 실패는 기존의 source별 실패 계약과 부분 완료 규칙을
  유지한다.
- 존재하지 않는 조사 실행은 계속 404이며, 다른 404를 포괄적으로 숨기지 않는다.

## 6. 현재 실행 기록 처리

`run.director.02239be5d8d84cc880b02c9030dd7830`은 실제 provider 응답 0개를 근거로
이미 `insufficient` 후보 snapshot을 저장했다. 새 계약을 구현해도 이 append-only 실행의
과거 산출물을 소급 변경하지 않는다.

새 검색 계약을 검증하려면 구현·빌드 후 새 조사를 실행한다. 기존 실행을 재사용하는 별도
재검색 기능은 이번 범위에 포함하지 않는다.

## 7. 테스트 기준

### Web API

- 한 목적 프로필은 YouTube 조사 범위 하나를 허용한다.
- 복수 목적 프로필은 서로 다른 범위 두 개를 허용한다.
- 세 개 이상, 중복 범위와 빈 검색어를 구조 validator가 거부한다.
- 서로 다른 목적을 한 검색어에 다시 합치는 의미적 퇴행은 prompt fixture와 대표
  프로필 회귀 테스트로 검출한다.
- query-plan prompt와 provider input contract version이 새 계약과 일치한다.

### Desktop Nest

- 검색어 하나는 `viewCount`와 `relevance` 두 번 호출한다.
- 검색어 두 개는 각 정렬을 적용해 정확히 네 번 호출한다.
- 각 호출은 최대 40개이고 기간·지역·언어·길이 조건을 유지한다.
- 네 lane의 결과를 모두 수집하고 video ID만 중복 제거한다.
- 중복 제거된 모든 결과를 Shorts URL로 검증한다.
- 하나의 검색어가 0개여도 다른 검색어 후보를 보존한다.
- 모두 0개면 실패가 아니라 `insufficient` snapshot을 저장한다.
- preflight 승인 범위를 초과하는 호출을 실행하지 않는다.
- 기존 단일 검색어 artifact를 읽을 수 있다.
- 선택 이력이 없는 기존 조사 실행의 reference-analyses collection은 빈 200 응답이다.
- 존재하지 않는 조사 실행의 reference-analyses 요청은 계속 404다.

### Angular

- 선택 이력이 없는 `awaiting_reference_selection` 실행 상세를 열어도 오류 배너가
  나타나지 않는다.
- 실제 reference selection이 있는 실행은 분석 목록과 진행 기록을 기존처럼 불러온다.
- 실제 실행·artifact 404는 계속 오류로 표시한다.
- 복수 검색어와 lane이 근거 화면에 표시된다.
