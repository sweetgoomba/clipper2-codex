# W14 인물 하이라이트: 등장 연속성과 얼굴·몸 근거 설계

2026-10-19 · 검토용 설계. [2026-10-01 MVP 설계](../features/highlights/records/2026/10/2026-10-01-person-highlight-mvp-design.md)의 제품 흐름·수정·내보내기 계약을 이어받고, 분석과 구간 생성에 관한 이전 face-only 가정은 이 문서로 갱신한다. 제품 코드는 아직 변경하지 않았다.

## 목적과 결정

입력은 특정 장르나 시연 파일로 제한하지 않는다. 사람이 나오는 처음 보는 영상에서도 인물별 등장 구간을 납득 가능하게 찾고, 연속 등장을 잘못 여러 클립으로 쪼개는 문제를 우선 해결한다. 서로 다른 사람의 오합침, 배경 인물 누락, 짧은 실제 등장 누락도 함께 측정한다. 얼굴이 안 보이는 뒷모습·전신은 근거가 충분하면 같은 인물에 자동 연결하고, 불확실하면 `확인 필요`로 남긴다. 모든 내보내기 클립은 확정된 등장 구간 앞뒤에 짧은 맥락을 더한다. 앞뒤 약 0.5초는 초기 후보이며 원본 길이와 품질 평가에 따라 조정한다. 이 여유는 등장 판정이나 인물 연결 근거가 아니다.

기존 미커밋 Person MVP는 폐기하지 않는다. 그 구현의 플러그인 골격, 얼굴 관측, 결과 편집, 내보내기 코드를 최신 `dev`에 선택적으로 이어 붙이고, 진단에서 실패한 구간·그룹화 방식은 교체한다. 기존 37분 영상은 회귀 사례다. 시연 품질은 별도 처음 보는 다양한 영상으로도 확인한다. 사용자는 YOLO를 필요하면 계속 사용해도 된다고 결정했으므로, 이전 W14의 YOLO 사용 금지 기록은 이 결정으로 갱신한다. YOLO 재사용은 정확도·속도·패키징 평가 결과로 선택한다.

## 선택한 구조와 대안

1. **채택할 경로:** 공통 얼굴 모듈은 얼굴 검출·정렬·특징 추출·모델 출처와 참조 매칭의 공통 계약을 맡는다. Person은 사람의 존재, 샷 안 추적, 샷 간 신원 연결, 등장 구간, `확인 필요` 판정과 클립을 맡는다. 몸 검출에는 현행 YOLOv8 Pose를 첫 비교 후보로 쓸 수 있다. 기존 Dance의 메인 한 명 선정이나 ROI·클립 정책은 Person에 가져오지 않는다.
2. **face-only 유지:** 구현량은 작지만 얼굴이 가려질 때 누락과 분리가 반복된다. 현재 37분 결과의 실패를 해결하지 못하므로 제품 기본안으로 선택하지 않는다. 평가 대조군으로 보존한다.
3. **기존 Dance 결과를 Person으로 변환:** 모델 실행은 줄 수 있으나 Dance가 선택한 메인/그룹에 종속되어 배경·여러 사람·일반 영상을 포괄하지 못한다. 검출 모델 파일과 설치 경로의 재사용은 가능하지만 Dance의 선별 결과는 재사용하지 않는다.

ByteTrack의 저신뢰 검출 재연결 방식을 현행 단순 IoU 추적과 비교한다. 가림·빠른 이동으로 끊기는 실제 사례에서 개선되면 사용한다. 카메라 이동이나 외형 재식별이 남은 오류의 원인일 때만 BoT-SORT의 해당 요소를 비교한다. 논문 이름만으로 채택하거나 별도 YOLOX·ReID 가중치를 자동 추가하지 않는다.

## 분석 데이터 흐름과 책임

```text
원본 프레임·시각 ─┬─> 샷 경계 후보 ───────────────────────────┐
                ├─> 모든 사람 검출 ─> 샷 안 몸 궤적 ──────────┤
                └─> 공통 얼굴 관측·SFace 특징 ─> 얼굴↔몸 연결 ─┤
                                                               ↓
                     인물 신원 판단 ─> 등장 구간 ─> 맥락 추가 ─> 클립·수정·내보내기
```

- **공통 얼굴 모듈:** `clipper_face_core` 0.2.0의 YuNet/SFace 관측과 embedding 공간·출처 계약을 재사용한다. Person에 검출·특징 코드를 복제하지 않는다. 등록 사진의 실명/참조 ID를 찾는 `match_reference`는 익명 `인물 1/2…` 흐름에 필수는 아니다. 나중에 참조 사진 입력이 생길 때 쓰도록 독립성을 유지한다. 기존 `group_observations`는 face-only 대조군이다. 그 결과를 새 구간 판단의 정답으로 사용하지 않는다.
- **사람 관측·추적:** 각 분석 프레임의 모든 사람 상자와 점수, 모델·원본 해시, 시각을 보존한다. 샷 안에서는 한 검출을 한 궤적에만 배정하고, 겹침·움직임·외형 단서를 순서대로 비교한다. 샷 경계에서 궤적 ID는 종료한다. 같은 샷의 짧은 검출 공백은 주변 관측으로 이어질 수 있으나, 완전 퇴장과 다른 사람의 진입은 별개 사건으로 둔다.
- **얼굴↔몸 연결:** 얼굴 중심이 몸 상자에 있다는 것만으로 신원을 확정하지 않는다. 같은 프레임의 경쟁 상자, 겹침, 몸·얼굴 이동, 품질과 반복 관측을 확인해 `confirmed / ambiguous / none`으로 기록한다. 동시에 보이는 서로 다른 두 인물은 자동 동일인으로 합칠 수 없다는 제약을 유지한다.
- **인물 신원:** 얼굴이 확인된 구간은 얼굴 특징을 강한 근거로 쓴다. 같은 샷에서 그 사람이 뒤돌아 얼굴이 사라져도 몸 궤적이 끊기지 않았다면 같은 사람의 등장 구간을 연장한다. 샷을 넘는 몸 ID는 신원 증거가 아니며, 얼굴 또는 충분히 구별되는 외형·전후 연결 근거로 재판정한다. **영상에서 얼굴이 한 번도 보이지 않은 사람**은 몸 검출로 사람이 등장한 시간만 알 수 있다. 그 구간을 누락하지 않고 `확인 필요` 항목으로 보여 주되, 떨어진 다른 장면의 사람과 같은 인물이라고 자동 확정하지 않는다. 사용자가 검토해 기존 인물에 붙이거나 별도 인물로 둘 수 있다. 이는 10/2의 body-only 결과 제외 방침을 사용자의 새 요구에 맞게 바꾸려는 제안이며, 화면에 표시하는 방식은 아직 검토 대상이다.
- **등장 구간:** 인물 그룹의 신원과 화면에 보인 시간 범위를 별도로 기록한다. 샷 전환만으로 등장을 끊지 않는다. 전환 전후 같은 사람이 계속 화면에 있다는 근거가 있으면 한 등장 구간으로 잇고, 다른 사람 교대·실제 퇴장·긴 미관측은 분리한다. 불확실한 연결은 근거와 함께 검토 상태로 남긴다. 기존 `group_observations._intervals`의 샷별 무조건 분리와 고정 관측 간격 기준은 대조군으로만 둔다.
- **클립과 맥락:** `appearance_start/end`는 관측으로 추정한 등장 시각, `export_start/end`는 맥락을 더한 시각으로 별도 저장한다. 초기 후보는 앞뒤 약 0.5초이며 영상 시작·끝에서만 자른다. 여유 때문에 이웃 클립이 겹쳐도 등장 구간이나 인물 그룹을 합치지 않는다. 사용자가 경계를 수정한 경우 수정된 등장 구간을 기준으로 내보내기 범위를 다시 계산하고, 미리보기·MP4·ZIP에서 같은 범위를 쓴다.

## 실패와 불확실성

모델 파일 누락, 디코딩 실패, 원본 해시 불일치는 작업 실패 이유를 노출하고 기존 결과·수정을 보존한다. 얼굴 실패와 사람 미검출을 같은 상태로 취급하지 않는다. 몸만 보이거나 경쟁 인물 때문에 신원 연결이 불명확한 구간은 `확인 필요`와 후보 근거를 보여 준다. 얼굴·몸 모델의 추론 버전이 달라지면 관측과 캐시를 구분하고, 서로 다른 embedding 공간의 벡터를 직접 비교하지 않는다. 사람 관측 실패를 성공한 전체 인물 분석처럼 표시하지 않는다.

## 검증과 채택 기준

1. 기존 37분 사례와 처음 보는 여러 장르·촬영 조건의 영상에서, 원본을 보고 사람별 등장·실제 컷·동시 인물·가림·뒷모습을 별도로 표시한다. 특정 시연 파일에만 맞춘 설정은 쓰지 않는다.
2. face-only MVP를 기준으로 같은 사람의 잘못된 분리, 다른 사람의 오합침, 누락, `확인 필요`의 적절성, 1초 미만 클립 수와 실제 짧은 등장 보존을 각각 보고한다. 분리 감소가 오합침 증가를 가리면 채택하지 않는다. 짧은 샷 자체가 진짜인 사례는 원본 확인 없이 오류로 세지 않는다.
3. 사람 검출, 단순 IoU, ByteTrack 방식, 필요시 BoT-SORT 요소를 **같은 입력과 정답**에서 단계별 비교한다. YOLO 사용 시 현행 Dance와 자원 충돌, Mac/Windows 설치, 37분 실행 시간과 메모리도 잰다. 논문의 일반 벤치마크 수치를 Clipper 품질로 환산하지 않는다.
4. 모든 생성 클립의 등장 시각과 내보내기 맥락 경계를 대조하고, 인물 재배정·그룹 병합/분리·경계 수정·대표 이미지 변경·MP4/ZIP 재생성 후 저장을 검증한다. 기존 Dance/Dialog 경로도 회귀 확인한다.

## 구현 순서와 현재 상태

최신 `origin/dev`를 기준으로 별도 작업 트리를 만들고, 기존 미커밋 Person 트리는 읽기 전용 donor로 보존한다. 먼저 원본에서 실패한 구간의 독립 정답과 face-only 기준선을 고정한다. 그다음 사람 관측·추적·얼굴 연결·등장 구간을 각각 교체·검증하고 마지막에 기존 UI·편집·내보내기를 연결한다. 공통 얼굴 모듈의 공개 계약 변경은 기존 Dance 소비자와 함께 검증한다. 이 문서는 아직 구현 계획이나 성능 통과 결과가 아니다. 커밋·푸시·배포는 하지 않는다.
