# AI 숏폼 디렉터와 Clipper 최종 렌더 통합 설계

## 목표

AI 숏폼 디렉터의 최종 영상 제작을 기존 Clipper 숏폼 제작과 동일한
프로젝트 준비·템플릿 해석·실행 큐·결과 보관 흐름으로 통합한다.

다음 상태를 완료 기준으로 삼는다.

- 같은 Full 템플릿과 같은 입력값이면 일반 Clipper 제작과 AI 숏폼
  디렉터 제작에서 타이틀·자막·배경의 크기와 위치가 동일하다.
- AI 숏폼 디렉터에서 최종 영상 만들기를 시작하면
  `clipper_video_render` 작업이 전역 실행 큐에 표시된다.
- 대기열이 몇 시간 밀려도 클라이언트나 서버가 작업 상태를 주기적으로
  조회하지 않고 작업 생명주기 이벤트로 상태를 갱신한다.
- 완료된 하나의 영상 파일을 AI 숏폼 디렉터 페이지와 프로젝트
  보관함 양쪽에서 재생할 수 있다.
- 같은 스토리보드를 다시 렌더링해도 이전 렌더 결과가 사라지지 않는다.
- 템플릿 페이지에서 `Clipper 기본 Full 템플릿`이 `1080×1920`
  캔버스와 실제 레이어를 사용해 정상적으로 표시된다.

## 현재 문제

최종 인코딩 작업은 이미 `ShortformProjectService.startRender()`를 거쳐
`clipper_video_render` 작업으로 실행 큐에 들어간다. 그러나 그 앞뒤에는
AI 숏폼 디렉터 전용 처리가 추가되어 있다.

1. `ShortformDirectorClipperRenderAdapter`가 일반 Clipper 화면의 프로젝트
   준비 흐름을 사용하지 않고 `ShortformProject`를 직접 조립한다.
2. 메인 타이틀 줄 나누기와 폭 제한을 Director 전용 상수와 함수로
   계산한다.
3. 렌더 완료 파일을 프로젝트 보관함의 결과 위치에서 Director 전용
   폴더로 다시 복사한다.
4. Director의 렌더 이력은 실행 큐·프로젝트 보관함의 프로젝트와 직접
   연결되지 않고 별도의 렌더 ID 중심으로 관리된다.
5. Angular Director store는 최종 렌더 상태를 1초 간격·최대 240회
   조회한다. 대기열이 약 4분보다 길면 화면의 감시가 먼저 끝난다.
6. 기존 `ShortformProjectService`도 렌더 후처리를 위해 작업 상태를
   1초 간격·최대 240회 조회한다. 따라서 프런트엔드 polling만
   제거해서는 충분하지 않다.

이 때문에 렌더 워커가 같더라도 워커에 전달되는 템플릿 스냅샷과
타이틀 입력이 일반 Clipper와 달라질 수 있다.

Full 템플릿 표시 문제에는 별도의 프런트엔드 원인이 있다. NestJS
템플릿 모델은 `full` variant를 지원하고 시스템 Full 템플릿도
`1080×1920`으로 생성하지만, Angular 템플릿 모델과 비율 선택 로직은
숏폼 비율을 `1:1`, `4:3`으로만 제한한다. 따라서 Full 시스템 템플릿을
열 때 존재하지 않는 `1:1` variant가 선택되고 `0 x 0` 빈 캔버스가
표시된다.

## 선택한 접근

### 선택안: 기존 Clipper 프로젝트를 단일 렌더 경계로 사용

AI 숏폼 디렉터는 최종 렌더를 위한 별도 렌더 파이프라인을 갖지 않는다.
스토리보드와 생성 완료된 장면 영상을 기존 Clipper 숏폼 프로젝트
입력으로 변환한 뒤, 일반 Clipper와 같은 프로젝트 서비스와 렌더
작업을 사용한다.

Director는 다음 참조만 보관한다.

- Director 프로젝트 ID
- 스토리보드 리비전 ID
- Clipper 숏폼 프로젝트 ID
- 프로젝트 보관함 프로젝트 ID
- 렌더 작업 ID
- 렌더 리비전 ID

렌더 작업은 실행기 식별자와 출처 기능 식별자를 구분한다.

- 실행기: `clipper_video_render`
- 출처 기능: `shortform_director`

실행 큐는 실행기로 작업을 수행하고, 화면의 라벨·완료 작업 분류와
프로젝트 보관함은 출처 기능을 사용한다. 따라서 기존 Clipper 렌더러를
재사용해도 Director 결과가 `클리퍼` 섹션으로 잘못 합쳐지지 않는다.

영상 파일과 렌더 결과 메타데이터의 단일 원본은 프로젝트 보관함이다.
Director 페이지는 별도 MP4 복사본을 만들지 않고 같은 결과 파일을
인증된 프로젝트 파일 API로 재생한다.

### 제외한 접근

- Director 전용 타이틀 크기 보정: 일반 Clipper와 다시 달라지므로
  사용하지 않는다.
- Director 전용 렌더러: 실행 큐와 프로젝트 보관함을 우회하므로
  사용하지 않는다.
- 완료 MP4 이중 저장: 결과 불일치와 불필요한 디스크 사용을 만들므로
  제거한다.
- 렌더 상태 주기 조회: 대기열 길이에 따라 불필요한 요청이 누적되고
  고정된 재시도 횟수 뒤에 감시가 끝나므로 사용하지 않는다.
- Full 템플릿 신규 생성 및 복제: 이번 작업에서는 시스템 Full
  템플릿을 정확히 조회하고 사용하는 데만 집중한다.

## 데이터 흐름

1. 사용자가 Director 페이지에서 최종 영상 만들기를 누른다.
2. 현재 스토리보드 리비전과 준비된 장면 영상·내레이션을 읽는다.
3. 기존 Clipper 숏폼 프로젝트 계약에 맞는 프로젝트를 생성하거나
   갱신한다.
4. Clipper 템플릿 카탈로그에서
   `Clipper 기본 Full 템플릿`의 게시된 프리셋과 버전 스냅샷을
   조회한다.
5. Director가 생성한 메인 타이틀 문구는 일반 Clipper 프로젝트의
   `mainTitle1`, `mainTitle2` 입력으로 전달한다. 이후 폰트 크기,
   위치, 줄 배치와 렌더 payload 변환은 기존 Clipper 로직만 사용한다.
6. `ShortformProjectService.startRender()`가
   `clipper_video_render` 작업을 예약한다.
7. 렌더 준비가 완료되면 같은 작업이 전역 실행 큐에서 실행된다.
8. 시작 응답으로 받은 작업 ID를 Director 렌더 리비전에 저장한다.
   페이지는 이동하지 않고 공유 `JobHistoryService`의 WebSocket
   연결을 통해 해당 작업이 포함된 `jobs.snapshot`을 구독한다.
   렌더 작업 params와 완료 프로젝트에는 출처 기능
   `shortform_director`를 함께 기록한다.
9. 대기·시작·실행·완료·실패 전환은 `JobsService`가 이미 발행하는
   `jobs.snapshot`과 `jobs.event`로 전달한다. 상태 확인용 타이머와
   반복 HTTP 요청은 만들지 않는다.
10. 작업이 종료되면 `JobsService`의 동일한 terminal lifecycle에서
    프로젝트 보관함 기록과 Director 렌더 리비전 후처리를 실행한다.
    이 후처리는 작업 완료 이벤트에 의해 한 번만 실행된다.
11. 작업 완료 시 프로젝트 보관함의 기존 완료 작업 기록 흐름이
    프로젝트와 결과물을 저장한다.
12. Director 프로젝트는 완료된 프로젝트 ID·작업 ID·렌더 리비전을
    참조하고 같은 파일 URL을 표시한다.

사용자가 Director 페이지를 떠나도 렌더 작업과 후처리는 서버에서
계속된다. 페이지를 다시 열거나 앱을 재시작하면 저장된 렌더 리비전과
작업 ID를 한 번 읽고, 현재 작업 snapshot을 한 번 동기화한 뒤
WebSocket 이벤트를 다시 구독한다. WebSocket이 재연결될 때 서버가
전체 `jobs.snapshot`을 보내므로 연결이 끊긴 사이의 상태 변화도
복구할 수 있다.

## 프로젝트 보관함과 렌더 버전

하나의 Director 스토리보드 프로젝트는 프로젝트 보관함의 프로젝트
하나에 대응한다. 재렌더는 새 프로젝트 카드를 계속 만들지 않고 같은
프로젝트 안에 렌더 리비전으로 누적한다.

각 렌더 리비전은 다음 정보를 가진다.

- 렌더 리비전 ID
- 원본 스토리보드 리비전 ID
- 실행 큐 작업 ID
- 완료 시각
- 결과 영상 상대 경로
- 활성 버전 여부
- 실패한 경우 오류 상태

새 렌더가 완료되기 전에는 기존 활성 버전을 유지한다. 새 렌더가
성공하면 새 버전을 활성화하고, 실패하면 기존 버전을 그대로 유지한다.
Director 페이지와 프로젝트 보관함 상세 페이지는 같은 버전 목록과
같은 결과 파일을 사용한다.

## Full 시스템 템플릿

`Clipper 기본 Full 템플릿`은 템플릿 카탈로그의 읽기 전용 시스템
템플릿으로 유지한다.

- 비율 키: `full`
- 출력 크기: `1080×1920`
- 원본 데이터: 첫 번째 레거시 템플릿 family의 Full 설정
- 배경: 시스템 gradient 에셋
- 메인 타이틀: JalnanGothic, 80px, 레거시 위치와 자간 유지
- 자막: Pretendard 계열 폰트, 레거시 박스·색상·위치 유지
- 편집·삭제·복제·새 Full 템플릿 생성: 이번 범위에서 제공하지 않음

Angular 템플릿 모델은 API 응답의 `full` variant를 표현할 수 있어야
한다. 다만 새 템플릿 생성 화면의 허용 비율은 기존 `1:1`, `4:3`을
유지한다. 템플릿 편집기의 비율 탭은 전역 상수만 보지 않고 선택된
family에 실제 존재하는 variant를 기준으로 구성한다. 따라서 Full
시스템 family에는 `Full` 탭 하나만 표시된다.

미리보기와 최종 렌더는 동일한 템플릿 family·variant·게시 버전
스냅샷을 사용한다. Director 코드에 폰트 크기나 위치 값을 다시
하드코딩하지 않는다.

## 화면 동작

### AI 숏폼 디렉터

- 최종 영상 만들기를 시작하면 렌더 상태와 함께 실행 큐 작업 상태를
  표시한다.
- 렌더 버튼을 눌러도 프로젝트 보관함으로 자동 이동하지 않는다.
- `실행 큐에서 보기`를 누르면 프로젝트 보관함의 해당 작업으로
  이동한다.
- 완료 후 현재 활성 영상과 이전 렌더 버전 목록을 표시한다.
- 영상 재생 URL은 프로젝트 보관함과 같은 결과 파일을 가리킨다.
- 프로젝트 보관함으로 이동할 수 있는 버튼을 제공한다.

### 프로젝트 보관함

- 완료 작업 목록에 `AI 숏폼 디렉터` 섹션을 추가하고 해당 Director
  프로젝트를 이 섹션에 표시한다.
- 실행 플러그인이 `clipper_video_render`이더라도 출처 기능이
  `shortform_director`이면 `클리퍼` 섹션에 넣지 않는다.
- 섹션 순서는 설치된 플러그인 순서를 사용하며
  `shortform_director`의 기존 탐색 메타데이터와 라벨을 재사용한다.
- 상세 화면에서 현재 활성 영상과 렌더 버전 목록을 표시한다.
- 버전을 선택하면 해당 결과 영상을 재생할 수 있다.

### 템플릿

- `Clipper 기본 Full 템플릿` 카드에 `기본 제공`, `Full`,
  `1080×1920`을 표시한다.
- 카드를 열면 빈 `1:1` variant가 아니라 실제 Full 캔버스를 표시한다.
- 실제 배경, 메인 타이틀 1·2줄, 자막 레이어의 위치와 스타일을
  미리보기에서 확인할 수 있다.
- 읽기 전용 상태이므로 저장·삭제·복제 동작은 제공하지 않는다.

## 오류 처리

- 렌더 프로젝트 준비 실패: 실행 큐 작업을 실패 상태로 끝내고 기존
  활성 렌더를 유지한다.
- 렌더 작업 실패: 실패한 리비전을 기록하되 활성 버전으로 승격하지
  않는다.
- WebSocket 연결 종료: 반복 HTTP 조회로 전환하지 않는다. 연결
  상태를 표시하고 기존 실시간 서비스의 재연결을 사용한다. 재연결
  직후 전달되는 전체 작업 snapshot으로 현재 상태를 복구한다.
- 앱 재시작: pending 렌더 리비전의 작업 ID를 기준으로 persisted job
  snapshot과 프로젝트 보관함 상태를 한 번 대조한다. 주기적인 복구
  작업은 두지 않는다.
- 프로젝트 보관함 기록 실패: 완료 작업과 결과 파일을 유지하고
  재동기화 가능한 상태로 기록한다.
- Full 템플릿 또는 게시 스냅샷 누락: 기본값으로 조용히 대체하지 않고
  최종 렌더를 시작하지 않으며 명확한 오류를 표시한다.
- 결과 파일 접근 실패: Director 전용 복사본으로 우회하지 않고 동일
  프로젝트 파일 참조의 오류를 표시한다.

## 마이그레이션

기존 Director 렌더 이력은 삭제하지 않는다.

- 기존 Director 전용 MP4가 있고 연결 가능한 렌더 작업·프로젝트가
  있으면 새 참조 구조로 연결한다.
- 연결할 프로젝트가 없는 기존 MP4는 레거시 결과로 읽기 전용
  표시한다.
- 새 렌더부터 프로젝트 보관함을 단일 원본으로 사용한다.

## 검증

### 계약 테스트

- 일반 Clipper 프로젝트와 Director에서 준비한 프로젝트가 같은 Full
  템플릿 스냅샷과 타이틀 입력으로 동일한 render payload를 만든다.
- Director 최종 렌더가 `clipper_video_render` 작업으로 예약되고 전역
  큐 상태를 따른다.
- 실행 작업은 `clipper_video_render`, 출처 기능은
  `shortform_director`로 각각 보존된다.
- 대기·실행 중 큐 카드와 완료 작업 카드가 모두
  `AI 숏폼 디렉터`로 표시된다.
- 완료 작업이 `AI 숏폼 디렉터` 전용 섹션에 들어가고 기존 `클리퍼`
  섹션에는 들어가지 않는다.
- 한 시간 이상 `waiting` 상태인 작업도 polling 횟수 제한 없이
  WebSocket snapshot을 통해 계속 추적된다.
- 렌더 상태를 확인하기 위한 `setTimeout` 반복이나 상태 GET 반복이
  발생하지 않는다.
- terminal job event 한 번에 프로젝트 보관함 기록과 Director 렌더
  리비전 후처리가 각각 한 번만 수행된다.
- WebSocket 재연결 시 전체 snapshot으로 누락된 완료 상태를 복구한다.
- 완료 작업이 프로젝트 보관함 프로젝트와 Director 렌더 리비전에
  같은 결과 경로로 연결된다.
- 재렌더 성공·실패 시 활성 버전 승격 규칙을 지킨다.

### 템플릿 테스트

- Angular 모델이 `full` variant를 보존한다.
- Full 시스템 family를 선택하면 기본 비율이 `full`이다.
- 화면에 `1080×1920`이 표시되고 `1:1 비율 템플릿이 없습니다` 문구가
  나타나지 않는다.
- 새 템플릿 생성 화면에는 기존 `1:1`, `4:3`만 표시된다.
- 미리보기와 렌더 payload의 Full 템플릿 ID·버전이 동일하다.

### 회귀 테스트

- 기존 Clipper 숏폼 제작의 렌더 payload와 프로젝트 보관함 등록이
  바뀌지 않는다.
- 기존 `1:1`, `4:3` 템플릿 생성·편집 동작이 유지된다.
- 패키징 빌드는 사용자가 직접 수행한다. 구현 검증에서는 관련
  단위·통합 테스트와 일반 Angular/NestJS 빌드만 실행한다.
