# 프로모션 캠페인·코드 현재 설계

기준: 2026-10-23 KST, Web API `0776268`, 관리자 웹 `98e2e8c`, 회원 웹 `fbd4573`의 원격 `dev`.
이 문서는 현재 구현된 규칙을 설명한다. [10/12 결정 메모](2026-10-12-promotion-code-decisions-and-open-questions.md)와 [10/19 최초 설계](2026-10-19-promotion-referral-design.md)의 이후 변경 사항에는 이 문서를 우선한다.

## 캠페인과 코드

- 캠페인은 등록 기간, 지급 이용권 등급(Basic/Pro/Business), 이용 개월 수, 크레딧 유효기간, 회원 이력 제한, **코드별 성공 등록 상한**을 공유한다. 월 지급 크레딧은 선택한 이용권 등급의 설정에서 가져오며 관리자가 직접 입력하지 않는다.
- 캠페인은 코드 없이 만들고 상세 화면에서 하나 이상의 코드를 발급한다. 캠페인은 처음에 비활성 상태이며, 코드가 없거나 캠페인 종료일이 지났으면 활성화할 수 없다.
- 각 코드는 전역에서 고유한 영문 대문자·숫자·밑줄·하이픈 5~20자이며 선택적인 `추천인`을 가진다. 입력한 소문자는 대문자로 정규화한다. 추천인은 회원의 혜택 확인·참여 내역과 관리자 코드/성과 화면에 표시된다.
- 캠페인과 코드에는 각각 독립적인 활성 상태가 있다. 캠페인을 비활성화해도 소속 코드의 저장 상태를 일괄 변경하지 않는다. 회원 등록은 캠페인과 해당 코드가 모두 활성이고 등록 기간 안에 있을 때만 가능하다. 어느 한쪽을 중지해도 이미 지급한 혜택은 유지된다.
- 상한을 `2건`으로 설정하고 코드가 A·B 두 개라면 **A에서 최대 2건, B에서도 최대 2건** 성공 등록할 수 있다. 캠페인 전체 합계 2건을 뜻하지 않는다. 상한이 없으면 코드별 인원 제한이 없다.

## 저장 구조와 정합성

- Web API의 관리자 DB에서 `promotion_campaigns`가 공유 설정을, `promotion_codes`가 개별 코드·추천인·상태를, `promotion_redemptions`가 회원·실제 사용 코드·지급 이용권·회수 이력을 보존한다. 회수 후에도 등록 이력을 삭제하지 않는다.
- 지급 이용권과 크레딧은 기존 이용권·크레딧 장부에 `promotion` 출처와 등록 ID를 연결한다. 주문과 구독에도 직접 연결된 등록 ID를 보존한다. 회원 계정은 별도 user DB의 ID로 참조하며 DB 사이에 외래키를 만들지 않는다.
- 등록 거래에서 회원과 캠페인/코드를 잠그고 자격·코드별 누적 건수를 다시 검사한 뒤 등록·이용권·크레딧을 함께 저장한다. `(campaign_id, user_id)`의 고유 제약과 거래 검사를 함께 사용해 동시 등록의 중복 지급을 막는다.

## 회원 자격과 지급

- 한 회원은 **같은 캠페인에서 코드 하나만** 성공 등록할 수 있다. 회수된 등록도 이력으로 남아 재등록은 막힌다. 다른 캠페인 참여 이력 자체는 새 캠페인의 등록 제한이 아니다.
- 관리자가 캠페인마다 선택하는 과거 이력 제한은 `유료 이용권 결제·사용 이력`과 `관리자 지급 이용권 이력` 두 종류다. 선택한 이력 중 하나라도 있으면 만료된 이력도 포함해 등록을 막는다. 무료체험과 다른 캠페인 코드 등록 이력은 선택지가 아니다. AI 부스 캠페인은 생성할 때 유료 이력 제한만 고르면 된다. 실제 코드·날짜·상한 값은 운영자가 필요할 때 입력한다.
- 과거 이력 설정과 별개로, 현재 사용 중이거나 시작 예정인 주 이용권 또는 첫 결제가 진행·예약 중인 구독이 있으면 새 프로모션 이용권을 겹쳐 지급하지 않는다. 무료체험만 있는 경우는 등록할 수 있다.
- 혜택은 등록 시 시작하는 이용권과 그 등급에 따른 월별 크레딧이다. 크레딧은 기존 차감 순서와 각 지급분의 유효기간을 따른다. 캠페인 종료, 코드 중지, 이용권의 정상 만료만으로 기존 지급 크레딧을 회수하지 않는다. 활성 프로모션 이용권으로 추가 크레딧 구매가 가능하다.
- 관리자가 등록 혜택을 회수하면 해당 이용권을 종료하고 **그 등록으로 지급된 미사용 크레딧만** 회수한다. 이미 사용한 크레딧·사용 기록과 별도 구매/지급 크레딧은 남긴다. 회수 사유와 운영 기록을 보존한다. 기존 관리자 지급 기능 외에 별도 복구 기능은 없다.
- 회원이 같은 코드를 다시 확인하면 `해당 코드 참여 이력`을, 같은 캠페인의 다른 코드를 확인하면 `캠페인 참여 이력`을 우선 안내한다. 그다음에 코드/캠페인 상태, 기간, 코드별 상한, 현재 이용권, 선택된 과거 이력 제한을 검사한다. 코드 확인에서 혜택과 등록 불가 이유를 보여주고 실제 등록 거래에서 다시 검사한다.

## 유료 전환과 성과

- 프로모션 이용권 이용 중 회원은 종료 후 첫 유료 결제를 예약할 수 있다. 예약 버튼의 모달에서 현재 등급·기간을 확인하고, 같은 등급의 판매 상품을 선택하거나 기존 `/pricing` 화면에서 다른 상품을 고른다. 첫 결제일·상품·금액에 대한 회원 동의가 필요하다.
- 카드 등록이 끝나지 않은 신청은 완료된 예약으로 표시하지 않는다. 유효한 예약 상태와 취소는 회원 대시보드에서 관리한다. 첫 결제가 성공해야 유료 이용권과 그 크레딧을 지급한다. 실패 시 기존 관리자 재시도 설정을 사용하되, 첫 결제 성공 전에는 유료 이용권 유예를 주지 않는다. 회원이 첫 결제 전에 예약을 취소하면 청구하지 않는다.
- 관리자가 프로모션 혜택을 조기 회수해도 회원이 동의한 첫 유료 결제일은 자동으로 앞당기거나 취소하지 않는다. 회수와 예약 유지 사실을 회원에게 알린다.
- 성과 귀속은 회원의 최근 코드 추정이 아니라 **등록 ID와 주문·구독의 명시적 연결**을 따른다. 프로모션 이용 중 신청한 첫 유료 결제, 활성 기간에 시작한 추가 크레딧 구매, 그 구독의 이후 갱신·즉시 업그레이드 결제 및 환불을 구분한다. 무관하게 나중에 새로 시작한 독립 구독은 과거 코드에 귀속하지 않는다.
- 성과 조회 한 행은 **회원의 코드 등록 1건**이다. 등록 건수·유료 전환·환불 반영 순결제액을 주요 지표로 보고, 무료/구매 크레딧 사용량은 이용 분석용 보조 지표로 분리한다. 이는 인플루언서 지급액을 자동 산정하지 않는다. 조회 기간은 등록일에 적용하며 해당 등록의 이후 결제·사용도 포함한다. 코드·회원·기간 필터와 XLSX 내보내기를 제공한다.

## 관리자·회원 화면과 변경 제한

- 관리자 메뉴 이름은 `프로모션`이다. 목록은 캠페인별 한 행에 기간·지급 이용권·코드별 상한·첫 코드와 `외 N건`·상태를 보여준다. 상세에는 `프로모션 코드`, `성과 조회`, `등록 내역`, `운영 기록` 탭이 있다. 성과 조회는 연결된 금액/사용량의 분석표이고 등록 내역은 등록 상태 확인·잔여 혜택 회수용이다. 두 표 모두 회원 이메일을 우선 표시하고 빈 상태와 공통 페이지 이동 UI를 사용한다.
- 캠페인에 등록 이력이 없으면 설정을 수정하거나 캠페인과 발급 코드를 삭제할 수 있다. 등록 이력이 한 번이라도 생기면 삭제할 수 없고, 시작일·등급·이용 개월 수·크레딧 유효기간·이력 제한은 고정된다. 캠페인 이름, 종료일 연장, 코드별 상한 조정은 허용하되 상한을 어느 코드의 누적 등록 건수보다 낮출 수 없다. 등록 이력이 없는 개별 코드는 문자열·추천인을 수정할 수 있다.
- 회원 `/my/promotions`에는 코드 입력을 항상 위쪽에 표시한다. 참여 내역은 현재 사용 중인 건과 종료·회수된 과거 건을 여러 행으로 표시하며, 없으면 빈 상태를 보여준다. 코드 확인 모달에서 선택적인 추천인과 혜택, 등록 가능 여부를 확인한다. 내부 캠페인 이름은 회원에게 보여주지 않는다.

## 구현·검증의 경계

결제 승인·자동 청구·환불은 기존 Toss 경로에 연결한다. 이번 병합에서는 코드/DB/프런트엔드 테스트와 빌드를 확인했으며 실제 Toss 결제망을 통한 승인·자동 청구·환불이나 운영 배포는 검증하지 않았다. [최종 병합 기록](../implementation/2026-10-23-promotion-campaign-dev-merge.md)에 커밋과 검증 범위를 적었다.
