# 과금 작업 전체 화면 진행 차단 설계

## 목표

설치형 Angular 앱의 과금 작업에서 과금 확인창 전후의 비동기 대기 중 페이지 전체를 차단하고 중앙 스피너를 표시한다. 사용자는 대기 중인 페이지의 클립, 입력, 버튼 등에 마우스·키보드로 접근할 수 없어야 한다.

## 승인된 화면 흐름

1. 사용자가 과금 작업 버튼을 누르면 전체 화면의 어두운 스크림과 중앙 스피너를 즉시 표시한다.
2. 사전 검사, 파일 확인, 저장, 과금 견적 조회가 끝날 때까지 유지한다.
3. 과금 확인창을 열기 직전에 진행 차단을 제거하고 확인창만 표시한다.
4. 사용자가 취소하면 현재 페이지를 다시 조작할 수 있게 한다.
5. 사용자가 크레딧 사용을 승인하면 확인창이 닫히는 즉시 진행 차단을 다시 표시한다.
6. 작업 생성, 서버 응답, 상태 갱신, 보관함 이동이 완료되거나 오류가 나면 진행 차단을 제거한다.

확인창과 진행 차단은 동시에 보이지 않는다. 화면에는 진행 문구나 별도 카드 없이 스크림과 스피너만 보이고, 접근성 이름은 시각적으로 숨긴다.

## 구조

- 공용 UI는 `desktop/clipper_angular/src/shared/ui/blocking-progress/`에 standalone component와 root service로 둔다.
- `BlockingProgressService.open()`은 한 작업이 소유하는 `BlockingProgressRef`를 반환한다.
- ref는 `suspend()`, `resume()`, `close()`로 확인창 전환과 최종 정리를 담당한다.
- `OperationChargeGuardService.confirm()`에는 `beforeDialogOpen`과 `afterDialogClose` 선택 훅을 추가한다. 견적 조회 중에는 스피너를 유지하고, 확인창을 실제로 열기 직전에만 `beforeDialogOpen`을 호출한다.
- 각 호출부는 `try/finally`로 ref를 닫는다. 승인일 때만 `afterDialogClose`에서 스피너를 재개한다.

## 적용 범위

- 프롬프트·URL·붙여넣기 숏폼 생성
- 대사 하이라이트 생성
- 댄스 하이라이트 생성
- Variation 일괄 생성
- Variation 개별 결과 재생성
- 보관함의 유료 작업 재시도

결제 정책, API 순서, 크레딧 차감·환급, 백엔드 코드는 변경하지 않는다.

## 실패·취소 규칙

- 견적 실패, 사전 검사 실패, 작업 생성 실패, 라우팅 실패 모두 `finally`에서 차단을 제거한다.
- 과금 확인 취소 또는 크레딧 부족 안내 종료 뒤에는 스피너를 재개하지 않는다.
- 중복 클릭을 막는 기존 `asyncAction`과 pending guard는 유지한다.
