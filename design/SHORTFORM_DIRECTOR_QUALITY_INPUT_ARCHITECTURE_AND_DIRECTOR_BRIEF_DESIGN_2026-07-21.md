# AI 숏폼 디렉터 — 품질 중심 입력 아키텍처와 Director Brief 설계

작성일: 2026-07-21 KST
상태: 거시 설계안 · 구현 전 검증 필요
현재 단계: 입력 품질 모델과 중간 산출물을 정의하며 production 코드·API·DB 구현은 시작하지 않는다.

## 0. 문서 목적과 기존 설계와의 관계

이 문서는 AI 숏폼 디렉터가 만들어내는 영상의 품질을 높이기 위해 **무엇을 입력으로
수집하고, 어떤 판단 과정을 거쳐 영상 기획으로 변환해야 하는지**를 정의한다.

기존 문서
`SHORTFORM_DIRECTOR_PERSISTENT_CONTENT_OPERATIONS_AND_VIRA_INTEGRATION_DESIGN_2026-07-21.md`의
다음 구조는 유지한다.

```text
운영 프로필
  → 콘텐츠 프로젝트
  → 콘텐츠 트랙
  → 영상 아이디어
  → 제작 실행
  → 결과 영상
```

다만 기존 설계가 `사용자 목적 + Vira 데이터`를 중심으로 입력을 설명했다면, 이 문서는
입력 품질을 더 넓게 재정의한다. Vira는 중요한 외부 관측 데이터의 source of truth이지만
전체 입력 시스템의 한 축이다.

이 문서는 기존 설계 문서나 V1/V2 목업을 대체하지 않는다. 품질 입력 아키텍처가 승인되기
전까지 목업은 UI 탐색안이며 구현 계약이 아니다.

## 1. 출발점

현재 Clipper Studio의 `프롬프트로 영상생성` 플러그인이 만드는 숏폼은 사용자가 매력을
느끼기 어려울 정도로 품질이 낮다. 단순히 렌더 오류나 해상도의 문제가 아니라 다음 문제가
겹쳐 있다.

- 입력 prompt가 짧거나 모호해 영상이 일반론을 반복한다.
- 영상이 누구를 위해 무엇을 말해야 하는지 충분히 판단하지 못한다.
- 대사에 검색 이미지가 순차적으로 붙는 구조가 반복된다.
- 주장과 근거, 장면과 에셋의 관계가 약하다.
- 설명에 도식이나 수치 시각화가 필요해도 같은 이미지 슬라이드 방식으로 처리한다.
- 생성 결과에서 무엇이 좋고 나빴는지 다음 영상에 학습되지 않는다.

AI 숏폼 디렉터는 이 문제를 검증하기 위한 독립 플러그인이다. 품질 개선 방향은 크게 두
축으로 구분한다.

1. **기획 입력과 판단 재료 개선**
   사용자 목적, 공식 자료, 시청자 정보, 시장 데이터, 레퍼런스와 과거 성과를 구조화한다.
2. **영상 생성과 표현 방식 개선**
   장면별 에셋 선택, 생성형 이미지·영상, 도식, 모션 그래픽, 대사·장면 매칭을 개선한다.

현재 우선순위는 첫 번째다. 그러나 두 방향을 완전히 분리하지 않는다. 입력 단계에서 이미
`어떤 내용을 어떤 시각 표현으로 전달할지`를 계획해야 두 번째 개선이 실제 품질로 연결된다.

## 2. 문제 재정의

### 2.1 입력을 많이 받는 것이 목표가 아니다

다음 등식은 성립하지 않는다.

```text
입력 필드 증가 = 정보 증가 = 영상 품질 증가
```

필드가 많아지면 사용자는 피로해지고, 모델은 중요도가 다른 정보를 한꺼번에 받아 핵심을
잃을 수 있다. 입력 품질의 핵심은 다음 세 가지다.

- 신뢰할 수 있는 자료가 있는가
- 이번 영상에 필요한 자료를 선별했는가
- 자료를 어떤 편집 판단으로 변환했는가

따라서 제품 목표는 `더 긴 prompt 만들기`가 아니라 **좋은 Director Brief를 컴파일하는
시스템**이다.

### 2.2 관련성과 시의성만으로는 충분하지 않다

운영 프로필은 대상 적합성을 높이고 Vira는 최신성과 시장 관련성을 높인다. 하지만 두
정보만으로 다음을 보장할 수 없다.

- 새로운 관점이 있는가
- 시청자가 실제로 궁금해하는가
- 주장을 증명할 근거가 있는가
- 첫 장면부터 끝까지 볼 이유가 있는가
- 시각적으로 보여줄 수 있는가
- 기존 영상과 다른가

현재 설계가 운영 프로필과 Vira에만 고정되면 `시의성은 있지만 뻔한 영상`을 대량으로
생산할 위험이 있다.

## 3. NotebookLM 벤치마크에서 가져올 원리

NotebookLM을 기능 단위로 복제하지 않는다. 공식 설명에서 확인되는 다음 설계 원리를
벤치마킹한다.

### 3.1 출처 기반 생성

NotebookLM은 사용자가 선택한 문서, 웹사이트, YouTube, 오디오, Google Docs·Slides 등의
자료를 notebook source로 사용한다. 결과물은 이 출처를 바탕으로 구성된다.

Clipper에 적용할 원리:

- 영상 생성 전에 프로젝트별 source library가 있어야 한다.
- 사실과 주장은 source reference를 가져야 한다.
- 외부 관측과 AI 해석을 구분해야 한다.

### 3.2 대상과 초점에 따른 변환

NotebookLM Video Overview는 사용자가 대상, 학습 목표와 집중할 주제를 지정할 수 있다.
같은 자료도 대상과 목적에 따라 다른 결과물로 변환한다.

Clipper에 적용할 원리:

- 사용자 목적은 단순 메타데이터가 아니라 자료 선별 기준이어야 한다.
- 같은 프로젝트에서도 영상 한 편마다 시청자 상태와 전달 목표가 달라질 수 있다.
- 프로젝트 기본값과 이번 영상의 episode intent를 분리한다.

### 3.3 설명에 맞는 시각 표현

NotebookLM의 Video Overview는 출처의 이미지뿐 아니라 도식, 인용, 수치와 새로 생성한
시각 자료를 사용해 개념을 설명한다. Short 형식은 약 60초 안에 핵심을 압축한다.

Clipper에 적용할 원리:

- 장면마다 `검색 이미지`를 기본값으로 두지 않는다.
- 설명 대상에 따라 공식 클립, 제품 컷, 생성형 영상, 도식, 수치 그래프, 텍스트 모션을
  선택한다.
- 입력 설계가 장면의 시각화 가능성을 평가해야 한다.

### 3.4 Creative Director와 자기 검토

Google은 Cinematic Video Overviews에서 Gemini가 creative director로서 내러티브, 시각
스타일과 형식에 관한 많은 결정을 내리고 일관성을 위해 결과를 다시 다듬는다고 설명한다.

Clipper에 적용할 원리:

- 하나의 LLM 호출로 prompt를 VideoPlan으로 바로 변환하지 않는다.
- 자료 선별, 콘텐츠 기회, Director Brief, 장면 계획을 구분한다.
- 기획 결과를 품질 기준으로 검토하고 부족하면 렌더 전에 보완한다.

## 4. 품질 모델

숏폼 품질을 다음 요소의 결합으로 본다.

```text
Source quality
  × Editorial selection
  × Audience relevance
  × Narrative quality
  × Visualizability
  × Production execution
  × Feedback learning
  = Perceived shortform quality
```

한 요소가 매우 낮으면 다른 요소가 좋아도 전체 품질이 제한된다.

- 자료가 정확해도 전개가 지루하면 보지 않는다.
- 트렌드가 맞아도 새 정보가 없으면 매력이 없다.
- 기획이 좋아도 장면이 검색 이미지 나열이면 완성도가 떨어진다.
- 한 번 좋은 영상이 나와도 피드백을 축적하지 않으면 재현할 수 없다.

현재 단계는 `Source quality`부터 `Visualizability`까지를 Director Brief에 담는 것을 목표로
한다. 실제 생성형 영상·도식 renderer 개선은 별도 단계지만 필요한 표현 의도는 지금부터
기록한다.

## 5. 설계 원칙

### 5.1 자료의 양보다 선별과 출처가 중요하다

프로젝트에 많은 자료를 저장할 수는 있지만 영상 한 편에는 필요한 부분만 선택한다. 선택된
자료는 source id, 관측 시점과 사용 목적을 가진다.

### 5.2 관측 사실과 기획 해석을 분리한다

예시:

```text
관측 사실:
  특정 영상의 최근 성장속도가 같은 게시 시기 영상 중 상위 6%다.

허용되는 기획 해석:
  첫 3초의 구성과 팬 반응을 살펴보는 영상 아이디어로 발전시킨다.

허용되지 않는 단정:
  첫 3초 구성 때문에 조회수가 상승했다.
```

Vira나 다른 source가 제공하지 않은 원인과 관계를 사실처럼 만들지 않는다.

### 5.3 영속 맥락과 일회성 맥락을 분리한다

- 영속 맥락: 운영 프로필, 프로젝트 정체성, 공식 source, 표현 원칙, 누적 피드백
- 일회성 맥락: 이번 영상의 목표, 사용할 signal, 이벤트, 마감과 출력 조건

과거 영상은 생성 시점의 일회성 맥락 snapshot을 보존한다.

### 5.4 사용자의 직접 입력을 최소화한다

정보 획득 우선순위는 다음과 같다.

1. 이미 저장된 프로젝트 기본값 재사용
2. 업로드·URL·연결된 서비스에서 가져오기
3. 시스템이 추천·추론하고 사용자가 확인하기
4. 꼭 필요한 값만 직접 입력받기
5. 결과에 대한 사용자 행동에서 학습하기

### 5.5 입력 단계부터 표현 가능성을 평가한다

좋은 주제라도 현재 확보할 수 있는 에셋과 표현 방법이 없으면 좋은 영상이 되기 어렵다.
Director Brief는 장면별로 필요한 표현 형태와 확보 가능성을 함께 기록한다.

### 5.6 모든 영상에 같은 생성 경로를 강제하지 않는다

트렌드 영상, 제품 설명, 교육 콘텐츠와 후속편은 필요한 입력의 우선순위가 다르다. 프로젝트
목적과 episode intent에 따라 적합한 생성 경로를 선택한다.

### 5.7 결과를 다음 입력으로 되돌린다

성과 지표뿐 아니라 사용자가 어떤 아이디어를 선택·보류·수정했는지도 프로젝트의
performance memory에 축적한다.

## 7. 입력의 일곱 가지 축

### 7.1 정체성·목적

누구를 위해 왜 콘텐츠를 운영하는지 정의한다.

포함 정보:

- 운영 프로필의 역할과 분야
- 프로젝트 대상과 장기 목적
- 콘텐츠 트랙
- 주 플랫폼과 언어
- 기본 시청자
- 말투, 분위기와 브랜드 원칙
- 금지 표현, 권리와 안전 기준
- 선택적 캠페인 목표와 CTA

이 정보는 매번 다시 입력하지 않고 상속과 override로 관리한다.

### 7.2 공식 지식과 source library

영상에서 사실로 사용할 수 있는 자료의 저장소다.

source 유형:

- 공식 웹페이지와 URL
- PDF, 문서, 프레젠테이션
- 제품 설명서와 사양표
- 보도자료와 공식 공지
- 공식 YouTube·SNS 영상
- 사용자가 소유한 이미지·영상·오디오
- 인터뷰와 발언 원문
- 사용자가 작성한 메모와 claim

source가 가져야 할 최소 속성:

- source id와 유형
- 제목과 원본 위치
- 공식·사용자 소유·제3자 등 권위 수준
- 수집·업로드 시점과 자료 기준일
- 권리·사용 가능 범위
- 추출된 claim과 인용 위치
- 최신성 또는 만료 여부
- 프로젝트·트랙 연결

source library는 파일 보관함만이 아니다. 기획에 사용할 수 있는 claim과 evidence를
검색·선별하는 지식 기반이다.

### 7.3 시청자 정보

시청자가 실제로 궁금해하고 반응하는 것을 알려준다.

가능한 source:

- 기존 채널 댓글
- 경쟁·관련 영상 댓글
- 자주 묻는 질문
- 제품 리뷰와 커뮤니티 질문
- CS·상담·영업 단계의 반복 질문
- 검색 query와 자동완성 후보
- 영상별 시청자 반응
- 사용자가 직접 입력한 시청자 가설

초기 버전에서 모든 source 연결을 구현하지 않는다. 사용자가 선택한 댓글, 질문 목록과
간단한 업로드부터 검증할 수 있다.

### 7.4 시장·트렌드 정보

외부에서 지금 무엇이 관찰되는지를 제공한다. Vira가 핵심 source of truth다.

Vira가 담당할 수 있는 범위:

- 수집된 숏폼 원본과 메타데이터
- 조회수 snapshot과 성장속도
- 키워드·카테고리·태그
- 댓글 반응 집계
- 근거 영상
- 향후 검증된 시장·트렌드 signal

Clipper가 담당할 범위:

- 프로젝트에 필요한 Vira 결과 조회
- 생성에 사용한 Vira source id와 snapshot 보존
- 관측 사실을 Director Brief의 evidence로 연결
- Vira 원본 상세 화면으로 이동

Clipper는 Vira의 수집, 시장 필터, 성장점수 계산과 분석 화면을 복제하지 않는다.

### 7.5 창작 레퍼런스와 표현 문법

사용자가 `이런 느낌으로 만들고 싶다`고 판단한 영상에서 내용이 아니라 표현 방식을
추출한다.

추출 후보:

- 훅 유형과 첫 장면 구성
- 전개 속도와 beat 수
- 컷 리듬
- 내레이션 밀도
- 자막과 화면 관계
- 도식·비교·실험·리스트 등 설명 형식
- payoff와 CTA 방식
- 시각적 일관성

원본의 문장, 장면과 창작 표현을 그대로 복제하지 않는다. 재사용 가능한 구조와 문법만
참조하고 reference source를 표시한다.

### 7.6 과거 성과와 편집 피드백

Clipper에서 만들어진 영상과 사용자의 선택을 다음 제작에 반영한다.

정량 정보 예시:

- 노출 대비 시청 비율
- 평균 시청 시간과 완주율
- 반복 재생
- 이탈 구간
- 댓글·공유·저장
- 플랫폼별 성과

정성 정보 예시:

- 사용자가 선택·보류·제외한 아이디어
- 제목, 대사와 장면의 수동 수정
- 에셋 교체 이유
- 승인·반려 메모
- `이 영상은 좋다/나쁘다` 피드백

초기 버전은 플랫폼 성과 API 없이도 제품 내부 행동부터 축적할 수 있다.

### 7.7 실행 조건과 제작 가능성

기획이 실제 영상으로 만들어질 수 있는지 판단하는 입력이다.

- 목표 길이와 화면 비율
- 출력 플랫폼
- 사용 가능한 공식·owned 에셋
- 검색 가능한 에셋
- 생성형 이미지·영상 사용 허용 여부
- 도식·그래프 필요 여부
- 인물 얼굴과 권리 제한
- 제작 시간과 비용 한도
- renderer가 지원하는 장면 유형

이 축은 입력 품질과 영상 생성 방식을 연결한다.

## 8. 정보 획득 방식

사용자에게 모든 정보를 form으로 받지 않는다.

| 방식 | 설명 | 예시 |
|---|---|---|
| 기본값 재사용 | 운영 프로필·프로젝트에서 상속 | 플랫폼, 언어, 표현 원칙 |
| 직접 입력 | 의미가 분명하고 꼭 필요한 최소값 | 프로젝트 이름, 이번 목표 |
| 선택형 입력 | dropdown·chip·preset | 목적, 대상 유형, 영상 형식 |
| source 추가 | 파일·URL·미디어를 등록 | 제품 PDF, 공식 영상 |
| 서비스 연결 | 외부 시스템에서 읽기 | Vira, 향후 채널 analytics |
| AI 추천 후 확인 | 자료에서 후보를 제안 | 시청자 질문, 트랙, 키워드 |
| 행동 학습 | 선택·수정·성과에서 축적 | 선호 훅, 반려 사유 |

AI가 추론한 값은 `확정 사실`이 아니라 추천값으로 표시한다. 사용자가 확인하지 않아도
사용할 수 있는 값과 반드시 확인해야 하는 값의 정책을 분리한다.

## 9. 콘텐츠 생성 경로

프로젝트는 하나 이상의 생성 경로를 사용할 수 있다. 초기에는 시스템이 추천하고 사용자가
확인하는 방식이 적합하다.

### 9.1 트렌드 대응형

중요 입력:

- Vira 최신 관측
- 시점과 근거 영상
- 프로젝트 관련성
- 공식 source

적합한 예:

- 아이돌 관련 최신 이슈
- 신제품·시장 변화
- 갑자기 성장하는 포맷 대응

### 9.2 source 해설형

중요 입력:

- 공식 문서와 영상
- 핵심 claim과 수치
- 시청자 지식 수준
- 도식화 가능성

NotebookLM에 가장 가까운 경로다.

### 9.3 제품·서비스 설득형

중요 입력:

- 제품 공식 claim
- 경쟁 비교 기준
- 사용자 질문·리뷰
- 광고·표현 안전 기준
- 원하는 행동

### 9.4 팬·인물 콘텐츠형

중요 입력:

- 공식 활동과 발언
- 팬 질문과 반응
- 관련 영상과 최신성
- 사생활·추측 방지 정책

### 9.5 에버그린 정보형

중요 입력:

- 전문 source
- 반복 검색 질문
- 이해하기 어려운 개념
- 설명용 도식과 예시

### 9.6 후속편 최적화형

중요 입력:

- 이전 영상 성과
- 이탈·반복 구간
- 댓글과 후속 질문
- 사용자 수정 이력

## 10. Episode Research Pack

프로젝트 전체 자료를 한 번에 LLM에 전달하지 않는다. 영상 아이디어 생성 실행마다 필요한
자료만 모아 `Episode Research Pack`을 만든다.

개념 필드:

```text
EpisodeResearchPack
  project_snapshot
  track_snapshot
  episode_intent
  audience_context
  selected_official_sources[]
  selected_audience_signals[]
  selected_market_observations[]
  selected_creative_patterns[]
  selected_performance_learnings[]
  production_constraints
  unavailable_or_stale_sources[]
  assembled_at
```

원칙:

- source의 원문과 요약을 구분한다.
- 관측 시점과 최신성을 보존한다.
- 사용한 자료와 제외한 자료를 추적할 수 있다.
- 연결 실패 시 과거 값을 최신 데이터처럼 사용하지 않는다.
- Research Pack은 생성 당시 immutable snapshot으로 보관한다.

## 11. Content Opportunity

`Vira signal`, `사용자 목적`, `공식 자료`를 곧바로 영상 아이디어로 바꾸지 않는다. 먼저
이 자료 조합이 실제로 한 편의 영상이 될 가치가 있는지 판단하는 `Content Opportunity`를
만든다.

정의:

```text
Content Opportunity
  = audience tension or question
  + useful or timely information
  + usable evidence
  + project relevance
  + visualizable payoff
```

개념 필드:

- opportunity title
- audience tension 또는 질문
- 새롭게 줄 수 있는 정보
- 프로젝트와의 연결 이유
- 근거 source 목록
- 최신성
- 예상 훅 방향
- 가능한 payoff
- 시각화 후보
- 유사 아이디어·과거 영상과의 중복
- 위험과 불확실성
- 품질 평가

### 11.1 기회 평가 기준

초기에는 자동 점수 하나로 숨기지 않고 항목별 평가를 보여준다.

| 기준 | 질문 |
|---|---|
| 시청자 관련성 | 대상 시청자가 실제로 궁금해할 이유가 있는가 |
| 새로움 | 기존 아이디어나 일반론과 다른 정보가 있는가 |
| 근거 충분성 | 핵심 주장을 뒷받침할 source가 있는가 |
| 프로젝트 적합성 | 프로젝트 정체성과 목적에 맞는가 |
| 시의성 | 지금 만들 이유가 있는가 |
| 시각화 가능성 | 화면으로 보여줄 수 있는가 |
| 제작 가능성 | 권리·에셋·시간·비용 안에서 만들 수 있는가 |
| 안전성 | 과장·추측·오해 위험을 통제할 수 있는가 |

평가가 낮은 기회는 억지로 영상을 생성하지 않고 자료 부족, 중복, 시각화 어려움 등의 이유를
표시한다.

## 12. Director Brief

Director Brief는 풍부한 입력을 실제 영상 기획으로 바꾸는 핵심 중간 산출물이다. 긴 prompt가
아니며 VideoPlan도 아니다.

```text
DirectorBrief
  identity
    project
    track
    generation_route

  audience
    target_viewer
    current_knowledge
    tension_or_question
    desired_after_state

  editorial
    one_sentence_thesis
    content_promise
    novelty
    tone
    hook_candidates[]
    recommended_hook
    narrative_arc
    payoff
    cta

  claims[]
    claim
    evidence_refs[]
    confidence
    allowed_wording
    prohibited_overstatement

  beats[]
    purpose
    narration_intent
    visual_intent
    evidence_refs[]
    asset_intent
    duration_target

  production
    target_duration
    aspect_ratio
    visual_language
    allowed_asset_sources
    generated_media_policy
    diagram_requirements
    rights_constraints

  quality
    relevance
    novelty
    evidence_sufficiency
    visualizability
    feasibility
    risks[]

  provenance
    research_pack_id
    opportunity_id
    generated_at
```

실제 API DTO나 DB schema는 검증 후 별도로 확정한다. 현재 필드는 판단 누락을 찾기 위한 개념
모델이다.

### 12.1 Director Brief와 VideoPlan의 차이

| Director Brief | VideoPlan |
|---|---|
| 무엇을 왜 말할지 결정 | 시간축 위에서 어떻게 재생할지 결정 |
| 주장·근거·시청자·훅을 정의 | scene, caption, TTS, asset slot을 정의 |
| 시각 표현 의도를 기술 | 실제 에셋과 renderer instruction을 연결 |
| 여러 제작 방식에 독립적 | 특정 rendering pipeline과 밀접 |

Director Brief는 향후 Motion Canvas, 생성형 영상, 도식 renderer 등 다른 제작 방식에서도
재사용할 수 있어야 한다.

## 13. 주장과 근거 계약

모든 핵심 claim은 하나 이상의 evidence reference를 가져야 한다. evidence가 없는 내용은
다음 중 하나로 분류한다.

- 사용자 의견
- AI 기획 가설
- 창작적 표현
- 확인 필요

화면과 결과물에서 필요한 구분:

- `관측 사실`: source가 직접 제공한 값
- `공식 사실`: 권위 있는 공식 source에서 확인한 내용
- `시청자 반응`: 댓글·질문·리뷰의 관측 또는 요약
- `AI 기획 해석`: 사실을 콘텐츠로 구성하기 위한 제안
- `가설`: 추가 확인이 필요한 관계

`함께 상승했다`와 `A 때문에 B가 상승했다`를 구분한다. 상관관계로 관측된 내용을 인과로
변환하지 않는다.

## 14. 시각 표현 의도와 두 품질 방향의 연결

입력 개선 단계에서도 각 beat가 요구하는 표현을 지정한다.

| 설명 목적 | 우선 검토할 표현 |
|---|---|
| 공식 장면을 보여주기 | owned·공식 영상 클립 |
| 제품 외형·사용 상황 | owned asset, 검색 이미지·영상, 생성형 장면 |
| 수치 변화 | 선 그래프, 막대, 숫자 모션 |
| 구조·원리 설명 | 실시간 도식, 단계별 애니메이션 |
| 비교 | 표, split screen, before/after |
| 감정·분위기 전달 | 생성형 영상, 분위기 B-roll |
| 인용·발언 | 원문 인용 카드와 출처 |
| 핵심 문장 강조 | 타이포그래피와 모션 |

Director Brief는 구체적인 에셋 파일을 고르지 않지만 다음을 명시한다.

- 왜 시각 자료가 필요한가
- 무엇을 보여줘야 하는가
- 사실 증명용인지 분위기 전달용인지
- 허용되는 source 유형은 무엇인가
- 생성형 미디어 사용이 가능한가
- 도식이 필요한가

이 계약이 있어야 에셋 자동 준비와 renderer 개선이 기획 의도에 맞게 동작한다.

## 15. 피드백 루프

대량 자동 제작을 하려면 좋은 결과를 우연히 한 번 만드는 것보다 다음 제작에서 재현하는
것이 중요하다.

```text
아이디어 생성
  → 사용자 선택·보류·제외
  → Director Brief 수정
  → 에셋 교체
  → 영상 완성
  → 내부 평가
  → 게시 후 성과
  → 프로젝트별 learning 생성
  → 다음 Research Pack에 선택적으로 반영
```

### 15.1 초기부터 수집할 수 있는 피드백

- 어떤 아이디어를 제작 선택했는가
- 보류·제외 사유는 무엇인가
- 제목과 한 문장 핵심 주장을 어떻게 수정했는가
- 어떤 훅을 선택했는가
- 어떤 에셋을 수동 교체했는가
- 어떤 장면을 삭제·추가했는가
- 결과 영상을 사용자가 좋음·나쁨으로 평가했는가

### 15.2 향후 연결할 수 있는 성과

- 시청 유지율과 완주율
- 초반 이탈
- 반복 재생
- 공유·저장·댓글
- 플랫폼별 결과

성과를 단순히 `잘된 포맷 재사용`으로 처리하지 않는다. 주제, 시청자, 훅, 전개와 표현
방식의 조건을 함께 보존한다.

## 16. 사용 사례 검증

### 16.1 립스틱 트렌드 프로젝트

입력:

- 프로젝트 목적: 립 제품 트렌드 큐레이션
- 공식 source: 브랜드별 신제품 페이지와 제품 사양
- 시청자 정보: 발색, 지속력, 피부톤 관련 질문
- Vira: 빠르게 성장하는 립 관련 영상과 근거 영상
- 레퍼런스: 손등 발색 비교, split screen, 순위형 전개
- 과거 성과: 색상 비교 영상의 완주율이 높음

Content Opportunity 예시:

> 최근 성장 영상에서 저채도 색상 비교가 반복되고, 시청자는 피부톤별 차이를 많이 묻는다.
> 공식 발색 자료가 있는 제품만 사용해 피부톤별 선택 기준을 설명한다.

### 16.2 음식물 처리기 시장과 브랜드 A

입력:

- 프로젝트 목적: 시장 정보를 제공하면서 브랜드 A 장점을 자연스럽게 전달
- 공식 source: 처리 방식, 용량, 소음, 인증과 관리 방법
- 시청자 정보: 냄새, 세척, 전기료 질문
- Vira: 최근 성장하는 음식물 처리기 영상과 사용 포맷
- 경쟁 정보: 비교 가능한 공개 사양
- 안전 기준: 근거 없는 1위·최고·완전 제거 표현 금지

Content Opportunity 예시:

> 시청자는 용량보다 냄새와 세척을 반복적으로 질문한다. 시장의 관리 방식 차이를 먼저
> 설명하고 공식 근거가 있는 범위에서 브랜드 A의 편의성을 보여준다.

### 16.3 아이돌 그룹 상시 콘텐츠

입력:

- 프로젝트 정체성: 공식 활동과 팬 친화형 정보
- 공식 source: 무대, 인터뷰, 공지와 SNS
- 시청자 정보: 팬 댓글과 질문
- Vira: 관련 영상 성장속도, 키워드와 근거 영상
- 안전 기준: 사생활 추측, 관계·원인 단정 금지
- 과거 피드백: 착장 정보형 아이디어 선택률이 높음

Content Opportunity 예시:

> 공식 무대 영상이 같은 게시 시기 영상 중 빠르게 성장하고 질문 댓글이 많다. 성장 원인을
> 단정하지 않고 첫 장면과 팬 질문을 공식 정보로 설명하는 숏폼을 만든다.

### 16.4 일반 유튜버·전문 지식 채널

입력:

- 운영 프로필: 경제 지식을 쉽게 설명하는 개인 채널
- source library: 기사, 통계와 사용자가 작성한 메모
- 시청자 정보: 어려워하는 용어와 반복 질문
- 레퍼런스: 화이트보드형 도식과 사례 중심 전개
- 과거 성과: 정의부터 시작한 영상보다 사례 훅의 유지율이 높음

Content Opportunity 예시:

> 시청자가 금리와 채권 가격 관계를 반복해서 어려워한다. 정의 대신 시소 도식과 실제 숫자
> 예시로 시작하는 50초 설명 영상을 만든다.

이 사례는 브랜드나 Vira가 없어도 AI 숏폼 디렉터가 유용해야 한다는 것을 확인한다.

## 17. 현재 영속 운영 설계에 미치는 영향

### 17.1 유지할 구조

- 운영 프로필
- 콘텐츠 프로젝트
- 콘텐츠 트랙
- 선택적 캠페인
- 영속 영상 아이디어 보관함
- 제작함과 결과 영상
- immutable 생성 snapshot

### 17.2 강화할 구조

콘텐츠 프로젝트 아래에 다음 개념을 추가로 검토한다.

```text
콘텐츠 프로젝트
  ├─ 프로젝트 정체성
  ├─ Source Library
  ├─ Audience Memory
  ├─ Vira Evidence References
  ├─ Creative Pattern References
  ├─ Performance Memory
  ├─ 콘텐츠 트랙
  ├─ Episode Research Packs
  ├─ Content Opportunities
  ├─ Director Briefs
  ├─ 영상 아이디어
  └─ 제작 실행
```

이 계층은 개념 모델이며 그대로 DB 테이블을 만들라는 의미가 아니다. 검증 후 합치거나
축소할 수 있다.

### 17.3 UI 목업에 대한 시사점

현재 V2 목업의 `사용한 근거`, `Vira 관측 사실 / AI 기획 해석` 구분은 유지할 가치가 있다.
다만 이후 목업에서는 Vira뿐 아니라 다음 정보가 함께 보여야 한다.

- 공식 source
- 시청자 질문
- 창작 레퍼런스에서 추출한 표현 패턴
- 과거 성과와 사용자 피드백
- 장면별 visual intent

새 UI를 바로 확정하지 않는다. 먼저 입력 축과 Director Brief가 사례별로 유효한지 검증한다.

## 18. 구현 전 검증 계획

### 18.1 목표

UI와 DB를 먼저 만들지 않고 어떤 입력이 실제 기획 품질을 높이는지 확인한다.

### 18.2 동일 주제 입력 비교

같은 주제에 대해 다음 Research Pack 변형으로 Director Brief와 storyboard를 생성한다.

1. 기존 짧은 prompt만
2. prompt + 운영 프로필
3. 2 + 공식 source
4. 3 + 시청자 질문
5. 4 + Vira 관측
6. 5 + 창작 레퍼런스
7. 6 + 과거 피드백

첫 실험에서는 전체 MP4를 모두 렌더할 필요가 없다. 입력 효과를 격리하기 위해 다음까지만
비교한다.

- Content Opportunity
- Director Brief
- 대사 초안
- scene storyboard
- visual intent

### 18.3 평가 기준

각 결과를 동일한 rubric으로 평가한다.

- 구체성
- 새로움
- 시청자 관련성
- 사실·근거 정확성
- 훅과 payoff
- 시각화 가능성
- 프로젝트 적합성
- 제작 가능성
- 기존 결과 대비 차별성

평가자는 사용자와 내부 검토자가 함께 참여한다. LLM self-score만으로 결정하지 않는다.

### 18.4 검증 시나리오

최소 다음 네 유형을 사용한다.

- 브랜드 없는 트렌드 큐레이션
- 특정 제품을 포함한 시장 정보
- 인물·아이돌 상시 콘텐츠
- 일반 유튜버의 전문 지식 설명

한 유형에서만 좋은 설계를 범용 구조로 확정하지 않는다.

### 18.5 승인 기준

다음이 확인된 뒤 UI와 schema 설계로 이동한다.

- 공식 source 추가가 일반론을 유의미하게 줄인다.
- 시청자 정보가 영상의 질문과 payoff를 구체화한다.
- Vira가 필요한 유형과 필요하지 않은 유형을 구분할 수 있다.
- 레퍼런스가 내용 복제 없이 표현 방식을 개선한다.
- Director Brief가 VideoPlan보다 앞선 독립 산출물로 유용하다.
- visual intent가 실제 제작 방식 결정에 사용할 수 있다.
- 사용자가 직접 입력해야 하는 값이 과도하지 않다.

## 19. 단계 제안

### Phase A — 품질 모델 검증

- 네 가지 대표 시나리오용 source pack 준비
- Content Opportunity와 Director Brief 수동·LLM 실험
- 입력 조합별 결과 비교
- 품질 rubric과 실패 사례 기록

### Phase B — 정보 모델 축소

- 검증에서 효과가 없었던 필드 제거
- 영속 정보와 episode 정보 확정
- source provenance와 snapshot 정책 확정
- 사용자 직접 입력과 자동 획득 범위 확정

### Phase C — UI 재설계

- 프로젝트 source library
- 시청자 질문과 Vira 관측 요약
- Content Opportunity 검토
- Director Brief 상세·수정
- 아이디어별 근거와 visual intent

### Phase D — 최소 production 연결

- 기존 AI 숏폼 디렉터의 VideoPlan 앞에 Director Brief 추가
- 한 가지 생성 경로부터 연결
- 기존 Motion Canvas 렌더 파이프라인 유지
- 전체 결과를 기존 prompt-only 결과와 비교

### Phase E — 시각 표현 확대

- 생성형 이미지·영상
- 실시간 도식과 수치 시각화
- 장면별 asset strategy
- 결과 검토와 자동 refinement

### Phase F — 성과 학습과 자동화

- 사용자 편집·승인 행동 학습
- 플랫폼 성과 연결
- 다음 아이디어 추천에 performance memory 반영
- 예약·야간 대량 제작

## 20. 비범위

현재 문서 단계에서 다음은 하지 않는다.

- Angular/Nest/Vira production 코드 수정
- DB schema와 migration 확정
- 구체적인 API URL·DTO 확정
- Vira 수집·분석 UI 복제
- 모든 외부 데이터 연결 구현
- 생성형 영상 provider 확정
- renderer 교체
- 자동 게시
- 야간 무인 대량 제작
- LLM 점수만으로 아이디어 자동 승인

## 21. 성공 기준

설계 검증이 성공하면 다음 질문에 답할 수 있어야 한다.

- 왜 이 영상 아이디어가 생성됐는가
- 어떤 사실과 관측값을 사용했는가
- 시청자가 왜 관심을 가질 것이라고 판단했는가
- 무엇이 새롭거나 유용한가
- 각 주장을 무엇으로 증명하는가
- 각 장면을 왜 그 방식으로 보여주는가
- 현재 에셋과 renderer로 만들 수 있는가
- 과장·추측과 권리 위험은 무엇인가
- 사용자의 선택과 결과가 다음 제작에 어떻게 반영되는가

최종 목표는 `더 많은 정보를 입력한 영상`이 아니라 다음 조건을 만족하는 영상이다.

```text
근거가 있고
대상에게 관련성이 있으며
한 편마다 분명한 관점과 payoff가 있고
화면으로 설명할 수 있으며
다음 제작에서 품질을 재현할 수 있는 숏폼
```

## 22. 후속 결정 항목

UI·구현 전 다음을 사용자와 함께 결정한다.

- 첫 검증에서 사용할 네 가지 실제 주제와 source
- 프로젝트 source library의 최소 입력 방식
- 시청자 정보의 초기 source 범위
- 창작 레퍼런스를 사용자가 직접 고를지 시스템이 추천할지
- Content Opportunity와 영상 아이디어를 별도 단계로 보여줄지
- Director Brief에서 사용자가 수정할 핵심 항목
- 품질 rubric의 항목과 평가 방식
- 첫 production 연결에 사용할 생성 경로
- visual intent와 기존 VideoPlan의 경계
