## 1. 확정된 제품 요구

### 공통 프로모션 코드 기능

- 이번 AI 부스 행사만을 위한 일회성 기능이 아니라, 이후 행사·인플루언서 홍보에도 다시 사용할 수 있는 프로모션 코드 등록 기능이다.
- 회원은 Clipper 웹사이트에서 가입·로그인한 뒤 **인쇄되거나 안내받은 텍스트 코드를 직접 입력**한다.
- 관리자는 캠페인과 그 캠페인에 속한 코드를 만들고, 코드별 사용 횟수와 **어떤 회원이 어떤 코드를 등록했는지** 조회한다. 인플루언서별로 서로 다른 공통 코드를 발급하면 각 코드의 등록량을 비교할 수 있다. 홍보비 자동 정산 기능은 논의된 범위에 없다.
- 등록 기회는 **Clipper 계정당 캠페인별 1회**다. 동일 캠페인의 다른 코드를 입력해도 두 번째 등록은 허용하지 않고, 이후 별개 캠페인에는 참여할 수 있다. 여러 계정을 사용하는 같은 사람을 식별하거나 막는 기능은 요구하지 않는다.
- **기존 이용자 등록 제한은 이번 AI 부스 캠페인에만 적용한다.** 향후 다른 행사·인플루언서 코드를 포함한 모든 프로모션 코드의 공통 제한으로 만들지 않는다.
- 캠페인마다 관리자가 **코드 등록 시작·종료 시각**을 설정한다. 기간 전·후 입력은 거절하고 화면에 이유를 알린다. 바우처를 개인별로 언제 받았는지는 기록하거나 등록 기한 계산에 사용하지 않는다.
- 이용권 혜택은 현행 Basic·Pro·Business 등급과 **이용 개월 수**를 선택한다. 별도 요금제 체계는 만들지 않는다. 크레딧 지급만 하는 코드의 세부 정책은 미결정이다.
- 코드의 배포처·인플루언서 정보가 필요하면 단순한 **선택 입력값**으로 둔다. 별도 인플루언서 관리 시스템은 이번 범위에 없다.
- 현장에서는 바우처 배포만 한다. 현장 확인, 참가 토큰, 손목띠, 휴대전화 본인확인 등은 등록 기능에 포함하지 않는다.

### 이번 AI 부스 캠페인에 적용할 값

| 항목 | 결정 |
|---|---|
| 코드 배포 | 모든 실물 바우처에 **동일한 행사 공통 코드 1개** 인쇄. 카드별 고유 코드는 사용하지 않음 |
| QR | Clipper 웹사이트 접속용. 코드 자체를 담거나 자동 등록하지 않음 |
| 혜택 | **Pro 1개월과 Pro 이용권에 포함된 1,000크레딧**. 별도의 1,000크레딧 중복 지급 없음 |
| 신규 회원 | 기존 무료체험 400크레딧 별도 유지. 두 지급 조건을 모두 충족하면 총 1,400크레딧 |
| 등록 기간 | 관리자가 캠페인 기간을 **행사 시작일부터 1년**으로 설정. 개인별 수령 시점과 무관 |
| 등록 제한 | Clipper 계정당 이번 캠페인 성공 등록 1회 |
| 등록 대상 | 전략팀이 **① 과거 이용권 결제 및 사용 이력이 있으면 현재 이용권이 만료됐어도 등록 불가**를 선택. **무료체험 이용권의 지급·사용 이력은 제외**. 관리자 지급 이용권 포함 여부는 미결정. 이번 행사에만 적용 |
| 담당·목표 | 한진아 대리, 구현 완료 목표 **2026-10-21** |

실제 인쇄할 코드 문자열은 아직 지정되지 않았다. 시안의 `CLIPPER-1M`을 확정 코드로 취급하지 않는다. 캠페인 전체 성공 등록 한도 역시 미정이다.

전략팀은 기존 이용자 제한에 대해 “네 1번입니다. 이번 바우처 발급의 목적은 신규 유저 유입이기 때문에 기존 활성 유저는 혜택에서 제외됩니다.”라고 답했다. **명시적으로 선택한 1번**에 따라 과거 이력이 있는 계정은 이용권이 만료됐더라도 이번 행사 등록 대상에서 제외한다. 답변의 “활성 유저”라는 취지 설명만으로 활성 이용권 보유자에게만 제한을 축소하지 않는다.

사용자 후속 결정: **무료체험 이용권은 기존 이용권 이력에 포함하지 않는다.** 따라서 가입 시 자동 지급된 무료체험 이용권이나 그 사용 이력만으로는 이번 행사 코드 등록을 거부하지 않는다.

### 현행 무료체험·유료 이용권 동작 확인 (2026-10-12, Web API `dev`)

- 무료체험은 `user_access_grants`의 열린 유료·관리자 이용권과 **별도 참여 기록 및 `free_trial` 크레딧 지급 내역**으로 관리한다. 따라서 무료체험만 보유한 계정은 열린 이용권 1개 제한에 걸리지 않는다.
- 무료체험 400크레딧의 유효기간은 **계정 생성 시각부터 30일**이다. 유료 구독의 첫 결제 이행 시 이용권은 결제 시각부터 시작하며, 무료체험 참여 기록·남은 크레딧은 삭제하지 않는다.
- 유료 이용권이 활성인 동안 유료 요금제 권한이 우선 적용된다. 아직 유효한 무료체험 크레딧도 사용할 수 있다. 유료 이용권이 끝났을 때 무료체험 크레딧의 잔액과 기간이 남아 있으면 무료체험 권한이 다시 적용된다.
- 현행 크레딧 차감은 **먼저 지급된 유효 크레딧부터** 처리한다. 무료체험 크레딧이 보존된다는 것은 유효기간 전까지 별도 잔액으로 존재한다는 뜻이며, 사용 작업에 따라 먼저 소진될 수 있다.
- 이는 **현행 유료 결제 동작**의 확인 결과다. 행사 프로모션의 Pro 지급 경로는 아직 구현되지 않았으므로, 동일하게 무료체험 크레딧을 보존하고 Pro 권한을 즉시 적용하도록 기존 모델에 연결해야 한다.

근거: Web API의 `free-trial-provisioner.service.ts`, `effective-access.service.ts`, `access-grants.service.ts`, `payment-fulfillment.service.ts`, `typeorm-credits.repository.ts` 및 `credit-access-launch-policy.e2e-spec.ts`. 관련 구현 파일은 조회 시 로컬 `origin/main`과 `dev` 간 차이가 없었다. 운영 DB는 직접 조회하지 않았다. 초기 8월 설계의 무료체험 크레딧 무기한 설명은 이후 30일 정책 변경 전 기록이다. 관련 단위 테스트 43개 중 41개 통과, 2개는 새 플러그인 키에 대한 기존 기대 목록 불일치로 실패했다. DB 연동 E2E는 이번에 실행하지 않았다.

## 2. 현재까지의 설계 방향

아래는 위 요구를 구현하기 위해 논의한 구조다. 테이블·API·화면의 상세 계약이나 미결정 정책을 확정한 정식 spec은 아니다.

### 개념과 데이터

- **캠페인**: 하나의 행사·홍보 활동을 묶는 단위. 등록 가능 기간, 계정당 1회 제한, 선택적인 전체 등록 한도를 둔다. 이번 행사의 기존 이용자 제외처럼 **캠페인에만 적용할 등록 대상 조건**을 공통 정책과 분리한다.
- **프로모션 코드**: 회원이 입력하는 텍스트. 반드시 캠페인에 귀속된다. 이번 행사는 캠페인에 공통 코드 하나, 인플루언서 홍보는 캠페인 안에 인플루언서별 코드를 둘 수 있다.
- **등록 기록**: 성공한 회원, 캠페인, 입력 코드, 등록 시각, 지급된 혜택을 연결한다. 이 기록을 바탕으로 코드별 등록 수와 회원별 이력을 조회한다.
- 캠페인과 코드의 생성 화면에 필요한 입력 후보: 관리자용 캠페인 이름, 등록 시작·종료 시각, 선택적인 캠페인 총 등록 한도, 캠페인별 등록 대상 조건, 코드 문자열과 활성 상태, 선택적인 배포처 메모, 혜택 종류 및 기존 요금제 등급·이용 개월 수 또는 크레딧 수량. **대상 판정 기준, 혜택 설정 위치, 크레딧 전용 코드와 개별 코드 한도는 최종 설계에서 확정한다.**

### 등록 흐름과 정합성

1. 회원이 웹사이트에서 가입·로그인하고 텍스트 코드를 입력한다.
2. 서버가 코드·캠페인 존재와 상태, 캠페인 등록 기간, **해당 캠페인의 등록 대상 조건**, 해당 계정의 같은 캠페인 등록 여부, 설정된 한도를 확인한다.
3. 성공 시 기존 이용권·크레딧 체계로 혜택을 지급하고 등록 기록을 남긴다. 중복 요청이나 동시 입력으로 같은 계정에 중복 지급되지 않도록 지급과 기록을 원자적으로 처리한다.
4. 실패 시 기간 전·기간 만료·등록 대상 아님·무효/중지 코드·이미 등록한 캠페인·한도 도달 등 **실제 거절 사유**를 회원에게 안내한다.
5. 관리자 화면에서 코드별 등록 횟수와 회원별 등록 내역을 조회한다.

웹 API가 이용권·크레딧 및 등록 기록의 기준 데이터를 관리하고 고객 웹은 입력·결과 화면, 관리자 웹은 생성·조회 화면을 맡는 방향이다. 실제 DB 스키마·API 경로·기존 이용권과의 병합 방식은 다음 설계 단계에서 정한다.

## 3. 아직 정해지지 않은 것

| 주제 | 남은 결정 |
|---|---|
| 관리자 지급 이용권 이력 | 전략팀의 ①안은 만료된 과거 이용권 이력도 제외하고, 사용자 후속 결정에 따라 무료체험 이력은 제외한다. **관리자가 지급한 이용권 이력을 제한 대상에 포함할지는 아직 미결정이다.** |
| 다른 캠페인의 기존 이용권 처리 | 이번 행사에서는 과거 유료 이용권 이력 보유자를 제외한다. 향후 기존 유료·관리자 이용권 보유자에게도 혜택을 주는 **다른 캠페인**에서 기간·혜택을 어떻게 적용할지는 미정이다. 무료체험과 유료 권한·크레딧의 현행 관계는 위에서 확인했다. |
| 캠페인 총 등록 한도 | 이번 캠페인에 한도를 둘지, 둔다면 성공 등록 몇 건까지 허용할지 |
| 크레딧만 주는 코드 | 이용권 없이 등록·사용할 수 있는지, 사용 기간과 기존 구매 크레딧 정책과의 관계. 범용 기능의 기대 범위에 있으나 정책 미확정 |
| 운영 예외 | 코드 공유·분실, 사용 전 취소·재발급, 등록 후 취소·혜택 회수 방식. 사용자가 별도 검토 중 |
| 상세 관리자 설정 | 혜택을 캠페인 단위로만 둘지 코드별로도 다르게 둘지, 코드별 한도·상태 전환 및 코드 문자열 생성 방식 |
| 행사 코드 문자열 | 실제 바우처에 인쇄할 텍스트 코드 |

## 4. 재개 지점

사용자가 보류한 정책을 확인한 뒤 정식 spec과 구현 계획을 완성한다. 특히 **관리자 지급 이력이 이번 행사의 제한 대상인지**를 확정해야 등록 성공 조건을 완성할 수 있다. 무료체험과 유료 이용권의 현행 관계는 확인했으며, 행사 Pro 지급 기능은 그 관계를 재사용하도록 설계·구현한다. 나머지 미결정 항목을 확정된 기본값처럼 구현하거나 외부 안내에 단정하지 않는다.

이번 기록은 문서화만 수행한다. 제품 코드·DB·API·화면은 변경하지 않았다.
