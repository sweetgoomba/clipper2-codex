# AI 숏폼 디렉터 — 영속 콘텐츠 운영, 적응형 온보딩, Vira 연동 설계

작성일: 2026-07-21 KST
상태: UI 목업 검토 전 설계안
현재 단계: 설계와 mock data 기반 정적 HTML 목업만 작성하며 production 구현은 시작하지 않는다.

## 1. 배경과 문제

현재 AI 숏폼 디렉터는 한 화면에서 캠페인 목표, 브랜드 정보, 타깃, 공식 claim,
Vira evidence와 자유 입력 prompt를 받아 `기획 초안` 하나를 만든다. 이후 전략 후보를
생성하고 사용자가 하나를 골라 VideoPlan, 에셋, TTS, RenderRecipe, immutable stage,
MP4 렌더로 진행한다.

이 구조는 단일 영상 제작에는 작동하지만, 사용자가 실제로 원하는 장기 운영 단위를
표현하지 못한다.

- 업종, 사용 목적, 기본 시청자와 콘텐츠 원칙처럼 여러 작업에서 반복되는 정보가 매번 입력된다.
- 브랜드, 인물, 그룹, 시장, 관심 주제처럼 오래 유지해야 하는 정체성이 일회성 초안에 섞인다.
- 립스틱 신제품, 아이돌 멤버별 이슈, 경쟁 제품 비교처럼 반복 관찰할 세부 주제를 분리할 수 없다.
- Vira 근거가 지속적인 관측 데이터가 아니라 한 번 붙여 넣는 정적 JSON처럼 취급된다.
- 생성된 전략이 장기 보관되는 아이디어 자산이 아니라 최신 프로젝트 상태에 종속된다.
- 현재 카드 제목은 자유 입력 prompt 앞부분이라 프로젝트를 식별하는 이름이 되지 못한다.

## 2. 제품 정의

AI 숏폼 디렉터는 범용 프롬프트 영상 생성기가 아니다. 특정 브랜드, 제품, 인물, 그룹,
시장 또는 주제를 지속적으로 관찰하고 다음 과정을 반복하는 **콘텐츠 운영 시스템**이다.

```text
지속적인 콘텐츠 정체성
  + 공식 자료와 운영 원칙
  + 최신 Vira 관측·트렌드 근거
  + 누적되는 영상 아이디어
  + 검토 가능한 제작 파이프라인
  → 반복·대량 숏폼 제작
```

초기 버전은 사용자가 아이디어와 제작 대상을 수동으로 선택한다. 이후 같은 계약 위에
예약 실행과 야간 대량 제작을 추가한다.

## 3. 대상 사용자

직업을 `마케터`로 제한하지 않는다. 공통 조건은 **특정 맥락에서 콘텐츠를 계속 만들어야
한다는 것**이다.

- 브랜드·제품 담당자와 마케팅 에이전시
- 유튜버와 소셜 크리에이터
- 아티스트·연예인·팬 채널 운영자
- 시장·제품·문화 트렌드 큐레이터
- 교육자와 전문 지식 콘텐츠 제작자
- 관심 주제를 장기적으로 다루는 일반 사용자

마케팅 전용 필드는 목적에 맞을 때만 노출한다. 브랜드, CTA, 경쟁사, 광고 고지와 공식
claim은 모든 사용자에게 필수로 요구하지 않는다.

## 4. 핵심 정보 계층

```text
사용자 계정
  └─ 운영 프로필 1..N
       └─ 콘텐츠 프로젝트 0..N
            ├─ 콘텐츠 트랙 0..N
            ├─ 선택적 캠페인 0..N
            ├─ Vira 모니터링 설정
            ├─ 인사이트 스냅샷 0..N
            ├─ 영상 아이디어 0..N
            └─ 제작 실행 0..N
                 └─ 결과 영상 0..N
```

### 4.1 사용자 계정

로그인과 소유권의 최상위 단위다. 서로 다른 업종·클라이언트의 규칙을 한 전역 설정에
섞지 않는다.

### 4.2 운영 프로필

여러 콘텐츠 프로젝트가 공유할 업무·채널 맥락이다. 한 사용자가 여러 운영 프로필을
만들고 전환할 수 있다.

예시:

- `뷰티 마케팅 업무`
- `엔터테인먼트 클라이언트`
- `가전 리뷰 채널`

저장할 수 있는 기본값:

- 사용 목적과 업종·관심 분야
- 기본 국가·언어
- 기본 시청자
- 주 플랫폼과 추가 플랫폼
- 콘텐츠 분위기와 표현 원칙
- 공통 금지 표현과 검토 기준
- 기본 제작 빈도와 승인 방식

필수값을 최소화한다. 처음에는 목적, 분야, 주 플랫폼 정도만 받고 나머지는 추천값을
확인하거나 나중에 설정한다.

### 4.3 콘텐츠 프로젝트

사용자가 직접 삭제하거나 보관 처리하기 전까지 유지되는 핵심 운영 단위다. 하나의
반복 가능한 콘텐츠 목적과 관찰 대상을 가진다.

예시:

- `립스틱 트렌드 레이더`
- `LANEIGE 워터뱅크 콘텐츠`
- `LE SSERAFIM 상시 콘텐츠`
- `음식물 처리기 시장과 브랜드 A`

프로젝트 대상 유형은 다음을 허용한다.

- 브랜드
- 제품
- 인물
- 그룹·아티스트
- 시장·카테고리
- 주제

브랜드나 홍보 대상은 선택 사항이다. `립스틱 트렌드`처럼 특정 브랜드가 없는 프로젝트와
`음식물 처리기 시장 속 브랜드 A`처럼 시장 관찰과 홍보 목적이 함께 있는 프로젝트를
모두 표현해야 한다.

### 4.4 콘텐츠 트랙

한 프로젝트 안에서 지속적으로 아이디어를 만들 세부 관찰·제작 영역이다.

예시:

```text
LE SSERAFIM 상시 콘텐츠
  ├─ 신곡·무대
  ├─ 멤버별 이슈
  ├─ 착장 정보
  └─ 밈·바이럴 연관어

음식물 처리기 시장과 브랜드 A
  ├─ 시장 트렌드
  ├─ 경쟁 제품 비교
  ├─ 사용자 불편
  └─ 브랜드 A 차별점
```

트랙은 프로젝트 정체성을 상속하고 추적 키워드, 시청자, 콘텐츠 형식과 표현 원칙을
부분적으로 덮어쓸 수 있다.

### 4.5 캠페인

캠페인은 모든 사용자에게 필수가 아닌 선택적·기간 제한 작업이다. 신제품 출시, 컴백,
행사, 프로모션처럼 시작과 종료가 있는 목표에만 사용한다. 상시 유튜브 채널이나 트렌드
큐레이션은 캠페인 없이 프로젝트와 트랙만으로 운영할 수 있다.

### 4.6 영상 아이디어

현재 `ContentStrategy.contentMatrix`의 최신 배열로 끝내지 않고 별도 영속 자산으로
누적한다. 아이디어 하나가 영상 한 편의 제작 후보가 된다.

아이디어는 최소한 다음 상태를 가진다.

- 새 아이디어
- 검토 중
- 제작 선택
- 제작 중
- 제작 완료
- 보류
- 제외
- 시의성 만료

각 아이디어는 생성 시점의 운영 프로필, 프로젝트, 트랙, 캠페인, Vira 인사이트와 공식
자료 snapshot을 참조해야 한다. 설정이 나중에 바뀌어도 과거 아이디어의 생성 근거가
달라지지 않는다.

## 5. 설정 상속과 snapshot

설정은 다음 우선순위로 합성한다.

```text
운영 프로필 기본값
  → 콘텐츠 프로젝트 설정
  → 콘텐츠 트랙 설정
  → 선택적 캠페인 설정
  → 개별 생성 실행의 임시 옵션
```

하위 설정이 명시한 항목만 상위 기본값을 덮어쓴다. 전략 생성 시 합성된 설정과 사용한
근거의 immutable snapshot을 만든다.

snapshot에는 secret, raw credential, 내부 절대 경로를 넣지 않는다.

## 6. 적응형 온보딩

모든 사용자에게 같은 긴 입력 폼을 보여주지 않는다. 첫 단계에서 직업이 아니라 콘텐츠
운영 목적을 선택한다.

### 6.1 시작 목적

- 브랜드·제품 알리기
- 채널 정기 운영
- 인물·아티스트 콘텐츠
- 트렌드·정보 큐레이션
- 전문 지식·교육 콘텐츠
- 직접 설정

### 6.2 최초 입력 최소화

최초 화면에서 결정할 항목은 네 가지 이내로 제한한다.

1. 어떤 목적으로 콘텐츠를 만드는가
2. 계속 다룰 주제나 대상은 무엇인가
3. 주로 배포할 플랫폼은 어디인가
4. 추천 설정을 확인하고 프로젝트를 생성할 것인가

입력 원칙:

- 목적은 설명이 있는 선택 카드로 제공한다.
- 업종·대상 유형·플랫폼은 dropdown보다 탐색이 쉬운 카드·chip·autocomplete를 우선한다.
- 플랫폼은 `YouTube Shorts`, `Instagram Reels`, `TikTok`, `여러 플랫폼`, `아직 정하지 않음`을 제공한다.
- 주 플랫폼 하나와 추가 플랫폼 여러 개를 선택할 수 있다.
- 자유 입력은 프로젝트 이름과 관찰 대상 설명처럼 의미가 분명한 최소 항목에만 사용한다.
- 타깃, 톤, 빈도, CTA, 경쟁 대상과 규제 정보는 추천 기본값 또는 조건부 상세 설정으로 둔다.
- 고급 설정은 프로젝트 생성 후 언제든 수정할 수 있다.

### 6.3 목적별 조건부 설정

브랜드·제품 알리기:

- 브랜드 또는 제품
- 홍보 목적
- 공식 정보와 금지 표현
- 비교·경쟁 대상

채널 정기 운영:

- 채널 주제
- 반복할 콘텐츠 유형
- 주 시청자
- 채널 분위기

인물·아티스트 콘텐츠:

- 대상 인물·그룹
- 다룰 범위
- 멤버·활동·패션·이슈 등의 추적 주제
- 공식 자료와 권리 조건

트렌드·정보 큐레이션:

- 관찰할 시장·카테고리
- 추적 키워드
- 비교·뉴스·랭킹 등의 콘텐츠 형식
- 특정 홍보 대상 포함 여부

전문 지식·교육 콘텐츠:

- 전문 분야
- 설명 수준
- 근거 출처 원칙
- 피해야 할 단정·오해 표현

## 8. 핵심 사용자 흐름

### 8.1 최초 사용

```text
운영 목적 선택
  → 최소 대상·플랫폼 설정
  → 추천 운영 프로필 확인
  → 첫 콘텐츠 프로젝트 생성
  → 추천 콘텐츠 트랙 확인
```

### 8.2 반복 사용

```text
운영 프로필 전환
  → 콘텐츠 프로젝트 선택
  → 최신 Vira 인사이트 확인
  → 트랙별 영상 아이디어 생성
  → 아이디어 보관함에 누적
```

### 8.3 초기 제작

```text
사용자가 아이디어 선택
  → VideoPlan
  → 에셋 자동 준비와 필요한 직접 교체
  → TTS 정렬
  → RenderRecipe
  → immutable stage
  → Motion Canvas MP4
  → 검토·다운로드
```

### 8.4 향후 야간 자동 제작

```text
예약 실행
  → 최신 Vira snapshot
  → 신규·중복 방지 아이디어 생성
  → 정책·권리 gate
  → 지정 수량 제작
  → 다음 날 검토 대기함 제공
```

자동 업로드는 별도 승인·정책 설계 전까지 포함하지 않는다.

### 9.2 프로젝트 홈

- 프로젝트 이름과 대상 유형

- 콘텐츠 트랙
- 최신 Vira 인사이트
- 새 영상 아이디어
- 제작 진행 현황

### 9.3 프로젝트 탭

- 개요
- Vira 인사이트
- 영상 아이디어
- 제작함
- 설정

### 9.4 영상 아이디어 보관함

한 아이디어 카드에서 다음을 확인한다.

- 영상 제목·hook
- 연결된 콘텐츠 트랙
- 생성 시각과 시의성
- 사용한 Vira signal과 공식 근거
- 추천 이유
- 상태
- 제작 선택·보류·제외 action

## 10. Vira의 역할

Vira는 Clipper 내부에서 임의로 복제하는 트렌드 로직이 아니라, 지속적으로 수집·계산한
시장 관측 데이터의 source of truth다.

필요한 정보 유형:

- 추적 중인 entity·keyword·topic
- 기간별 급상승 키워드와 연관어
- 상승 폭, 조회·반응 변화와 신뢰 가능한 수치
- 왜 해당 신호가 발생했는지 설명할 근거
- 근거가 된 영상·게시물·관측 시각
- 주제·인물·브랜드 간 연결 관계
- signal freshness와 데이터 부족 상태

예시:

```text
LE SSERAFIM 추적
  → 연관어 `떡꼬치` 급상승
  → 특정 멤버의 먹방 영상이 확산 원인
  → 근거 영상과 시간대·반응 변화 제공
  → `멤버별 이슈` 트랙의 신규 영상 아이디어 후보
```

Vira가 제공하지 않은 원인이나 관계를 Clipper가 추측해 사실처럼 만들지 않는다.

## 11. Vira 연동 경계

UI 목업을 승인하고 구현 단계로 전환한 뒤에만 다음 작업을 시작한다.

1. `/Users/jina/project/vira`의 저장소 지침과 현재 상태를 확인한다.
2. 사용자가 이번 대화에서 변경한 권한에 따라 기존 read-only 제한을 해제한다.
3. Vira `main`을 원격 최신 상태로 동기화한다.
4. 최신 `main`에서 Clipper 연동 전용 feature branch를 만든다.
5. 실제 schema, service와 현재 데이터 계산 경로를 감사한다.
6. Clipper가 필요한 read-only API endpoint를 Vira 서버 안에 구현한다.
7. Vira 서버를 로컬로 실행하고 실제 DB 데이터가 API 응답으로 나오는지 확인한다.
8. 필요한 DB·env 정보가 로컬에 없으면 secret 값을 채팅이나 문서에 노출하지 않고 사용자에게 필요한 파일·경로만 요청한다.
9. 실제 응답을 기준으로 API 계약을 고정한다.
10. Clipper adapter가 Vira API를 호출하고 응답을 immutable evidence snapshot으로 저장하게 한다.

Clipper가 Vira DB에 직접 연결하거나 내부 테이블을 조회하지 않는다. API가 유일한 연동
경계다.

### 11.1 Vira API가 제공해야 할 capability

실제 Vira 코드를 감사하기 전에는 URL과 내부 이름을 확정하지 않는다. 필요한 capability는
다음과 같다.

- 추적 대상 검색·조회
- 대상별 최신 signal 목록
- signal의 원인·근거 상세
- 기간·키워드·entity·signal 종류 필터
- 근거 영상 또는 source reference 조회
- freshness, 관측 범위와 데이터 부족 상태

응답에는 안정적인 id, schema version, 생성 시각, 관측 기간, provenance가 필요하다.
credential, DB 연결 정보와 Vira 내부 절대 경로는 응답하지 않는다.

### 11.2 실패와 stale data

- Vira 연결 실패와 데이터 부족을 구분한다.
- 마지막 성공 snapshot이 있으면 시각과 stale 상태를 명확히 표시한다.
- Vira 근거가 없을 때 임의의 트렌드 근거를 생성하지 않는다.
- 사용자는 공식 자료만으로 아이디어를 만들지, Vira가 복구될 때까지 기다릴지 선택할 수 있다.
- 일부 signal 실패가 기존 프로젝트·아이디어·영상 기록을 손상시키지 않는다.

## 14. 목업 수용 기준

- 사용자 직업을 마케터로 가정하지 않는다.
- 최초 설정은 네 가지 이하의 핵심 결정만 요구한다.
- 운영 프로필과 콘텐츠 프로젝트의 차이를 화면에서 이해할 수 있다.
- 브랜드 없는 시장·주제 프로젝트를 만들 수 있다.
- 주 플랫폼과 추가 플랫폼을 선택할 수 있다.
- 콘텐츠 트랙과 Vira 인사이트가 프로젝트 안에서 지속된다는 점이 보인다.
- 영상 아이디어가 누적되고 상태를 가진다는 점이 보인다.
- 자동 제작은 현재 기능처럼 오해되지 않도록 `향후 자동화` 또는 mock 상태로 표시한다.
- 모든 데이터는 mock이며 외부 API·provider·DB를 호출하지 않는다.
