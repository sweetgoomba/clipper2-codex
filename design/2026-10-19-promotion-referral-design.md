# 범용 프로모션 코드와 레퍼럴 성과 설계

> **초기 설계 이력 (2026-10-19).** 이후 무료체험·다른 캠페인 이력 제한 선택지 제거, 코드별 등록 상한, 코드 없이 캠페인 생성, 현재 회원/관리자 화면 흐름이 변경됐다. 현재 규칙은 [2026-10-23 설계](2026-10-23-promotion-campaign-current-state.md)를 우선한다.

작성일: 2026-10-19 · 기준: Web API/회원 웹/관리자 웹/데스크톱 백엔드/데스크톱 화면 `origin/dev`, 문서 저장소 기존 `main`

## 목적과 범위

관리자는 캠페인 하나에 여러 코드를 만들 수 있다. 인플루언서는 각자의 코드를 홍보한다. 회원은 QR 등의 링크에서 코드 입력 화면을 열고 직접 등록한다. 성공한 등록은 이용권과 크레딧을 지급하며, 코드별 회원·무료 혜택 사용·직접 유료 전환·이후 동일 구독의 매출을 조회하고 Excel에서 열 수 있는 파일로 내보낸다. 지급액 계산과 송금은 경영실/기획팀 업무다.

이번 구현은 이용권을 지급하는 캠페인만 지원한다. 크레딧만 지급하는 코드는 추후 요구가 생기면 혜택 유형을 확장한다. 10% 전환 할인, 자동 정산, 실제 AI 부스 코드 문자열·시작일·등록 총량은 구현 대상이 아니다. 운영자가 캠페인을 만들 때 입력한다.

## 도메인과 저장 위치

* `promotion_campaigns`: 이름, 상태, 등록 시작/종료, 선택적 성공 등록 상한, 지급할 Basic/Pro/Business 이용권 등급, 개월 수, 월 지급 크레딧과 크레딧 유효기간, 차단할 과거 이력 유형 집합. 캠페인 상태를 중지로 바꾸면 새 등록만 막는다.
* `promotion_codes`: 캠페인 ID, 고유 코드, 홍보자 이름/식별자, 활성 여부. 같은 캠페인의 코드는 동일한 혜택/등록 규칙을 따른다.
* `promotion_redemptions`: 회원 ID, 캠페인 ID, 코드 ID, 생성된 이용권 ID, 등록 시각, 상태와 회수 기록. `(campaign_id,user_id)` 유일 제약으로 회수 후에도 같은 캠페인 재등록을 막는다. 성공 등록 건수는 이 기록을 근거로 센다.
* 기존 `user_access_grants`에 `promotion` 출처와 등록 ID를 추가한다. 기존 구독/관리자 지급/프로모션은 공통 이용권 기간과 하나의 열린 이용권 제약을 사용한다. 무료체험은 판매 등급이 아닌 별도 체험 상태로 유지하며, 그 크레딧은 자체 유효기간을 따른다.
* 기존 `credit_grants`의 `promotion` 출처를 사용하고 등록 ID를 보존한다. 장부 `credit_ledger_entries`는 기존 FIFO(지급일, ID) 순서를 사용한다. 결제로 받은 크레딧은 기존 결제 주문 ID로 역추적한다.
* 구독/결제 주문에는 `promotion_redemption_id`를 선택적으로 저장한다. 등록과 유료 결제의 인과관계를 판단할 때 회원의 최근 코드로 추론하지 않고 실제 예약/주문 생성 시 연결한 ID를 사용한다.

이 테이블은 모두 Web API의 `admin` DB에 둔다. 회원 계정은 기존 user DB의 ID를 참조하지만 DB 간 외래키를 만들지 않는다.

데스크톱 백엔드의 웹 API 응답 검증과 데스크톱 화면의 이용권·현재 기간 크레딧 표시에서도 `promotion` 출처를 인식한다. 새 결제·등록 로직은 Web API에만 둔다.

## 등록 규칙

관리자는 캠페인별로 다음 이력 유형을 복수 선택한다. **선택한 이력 하나라도 있으면** 만료 여부와 관계없이 등록을 막는다. 선택하지 않으면 과거 이력 제한이 없다.

1. 유료 이용권 결제 또는 사용 이력
2. 관리자 지급 이용권 이력
3. 다른 캠페인의 프로모션 이용권 지급 이력
4. 무료체험 이력

이력 선택과 별개로 현재 활성 또는 예약된 주 이용권이나 진행 중인 유료 구독 신청이 있으면 등록을 막는다. 무료체험만 활성인 회원은 등록할 수 있다. 한 회원은 한 캠페인에서 한 코드만 성공 등록할 수 있으며 회수해도 다시 등록할 수 없다. 등록은 회원 잠금, 캠페인/코드 상태·시간·상한·이력 검사, 이용권·크레딧·등록 기록 저장을 하나의 DB 트랜잭션으로 처리한다. 동시 등록에서 유일 제약과 캠페인 잠금으로 중복 지급/상한 초과를 막는다. AI 부스 캠페인은 운영자가 `유료 이용권 결제 또는 사용 이력`만 선택한다. 관리자 지급/무료체험 이력은 해당 캠페인의 과거 이력 검사에서 제외된다.

## 혜택과 회수

혜택은 등록 시점에 시작하는 정식 프로모션 이용권과 그 이용권으로 지급되는 크레딧이다. 기간 중 크레딧을 모두 써도 이용권 기간은 남는다. 캠페인 종료/코드 중지/이용권의 정상 만료는 이미 지급된 크레딧을 회수하지 않는다. 각 크레딧은 자기 유효기간까지 사용할 수 있다. 프로모션 이용권이 활성 상태면 추가 크레딧을 구매할 수 있다. 무료체험이나 관리자 지급 이용권만 있는 경우에는 현행 구매 제한을 유지한다. 프로모션 중 구매한 추가 크레딧은 프로모션 회수 대상이 아니며 자체 유효기간까지 사용할 수 있다.

관리자가 성공 등록을 취소·회수하면 해당 등록에서 받은 이용권을 즉시 종료하고, 그 등록에서 받은 크레딧의 **미사용분만** 회수한다. 이미 사용한 크레딧/장부와 다른 출처의 크레딧은 유지한다. 회수 사유, 운영자, 시각을 보존하고 멱등성을 보장한다. 별도의 회수 범위 선택 또는 복구 기능은 만들지 않는다. 실수 보상은 기존 관리자 지급 기능으로 처리한다.

## 유료 전환과 성과 귀속

프로모션 이용권이 활성일 때 회원은 종료 후 유료 이용을 예약할 수 있다. 화면에서 먼저 `같은 등급의 유료 상품으로 이어가기`와 `다른 상품 선택`을 보여준다. 실제 판매 중인 상품의 가격·주기·첫 결제일에 동의한다. 예약 당시의 등록 ID를 구독에 고정한다. 동의한 날짜 전에는 청구하지 않는다. 첫 결제가 성공한 뒤 유료 이용권·크레딧을 지급한다. 회원이 청구 전에 예약을 취소하면 청구하지 않고 프로모션 혜택은 유지한다. 관리자 회수 후에도 회원이 동의한 첫 결제일과 예약은 유지하고 통지한다. 청구일을 앞당기려면 회원의 별도 동의를 받는다.

첫 결제 실패의 재시도 일정은 기존 관리자 갱신 실패 설정을 재사용한다. **첫 결제가 성공하기 전에는 유료 이용권 유예기간을 부여하지 않는다.** 화면에 안내한 첫 결제일과 프로모션 등록 ID를 결제 신청 때 서버가 다시 확인하고, 바뀌었다면 재동의를 요구한다. 같은 유료 구독의 이후 정기결제와 즉시 업그레이드 결제는 계속 그 등록의 후속 매출로 표시하되 전환 회원을 다시 세지 않는다. 해당 구독이 끝난 뒤 독립적으로 만든 새 구독은 연결하지 않는다.

프로모션 이용권 활성 중 시작한 추가 크레딧 주문도 등록 ID를 고정한다. 결제가 나중에 성공해도 그 주문과 지급 크레딧/사용 기록은 코드 성과다. 이 밖의 임의 후속 결제는 코드에 배정하지 않는다. 예: 11월 민지 코드, 12월 수진 코드로 각각 무료 이용 후 3월 독립 결제는 어느 코드에도 직접 귀속하지 않는다.

보고에서는 무료 지급량·사용량, 귀속 추가 크레딧 주문 결제/환불, 귀속 구독 첫 결제/환불, 같은 구독의 정기결제·즉시 업그레이드 결제/환불, 그 결제로 지급된 크레딧의 사용량을 분리한다. 결제 주문은 한 번만 집계한다. 결제 승인 전 주문은 매출에 넣지 않는다. 회원 ID·코드·캠페인·등록일 범위로 조회한다. 관리자 화면의 등록·성과 행은 50건씩 표시하고 성과 합계는 전체 필터 결과로 계산한다. 전체 결과는 숫자 셀을 숫자로 보존한 XLSX로 내보낸다. 각 행은 등록 ID와 회원 ID를 포함한 합계다. 결제 주문·크레딧 지급·장부의 원본 ID와 시각은 각각의 저장 기록에 보존한다. 기간 필터는 등록일에 적용하며 선택한 등록의 이후 결제·사용도 합계에 포함한다.

혜택을 조기 회수하면 회원 화면에 회수 시각·사유·유료 첫 결제 예약 유지 여부와 날짜를 확인할 때까지 표시한다. 회수 및 캠페인·코드 변경은 운영자 ID와 함께 기존 관리자 감사 장부에 기록한다. 만료 프로모션에서 유료 이용권으로 넘어갈 때는 미처리 월별 크레딧을 먼저 정산한다. 프로모션 등록 또는 감사 기록이 생긴 DB는 해당 마이그레이션을 역방향으로 실행하지 않고 안전하게 거부한다.

## 운영/검증 경계

관리자 캠페인 생성·중지·코드 생성·등록 조회·회수·성과 조회/내보내기, 회원 코드 등록·상태 확인·유료 예약/취소·프로모션 중 추가 크레딧 구매를 제공한다. 관리자 권한을 적용하고 회수의 운영자·사유·시각을 등록 기록과 이용권 이벤트에 남긴다. 금액을 정산 확정치로 표현하지 않고 `귀속 결제/환불` 합계로 보여준다. 결제 API의 실제 승인/환불은 기존 Toss 경로를 재사용한다.

필수 검증: 중복/동시 등록과 상한, 네 가지 이력 선택 조합, 주 이용권 충돌과 무료체험 공존, 정상 종료 후 크레딧 유효기간, 일부 사용 후 회수, 관리자/무료체험의 추가 크레딧 구매 거부, 예약 취소와 청구 경합, 첫 결제 실패 재시도, 회수 후 예약 유지, 코드 귀속과 독립 결제 비귀속, 환불/후속 결제 중복 집계 방지.
