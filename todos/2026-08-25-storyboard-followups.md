# Storyboard 후속 TODO

작성일: 2026-08-25 KST

## 목적

이번 일정에서 의도적으로 미룬 작업과 임시 표시 처리된 기능을 다음 세션에서 놓치지 않기
위한 목록이다. 현재 동작하는 Storyboard 흐름을 넓히기 전에 아래 항목의 제품 의도와 완료
기준부터 확인한다.

## P0 — 화면에서만 숨긴 기능의 최종 처리

영상 후보 화면의 아래 항목은 현재 CSS·템플릿 조건 등으로 보이지 않게 했을 뿐, 기능과
데이터 흐름을 최종 정리한 상태가 아니다.

- `생성 기록 상세`
- `근거와 과정`
- `근거 ID와 기술 정보 보기`

후속 작업에서는 단순히 다시 노출하지 않는다.

1. 일반 사용자가 판단에 필요한 근거·품질 정보와 개발자 진단 정보를 나눈다.
2. 일반 정보는 짧은 요약으로 후보 카드 또는 공통 모달에 제공한다.
3. artifact ID, 공급자 응답, 내부 trace 같은 기술 정보는 별도 고급 정보 영역으로 분리한다.
4. 비어 있음, 일부 실패, 권한 없음, 오래된 실행 기록 상태를 정의한다.
5. 접근성, 모바일 너비, 키보드 닫기와 바깥 클릭 동작을 공통 모달 계약에 맞춘다.
6. 필요 없는 기능으로 결정되면 UI뿐 아니라 route, component, service와 API까지 제거하고
   회귀 테스트로 확인한다.

완료 기준:

- 세 항목 각각을 `사용자용으로 재설계`, `개발자용으로 이동`, `완전 제거` 중 하나로 결정
- 숨김 스타일이나 항상 false인 표시 조건이 남아 있지 않음
- 선택한 결정에 맞춰 프런트엔드와 백엔드의 사용되지 않는 흐름까지 정리됨

## P1 — 스토리보드 복구 결과의 계약 일치

모델·응답 형식 문제로 정상 결과를 만들 수 없을 때 로컬 스토리보드 복구는 유지한다. 다만
복구 결과에서도 정상 생성과 같은 필수 필드를 제공해야 한다.

- 컷별 이미지 검색어와 활용 가이드
- 컷별 한국어 내용과 영문 AI 프롬프트
- 시간, 내레이션, 자막, 화면 구성과 전환
- 비차단 품질 경고와 복구 사용 여부 표시

완료 기준:

- 정상 생성과 로컬 복구가 같은 응답 스키마·화면 구조를 사용
- 검색어가 비어 있던 회귀 사례를 자동 테스트로 고정
- 사용자는 복구 결과도 복사·활용할 수 있고, 복구 여부는 과장 없이 확인 가능

## P1 — 품질 경고를 이용한 개선 흐름

현재 내레이션 밀도, 시간 합계, 근거 연결, 프롬프트 이상 등을 탐지하지만 생성을
실패시키지는 않는다. 다음 단계에서는 경고를 이용해 사용자가 필요한 부분만 개선할 수 있게
한다.

- 장면·필드·경고 종류를 구조화해 저장
- 경고를 모아 보기와 해당 컷으로 이동
- 사용자가 선택한 경고만 AI에게 다시 개선 요청
- 재생성 전 변경 범위와 예상 비용 표시
- 원본과 개선본 비교 및 되돌리기

이번 세션에는 개선 요청 기능을 구현하지 않았다.

## P1 — 영상 생성 관련 잔여 코드 정리

제품 방향은 Storyboard 플러그인 안에서 영상을 생성하지 않는 것이다. 사용자 흐름에서는
영상 생성·렌더를 제거했지만 관련 저장소의 과거 provider job, transport, 제작 설정,
렌더 연결 코드가 남아 있을 수 있다.

후속 작업:

1. Desktop NestJS, Electron, Angular, Python과 Web API/Admin에서 Storyboard가 참조하는
   영상·이미지 생성 코드를 실제 호출 그래프로 조사한다.
2. 다른 제품 기능이 공유하는 코드와 Storyboard 전용 코드를 구분한다.
3. Storyboard 전용 API, DTO, migration 이후의 미사용 repository·service·UI를 순서대로
   제거한다.
4. 이미 배포된 migration 파일은 수정하지 않고 필요한 경우 새 forward migration을 만든다.
5. 기존의 독립적인 영상 처리 기능을 깨뜨리지 않는 회귀 테스트를 실행한다.

완료 기준:

- Storyboard 실행 중 영상·이미지 생성 provider 호출이 없음
- Storyboard 화면과 API에 영상 모델 선택·생성 job·렌더 상태 계약이 없음
- 미사용 코드와 설정을 정적 검색 및 테스트로 확인

## P1 — 프로필 복제·보관 제거 상태 감사

복제·보관은 숨김이 아니라 완전 제거가 요구사항이다. UI와 백엔드에서 제거했지만 다음
세션에서 잔여 참조를 한 번 더 확인한다.

- 버튼, 메뉴, 번역 문자열과 접근성 레이블
- archive/duplicate route, DTO, service와 테스트 fixture
- 프로필 상태 필드와 저장 데이터 변환
- 관리자 화면·문서·OpenAPI의 잔여 계약

완료 기준:

- 코드 검색 결과가 의도적으로 보존한 일반 용도의 용어 외에는 없음
- 활성 상태만 허용하는 별도 대체 상태 필드를 만들지 않음
- 기존 K-POP 프로필이 정상 조회·선택·수정됨

## P2 — 생성 품질 보완 후보

- 회사·그룹·곡명 결합으로 `아워벌스데뷔곡` 같은 잘못된 단어가 만들어지는 사례가
  반복되는지 관찰한다. 단발성 모델 실수면 규칙을 추가하지 않는다.
- 반복된다면 근거에 등장한 고유명사를 보존하는 가벼운 후처리 또는 경고를 검토한다.
- 주제 다양성은 개수보다 프로필 관련성과 사건 중복 방지를 우선한다.
- 특정 근거에 직접 없는 가능성을 덧붙인 주제도 프로필 활용 가치가 있으면 허용하되,
  사실과 전망을 문장에서 구분한다.

## P2 — 비용과 관측성

- 조사, 후보 생성, 스토리보드 생성의 provider 호출별 usage와 원화 환산 근거를 기록한다.
- 정상 생성과 재시도·로컬 복구의 비용을 구분한다.
- 모델 단가가 바뀌어도 계산식을 갱신할 수 있도록 가격 기준일과 출처를 함께 남긴다.
- 현재 모델은 비용 때문에 변경하지 않는다. 품질과 실측 비용이 다시 문제가 될 때만
  모델 변경을 검토한다.

## 명시적으로 이번 범위가 아닌 항목

- 스토리보드 직접 편집
- 이미지 자동 검색·다운로드·삽입
- 영상 생성과 렌더
- 개인화 추천 API: 현재 프로필 추천은 고정 프리셋 10개다.
