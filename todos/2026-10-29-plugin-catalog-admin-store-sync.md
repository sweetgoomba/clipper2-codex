# 웹 관리자와 앱 스토어의 플러그인 목록 및 운영 정책 동기화

등록일: **2026-10-29 KST**, 현재 범위 정리: **2026-11-03 KST**. 상태: **후속 TODO, 이번 세션 구현 제외**. 우선순위·일정·구현 방식은 미정이다.

## 배경과 시작 조건

사용자가 복잡성 때문에 이 세션에서는 관리자와 앱 스토어의 플러그인 목록 동기화를 진행하지 않기로 했다. 사용자에게서 후속 착수 지시가 오면 아래 논의 기록을 읽고 범위를 다시 정한다. 이 TODO를 근거로 자동 착수하거나 다른 기능에 동기화 트랙을 끼워 넣지 않는다.

[전체 논의와 최신 정책·미확정 항목](../features/plugin-catalog/records/2026/10/29-admin-store-sync-discussion-and-deferral.md)

## 보존할 정책과 확인 상태

- 회사가 허용 플러그인을 지정한다. 회원의 임의 N개 선택 방식이 아니다.
- 초기 전략실 답변은 **Basic ⊆ Pro ⊆ Business**였다. 이후 사용자 승인으로 W19는 Free 포함 전역 자동 포함 ON/OFF를 구현했다. ON이면 하위 목록을 상위에 포함하고 OFF이면 독립 설정한다. 고정 유료 포함 모델을 다시 구현하지 않는다.
- 기본 Free의 별도 허용 목록·지속 상태·가입 혜택1회는 W19에 구현됐다. Free를 포함한 관계도 같은 전역 정책을 따른다.
- 초기 스토어 노출 문의 후 사용자가 표시·설치·준비를 허용하고 권한이 필요한 실제 실행에서 검사하는 흐름을 지시했고 W19에 반영됐다. 별도 이사님 승인 회신을 확보했다고 주장하지 않되 이를 W19 전체의 미구현 상태로 되돌리지 않는다.
- 사이드바 카테고리 내부 설치 순서와 즐겨찾기 개인 순서는 유지한다. 관리자 내부 순서는 스토어 대상이다.
- 전체 비활성화는 요금제 허용 목록을 지우지 않아야 한다. 숨김과 실제 실행 차단은 구분한다.
- 기존 가입·결제·크레딧 정책을 동기화 설계 때문에 임의 변경하지 않는다.

## 재개 시 설계와 구현 후보

- [ ] 수동 등록과 릴리스 목록 전송을 비교해 최소 범위 선택. 앞서 추천한 자동 전송을 확정안으로 간주하지 않기.
- [ ] 사용자용 plugin ID의 정본·공통 목록을 정의하고 무료 기능·다중 과금 작업·내부 공통 모듈을 구분.
- [ ] 개발 등록과 관리자 이름·분류·순서·공개·전체 활성·등급 허용의 소유권 분리.
- [ ] 플러그인 관리와 카테고리 CRUD·순서·소속 이동 및 관리자 소식 등 다른 소비자 검토.
- [x] `/plans` 허용 선택 UI/API·Free 포함 자동 포함 ON/OFF·원자 저장/revision은 W19 구현 완료. W18 재개 시 기존 구조를 재사용하고 새 카탈로그 ID와의 연결만 설계한다.
- [ ] 전체 카탈로그의 표시/공개/전역 중지를 기존 W19의 스토어 안내·설치/준비 허용·실행 검사에 연결한다. W19 기본 흐름을 처음부터 재구현하지 않는다.
- [ ] 앱이 구현한 기능과 서버 운영 목록을 결합하고 없는 코드를 원격 등록만으로 실행시키지 않기.
- [ ] 전체 활성/비활성 토글과 스토어·사이드바·이미 열린 화면·직접 실행·대기/재시작 경로 처리.
- [ ] 실행 중 작업·오프라인/서버 장애·캐시/전파 주기와 차감된 대기 작업의 반환 처리 결정.
- [ ] 자동 전송을 선택한 경우에만: 대상 릴리스 등록 추출, 계약 검증, 환경별 인증, 중복 방지, 운영값 보존, 설정 전 비공개, 실제 배포 절차 연결.
- [ ] 지원 릴리스의 목록 차이를 보존하되 출시 전 옛 개발판 전용 호환 adapter/예외를 임의 추가하지 않기.
- [ ] 실제 앱·관리자·서버 통합 검증 및 재시작/재전송/중지·재개 경계 검증.

위 체크리스트는 후속 후보이며 전체를 이번 작업 범위로 확정한 구현계획이 아니다. 실제 저장소와 세부 계약은 재개 시 최신 코드에서 정한다.

## 완료 판정 후보

- 앱에서 제공 가능한 기능과 관리자 목록의 ID가 맞고 과금 없는 기능도 관리 가능하다.
- 재동기화가 중복을 만들거나 운영자의 긴급 중지·허용 설정을 덮지 않는다.
- 필수 설정 전 공개되지 않고 실제 앱 지원 여부·회원 허용·전체 활성 판단이 일치한다.
- 저장된 자동 포함 ON/OFF와 스토어 실행 흐름, 기존 설치·즐겨찾기 순서가 보존된다.
- 새 실행 거절 때 불필요한 차감이 없고 진행/취소/정산 복구가 일관된다.
- 자동화를 택하면 임시 실험이 아닌 제품 인증·DB·릴리스·실제 앱으로 검증한다.
