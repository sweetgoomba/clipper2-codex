## BUG-02-005 — 결제 완료 후 뒤로 가기 시 종료된 토스 결제창 잔류

- 사용자 제보: Windows PC에서 앱의 `이용권 → 이용관리`로 웹에 이동해 정기결제·영수증 확인 후 뒤로 가면 토스 결제창이 다시 나타나 `이미 종료된 세션입니다`를 표시한다. 뒤로 가기는 되지만 결제창이 남고 `닫기`도 작동하지 않는다. 브라우저는 미확인이고 조사에는 Chrome을 가정한다.
- 코드 경로: 앱의 `이용관리`는 브라우저 인계 뒤 웹 `/pricing`으로 이동하고, 요금제 선택은 `/my/payment/checkout`으로 이어진다. PC 빌링 인증 요청은 SDK 기본 iframe 방식을 사용한다. 화면 잔류의 실제 원인과 결제/영수증/뒤로 가기 탭 순서는 아직 재현으로 확인하지 않았다.
- 10/13 추가 조사: 운영 당시 고객 웹 `a27c346`에서 빌링 인증은 `windowTarget`을 지정하지 않아 PC 기본 iframe으로 열린다. 결제 결과는 `/my/payment/result`이며 영수증 링크는 새 탭이다. 체크아웃 `ngOnDestroy`는 구독만 해제하고 빌링 결제창을 정리하지 않는다. Chrome의 뒤로 가기가 iframe 내부 이력을 이동하거나 이전 페이지와 iframe을 복원할 수 있어, 완료된 세션 화면이 남는 현상과 부합한다. **가능성 높은 설명이며 실제 브라우저 복원 경로는 미확인**이다. 현재 고정 npm 패키지 2.7.1의 `TossPaymentsPayment` 타입에는 공식 최신 문서의 `payment.destroy()`가 없어 적용 전 SDK 버전·동작 확인이 필요하다. `2.7.1`은 패키지 출시 버전이며 문서의 `결제창(구버전)` 제품 분류와 다른 개념이다. 토스 공식 자동결제 가이드는 현재도 `payment().requestBillingAuth()`를 사용하고, 새 `widgets().renderPaymentWindow()` 결제창형 일반결제와 구분한다. 재현 원인 확정과 별개로 결제창 정리 누락은 수정 대상으로 본다.
- 사용자가 제시한 10/8 관리자 기록에는 12:59 Pro 월간 최초 결제, 13:05 Business 월간 즉시 상향 차액 결제, 13:13 크레딧 추가 구매 결제가 있다. 어느 영수증 뒤에 BUG-02-005가 발생했는지는 특정되지 않았다.
- 사용자가 10/13에 수정 설계를 승인했다. `web/clipper_web_client`의 격리 브랜치 `fix/bug-02-005-billing-window`에서 Toss SDK를 `2.8.1`로 고정했다. 이 버전의 공개 타입은 `payment.destroy()`를 제공한다. 빌링 인증창 인스턴스를 유지하고 Angular 체크아웃 화면 종료·브라우저 페이지 복원·영수증 탭에서의 복귀 시 닫는다. 성공 URL로 이동하는 `pagehide`에서는 진행 중인 인증을 중단하지 않는다. 복원된 주문이 결제 완료 또는 처리 중이면 결과 화면으로 이동해 재시도를 막는다.
- 로컬 검증: 수정 전 회귀 테스트 실패를 확인했고, 수정 후 ChromeHeadless 전체 테스트 `290 SUCCESS`, 프로덕션 빌드 성공(초기 번들 예산 경고 12.68 kB)을 확인했다. 실제 Windows Chrome에서 결제 → 영수증 → 뒤로 가기 순서는 아직 수동 검증하지 않았다. 코드 수정만으로 제보 당시 브라우저 내부 이력 경로를 확정했다고 보지 않는다.

## 나중에 할 작업 — 관리자 회원 상세 크레딧 원장 표

- **현재 구현하지 않음.** `처리 후 잔여`는 회원 전체 잔액이 아니라 각 행의 `지급 ID`에 해당하는 지급분의 잔액이다. 예: 13:05 Business 지급분 `+4,000 → 4,000`, 13:13 추가 구매 지급분 `+1,000 → 1,000`; 두 지급분을 합산하고 무료 체험 400을 더한 당시 회원 총 잔액은 5,400이다.
- 기존 열 이름을 지급분 기준임이 드러나도록 바꾸고, 사용자가 요청한 **`전체 잔액` 열을 추가**한다. 구현 전에는 각 이벤트 직후의 전체 사용 가능 잔액 정의와 같은 시각의 여러 원장 행 순서를 확인한다. 기존 지급분별 `balanceAfter` 저장값을 전체 잔액으로 오해해 재사용하지 않는다.

## 10/8 QA 거래의 외부 취소·환불 맥락 — 사용자 설명

- 사용자가 토스페이먼츠 대시보드에서 13:13 추가 구매 결제를 **부분환불**했고, 해당 회원의 다른 결제 건도 토스 대시보드에서 취소했다고 설명했다. 주문별 취소 금액·시각은 이 세션에서 대시보드와 대조하지 않았다.
- 클리퍼 관리자페이지의 환불 경로를 사용하지 않았으므로, 관리자 화면의 해당 주문은 `PARTIAL_CANCELED` 저장 상태와 내부 환불액 0원·환불 기록 없음이 함께 보이고, 크레딧 회수 등 내부 후처리도 반영되지 않았다는 사용자 설명이다. 이를 결제 미취소나 일반적인 표시 오류로 해석하지 않는다. 내부 크레딧·구독·빌링키 상태의 별도 대사는 W06 운영 후처리와 연결한다.
