# W14 — 신규 인물 하이라이트 구상・설계・구현

최종 확인: 2026-10-02 KST. 상태: **W14 개발 앱 첫 실영상 결과는 사용자 판정 품질 불합격. 원본 우선 연속 등장·얼굴/몸 연결의 별도 30초 격리 점검도 제품 적용 gate 실패. 기존 카드·편집·제품 기본값은 보존했고 시험용 수정은 격리 worktree에 미커밋. YOLO 몸 모델은 후속 사용 대상에서 제외.**

**10/2 최신 사용자 결정 — 모델:** 이번 격리 시험에 쓴 YOLOv8 pose는 앞으로 사용할 수 없다. W13 Dance는 다른 모델로 교체를 진행 중이나 **대체 모델은 아직 미정**이다. W14는 YOLO를 Person에 연동하거나 추가 추론하지 않으며, 아래 YOLO 수치는 과거 진단 기록으로만 읽는다. W13의 향후 모델을 W14가 자동으로 공유한다고 가정하지 않는다. 얼굴 기반 인물 묶기 품질 개선은 별도로 다루고, 얼굴/몸 연동은 사용 가능한 모델과 독립 검증 범위가 정해질 때까지 보류한다.

**10/2 신규 조사 — 인물용 몸 경로:** 사용자 요청에 따라 Dance 모델과 독립적으로 무료·비공개 소스 SaaS 후보를 공식 코드/weight 조건까지 다시 비교했다. D-FINE-S/N의 **COCO-only** weight, RF-DETR-S/N의 Apache 지정 weight, RTMDet-tiny의 MMDetection 경로를 제안하며 **선정/다운로드/추론/제품 적용은 아직 0건**이다. 얼굴이 잠깐 안 보이지만 몸이 계속 보이는 경우의 같은-shot 연결, 완전 퇴장·컷·가림·동시 인물 교차·앵커 모호성의 분리 규칙과 독립 GT/속도 gate는 [후보·예외 설계 기록](../../features/highlights/records/2026/10/02-w14-person-body-model-candidates-and-continuity-rules.md)에 있다. 몸 검출기만으로 동일인을 판정하지 않으며 얼굴 앵커 없는 몸만의 Person 결과는 만들지 않는다.

**10/2 사용자 설명 정정:** Dance/Person은 **하나의 앱·SaaS 내부 기능**이다. 앞서 동일 YOLO의 Person 사용에 플러그인별 별도 허가가 필요하다고 쓴 표현은 철회한다. 이 말이 YOLO를 현재 사용할 수 있다는 뜻은 아니다. 기존 도입 이력은 [W13 조사](../../features/highlights/records/2026/10/01-w13-yolo-license-provenance.md)에 남긴다. 또한 **흐린 배경의 몸 상자만으로는 누구인지 알 수 없으므로 Person 카드·클립·`확인 필요` 그룹을 만들지 않는다.** 이전의 몸만 검출된 배경을 화면에 남기자는 제안을 철회한다. 향후 사용 가능한 몸 모델이 별도로 정해지더라도, 몸 추적은 같은 편집 shot에서 얼굴로 이미 확인한 한 사람과 모호함 없이 연결될 때의 등장 구간 연장 *내부 단서*로만 재검토한다. ## 사용자 구상

인물이 등장하는 임의의 영상을 넣으면 같은 인물이 나온 장면을 인물별로 묶어 볼 수 있는 플러그인. 정확한 결과물·범위는 아직 정하지 않았다.

- [ ] 인물 이미지를 미리 선택할지, 참조 이미지 없이 영상의 얼굴 track/임베딩을 clustering해 인물 그룹을 만들지 비교한다. 사용자는 후자 흐름을 구상 중이다.
- [ ] 활용 상황·소구점·유저 플로우·첫 버전의 출력/MVP를 정한다.
- [ ] 사용자 결정: 배경 길거리의 일시적 인물도 포함해 검출된 모든 인물 그룹을 기본 목록에 나열한다. 자동 숨김/제외·soft filter·등장 시간/반복/크기 표시 제한은 후속으로 미룬다. 그룹 불확실한 관측도 확인 필요 결과로 보존한다.
- [ ] 대표 얼굴 이미지로 인물 카드/썸네일을 보여주고, 카드 선택 시 해당 인물의 모든 장면/clip을 볼 수 있는 UX.
- [ ] 원하는 clip의 개별/복수 선택·다운로드, 선택 clip을 하나의 쇼츠로 합치는 출력 등을 비교한다. 전부 구현 확정 사항은 아니다.
- [ ] 오분류/그룹 분리·병합/사용자 수정, 얼굴이 안 보이는 구간·재등장·동시 출연을 처리할 범위를 정한다.
- [ ] 얼굴 도구는 향후 다른 플러그인도 재사용할 독립 공통 모듈/공개 API로 설계한다. 안무와 인물은 초기 소비자이며 두 플러그인에 이용 대상을 제한하지 않는다. 검출/임베딩/track/cluster 계약을 찾아 재사용한다. 신규 모델 후보는 공식 문서/모델 카드·라이선스·속도·정확도·OS 지원으로 검증한다.

## 아직 결정되지 않은 사항

일반 인물 grouping과 실명 식별의 구분, 알려진 인물 참조 이미지의 선택적 사용, 후속 배경 필터의 도입 시점, clip 경계/출력 길이, 원본 타임라인 검토 여부, 최소 입력 범위, 과금/작업 재개/저장 정책.

## 작업 공간・다음 행동

W12에서 현행 안무 재사용 범위와 모델 후보를 조사한 뒤 이 세션으로 인계한다. 먼저 구상·MVP·유저 플로우와 검증 기준을 구체화하고, 선택된 범위에 맞춰 필요한 Desktop repo 및 Web API 계약을 정한다.

코드 수정 전에 최신 origin/dev 기반 새 브랜치·격리 worktree를 준비한다. 설계가 미정인 산출물이나 대규모 공통 추상화를 먼저 구현하지 않는다. 얼굴 공통 경로는 안무 세션과 소유권/병합 순서를 기록한다.

## W12 MVP·공통 계약·평가 인계

[종합 인계 §5–8](../../features/highlights/records/2026/09/29-pipeline-design-handoff.md) · [공식 모델 후보](../../features/highlights/records/2026/09/29-official-model-candidates.md) · [새 인물 세션 프롬프트](../prompts/2026-09-29-highlight-sessions.md).

- 기본 가정은 인터뷰·토크의 반복 등장 인물을 참조 없이 익명 grouping하는 MVP다. 사용 목적 선택에 따라 드라마·예능/행사·브이로그의 순서를 조정한다. 실명 식별·화자 식별·body ReID는 첫 버전과 분리한다.
- 카드 → 인물의 등장 구간/원본 preview → 재배정/merge·대표 이미지/제외 수정 → 선택 MP4·ZIP export를 필수 후보로 제안했다. 선택 합치기·템플릿/자동 제목/BGM/crop은 scope 선택 항목이다.
- 사용자 후속 결정으로 배경·잠깐 등장한 인물도 전부 기본 목록에 표시한다. 자동 soft filter와 48px·2초·2shot 표시 제한 제안을 철회하고 후속으로 미뤘다. 모델이 실제 사람을 미검출한 경우까지 모두 찾는다는 보장은 아니다.
- 현행 안무는 main 한 명/ROI 얼굴 하나 경로다. 인물은 다중 얼굴 관측·shot-local track·재등장 cluster, Scene↔PersonGroup 다대다 계약이 필요하다. 현행 clip.personId/category/숏폼 origin/선택 ZIP 계약은 그대로 일반 인물에 적용되지 않는다.
- W14가 플러그인 공용 얼굴 모듈/공개 관측 계약의 초기 작업 소유 세션이라는 제안을 남겼다. 향후 다른 플러그인도 사용하며 안무·인물은 초기 소비자다. 공개 API를 두 도메인에 종속시키지 않고 W13 기존 adapter를 유지한다. main/member mapping/결과 표시 정책은 각 플러그인이 소유한다.
- 평가 제안은 3개×120초 이하, 다중 얼굴 adapter 준비 후 관측 추론 최대3회+같은 embedding에서 grouping 기준 하나 대조, 최대6개 조건 결과다. soft-filter 비교는 제거했다. 배경·단역 포함 인물 recall·false merge/split·대표 이미지·수정 시간·동일 편집 구간 export 중복/영속화를 구분한다. 실제 경로/라벨·ML 실행은 아직 없다.

## 9/30 W14 제안과 결정 대기

[사용 목적·3접근·MVP·artifact/UI/export 계약 초안](../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md) · [실행 전 평가 manifest](../../features/highlights/records/2026/09/30-w14-evaluation-manifest.yaml) · [W13 공통 API/소유권 인계](../../features/highlights/records/2026/09/30-w14-to-w13-face-contract-handoff.md).

- **확정 사용자 방향:** 참조 이미지 없이 영상 속 같은 사람 등장 구간을 묶고, 배경·잠깐 등장한 사람까지 검출된 모든 그룹을 기본 표시한다. 자동 배경 숨김/제외·soft filter·시간/반복/크기 표시 제한은 후속이다. 불확실한 검출은 확인 필요로 보존한다.
- **W14 권고, 아직 승인 스펙 아님:** 인터뷰·토크의 익명 face-only grouping → 대표 카드/원본 seek/등장 목록 → 재배정·새 그룹/병합·이름/대표 이미지·제외/복원 → source 경계 검토 → 단일 MP4 또는 복수 MP4 ZIP. 이어 붙인 MP4/쇼츠는 10/1 사용자 결정으로 MVP에서 제외. 실명 식별·화자 결합·body ReID·템플릿/BGM/자동 타이틀/crop은 첫 slice에서 제외 제안.
- 현행 Python은 main segment의 최고 score ROI 얼굴 하나와 단일 bbox tracker다. Person에는 전체 얼굴 검출·shot-local 1:1 다중 track·embedding·cannot-link cluster·appearance interval이 필요하다. Nest 단일 `clip.personId`/dance-dialog origin/전체·한 인물 ZIP으로는 다대다 scene 및 선택 export를 표현하지 못한다. 원본과 edit overlay, revision/CAS, 분석·export job 분리, 같은 편집 구간 중복 제거·다른 경계 보존을 제안했다.
- 공통 독립 Python package는 W14 초기 소유, W13은 기존 Dance adapter·main/mapping/crop 소비자로 **상호 확인 대기**다. Electron plugin venv fingerprint에 새 workspace package 소스가 현재 포함되지 않는 점을 찾았고 compatibility gate에 넣었다. 서로 다른 embedding 모델/전처리 공간의 cache·threshold 혼용을 거절한다.
- 공식 OpenCV Zoo 자료상 YuNet 2026may는 dynamic-shape 재export이며 현행 2023mar보다 제품 정확도가 높다는 근거가 아니다. SFace 디렉터리 Apache-2.0, YuNet MIT, OpenCV Python wheel CPU-only; InsightFace SDK MIT와 제공 pretrained weights의 비상업 연구용 조건을 구분했다. Mac/Windows 실행·weight 실제 hash·SFace 학습 데이터 권리는 미확인.
- 평가 제안은 3개×120초 이하, 다중 얼굴 adapter 뒤 face-only 추론 최대3회와 같은 embedding의 grouping 기준 하나 대조 최대6조건이다. 입력 절대경로/원본 hash/익명 GT·모델 실제 hash/실행 SHA·OS/device/RAM/출력 위치가 비어 있어 실행하지 않았다. 합친 MP4는 제외됐다. 과금·보존 정책과 실제 평가 입력은 계속 결정해야 한다. 선택 scope의 Superpowers 디자인 리뷰→승인 스펙→계획 절차 전 제품 구현은 시작하지 않는다.

## 10/1 사용자 성공 기준 확인

사용자는 **인물·등장 구간 누락 최소화와 서로 다른 사람의 오합침 최소화가 둘 다 중요하다**고 확인했다. 둘을 동등한 1차 기준으로 따로 측정하며, 한쪽 악화를 다른 쪽 개선으로 상쇄해 단일 평균 점수로 채택하지 않는다. 불확실한 관측은 숨기거나 강제 병합하지 않고 확인 필요로 보존한다. 허용 수치와 편집 시간 등 후속 기준은 GT·scope 결정 뒤 정한다. [W14 제안 §1](../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md)과 [평가 manifest](../../features/highlights/records/2026/09/30-w14-evaluation-manifest.yaml)에 반영했다.

## 10/1 UI 목업 피드백

현행 앱의 영상 입력(YouTube URL/로컬 파일)→영상 확인→홈 작업 큐(대기·실행)→완료 카드 `결과 보기` 흐름을 확인했다. 결과는 앱 사이드바나 단계 탭을 목업 내부에 중복하지 않고, 안무·대사의 열 카드 패턴에 맞춘 인물/클립/원본 미리보기 3열 제안이다. 사용자는 각 클립의 시작·끝을 숫자로 입력하기보다 첨부 예시처럼 핸들로 조절하는 방향을 선호한다. 플레이어 바로 아래에는 보기/편집 공통 구간 타임라인 하나만 두며, 기본 상태에서는 선택 구간만 재생·구간 내 seek가 가능하고 양끝 경계 조절은 비활성이다. `구간 편집`을 누르면 같은 타임라인의 핸들이 활성화된다. 현행 `clip-trimmer`의 드래그 조작을 참고하되 숫자 입력칸은 인물 결과 목업에서 제거하고 읽기 전용 시각, 원래 경계, 저장·취소 동작으로 표현했다. [W14 제안 §3](../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md)에 반영. 제품 코드·ML·사용성 검증은 하지 않았다.

사용자는 수정된 공통 타임라인 목업을 **확인했다**. 이는 해당 UI 방향에 대한 피드백이며 출력 범위·전체 MVP·계약·평가 실행의 승인으로 확대하지 않는다. 이 목업 확인 뒤 사용자는 직접 다운로드와 이어 붙인 MP4 제외를 선택했다.

후속 UI 요청: 인물 행 hover 아이콘으로 해당 인물의 제외되지 않은 모든 클립 ZIP 다운로드, 클립 행 hover 아이콘으로 해당 클립 MP4 다운로드. 클립 체크박스와 선택 내보내기 하단 영역은 목업에서 제거했다. 현행 안무는 인물 행 ZIP 아이콘, 대사는 클립 행 다운로드 아이콘 패턴을 쓴다. 키보드 포커스·터치에서도 접근 가능하게 제안했다. 과금/작업 큐 세부 계약은 설계 검토 대상이다.

사용자는 목업을 확인하고 **이어 붙이는 기능은 없다**고 결정했으며 설계를 진행하라고 했다. [10/1 W14 MVP 서면 설계](../../../docs/superpowers/specs/2026-10-01-person-highlight-mvp-design.md)에 직접 다운로드/분석/수정/공통 얼굴 API/export job/평가·W13 소유권을 통합했다. 임의 다중 선택 체크박스도 첫 MVP UI에서 제외한다. 서면 설계 리뷰 뒤 Superpowers 구현 계획으로 넘어간다. 과금/보존 정책·실제 GT 입력·W13 상호 확인은 실행/출시 gate다.

## 10/1 첫 완료 결과 피드백과 수정

이전 단락의 진행 중 작업은 완료됐고 사용자가 결과를 확인했다. 장면 과분할·동일인 과분리·흐린 대표 얼굴·Person 8의 중복 clip·긴 원본 타임라인·불필요한 동시 출연 문구를 지적했다. 사용자는 **Person 5/6/8/13이 동일인**임을 알려주고, 편집은 **선택 장면 확대+좌우 이동**을 선택했다. [첫 결과 진단과 시험용 수정](../../features/highlights/records/2026/10/01-w14-first-result-debug.md)에 원본 SHA/720p 545kb/s, 관측·그룹·clip 수, 원인, 수정, 검증·미검증을 기록했다. 새 코드의 실제 영상 재분석과 익명 GT 정확도 측정은 아직 없다. 기존 결과는 자동으로 바뀌지 않는다.

사용자에게 37분 재실행을 권하기 전 [0–20초 회귀 후보](../../features/highlights/records/2026/10/01-w14-quick-check-candidate.yaml)를 준비했다. 원본 경로/hash, 기존 결과의 동일인 관계, 기존 관측 시각, 모델 hash/OS/OpenCV를 기록했다. 다른 사람·배경·동시 출연·shot/interval 경계 GT 및 실행 자원/출력 상한은 미완성이다. 이 후보로 새 ML을 돌리지 않았다.

후속 사용자 요청으로 작업을 계속해 [20초 통제 실행·결과](../../features/highlights/records/2026/10/01-w14-controlled-first-result-evaluation.md)를 수행했다. 위 후보의 미완성 상태는 **이 시점의 상태**이며, 새 개발용 GT와 자원 상한을 정한 뒤 20초 face-only 추론 총 3회(첫 회 감시 실패 포함)로 상한을 소진했다. 새 플러그인 결과는 이전 같은 구간 클립 22→11, 같은 shot 겹침 20쌍→0, 다른 shot 겹침 1쌍→0, MP4 11개 전부 영상+오디오다. 그러나 익명 출연자 A가 **11개 그룹**으로 남아 인물 정확도는 불합격이다. 보수적 threshold 0.55에서 개발 라벨 pairwise recall 0.342, A의 한 카드 구간 recall 0.38이며, 0.40 전역 적용은 37분 저장 관측에서 실물 false merge가 보여 철회했다. 대표 선택의 작은 crop 선명도 과대평가를 보정했다. 37분 새 코드 재분석, 배경·단역 GT, 독립 정확도 평가는 아직 없다.

이후 추가 ML 없이 저장 관측을 replay해 같은 shot의 단일 얼굴이 빠르게 움직일 때 끊긴 track을 잇는 보조 규칙을 Person adapter에 넣었다. 20초 개발 라벨 기준 A는 11→7그룹, pairwise recall 0.342→0.396, false merge 0으로 **부분 개선이지만 여전히 불합격**이다. 약한 보조 연결 6개 관측을 `association_uncertain`으로 기록하고 해당 그룹을 확인 필요로 보존한다. 대표 이미지 교체 후보의 raw sharpness 정렬을 공용 대표 순위와 일치시켰다. 최신 Python/core 단위 테스트 22개·Ruff·compileall 통과. 이 변경들은 앞의 세 번째 실제 플러그인 실행 **뒤의 코드**라 MP4/37분 정확도에는 검증되지 않았다. 영상 전체 threshold는 0.55를 유지하며, 결과의 사용자 수정 overlay를 자동 변경하지 않는다.

해상도는 요청 1080p/공급자 메타데이터 1920×1080과 달리 실제 내려받은 파일 1280×720이다. 10/1 로그인 계정의 yt-dlp 형식 목록에는 최대 720p만 있어 이 영상에서 1080p를 받을 수 없음을 확인했다. Nest 공용 YouTube ingest가 다음 작업부터 공급자 선언 대신 **실제 저장 파일 ffprobe 폭·높이·길이**를 기록하도록 수정했고, 실패 시 기존 메타데이터 fallback을 유지한다. Nest 빌드와 관련 회귀 44개 통과. 이미 저장된 결과·픽셀 품질은 바뀌지 않는다. [형식 조회·메타데이터 검증 기록](../../features/highlights/records/2026/10/01-w14-controlled-first-result-evaluation.md).

554개 그룹이 있는 기존 결과에서는 병합 메뉴 전체 항목이 탐색을 막아, Angular 결과 화면의 병합 대상을 이름/Person 번호로 검색하도록 수정했다. 왼쪽 인물 기본 목록은 전부 유지한다. Chrome Headless 해당 화면/실제 메뉴 7개 테스트와 devapp 빌드 통과. 이는 이미 저장된 분류를 자동 고치는 기능이 아니라 수정 UX 개선이다.

Angular(4200)·Electron 기존 개발 앱은 실행 중이었고 Nest(9019)는 활성 작업 없음 확인 후 새 빌드로 재시작했다. 두 HTTP 상태 200, Person plugin은 `installed/stopped`다. 기존 Electron 소유의 Person Python 프로세스는 다른 소유 경로라 건드리지 않았다. 다음 Nest 작업의 Python은 새 프로세스에서 로드되지만 이 시점에 새 얼굴 추론은 실행하지 않았다.

후속 병합 UX 점검에서 Nest 결과 빌더가 병합 후 남은 Person 번호를 다시 매기고, 병합된 원본 그룹의 이름·대표 이미지 선택과 후보를 표시에서 잃는 결함을 찾았다. 원본 manifest 순번을 표시 기본값으로 고정하고, 대표 그룹에 사용자 지정값이 있으면 우선하며 없으면 병합된 그룹의 사용자 지정 이름·이미지를 이어받도록 수정했다. 이미지 후보는 병합 대상의 후보·기본 이미지를 중복 없이 합친다. Nest 빌드와 관련 회귀 18개 통과. 저장된 37분 artifact에 Person 5/6/8/13 병합을 **메모리에서만** 적용해 554→551 그룹, Person 7 번호·병합 이미지 선택 보존을 확인했다. 사용자 편집이나 원본 결과는 저장하지 않았고 새 ML 추론도 없다. 활성 job 0 확인 뒤 Nest 개발 서버를 재시작해 `/v1/app/info` 200을 확인했다. 인물 자동 묶기 품질은 여전히 불합격이며 이번 편집 계약 수정으로 개선됐다고 주장하지 않는다. [검증 기록](../../features/highlights/records/2026/10/01-w14-controlled-first-result-evaluation.md).

장면의 잘못된 인물 소속을 바꾸는 Angular `더보기` 메뉴도 554개 전체 그룹을 한 번에 펼치고 있었다. 현재 연결된 인물은 검색 없이 보여 바로 제외할 수 있게 하고, 다른 인물 추가는 이름/번호 검색 결과 최대 30개만 보여주도록 수정했다. 왼쪽 인물 기본 목록의 전체 표시는 유지한다. 해당 화면 Chrome Headless 9개 테스트와 devapp 빌드 통과. 기존 Angular 개발 서버의 실제 화면에서 재배정 저장까지 손으로 클릭한 검증은 아직 없다.

추가 ML 없이 저장된 embedding에서 상호 최고 유사도+차점 격차 조건의 자동 병합을 검토했다. 20초 자체 라벨에서는 3쌍이 맞았지만 37분 저장 결과에서 서로 다른 여성 `person_303/342` 및 방송 로고 오검출 `person_111/516` 등을 병합 후보로 제시해 **기각**했다. 자동 병합 기준을 낮추지 않았다. 기존 원본의 180–210초에는 객석의 배경/단역과 동시 출연이 있어 다음 GT 후보로 삼을 수 있으나 정답 라벨·새 실행 범위는 아직 확정하지 않았다. [오프라인 기각 근거](../../features/highlights/records/2026/10/01-w14-controlled-first-result-evaluation.md).
