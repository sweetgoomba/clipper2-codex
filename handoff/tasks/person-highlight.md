## 10/13 현재 방향과 공통화의 실제 상태

**현재 실행 단계:** 사용자 “니 추천대로 진행해” 승인으로 Native 실행 완료. 새 격리 branch의 `clipper_face_core` 0.2.0에 참조 gallery/독립 비교/동일인 표본 합의·충돌/공개 provenance와 소비 예제를 구현했다. core·replay73개, donor호환27개, 확대회귀617개 통과(모델부팅11개 제외·3skip). 독립 리뷰 Important3건 수정, 저장23참조/54query 거리·개별 배정 재현. **W13 제품 adapter 연결과 독립 품질 개선 검증은 아직 남는다.** [구현·검증·인계](../../features/highlights/records/2026/10/13-w14-shared-reference-matching-implementation.md).

- **실제 구현:** 새 `shared-reference-face-matching-20261013/desktop/clipper_python` checkout의 `clipper_face_core` 0.2.0에 플러그인 비종속 참조 매칭을 추가했다. 기존 Person 시험판의 0.1.0은 보존되어 있으며 실제 소비 교체는 하지 않았다. 기본 SDK에는 ML 의존성을 넣지 않았다.
- **미완료:** 새 package는 미커밋이며 앱/dev에 적용되지 않았다. Dance의 기존 FaceClusterService는 W13 소유로 그대로다. 두 플러그인이 새 참조 매칭을 함께 쓰는 상태가 아니며, adapter/venv·Electron fingerprint/Windows·독립 품질 평가는 후속이다. 새 reference 계약에 시간축·실패·embedding 공간은 구현했으나 legacy Person 관측 API를 자동 변환하지 않는다.
- **담당:** W14는 플러그인에 종속되지 않는 얼굴 분석·비교·참조 매칭 품질과 공통 API를 우선한다. W13은 메인 댄서 선택·추적·구간 분리·군무/복수 메인·crop 및 Dance adapter의 통합을 맡는다. W13의 10/13 카드에도 얼굴 매칭 후속을 W14에 맡긴다는 사용자 결정이 있다. 기존 파일 소유권은 W13이 10/1 수용했으며, API 이식 완료와 구분한다.
- **다음 평가 방향:** 동일한 안무 원본·참조 사진·익명 인물 정답을 고정하고, 올바른 대상 얼굴을 준 경우의 매칭과 실제 Dance ROI/track을 준 경우의 결과를 따로 측정한다. 얼굴 미검출, 다른 사람 얼굴 선택, 같은 인물 비교 실패, 참조 멤버 배정 실패를 구별한다. 올바른 멤버 매칭률·다른 멤버 오배정·미배정·멤버별 편차를 함께 본다. W13의 잘못된 사람 선택/구간 혼합을 얼굴 모델 실패로 계산하지 않는다.
- **보류:** Person UI·내보내기·짧은 클립/등장 interval·몸 검출 후보 비교 등 플러그인 전체 개발. 방향 전환 정리 자체는 제품 변경·새 추론·다운로드·merge를 수행한 것이 아니다. 이후의 실제 얼굴 추론은 바로 아래 10/13 진단으로 구분한다.

**10/13 구현 전 진단(보존 이력):** 기존 안무 원본/모델/참조/hash를 잠그고 참조 23사진 및 18프레임×3 ROI 조건을 실행했다. 참조 leave-one-out는 입력 라벨 23/23 일치였지만 영상 정확도를 뜻하지 않는다. 정답 사람의 몸 ROI 직접 비교는 14/18 일치·다른 라벨2·미배정2였다. 올바른 해린 특징이 전역 군집 후 하니로 바뀐 사례와 ROI 확장 뒤 옆 얼굴을 최고 검출 점수로 선택한 사례를 확인했다. 최근접 배정만 적용한 저장 대조는 256 악화/512 개선으로 단순 수정 미채택. 초기 감시 실패 시도와 성공 2회 및 자원/출력을 분리 보존했다. [실제 실행·한계](../../features/highlights/records/2026/10/13-w14-dance-face-matching-baseline.md), [검토용 공통 API 설계](/Users/jina/project/adlight/docs/superpowers/specs/2026-10-13-shared-reference-face-matching-design.md). 당시 제품 수정·공통 API 이식·안무 적용은 없었다. 이후 위 현재 단계처럼 공통 package 구현/격리 검증까지 진행했으며 안무 앱 연결은 남아 있다.

**10/2 최신 사용자 결정 — 모델:** 이번 격리 시험에 쓴 YOLOv8 pose는 앞으로 사용할 수 없다. W13 Dance는 다른 모델로 교체를 진행 중이나 **대체 모델은 아직 미정**이다. W14는 YOLO를 Person에 연동하거나 추가 추론하지 않으며, 아래 YOLO 수치는 과거 진단 기록으로만 읽는다. W13의 향후 모델을 W14가 자동으로 공유한다고 가정하지 않는다. 얼굴 기반 인물 묶기 품질 개선은 별도로 다루고, 얼굴/몸 연동은 사용 가능한 모델과 독립 검증 범위가 정해질 때까지 보류한다.

**10/2 신규 조사 — 인물용 몸 경로:** 사용자 요청에 따라 Dance 모델과 독립적으로 무료·비공개 소스 SaaS 후보를 공식 코드/weight 조건까지 다시 비교했다. **10/2 사용자 설명 정정:** Dance/Person은 **하나의 앱·SaaS 내부 기능**이다. 앞서 동일 YOLO의 Person 사용에 플러그인별 별도 허가가 필요하다고 쓴 표현은 철회한다. 이 말이 YOLO를 현재 사용할 수 있다는 뜻은 아니다. 기존 도입 이력은 [W13 조사](../../features/highlights/records/2026/10/01-w13-yolo-license-provenance.md)에 남긴다. 또한 **흐린 배경의 몸 상자만으로는 누구인지 알 수 없으므로 Person 카드·클립·`확인 필요` 그룹을 만들지 않는다.** 이전의 몸만 검출된 배경을 화면에 남기자는 제안을 철회한다. 향후 사용 가능한 몸 모델이 별도로 정해지더라도, 몸 추적은 같은 편집 shot에서 얼굴로 이미 확인한 한 사람과 모호함 없이 연결될 때의 등장 구간 연장 *내부 단서*로만 재검토한다. ## 초기 사용자 구상 — 보존 이력, 현재 실행 범위 아님

인물이 등장하는 임의의 영상을 넣으면 같은 인물이 나온 장면을 인물별로 묶어 볼 수 있는 플러그인. 정확한 결과물·범위는 아직 정하지 않았다.

- [ ] 인물 이미지를 미리 선택할지, 참조 이미지 없이 영상의 얼굴 track/임베딩을 clustering해 인물 그룹을 만들지 비교한다. 사용자는 후자 흐름을 구상 중이다.
- [ ] 활용 상황·소구점·유저 플로우·첫 버전의 출력/MVP를 정한다.

## 10/1 UI 목업 피드백

현행 앱의 영상 입력(YouTube URL/로컬 파일)→영상 확인→홈 작업 큐(대기·실행)→완료 카드 `결과 보기` 흐름을 확인했다. 결과는 앱 사이드바나 단계 탭을 목업 내부에 중복하지 않고, 안무·대사의 열 카드 패턴에 맞춘 인물/클립/원본 미리보기 3열 제안이다. 사용자는 각 클립의 시작·끝을 숫자로 입력하기보다 첨부 예시처럼 핸들로 조절하는 방향을 선호한다. 플레이어 바로 아래에는 보기/편집 공통 구간 타임라인 하나만 두며, 기본 상태에서는 선택 구간만 재생·구간 내 seek가 가능하고 양끝 경계 조절은 비활성이다. `구간 편집`을 누르면 같은 타임라인의 핸들이 활성화된다. 현행 `clip-trimmer`의 드래그 조작을 참고하되 숫자 입력칸은 인물 결과 목업에서 제거하고 읽기 전용 시각, 원래 경계, 저장·취소 동작으로 표현했다. [W14 제안 §3](../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md)에 반영. 제품 코드·ML·사용성 검증은 하지 않았다.

사용자는 수정된 공통 타임라인 목업을 **확인했다**. 이는 해당 UI 방향에 대한 피드백이며 출력 범위·전체 MVP·계약·평가 실행의 승인으로 확대하지 않는다. 이 목업 확인 뒤 사용자는 직접 다운로드와 이어 붙인 MP4 제외를 선택했다.

사용자는 목업을 확인하고 **이어 붙이는 기능은 없다**고 결정했으며 설계를 진행하라고 했다. [10/1 W14 MVP 서면 설계](../../../docs/superpowers/specs/2026-10-01-person-highlight-mvp-design.md)에 직접 다운로드/분석/수정/공통 얼굴 API/export job/평가·W13 소유권을 통합했다. 임의 다중 선택 체크박스도 첫 MVP UI에서 제외한다. 서면 설계 리뷰 뒤 Superpowers 구현 계획으로 넘어간다. 과금/보존 정책·실제 GT 입력·W13 상호 확인은 실행/출시 gate다.
