## 목표・배경

사용자가 다른 팀원이 수정/추가한 홈(보관함) 기능들을 이해하고, 이해한 뒤 원하는 부분을 고친다.

핵심 질문:

> 대기 중 작업이 없을 때 새 작업을 추가하면 왜 큐에 남지 않고 바로 보관함 작업 목록에 나타나는가? 언제, 어떤 이유로 바뀌었나? 원래 성공/실패 등 완료된 작업의 보관함으로 생각했는데 현재 생성 중 작업도 포함되며, 큐는 대기 중 작업만 담는 것처럼 보인다.

이는 최초 **사용자 관측·질문**이다. 아래 9/29 조사에서 코드·상태 전이·Git·설계 문서로 현재 표시 정책 변경을 확인했다. 조사 결과를 실제 배포일·실제 ML/금융 검증으로 확대하지 않는다.

## 9/29 조사 결과

- 홈과 보관함은 같은 `/projects` 화면이다. `preparing/starting/running`은 `내 파일` 그리드의 상단 고정 생성 중 카드, `queued`만 상단 큐 행이다. 대기 0개여도 큐 바는 항상 보인다.
- 정확한 표시 분리 커밋은 Angular `6fd329f6`, **2026-09-18 15:24:33 KST**. 작성 spec은 ‘생성 중 작업의 얇은 큐 행과 종료 카드의 표현이 갈라짐’을 이유로 기록한다. 현재 dev의 명시적 병합 기록은 `757d5e63`, **9/21 07:31:38 KST**다. 배포일은 미확인.
- 빈 큐에서 백엔드는 queued snapshot을 발행한 뒤 바로 drain→starting으로 진행한다(전역 동시 실행 1개). ‘큐에 남지 않는다’는 빠른 상태 전이와 현재 표시 필터가 함께 설명한다. 내부적으로 queued를 생략한다고 주장하지 않는다.
- preparing은 아직 큐에 없거나 앞 베리에이션 배치의 준비를 기다리는 상태도 포함한다. 화면의 생성 중과 실제 executor 실행은 구분한다.
- 베리에이션 활성 행/카드는 render 단위, 종료 결과 카드는 project 단위다. 모든 관련 잡이 종료되기 전 일반 결과 카드는 숨긴다. 일반 재시도는 새 jobId/retryOf로 조상 카드를 숨기며, 스토리보드는 전용 화면에서 동일 job 재개를 사용한다.
- 기존 Angular 집중 회귀 **362/362 PASS**; Nest 현재 소스 build와 취소·삭제·재시도·차감/환급·재시작 회귀 **117/117 PASS**. 임시 JSON/가짜 실행기·금융 원장 기반이며 실제 앱·ML·원격 차감/환급은 미실행.
- 이번에는 fetch/제품 소스 수정/새 branch·worktree/commit/push/merge/deploy를 하지 않았다. 원본 Angular/Nest/Web API dev는 clean이며 조회 당시 로컬 origin/dev와 같았다. 실제 수정 직전에 최신 원격 기준선을 다시 확인한다.

## 완료 기준・경계

현행 기능 지도 + 상태별 표시 표 + 변경 이력/이유의 근거를 먼저 제공한다. 이후 사용자 선택한 개선의 전후 동작과 회귀를 확인한다.

스토리보드/하이라이트 카드의 홈 노출, 공통 버그 세션의 공통 컴포넌트와 겹칠 수 있다. 공유 경로 수정은 각 세션에 인계하고 중복 구현을 피한다. 과거 PG 통합 문서의 “보관함”이라는 용어만으로 현재 화면 필터를 추정하지 않는다.
