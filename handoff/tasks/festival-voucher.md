## 제품 범위와 결정

- 관리자 메뉴 `프로모션`에서 캠페인을 코드 없이 만들고 상세에서 여러 고유 코드를 발급한다. 캠페인 설정은 혜택·기간·이력 제한·**각 코드에 공통으로 적용할 코드별 등록 상한**이며, 코드별로 추천인·활성 상태·실제 등록 건수를 관리한다.
- 한 회원은 같은 캠페인에서 한 코드만 성공 등록할 수 있다. 다른 캠페인 참여 이력과 무료체험 이력은 제한 선택지에 없다. 과거 유료 이용권 결제·사용 및 관리자 지급 이용권 이력은 캠페인마다 각각 선택할 수 있다. 현재 또는 시작 예정인 주 이용권과 첫 유료 결제 진행/예약 중인 구독은 중복 지급을 막는다.
- AI 부스 행사에는 필요할 때 관리자가 캠페인과 공통 행사 코드를 직접 만든다. 혜택은 Pro 1개월 및 해당 등급의 월 크레딧이고, 과거 유료 이력만 제한으로 선택한다. 무료체험·관리자 지급 이력은 이 행사 제한에서 제외한다. 코드 문자열·시작/종료일·코드별 상한 건수는 이 기능의 구현 전 결정값이 아니다.
- 관리자에서는 등록 내역의 남은 혜택 회수, 코드별 등록·직접 유료 전환·환불 반영 결제액·크레딧 사용량 조회와 XLSX 내보내기를 제공한다. 금액 자동 정산·송금은 제공하지 않는다. 회원은 코드 확인 모달을 거쳐 등록하고, 자신의 종료·회수 이력까지 표에서 확인한다.
- 프로모션 이용 중 유료 전환 예약은 같은 등급 판매 상품 또는 기존 `/pricing`의 다른 상품 선택으로 이어진다. 카드 등록 미완료는 완료된 예약이 아니다. 결제 귀속은 등록 ID에 직접 연결된 주문·구독을 따른다.

## 현재 Git·검증

세 저장소의 기능 브랜치 `feat/promotion-followups-20261023`에서 커밋한 뒤 최신 원격 `dev`와 병합했다. 원격 병합 커밋: API `0776268`, 관리자 `98e2e8c`, 회원 `fbd4573`. API의 마이그레이션 등록 파일에서 충돌 1건을 해결했고, 각 원격 `dev` SHA를 다시 확인했다. 병합 결과의 API Jest 4,169개, 관리자 ChromeHeadless 2,382개, 회원 웹 504개 테스트와 세 빌드가 통과했다. 상세 범위·기존 API 작업 폴더의 별도 미커밋 변경은 [병합 기록](../../implementation/2026-10-23-promotion-campaign-dev-merge.md)을 따른다.

이어서 데스크톱 두 저장소의 미커밋 프로모션 변경만 최신 `origin/dev`에서 새 브랜치 `feat/promotion-desktop-followups-20261023`에 커밋해 병합했다. 원격 병합 커밋: NestJS `b9602b2f`, Angular `1a839571`. NestJS 빌드·관련 테스트 9개, Angular 빌드·전체 8,195개 테스트가 통과했다. NestJS 전체 테스트는 변경 범위 밖의 실패 15개·취소 27개로 통과하지 못했다. 기존 인물 하이라이트 작업 트리는 수정하지 않았다.

## 다음 확인

1. 실제 배포 전에 Web API 관리자 DB 마이그레이션과 세 앱 배포 순서를 확인한다. 원격 `dev` 병합이 곧 배포를 뜻하지 않는다.
2. 실제 Toss 결제망에서 카드 등록 완료/이탈, 예약 첫 청구·재시도, 자동 갱신, 환불을 별도 검증한다. 이번 병합에는 실결제 검증 결과가 없다.
3. AI 부스 캠페인을 운영할 때 실제 코드·날짜·코드별 상한을 관리자에서 입력하고 회원 등록 및 코드별 성과/XLSX를 확인한다.
