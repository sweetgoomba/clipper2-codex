## 버전 관리와 배포 전략의 관계 — 검토할 가설

앱 버전은 **설치 파일과 자동 업데이트 대상**을 가리키고, 플러그인 버전은 **각 플러그인의 기능/호환성 단위**를 가리킬 수 있다. 두 번호를 같게 맞출 필요는 없지만, 특정 앱 빌드가 어떤 플러그인 코드·공통 라이브러리·API와 조합됐는지 재현 가능해야 한다. 따라서 릴리스별 앱 버전 → 플러그인 버전/소스 지문 → 배포 API revision의 대응표는 6번 배포 전략과 함께 다룬다.

현재 코드상 Python 플러그인 소스는 앱 번들 안에 들어가고, Electron의 venv 갱신 기준에는 플러그인 manifest 버전뿐 아니라 앱 버전과 소스 fingerprint도 들어간다([`plugin-venv.ts`](../../desktop/clipper_electron/src/main/plugin/plugin-venv.ts)). 플러그인 `manifest.json`과 `pyproject.toml`에는 `0.1.0` 같은 버전이 별도로 적혀 있으며 사용자 화면이 `v`를 앞에 붙인다. **현재 배포 구조에서 버전 숫자만 올린다고 설치된 앱의 플러그인 코드가 바뀌지는 않는다.** 앱과 독립적으로 플러그인만 올리려면 별도 배포·검증·호환·롤백 경로가 필요한지 먼저 판단한다.

잠정 권고: 앱 버전은 배포 단위로 유지하고, 플러그인 버전은 호환성·진단에 실제로 쓰는 경우에 유지하되 중복 하드코딩을 줄인다. 앱 릴리스마다 포함된 플러그인 버전과 코드 지문을 함께 기록한다. 독립 플러그인 업데이트가 당장 필요하지 않다면 이를 전제로 한 복잡한 배포 체계는 만들지 않는다. 사용자 표시 여부와 정확한 증가 규칙은 설계에서 결정한다.
