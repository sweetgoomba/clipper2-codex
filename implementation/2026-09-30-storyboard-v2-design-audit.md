## 화면·백엔드·검증 범위

설계 §4는 7개 화면(빈 목록, 카드, 추천 모달, 결제 모달, 결과, 상세, 생성 폼)의 배치를 위 결정으로 구체화한 것이다. §5의 백엔드 접점은 진행 콜백(D9), DELETE API(D6/7), 옛 잠금 제거(D12), 설정 없는 프로필 판별/400(D13), 잡 신호 구독(D15)이다. §6 작업 순서의 1~3단계는 W07 착수 전에 이미 dev에 포함됐고, 4~6단계가 이번 후속 구현의 중심이다. 단, D10은 사용자 요청으로 철회했다.

§7은 **이번 UI 설계 밖의 별도 위험 메모**다. ① 정산 중단 시 관리자 복구 경로, ② 플러그인 카탈로그의 런타임 종류, ③ shell→feature 역방향 import, ④ inference→operations 의존, ⑤ 영수증 테이블을 DROP하는 migration down, ⑥ LLM 원문 JSONB 저장량/개인정보, ⑦ 셸 `app-page` 위치. ⑦은 D25와 W07 옛 셸 철거로 다뤘다. ③·④ 의존은 현행 코드에도 보인다. 나머지는 이번에 재감사해 해결했다고 주장하지 않는다.

§8은 단위/스타일/백엔드 회귀와 다크·라이트 실제 렌더, 선택/잠긴 행, 진행 미터, 좁은 상세, 옛 프로필 전환을 확인하자는 계획이다. W07 기존 브라우저 fixture 검증은 [후속 검증](2026-09-29-storyboard-followups-verification.md)을 보되, 현재 사용자의 **실제 프로필 삭제 및 보관함 확인**은 아직 수행하지 않았다.
