> 이 문서는 설계·구현 당시의 결정과 검증 이력을 보존한다. 이후 수정 및 최신 Git/승인 상태는 [스토리보드 작업 카드](../handoff/tasks/storyboard.md)를 우선한다. 9/21 현재 제품 구현은 별도 worktree에 미커밋이며, 사용자는 `.codex` 문서만 커밋·푸시하도록 승인했다.

## 사용자 문제 제기

장면 상세가 실제로 쓸 수 있는 정보인지, 장면과 컷의 차이 및 1장면 다중 컷 여부, 장면 단위 하나로 단순화할 수 있는지 확인 요청. 장면마다 외부 AI로 화면을 생성하는 사용자와 이미지/영상 자료를 찾아 쓰는 사용자를 모두 고려해 스토리보드 자체를 재설계해야 한다.

## 코드 확인

대상은 feature/storyboard-ux-overhaul-20260920 격리 작업 트리다. 이번 확인은 읽기 전용이며 실제 ML/생성 호출은 하지 않았다. 따라서 실제 신규 생성물의 품질 검증 결과가 아니다.

- Angular `src/features/shortform-director/models/shortform-director-storyboard.ts`: `StoryboardSceneV1`은 narration/onScreenText/intent/claim/evidenceIds 및 `shots: StoryboardShotV1[]`를 가진다. shot은 화면 연출, 대상/장소/동작, 카메라/조명/색감, 오디오/전환, 영문 AI 영상 프롬프트 등이 있다. 검색용 이미지/영상 키워드/선정 기준 전용 구조가 없다.
- Angular `components/storyboard-scene-list/storyboard-scene-list.component.html`: scene→shots 이중 계층으로 모든 제작 필드를 나열한다. 사용자 제작 방식에 맞춰 정보가 분리되지 않는다.
- Nest `application/shortform-director-storyboard.assembler.ts`: 각 scene에 sceneIndex가 일치하는 모든 shot을 연결한다. 1장면 여러 컷 구조이며 첫 컷만 표시하면 정보가 유실된다.
- Nest `application/shortform-director-candidate-production.service.ts`: video-plan/editorial → scene-media-decision/shot-direction 단계를 이어서 수행한다. 후자가 전자의 editorialPlan을 입력으로 받는다.
- Web `application/shortform-director-inference.prompt.ts`: 장면은 의미/근거 전환에서 나누고, 컷별 연출·모델 중립 영문 AI 프롬프트를 작성하도록 한다. 검색어 2~3개와 선정/편집 기준을 반환하라는 지시문도 남아 있다.
- 그러나 Web `domain/shortform-director-inference.contract.ts`의 SCENE_MEDIA_DECISION_SCHEMA 및 validateSceneMediaDecision에는 검색 필드가 없다. Nest 저장모델/assembler와 Angular 모델·화면에도 전용 검색 항목이 없다. 따라서 검색 지원이 완성돼 있다고 볼 수 없고 프롬프트·계약 정합성도 수정 필요하다.
- Angular 테스트 fixture에는 1장면 아래 6초짜리 컷 2개가 있는 사례가 있다. 테스트 fixture는 실제 생성 품질의 근거가 아니다.
- 재검토 당시 대화용 v2 시안은 장면별로 고정 예시 1컷만 보여줬다. 실제 다중 컷 정보를 반영한 상세 설계가 아니며 생성 데이터와 연결돼 있지 않다.

## 현재 방향 — 대본 흐름 중심

중앙 목록은 화면 동작 이름이 아니라 TTS 대본 전문을 표시한다. 이야기의 의미/호흡에 따라 나눈 대본 구간을 중심으로 화면·소재가 대응하며 화면 변화마다 대본을 기계적으로 분할하지 않는다. 영역명 ‘대본 흐름’과 번호 표기는 검토용 제안이다. 오른쪽에는 대본·화면 문구·보여줄 화면과 AI 영상 생성 프롬프트, AI 이미지 생성 프롬프트, 이미지·영상 검색어를 모두 표시한다. 소재 방식/종류 토글 및 선정·활용 안내는 제거한다. 검색어는 짧고 구체적인 대상/행동/필요한 장소 조합을 독립된 검색 후보로 제공하고 각 항목을 복사한다. 한국어/영어 각 2개 예시는 검토용이며 개수는 최종 계약 요구가 아니다. 문장형 검색이 항상 열등하다는 뜻은 아니며 긴 연출 지시문을 검색어로 재사용하지 않는다. 실존 인물·사건 등은 정확한 이름/작품/사건을 유지해야 하고, ‘영상/사진’ 접미사를 일괄 추가하지 않는다. 실제 검색 결과 적합성은 아직 검증하지 않았다.

3열/뒤로 가기와 장면·컷 이중 UI 제거는 유지한다. 단일 화면 동작을 제작 단위로 확정했던 이전 해석은 정정한다. 기존 다중 컷 데이터의 시간·대본·화면 대응을 보존하는 호환/계약 설계가 필요하다. 단순 필드 숨김으로 완료할 수 없으며 프롬프트·응답 검증·저장/조회·화면·복사 출력이 일치해야 한다. 실제 검색/다운로드/삽입이나 AI 생성 실행 기능을 뜻하지 않는다.

## 이전 시안 이력 — 아래 소재 선택 방식은 후속 정정으로 대체

사용자는 장면/컷 두 단계를 없애고 각 장면에서 대본·화면 구성·소재 준비를 확인하는 방향에 동의했다. 전체 영상을 하나의 장면으로 합치는 뜻은 아니다. 기존 저장 결과의 다중 컷 변환/호환 방식은 구현 설계에서 정한다.

v2 시안은 개요/장면/선택 장면 상세의 3열을 유지하며 중앙에 시간과 화면 내용을 담은 장면 5개를 표시한다. 우측 공통 정보는 대본·화면 문구·보여줄 화면이다. 소재 준비에서 이미지·영상 찾기/AI로 만들기 및 영상/이미지를 선택하며 장면별 선택을 유지한다. 자료 찾기는 구체적 검색어·선정 기준·활용 안내, AI는 선택한 소재 종류에 맞는 복사 가능한 프롬프트를 표시한다. 기본은 자료 찾기/영상이며 이는 검토용 시안 선택이다. 실제 검색·생성·파일 삽입 기능은 아니다.

예시는 3개 주제별 5장면(총 15개)이며 동일 주제의 시나리오들은 예시 장면을 공유한다. 실 API 응답이나 생성 품질을 증명하지 않는다. 실제 구현은 시나리오마다 생성된 데이터와 연결해야 한다.

로컬 Chrome에서 단일 장면 목록, 소재/종류 선택 유지, 이미지/영상 프롬프트 구분 및 복사 값, 15개 예시 필수 정보, 뒤로 가기, 1056/390px 3열 유지, 런타임 오류 없음을 검증했다. 자료 찾기/AI 화면 스크린샷도 확인했다. 이번 검증은 시안 동작이며 Angular/백엔드 제품 검증은 아니다.

관련 문서 미커밋. 제품 코드 변경·실제 ML·Build5·서버 접속·배포·커밋·푸시 없음.

## 화면 문구 유지 및 검색어 우선 표시

사용자는 ‘화면 문구’의 강조 텍스트 역할을 이해한 후 유지를 선택했다. 삭제 제안은 채택하지 않는다. 소재 표시 순서는 이미지·영상 검색어 → AI 영상 생성 프롬프트 → AI 이미지 생성 프롬프트다. ‘보여줄 화면’은 직접 촬영을 기본 전제로 삼지 않고, 찾거나 생성한 소재로 무엇을 보여주고 대본의 어떤 의미를 전달하는지 설명한다. 인물/장소 연속 촬영이나 카메라 위치·촬영 동작을 사용자에게 요구하지 않는다. 자료 선정/활용 안내 항목을 별도로 부활시키지 않는다. 이는 유튜버 전반의 촬영 여부에 대한 통계적 주장이 아니라 이 플러그인의 사용자 흐름 설계 기준이다.


## 전체 스토리보드 PDF 내보내기

스토리보드 개요 하단의 전체 대본 복사 옆에 PDF 다운로드를 추가한다. 내보내기 범위는 현재 선택한 스토리보드 한 개와 그 상위 프로필·주제 맥락이다. 같은 프로필의 모든 주제/스토리보드 일괄 내보내기로 확장하지 않는다. 문서에는 (1) 프로필 이름, 1·2뎁스 분야, 성별/연령, 목적, 스타일, 관련/금지 키워드 (2) 주제명, 추천 이유, 시청자의 궁금증, 기획 포인트 (3) 시나리오 번호, 제목, 타입, 훅, 예상 길이 (4) 전체 TTS 대본 (5) 모든 구간의 번호/예상 시간, 대본, 화면 문구, 보여줄 화면, 검색어, AI 영상·이미지 프롬프트를 포함한다. 현재 선택 중인 구간만 내보내지 않는다.

제품 구현 시 생성 당시 프로필/주제와 결과의 연결을 보존하고 저장된 결과로 문서를 구성해야 한다. 내보내기를 위해 AI를 재호출하거나 추가 생성 과금을 하지 않는다. 한글 폰트, 긴 문장/프롬프트 줄바꿈, 페이지 나눔과 잘림 여부 및 모든 구간 포함 여부를 실제 PDF 렌더 결과로 검증해야 한다. 원시 API 정보/모델 비용은 문서의 사용자 정보에 포함하지 않는다.

현재는 UI 설계 단계이므로 버튼을 눌러 문서 구성 미리보기를 여는 시안만 구현했다. 실제 PDF 파일 생성·다운로드/인쇄 페이지 레이아웃은 미구현이며 제품 구현에 포함할 요구사항이다. 미리보기에 이 상태를 명시한다.


## PDF 문서 영역·페이지 레이아웃 개선

사용자는 다운로드 PDF가 줄글 나열이 아니라 영역을 구분한 정식 문서여야 한다고 피드백했다. 시안의 PDF 미리보기를 페이지별 문서로 재구성했다. 현재 예시는 A4 세로 7쪽: 1쪽 프로필/주제/개요 요약 표, 2쪽 구간·예상 시간·TTS 전체 대본 표, 3~7쪽 구간별 제작 시트다. 각 제작 시트는 대본 강조 영역, 화면 구성 표, 검색어 표, AI 영상/이미지 프롬프트 박스로 나누며 머리말·꼬리말·페이지 번호를 일관되게 표시한다. 전체 정보는 유지한다. 예시 내용에 맞춘 검토용 레이아웃이며 7쪽을 제품의 고정 페이지 수로 정하지 않는다. 실제 긴 콘텐츠는 글자 축소/잘림 대신 다음 페이지로 이어지고 머리말을 반복하도록 구현해야 한다.

실제 검토용 PDF `output/pdf/storyboard-document-design-sample.pdf`를 로컬 Chrome으로 생성했다(기존 예시 데이터, AI 실행 없음). 7개 A4 페이지, 콘텐츠/푸터 비겹침, 한글 텍스트 및 필수 항목 추출, 다섯 제작 시트의 두 프롬프트 포함을 확인했다. Poppler로 모든 페이지를 렌더링해 전체 컨택트 시트와 상세 페이지를 검토했다. 최초 텍스트 검사에서 표 레이블 줄바꿈으로 일치 검사가 실패해 공백 정규화 후 검증했다. 내용 누락은 아니었다. 미리보기의 선택 결과 연결/전체 구간 포함/닫기/390px 줄바꿈도 검증했다.

이 PDF는 다운로드해 볼 수 있는 디자인 예시이며 제품의 PDF 내보내기 기능이 완성된 것은 아니다. 제품 코드 미변경, 관련 문서 미커밋. 커밋·푸시 없음.


## PDF 문서 구성 승인

사용자가 실제 PDF 예시를 확인하고 “좋아”로 승인했다. 승인 범위는 프로필·주제·스토리보드 요약 표, 전체 대본 표, 구간별 제작 시트의 영역 구분과 페이지 구성이다. 예시의 7쪽을 고정하지 않고 실제 내용 길이에 맞춰 페이지를 나눈다. 전체 제품 구현 완료나 커밋·푸시 승인을 의미하지 않는다. 제품의 실제 내보내기 연결은 미구현이다.
