# 프로모션 캠페인 후속 구현·`dev` 병합 기록

기록일: 2026-10-23 KST. [현재 설계](../design/2026-10-23-promotion-campaign-current-state.md) · [W17 작업카드](../handoff/tasks/festival-voucher.md).

10/19~20의 최초 구현은 Web API·관리자 웹·회원 웹과 데스크톱 NestJS·Angular의 `promotion` 출처 인식을 포함했다. 그 당시 실행·검증은 [초기 구현 기록](2026-10-19-promotion-referral-verification.md)에 보존한다. 아래 내용은 이후 관리자/회원 흐름과 캠페인 구조를 고쳐 세 웹 저장소의 최신 `dev`에 병합하고, 누락된 데스크톱 두 저장소의 출처 인식을 이어서 병합한 작업이다.

## 이번 작업에서 반영한 내용

- 단일 프로모션당 코드 하나로 좁혔던 구조를 **캠페인 1개에 코드 여러 개**로 복원했다. 캠페인은 코드 없이 생성하고 상세에서 코드를 발급한다. 코드별 추천인·활성 상태·성공 등록 건수를 유지한다.
- 등록 상한은 캠페인 전체 누적치가 아니라 **캠페인에서 공통으로 설정해 각 코드에 따로 적용하는 상한**으로 바꿨다. 회원당 같은 캠페인 한 번 규칙은 유지했다. 다른 캠페인 참여·무료체험 이력 제한 선택지는 없애고 유료/관리자 지급 이력만 캠페인별로 선택한다.
- 관리자 목록을 캠페인 표로 정리하고 상세에서 코드·성과·등록 내역·운영 기록을 분리했다. 생성/수정 패널, 삭제 제한, 캠페인/코드 상태 토글, 코드별 성과, 날짜 필터, 빈 상태, 페이지 이동, 감사 기록 문구를 보완했다. CSV 대신 XLSX를 내보낸다.
- 회원 화면은 코드 입력을 항상 노출하고 확인 결과를 모달로 보여준다. 등록 불가 사유를 확인 단계에서 안내하고 등록 시 재검사한다. 참여 내역은 종료·회수 이력을 포함한 여러 행으로 표시한다. 예약 선택은 모달에서 시작하고 다른 요금제는 기존 `/pricing` 화면을 사용한다. 카드 등록이 완료되지 않은 신청은 완료된 예약으로 표시하지 않는다.
- 실제 등급별 크레딧을 관리자 입력값 대신 상품 설정에서 가져오고, 코드 형식을 5~20자로 통일했다. 선택한 지급 등급을 사용 중인 캠페인과의 충돌 등 운영 경계를 검증했다.

## Git 병합

세 코드 저장소에서 최신 `origin/dev`를 기준으로 같은 이름의 **로컬 기능 브랜치** `feat/promotion-followups-20261023`를 만들고 다음 커밋을 작성했다.

| 저장소 | 기능 커밋 | 원격 `dev` 병합 커밋 |
|---|---|---|
| `web/clipper_web_api` | `dfd5e16` | `0776268` |
| `web/clipper_web_admin` | `ea70397` | `98e2e8c` |
| `web/clipper_web_client` | `fb44368` | `fbd4573` |

병합 전 `git merge-tree` 검사에서 관리자·회원 웹은 충돌이 없었다. API의 `src/core/database/admin.datasource.ts` 한 파일은 원격 `dev`의 `AddAppNewsTarget1792500000000`와 기능 브랜치의 프로모션 마이그레이션 등록이 같은 위치를 수정해 충돌했다. 병합 작업 트리에서 양쪽 import와 migration 목록을 모두 포함해 해결했다. 병합 커밋을 세 원격 `dev`에 푸시하고, 이후 `git ls-remote origin refs/heads/dev`로 위 SHA가 실제 원격 값과 일치함을 확인했다. 로컬 `dev` 브랜치 포인터도 해당 원격 커밋으로 맞췄다. 임시 병합 작업 트리는 제거했고 기능 브랜치는 남겨 두었다.

API 기본 작업 폴더의 `person_highlight` 관련 변경과 로컬 환경/인증 설정 변경은 프로모션 커밋에서 제외하고 원래 미커밋 상태로 보존했다. 관리자·회원 기본 작업 폴더는 기능 브랜치에서 깨끗하다. `.codex`는 별도 `main` 문서 저장소이므로 세 코드 저장소의 `dev` 병합 대상이 아니다.

### 데스크톱 누락분 후속 병합

기존 `feat/promotion-referral-20261019` 작업 트리에 커밋되지 않은 채 남은 변경 6파일을 각각 최신 `origin/dev`에서 만든 새 기능 브랜치 `feat/promotion-desktop-followups-20261023`에 옮겨 커밋했다. 기존 인물 하이라이트 작업 트리와 기본 checkout은 수정하지 않았다.

| 저장소 | 기능 커밋 | 원격 `dev` 병합 커밋 | 변경 |
|---|---|---|---|
| `desktop/clipper_nestjs` | `4edb9adf` | `b9602b2f` | Web API의 프로모션 이용권·현재 크레딧 혜택 응답 허용 |
| `desktop/clipper_angular` | `f7a1f97a` | `1a839571` | 프로모션 이용권·현재 크레딧 타입 및 계정 요약 표시 |

두 저장소 모두 병합 전 `git merge-tree` 검사에서 충돌이 없었다. 병합 결과 tree가 검증한 기능 커밋 tree와 같고, 원격 `dev` SHA가 병합 커밋과 같은 것을 `git ls-remote`로 확인했다. 기존 10/19 작업 트리의 미커밋 변경은 삭제하거나 되돌리지 않았으므로, 작업 트리 정리는 별도다.

## 병합 결과 검증

| 대상 | 병합 작업 트리 결과 |
|---|---|
| Web API | Nest 빌드 통과, Jest 404개 스위트·4,169개 테스트 통과(26개 건너뜀) |
| 관리자 웹 | 로컬 빌드 통과, ChromeHeadless 전체 2,382개 테스트 통과 |
| 회원 웹 | 로컬 빌드 통과, 전체 504개 테스트 통과 |
| 데스크톱 NestJS | 빌드 및 변경 경로의 `access-credit-proxy` 9개 테스트 통과. 전체 4,155개 중 4,106개 통과, 15개 실패, 27개 취소, 7개 건너뜀. 실패는 폰트·프로세스·타이머 등 변경 범위 밖 테스트에서 발생했으며 전체 테스트 통과를 주장하지 않는다. |
| 데스크톱 Angular | 배포 빌드, 타입 검사, ChromeHeadless 전체 8,195개 테스트, 스타일 검사 14개 통과. 병합 결과의 계정 요약 테스트 30개도 통과. |

세 병합 작업 트리의 `git diff --cached --check`도 통과했다. 관리자 웹의 일반 Chrome 전체 실행에서는 포커스 스타일 테스트 6개가 일시 실패했지만, 같은 포커스 테스트를 ChromeHeadless로 다시 실행한 52건과 전체 ChromeHeadless 2,382건은 통과했다. 이 결과를 실제 브라우저 수동 검증의 대체로 해석하지 않는다.

## 남은 검증 경계

- 원격 `dev`에 코드가 반영된 사실과 운영 환경 배포·DB 마이그레이션 적용은 별개다. 이 병합 과정에서 운영 배포를 수행하지 않았다.
- 실제 Toss 결제망의 카드 등록, 첫 예약 청구, 정기 자동 청구, 환불은 이번 로컬 병합 검증에서 실행하지 않았다. 기존 결제 경로에 대한 테스트와 빌드만 통과했다.
- 사용자별 실데이터의 프로모션 등록/성과·XLSX 운영 검증이나 AI 부스 실제 코드·일정·상한 입력은 운영 시 별도로 확인한다. 제품은 해당 값을 캠페인 생성 시 입력하도록 구현되어 있다.
