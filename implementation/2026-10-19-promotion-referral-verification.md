## 배포 전 확인할 외부 경계

- 실제 Toss 승인·자동 청구·환불을 수행하는 실결제 연동 검증은 로컬에서 실행하지 않았다. 기존 결제 경로를 재사용하도록 구현했으며, 배포 환경에서 첫 예약 결제일·실패 재시도·취소 경합을 확인해야 한다.
- 관리자/회원 API와 세 화면 앱을 함께 배포하고, API의 관리자 DB 마이그레이션을 먼저 적용해야 한다.
- XLSX는 등록별 성과 합계를 제공한다. 주문·크레딧 장부의 원본 ID/시각은 DB에 보존되며 파일 자체에는 원본 이벤트 한 건씩의 상세 행을 넣지 않았다.

## 2026-10-20 점검 후 수정

- 프로모션 만료와 첫 유료 결제가 같은 경계에서 실행될 때 미처리 월별 크레딧을 동일 거래·회원 잠금 안에서 먼저 처리한다. 현재 기간 표시에서는 자체 유효기간이 끝난 크레딧을 제외한다.
- 추가 크레딧 주문은 이용권 저장소의 현재 유효 이용권 조회와 회원 잠금을 재사용한다.
- 관리자 성과·등록 목록을 페이지로 제한하고, 전체 XLSX는 200건씩 읽어 행을 즉시 기록한다. 회원 화면은 첫 결제 실패를 예약 성공으로 표시하지 않고 재시도 동작을 제공한다.
- 혜택 회수 통지는 로그인 후 회원 대시보드에서 확인할 때까지 보인다. 유료 첫 결제 예약이 남아 있으면 날짜를 함께 표시한다. 운영자 변경·회수는 감사 장부에 기록한다.
- 임시 PostgreSQL에 전체 admin 마이그레이션을 적용했다. 등록 1,201건 성과 조회에서 2페이지 50건, 전체 합계 1,201건, XLSX 1,202행(머리글 포함)을 확인했다. 실제 파일을 ExcelJS로 다시 열어 수식처럼 보이는 홍보자 이름이 문자열 셀임을 확인했다. 등록 데이터가 있을 때 역마이그레이션은 `PROMOTION_ROLLBACK_HAS_DATA`로 변경 전 거부됐다.
- 같은 PostgreSQL에서 미처리 월별 지급 두 건이 있는 프로모션 이용권을 정산했다. 이용권이 종료돼도 각 크레딧의 자체 유효기간에 따라 만료된 건과 사용 가능한 건이 구분됐다. 비어 있는 별도 DB에서는 프로모션 마이그레이션의 실행과 역실행이 모두 성공했다.
- 수정 후 Web API 전체 Jest: 389개 스위트, 3,920개 테스트 통과, 26개 건너뜀. Web API 빌드 통과. 회원 웹 로컬 빌드 및 ChromeHeadless 52개, 관리자 웹 로컬 빌드 및 관련 ChromeHeadless 12개 통과. 세 코드 저장소에서 `git diff --check` 통과.
- 실제 Toss 실결제 승인·자동 청구·환불은 테스트 키와 외부 결제 환경이 없어 실행하지 않았다. 기존 결제 흐름의 단위·회귀 테스트와 PostgreSQL 데이터 검증을 완료했으며, 배포 전 실결제 경계 확인이 남아 있다.

## 2026-10-20 독립 검토 7건 후속 수정

- 일반 구독의 첫 결제일이 `null`인 상태도 자동 복구 조회·실행 대상으로 포함했다. 결과 불명 주문의 기존 주문 번호와 멱등 키를 이용한 재조정 경로를 유지한다.
- 성과·XLSX의 등록 배치를 `OFFSET` 대신 등록 시각·ID 커서로 읽는다. 배치 사이에 새 등록이 앞에 추가돼도 이미 읽은 등록을 다시 합산하지 않는다.
- 회원 웹에서 프로모션 종료일 확인 전 결제 동의 체크를 막고, 확인 응답 후에는 기존 동의를 해제한다.
- 새 코드 등록 전 같은 회원의 날짜상 만료됐지만 DB 상태가 열린 이용권을 회원 잠금·동일 거래 안에서 월별 지급 정산 후 종료한다. 환불 진행으로 정산할 수 없거나 다른 열린 이용권이 남으면 중복 지급 대신 명시적으로 거부한다.
- 관리자 조회 화면은 캠페인 목록을 카탈로그 호출과 분리했다. `members.read`만 있는 developer 역할도 캠페인과 성과를 볼 수 있다.
- 캠페인을 바꾸면 이전 코드 입력 초안을 지우고, 이전 캠페인의 늦은 발급 응답을 현재 코드 목록에 넣지 않는다.
- 캠페인 상태 변경은 거래 안에서 행을 `FOR UPDATE`로 잠그고 이전 상태를 읽어, 동시 변경에서 실제 재활성화 감사 기록이 누락되지 않게 했다.
- 각 결함에 실패하는 회귀 테스트를 먼저 추가해 수정 전 실패와 수정 후 통과를 확인했다. 전체 API Jest 389개 스위트/3,926개 테스트 통과(26개 건너뜀), API 빌드 통과. 관리자 웹 전체 ChromeHeadless 2,322개, 회원 웹 전체 484개 통과. 세 웹 앱 로컬 빌드 통과.
- 임시 PostgreSQL 15에 전체 관리자 마이그레이션을 적용했다. 실제 DB에서 201건 성과를 읽는 중 앞쪽에 새 등록을 넣어도 합계·XLSX 등록 ID가 201개로 고유함을 확인했다. `first_charge_at IS NULL`인 결과 불명 첫 결제의 자동 복구 조회, 만료된 열린 이용권의 유일 제약 해소, 동시 캠페인 잠금 후 두 번째 거래의 최신 상태 관찰을 확인했다.
- 전체 웹 테스트에서 발견된 새 프로모션 메뉴의 오래된 정적 기대값(관리자 5건·회원 2건)을 실제 경로·메뉴 계약에 맞게 갱신하고 전체 테스트를 다시 통과시켰다. 실제 Toss 결제망 검증은 수행하지 않았다.
