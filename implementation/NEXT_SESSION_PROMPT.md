각 링크의 코드 블록을 해당 새 세션에 붙여넣는다. 이 문서 작성으로 새 세션을 자동 생성하지 않았다.

## 두 세션의 접점

- A는 TEST 결제 결과와 복구 동작, B는 운영 인프라와 배포 산출물을 담당한다.
- API/Customer/Admin/Infra 등 같은 repo를 함께 수정할 수 있다. 먼저 현재 diff를 확인하고, 동일 파일 수정/배포 충돌은 조율한다. 다른 세션 수정까지 커밋·푸시하지 않는다.
- 공용 운영 서비스 재시작, worker/호스트 재부팅, DB 복원, 키·웹훅 변경은 테스트에 영향을 줄 수 있으므로 대상과 실행 시점을 조율한다.
- 전용 진행기록을 각각 작성하고 TASKS는 자기 담당 항목만 부분 갱신한다. 기존 인수인계·WORKLOG 전체를 덮어쓰지 않는다.
- B의 라이브 준비는 즉시 라이브 전환 승인이 아니다. 실제 전환은 A 검증 결과와 함께 별도 결정한다.
- 서버 명령은 사용자가 직접 한 단계씩 실행. 개발 전환, 운영DB 재초기화, 무승인 실결제/식별자 변경은 하지 않는다.

문서는 로컬 .codex에 저장돼 있다. 다른 PC/새 worktree에서는 미커밋 문서가 전달됐는지 먼저 확인한다.
