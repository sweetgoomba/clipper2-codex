## 프로필 목록 — 확정된 변경

- 프로필 이름/분야 왼쪽 아이콘을 제거한다.
- 이름 아래 분야, 가운데 성별·연령·목적·스타일·좁힌 키워드를 각각 레이블 위/값 아래로 표시한다. 넓을 때 가로 한 줄, 폭이 줄면 정보 영역은 두 줄로 배치한다. 아주 작은 폭에서는 추가 줄바꿈으로 정보를 보존한다.
- 미생성 카드는 전체 클릭으로 이동하지 않고 ‘스토리보드 생성하기’ 버튼으로만 시작한다.
- 생성 완료 후 같은 프로필의 생성 버튼은 다시 표시하지 않는다. ‘스토리보드 N개 생성 완료’를 표시하고 카드 전체가 결과 진입점이 된다.
- 맨 오른쪽 세로 점 3개 메뉴: 완료는 ‘프로필 복제’만, 미생성은 ‘프로필 복제’와 ‘프로필 수정’. 프로필 삭제 버튼/기능은 이번 UI 범위에서 제외한다.
- 완료 프로필은 수정하지 못한다. 복제본은 설정만 복사한 미생성 프로필로, 생성 결과를 이어받지 않는다. 목업의 복제는 이름 뒤 ‘(복사)’를 붙여 목록에 추가한다.
- 진행 중인 생성에는 중복 생성/편집을 막는 모의 잠금을 적용했다. 모든 결과가 실패한 프로필의 최종 상태/이후 행동 등은 실행 설계에서 구체화해야 한다.

## 생성 폼과 추천

- 제작 목적의 추천 선택지 아래에 직접 입력란을 항상 표시한다. 단일 목적 규칙은 유지하며, 직접 입력하면 추천 선택이 해제된다.
- 입력 모달의 ‘추천 보기’를 제거한다. 프로필 추천은 프로필이 없는 최초 화면의 ‘프로필 추천’ 진입점에서만 제공한다. 생성 후 목록에는 ‘프로필 생성’만 제공한다.
- 입력/선택 버튼을 첨부 시안처럼 작은 사각형과 얇은 경계선으로 정리했다. 필수/선택 구분과 생성 가이드, 레이블 옆 짧은 태그 안내를 반영한다.
- 최신 사용자 결정: **목적·스타일의 AI 추천은 이번 버전에서 제외하고 후속 고도화로 보류**한다. 이번에는 미리 준비한 선택지를 제공한다. 목적은 단일 선택 또는 직접 입력, 스타일은 복수 선택을 유지한다. 실제 선택지 문구는 별도 검수 대상이며 목업의 예시를 그대로 최종 목록으로 확정하지 않는다.
- 현재 Angular `shortform-director-profile-presets.ts`는 고정 10개 프로필 프리셋이다. 프로필 추천 진입점과 목적/스타일 AI 추천은 별개이며, 후자의 API/프롬프트/호출 연결은 이번 구현 범위에서 제외한다.
- v2 목업에서 ‘AI 추천 예시’ 및 AI가 추천한다는 안내를 제거했다. 목적·스타일의 준비된 선택지를 바로 보여주며, 실제 AI 호출은 없다.
- 추천 갱신이 사용자의 직접 입력/선택을 조용히 덮어쓰지 않도록 보존한다. 1뎁스는 폭넓게 갖춘 검수된 고정 목록에서 선택하는 방식으로 확정했다. 이전 임시 6개 분야를 승인된 21개 1뎁스와 128개 2뎁스 목록으로 교체해 목업에 적용했다. 2뎁스도 각 1뎁스에 대응하는 검수된 고정 목록으로 확정했다. 맨 앞의 ‘전체’와 복수 선택을 유지하고, ‘전체’ 선택 시 다른 항목을 해제한다. 2뎁스 세부 항목도 승인됐으며, AI 목적/스타일 추천의 로딩·실패·호출 시점은 추후 고도화를 재개할 때 설계한다.
- 기존 필수값 검증, 작성 취소 확인, Enter 태그 추가 및 공백 보존은 유지한다.
- 프로필 모달 높이는 화면 높이에 맞춰 제한하고 모달 내부에 세로 스크롤을 둔다. 시안은 `max-height: min(800px, calc(100dvh - 96px))`와 `overflow-y: auto`를 사용한다. 선택·태그 추가 등의 재렌더에서 스크롤 위치를 보존한다. 제품 구현에서도 모달이 화면 밖으로 길어지지 않도록 적용한다.

분야의 실제 항목은 [1·2뎁스 목록 초안](2026-09-21-storyboard-category-catalog-draft.md)에서 검토한다. 21개 1뎁스와 128개 2뎁스 항목 모두 승인됐고 목업에 적용했다. 제품 코드는 아직 변경하지 않았다.

목적·스타일의 실제 항목은 [분야별 목적·말투 스타일 24개 제안](2026-09-21-storyboard-purpose-style-catalog-draft.md)으로 검토한다. 사용자 요청에 따라 분야별 목적·말투 스타일 24개를 v2 목업에 적용했다. 목적은 승인된 21개 1뎁스별 목록(각 5개), 스타일은 8개씩 펼치는 공통 목록으로 제공하며 제품 구현은 아직 진행하지 않았다.

## 최초 안내와 결과 화면

- 안무/대사 하이라이트 등은 `src/core/navigation/page-guide-content.ts`의 소개/단계 문구를 공통 `src/shared/ui/guide-sheet/`로 표시한다. 이들은 우측 사용법 패널이며 최초 빈 화면과 완전히 같은 컴포넌트는 아니다.

- 기존 Storyboard 사용법 문구는 다섯 화면을 순서대로 지난다는 이전 흐름이다. 제품 구현 시 새 자동 흐름에 맞춰 함께 갱신해야 한다.
- 결과 화면 최상단의 프로필 이름·아이콘을 제거하고 왼쪽에 `뒤로 가기 >`를 표시한다. 아래에는 프로필 목록과 동일한 카드(이름/분야, 성별/연령/목적/스타일/좁힌 키워드, 완료 상태, 복제 메뉴)를 재사용한다. 결과 화면의 카드에는 자기 자신으로 이동하는 클릭 영역을 두지 않는다. 최종 실패/환급 정보는 카드 아래에 유지한다.
- 주제 제목 아래 정보는 **추천 이유 / 시청자의 궁금증 / 기획 포인트** 3개로 합의했다. 최신 사용자 정정에 따라 신규 생성 결과에서 세 정보를 모두 제공하도록 생성/API 연결을 변경한다. 정보가 없다는 이유로 항목을 숨기는 방침은 폐기한다. 각 설명은 핵심 한 문장 또는 짧은 구로 전달하며 장황한 배경 설명·반복·군더더기를 넣지 않는다. 임시 ‘지금 주목받는 이유 / 어떻게 꾸려낼지’를 대체한다.
- 결과 목록: 주제 정보 옆에 시나리오 카드를 **가로 한 줄**로 나열하고 가로 이동한다. 카드의 ‘숏츠 타입·타이틀·훅’ 레이블/값을 유지한다. ‘시나리오 보기 →’ 문구/버튼 없이 카드 전체 클릭으로 이동한다.
- 시나리오 상세 최상단도 제목·아이콘을 제거하고 왼쪽에 `뒤로 가기 >` 버튼을 표시한다. 클릭하면 해당 프로필의 주제·시나리오 목록으로 돌아간다.
- 상세: **왼쪽 스토리보드 개요 / 중앙 장면 / 오른쪽 선택 장면 세부정보의 3열을 항상 유지**한다. 작은 화면에서도 세로로 쌓지 않고 필요한 경우 가로 스크롤을 사용한다. 이전 초안의 축소 시 2열/1열 전환과 제작 상세 접기 제안을 대체한다.

## 주제 정보 생성·API 확장 — 최신 사용자 정정 (9/21)

사용자는 ‘기존 정보가 부족하면 생략’ 방침을 거부했다. 추천 이유·시청자의 궁금증·기획 포인트가 실제 응답에 포함되도록 필요한 생성/API 변경을 허용했다. 이전의 API/생성 로직 보존 원칙에 대한 이 세 정보의 필요한 확장은 승인 범위이며, 그 밖의 불필요한 변경은 하지 않는다. 신규 생성 성공 결과에는 세 정보를 모두 제공한다.

문구 기준:
- 추천 이유: 왜 이 프로필/시청자에게 이 주제가 적합한지 핵심만.
- 시청자의 궁금증: 주제가 답할 중심 질문 하나. 확인되지 않은 시청자 반응을 조사 사실처럼 표현하지 않는다.
- 기획 포인트: 다룰 관점이나 비교/전달 방법 한 가지.
- 각 항목은 짧은 한 문장 또는 구. 화면에서 잘라 의미를 잃게 하지 말고 생성 단계부터 간결하게 작성한다. 시안 9개 설명은 각각 45자 이하이며 이는 검토용 예시의 확인값이지 API 길이 제한 확정값은 아니다.

현재 코드 확인:
- Angular `models/shortform-director-research.ts`의 주제 모델: `whyNow`, `angle`, `audienceSignalIds`.
- Nest `application/shortform-director-research-topic.builder.ts`: audienceSignal은 `summary/evidenceIds`, 주제 추출 시 title/whyNow/angle 검증. `shortform-director-inference-response.projector.ts`도 주제 응답 필드를 검증한다.
- Web `shortform-director-inference/domain/shortform-director-inference.contract.ts`: topic-synthesis 응답 스키마/검증. `application/shortform-director-inference.prompt.ts`: whyNow는 최근 사건·변화·신호 설명으로 명시되어 있다.

구현 방향(아직 제품 코드 미변경):
1. 기존 주제 생성 호출에서 프로필과 조사 근거를 사용해 세 정보를 함께 생성한다. 검토용 새 필드명은 `recommendationReason`, `audienceQuestion`, `planningPoint`이며, 기존 whyNow/angle을 의미가 다른 필드로 무작정 재명명하지 않는다.
2. Web 생성 프롬프트/응답 스키마·검증 → Nest 응답 projector/주제 builder/저장·조회 → Angular 모델·표시까지 연결한다. 계약 버전 및 기존 저장 결과 호환 처리는 상세 구현 계획에서 정한다.
3. 세 정보 누락·빈 값·형식 오류는 신규 생성 성공으로 통과시키지 않는다. 성공한 앞 단계 결과를 보존한 채 필요한 주제 생성 결과를 보완/제한 재시도한다. UI에서 항목을 지우거나 임의 고정 문구로 채우지 않는다. 재시도는 사용자에게 노출하지 않는다.
4. 최종 생성 실패/환급은 기존 합의한 묶음 작업 정책과 통합한다. 이미 저장된 구형 결과의 보완·호환 처리는 누락 필드 숨김으로 종결하지 않고 별도 설계한다.

시안은 세 정보의 짧은 예시 문구로 수정했다. 세 주제 모두 3항목 표시, 빈 값/undefined 없음, 예시 길이, 런타임 오류 없음을 로컬 Chrome으로 확인했다. 실제 생성 호출이나 제품 구현/테스트는 아직 수행하지 않았다.

## 최종 상세 재설계 진행 중

최신 사용자 정정으로 단일 화면 동작보다 TTS 대본의 흐름을 중심으로 상세를 구성한다. 3열/뒤로 가기와 이중 계층 제거는 유지한다. [코드 확인 및 재설계 기록](2026-09-21-storyboard-final-detail-reassessment.md) 참고.

중앙 목록은 화면 동작 이름이 아니라 TTS 대본 전문을 표시한다. 이야기의 의미/호흡에 따라 나눈 대본 구간을 중심으로 화면·소재가 대응하며 화면 변화마다 대본을 기계적으로 분할하지 않는다. 영역명 ‘대본 흐름’과 번호 표기는 검토용 제안이다. 오른쪽에는 대본·화면 문구·보여줄 화면과 AI 영상 생성 프롬프트, AI 이미지 생성 프롬프트, 이미지·영상 검색어를 모두 표시한다. 소재 방식/종류 토글 및 선정·활용 안내는 제거한다. 검색어는 짧고 구체적인 대상/행동/필요한 장소 조합을 독립된 검색 후보로 제공하고 각 항목을 복사한다. 한국어/영어 각 2개 예시는 검토용이며 개수는 최종 계약 요구가 아니다. 문장형 검색이 항상 열등하다는 뜻은 아니며 긴 연출 지시문을 검색어로 재사용하지 않는다. 실존 인물·사건 등은 정확한 이름/작품/사건을 유지해야 하고, ‘영상/사진’ 접미사를 일괄 추가하지 않는다. 실제 검색 결과 적합성은 아직 검증하지 않았다.

실제 생성 계약 연결 및 기존 저장 데이터 호환 설계는 남아 있다. 제품 코드 미변경.


## 화면 문구 유지 및 검색어 우선 표시

사용자는 ‘화면 문구’의 강조 텍스트 역할을 이해한 후 유지를 선택했다. 삭제 제안은 채택하지 않는다. 소재 표시 순서는 이미지·영상 검색어 → AI 영상 생성 프롬프트 → AI 이미지 생성 프롬프트다. ‘보여줄 화면’은 직접 촬영을 기본 전제로 삼지 않고, 찾거나 생성한 소재로 무엇을 보여주고 대본의 어떤 의미를 전달하는지 설명한다. 인물/장소 연속 촬영이나 카메라 위치·촬영 동작을 사용자에게 요구하지 않는다. 자료 선정/활용 안내 항목을 별도로 부활시키지 않는다. 이는 유튜버 전반의 촬영 여부에 대한 통계적 주장이 아니라 이 플러그인의 사용자 흐름 설계 기준이다.


## 전체 스토리보드 PDF 내보내기

스토리보드 개요 하단의 전체 대본 복사 옆에 PDF 다운로드를 추가한다. 내보내기 범위는 현재 선택한 스토리보드 한 개와 그 상위 프로필·주제 맥락이다. 같은 프로필의 모든 주제/스토리보드 일괄 내보내기로 확장하지 않는다. 문서에는 (1) 프로필 이름, 1·2뎁스 분야, 성별/연령, 목적, 스타일, 관련/금지 키워드 (2) 주제명, 추천 이유, 시청자의 궁금증, 기획 포인트 (3) 시나리오 번호, 제목, 타입, 훅, 예상 길이 (4) 전체 TTS 대본 (5) 모든 구간의 번호/예상 시간, 대본, 화면 문구, 보여줄 화면, 검색어, AI 영상·이미지 프롬프트를 포함한다. 현재 선택 중인 구간만 내보내지 않는다.

제품 구현 시 생성 당시 프로필/주제와 결과의 연결을 보존하고 저장된 결과로 문서를 구성해야 한다. 내보내기를 위해 AI를 재호출하거나 추가 생성 과금을 하지 않는다. 한글 폰트, 긴 문장/프롬프트 줄바꿈, 페이지 나눔과 잘림 여부 및 모든 구간 포함 여부를 실제 PDF 렌더 결과로 검증해야 한다. 원시 API 정보/모델 비용은 문서의 사용자 정보에 포함하지 않는다.

현재는 UI 설계 단계이므로 버튼을 눌러 문서 구성 미리보기를 여는 시안만 구현했다. 실제 PDF 파일 생성·다운로드/인쇄 페이지 레이아웃은 미구현이며 제품 구현에 포함할 요구사항이다. 미리보기에 이 상태를 명시한다.


## PDF 문서 영역·페이지 레이아웃 개선

사용자는 다운로드 PDF가 줄글 나열이 아니라 영역을 구분한 정식 문서여야 한다고 피드백했다. 시안의 PDF 미리보기를 페이지별 문서로 재구성했다. 현재 예시는 A4 세로 7쪽: 1쪽 프로필/주제/개요 요약 표, 2쪽 구간·예상 시간·TTS 전체 대본 표, 3~7쪽 구간별 제작 시트다. 각 제작 시트는 대본 강조 영역, 화면 구성 표, 검색어 표, AI 영상/이미지 프롬프트 박스로 나누며 머리말·꼬리말·페이지 번호를 일관되게 표시한다. 전체 정보는 유지한다. 예시 내용에 맞춘 검토용 레이아웃이며 7쪽을 제품의 고정 페이지 수로 정하지 않는다. 실제 긴 콘텐츠는 글자 축소/잘림 대신 다음 페이지로 이어지고 머리말을 반복하도록 구현해야 한다.

실제 검토용 PDF `output/pdf/storyboard-document-design-sample.pdf`를 로컬 Chrome으로 생성했다(기존 예시 데이터, AI 실행 없음). 7개 A4 페이지, 콘텐츠/푸터 비겹침, 한글 텍스트 및 필수 항목 추출, 다섯 제작 시트의 두 프롬프트 포함을 확인했다. Poppler로 모든 페이지를 렌더링해 전체 컨택트 시트와 상세 페이지를 검토했다. 최초 텍스트 검사에서 표 레이블 줄바꿈으로 일치 검사가 실패해 공백 정규화 후 검증했다. 내용 누락은 아니었다. 미리보기의 선택 결과 연결/전체 구간 포함/닫기/390px 줄바꿈도 검증했다.

이 PDF는 다운로드해 볼 수 있는 디자인 예시이며 제품의 PDF 내보내기 기능이 완성된 것은 아니다. 제품 코드 미변경, 관련 문서 미커밋. 커밋·푸시 없음.


## PDF 문서 구성 승인

사용자가 실제 PDF 예시를 확인하고 “좋아”로 승인했다. 승인 범위는 프로필·주제·스토리보드 요약 표, 전체 대본 표, 구간별 제작 시트의 영역 구분과 페이지 구성이다. 예시의 7쪽을 고정하지 않고 실제 내용 길이에 맞춰 페이지를 나눈다. 전체 제품 구현 완료나 커밋·푸시 승인을 의미하지 않는다. 제품의 실제 내보내기 연결은 미구현이다.
