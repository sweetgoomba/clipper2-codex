## 원장 문구가 아직 예전대로 보일 수 있는 이유

W07 Web API의 `src/modules/credits/domain/credit-ledger-display.ts`에는 새 이름이 있다. 이번 재확인에서 관련 **2 suites / 19 tests 통과**했다. 원장 저장 reason/delta/정산 방식은 바꾸지 않고 조회할 때 표시명만 만든다.

현재 localhost:3000 프로세스(PID 11863)는 `/Users/jina/project/adlight/web/clipper_web_api` 원본 checkout에서 실행 중이다. 해당 원본의 source와 dist 표시 map에는 `shortform_director.generate`가 없음을 재확인했다. 따라서 W07 테스트 앱만 열어도 이 서버의 원장 문구는 바뀌지 않는다. 이는 요구 누락이 아니라 **실행 서버 미반영** 상태다. 이번 상태 조사에서 공유 서버를 재시작하거나 다른 작업의 checkout을 수정하지 않았다. 서버 반영은 미완료로 표시한다.

## 진행 메시지와 미터의 구현 범위

Nest discovery가 세분된 메시지를 보내고 executor가 job progress를 갱신한다. Angular 카드가 실제 job의 message/progress를 받아 표시한다. 초기 조사는 5~10%, 본문 생성은 완료 개수에 따라 10~90% 범위에서 단조 증가하도록 구현되어 있다. 오래 걸리는 단계 동안 같은 비율에 머물 수 있으며, 남은 시간 예측 기능은 아니다.

이번 재확인에서 discovery/pipeline/executor/retry 관련 **27/27 통과**했다. 최신 테스트 앱은 이 UI와 Nest 코드를 포함한다. 화면 캡처와 최초 회귀 근거는 [원래 검증](2026-09-29-storyboard-followups-verification.md)에 있다.

## 이번에 추가로 확인한 실제 실행 시간

앱에 이미 남은 `/Users/jina/Library/Application Support/Clipper Studio Dev/logs/nest.jsonl`에서 내용 없는 timing 필드만 집계했다. 새로운 유료 생성 요청은 보내지 않았다. 상세는 [성능 기록의 최신 실측](../diagnostics/2026-09-29-storyboard-performance.md)에 있다.

- 2026-09-29 21:08:19~21:12:13 KST 성공 job: **233926ms, 약 3분 54초**. queue 실행 이후 시간이며 사용자 클릭부터의 전체 지연은 아니다.
- 같은 실행 시간대의 batch: stage attempt 누적 229315ms. 소재 결정 4회 **98520ms (43.0%)**, 본문 구성 4회 **43930ms (19.2%)**, 조사자료 정규화 두 단계 **39996ms (17.4%)**, 시나리오 후보 2회 **23385ms (10.2%)**.
- 검색 API 12회는 **1961ms**. 이 표본에서는 검색·저장보다 생성 단계가 더 오래 걸렸다.
- query-plan 두 실패 후 세 번째 성공, 재시도 대기 1508ms도 따로 관측했다. stage 시간은 서버 왕복과 응답 검증을 포함하며 모델 자체 시간만을 뜻하지 않는다.
- 단일 표본이고 조건이 다른 과거 job과 비교하지 않았다. **계측 완료는 생성 시간 단축 완료를 뜻하지 않는다.**

현재 우선 검토 후보는 서로 다른 스토리보드의 본문 구성→소재 결정 묶음을 제한적으로 병렬 실행하는 것이다. 같은 스토리보드 안의 두 단계는 receipt/hash 의존성이 있어 순차로 유지해야 한다. 요청 제한, 중복 provider 비용, 취소 시 in-flight 정리, 저장 결과 재개, 완료 산출물 개수에 따른 환급을 지키는 구현과 전후 검증은 아직 남아 있다.
