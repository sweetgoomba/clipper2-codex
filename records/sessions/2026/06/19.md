## Next Session First Task

다음 세션의 첫 작업은 최신 `dev`에서 새 브랜치를 만들고, 플러그인을 연달아 실행할 때
메모리가 부족해 앱과 다른 앱들까지 freeze되는 문제를 줄이는 것이다.

사용자 요구:

- 최신 `dev`를 기준으로 새 작업 브랜치를 만든다.
- 여러 plugin을 이어서 실행하면 메모리가 누적되어 앱이 종료되거나 Chrome 등 다른 앱도 freeze된다.
- 메모리가 부족해진다고 판단되면 현재 사용하지 않는 plugin/runtime process를 종료하는 기능이
  이미 있는지 먼저 조사한다.
- 기능이 없으면 구현한다.
- 기능이 있어도 누락/버그/정책 문제가 있으면 수정 및 개선한다.
- 메모리 부족 감지가 어렵다면, 특정 plugin들을 하나의 exclusive group으로 분류하고
  그 group 중 하나가 실행될 때 다른 plugin/runtime process를 종료하는 정책도 허용된다.

조사 우선순위:

1. `clipper_electron` main process가 NestJS/Python/plugin child process를 어떻게 생성/종료하는지 확인한다.
2. `clipper_nestjs` job/plugin lifecycle에서 worker/runtime stop API나 idle cleanup이 있는지 확인한다.
3. `clipper_python` plugin worker가 long-lived process인지 per-job process인지 확인한다.
4. Angular queue/project UI가 process lifecycle action을 갖고 있는지 확인한다.
5. OS memory pressure를 Electron에서 감지할 수 있는지, 또는 app-level exclusive plugin group 정책이 더 단순하고 안전한지 판단한다.

추천 접근:

- 먼저 existing lifecycle/cleanup 기능을 grep/테스트로 확인한다.
- 그 다음 최소 정책을 정한다.
  - option A: memory pressure 감지 시 idle runtime 종료
  - option B: plugin group exclusive 실행 정책
  - option C: 둘 다, 단 기본은 group-exclusive로 단순하게 시작
- 구현 전 각 레포별 책임을 분리한다.
  - Electron: child process owner / kill policy
  - NestJS: running job/plugin state와 shutdown endpoint/event
  - Python: graceful shutdown 가능 여부
  - Angular: 필요할 때만 user-facing 상태 표시
