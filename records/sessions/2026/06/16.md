### Angular Preview Engine

`clipper_angular` changes:

- Added pure timeline builder:
  - `src/features/shortform/components/preview/shortform-browser-preview-timeline.ts`
  - `src/features/shortform/components/preview/shortform-browser-preview-timeline.spec.ts`
- Added browser preview component:
  - `src/features/shortform/components/preview/shortform-browser-timeline-preview.component.ts`
  - `.html`
  - `.scss`
  - `.spec.ts`
- Production page preview now uses the browser preview component instead of the
  old static composition stage.
- The preview component:
  - builds ordered line/media timeline segments from generated clips;
  - supports play/stop and range seek;
  - syncs current caption with playhead;
  - plays TTS and BGM through browser `Audio`;
  - renders media, main title line 1, main title line 2, and caption from the
    selected template runtime spec;
  - emits media failures so the page can fallback to another URL.
- Preview area is split into a top video frame area and a fixed lower controls
  area.
- Stage aspect ratio is driven by runtime canvas and is now 1080/1920 for
  shortform.
- Text style mapping now includes font, font size, weight, line height, letter
  spacing, color, align, background, padding, border radius, border, outline,
  shadow, and max lines.
- Image/video URL selection now prefers `contentUrl` first and falls back to
  `thumbnailUrl` only after failure. This fixed low-quality preview media.

### Template Catalog Behavior

Angular shortform template catalog behavior changed to match the updated product
direction:

- `ShortformProjectService.listShortformTemplates()` now loads only
  `source=template_builder.custom`.
- It no longer calls `source=shortform.simplified` when Builder templates are
  empty.
- If Template Builder has no shortform templates, shortform production page
  shows no fake/default template.
- If a Builder draft exists, it appears in the production page template strip.
- A newly created draft without sample render/card thumbnail is kept in the
  catalog and rendered as a simple ratio fallback card.
- If one template exists, the production page auto-selects that template through
  catalog defaults.

이번 follow-up의 범위:

### 주요 수정 내용

`clipper_angular`:

- TTS duration을 preview 재생 전에 측정해 total duration이 재생 중 증가하지 않도록
  했다.
- preview playback 중 clip/project/TTS update가 발생하면 preview를 멈추고 0초로

- TTS 재생성 완료 후 preview state를 한 번에 갱신한다.
- caption은 실제 줄 단위 box로 그린다. 한 줄 caption은 한 줄 box만 표시하고, 두 줄
  caption은 template의 line position/gap을 사용한다.
- template background color, font style, font file, media `contentUrl`, BGM, voice
  sample playback 상호 배제를 preview에 반영했다.
- style section BGM에 `선택 안 함`을 추가하고, 선택 시 preview BGM URL을 만들지
  않는다.
- preview playback과 style section BGM/voice sample playback이 동시에 재생되지
  않도록 했다.
- 개별 subtitle 수정 시 per-line TTS regeneration spinner/status를 표시하고, 한글
  마지막 글자가 잠깐 중복되어 보이는 상태 경합을 제거했다.
- full TTS regeneration 후 현재 UI의 clip drag order를 보존하고 clip duration label을

`clipper_nestjs`:

- `/v1/template-builder/assets/file?uri=template-assets/...` endpoint가 font file도

### Font 500 Root Cause

오래 남았던 preview font 미적용의 직접 원인은 URL path 자체가 아니라 CORS였다.

확인한 현상:

- 같은 font URL을 Origin 없이 `curl`하면 200으로 font file이 내려왔다.
- 같은 font URL에 `Origin: file://`를 붙이면 500이 발생했다.
- packaged Electron renderer의 `FontFace.load()` request는 `Origin: file://`를 보낸다.

수정:

- `clipper_nestjs/src/config/local-api-cors-origin.ts`를 추가했다.
- `clipper_nestjs/src/main.ts`의 CORS origin 판정이 `file://`를 허용하도록 바꿨다.

새 bundle 검증 결과:

```text
HTTP/1.1 200 OK
Access-Control-Allow-Origin: file://
Content-Type: font/ttf
Content-Length: 8849936
```

현재 preview font URL 형태:

```text
http://127.0.0.1:{port}/v1/template-builder/assets/file?uri=template-assets%2Fcustom.template...%2F1_1%2Ffonts%2F...ttf
```

재시도 시에는 cache busting query만 붙는다.

```text
&previewFontRetry=1
```
