# 2026-06-18

## Shortform TTS Duration Truncation Follow-Up

사용자 QA:

- 새로 만든 shortform의 마지막 대사 `큰 환경 보호가 가능해요! 함께 실천해요.` 중
  TTS가 `큰 환경 보호가 가능해요!`까지만 재생됐다.

원인:

- 최신 job `shortform_render_1781743028087`의 payload에는 마지막 subtitle text와
  `tts_url`이 온전하게 들어 있었다.
- 실제 TTS 파일
  `tts.shortform_project_1781743003682.clip.7.line.clip.7.1.1781743024154.mp3`은
  ffprobe 기준 `2.760s`였지만, `shortform/projects.json`과 render payload에는
  `durationMs=1981` / `duration=1.981`로 저장돼 있었다.
- 저장된 `1981ms`는 `estimatedTtsDurationMs()` fallback 공식과 정확히 일치했다.
  즉 packaged/backend 환경에서 ffprobe duration 측정이 실패했고, 짧은 추정 duration이
  저장됐다.
- Python render worker는 subtitle duration을 믿고 TTS segment에
  `atrim=0:1.981`을 적용하므로 뒤 문장이 잘렸다.

구현:

- `clipper_nestjs`
  - `NaverClovaShortformTtsProvider`가 ffprobe를 사용할 수 없을 때도 TTS 응답 buffer에서
    WAV/MP3 duration을 직접 계산하도록 fallback parser를 추가했다.
  - 기존 프로젝트처럼 이미 짧은 duration이 저장된 경우도 다시 렌더하면 고쳐지도록,
    render job 준비 시 local TTS 파일의 실제 duration을 읽어 in-memory render project의
    narration line duration, clip duration, media slots를 보정한다.
  - 저장 project 구조는 바꾸지 않고 render manifest/payload 생성에 쓰는 project copy만
    보정한다.
