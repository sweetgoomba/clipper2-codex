## Shortform Template Snapshot / Edit Preview Parity

구현 커밋:

```text
clipper_nestjs:  0c78413 Preserve shortform template snapshots
clipper_angular: e850888 Use shortform template snapshots in preview
clipper_nestjs:  5c7112b Allow refreshing shortform template snapshots
clipper_angular: b1b7a34 Explain stale shortform template snapshots
```

구현:

- `clipper_nestjs`
  - `ShortformProject`에 `templateVersionSnapshot`을 추가했다.
  - project 생성 또는 `renderSettings.templateId` 변경 시 현재 Template Preset catalog 항목을
    snapshot으로 저장한다.
  - 같은 project를 나중에 편집/렌더할 때는 같은 template id의 catalog 최신본보다 저장된
    `templatePresetSnapshot`을 render recipe에 우선 적용한다.
  - 기존 render payload 구조는 유지하고, manifest `detail.editState`에 optional snapshot만
    추가했다.
- `clipper_angular`
  - shortform project model에 `templateVersionSnapshot`을 추가했다.
  - `ShortformWorkflowStore.selectedShortformTemplate()`가 project snapshot의
    `shortformTemplateRuntimeSpec`을 catalog 최신본보다 우선 반환하도록 바꿨다.
  - snapshot이 없는 신규/기존 project는 기존처럼 최신 catalog template을 사용한다.
  - Template selector 목록/thumbnail은 최신 catalog 상태를 유지한다.
  - snapshot preview와 최신 catalog runtimeSpec이 다르면 템플릿 섹션 아래에 안내를 표시한다.
  - 사용자가 `현재 템플릿 적용`을 누르면 backend에 `refreshTemplateSnapshot: true`를 보내
    같은 template id의 snapshot을 최신 catalog preset으로 갱신한다.

## Shortform Project Storage / Remaining Work Audit

사용자 질문:

- `shortform/projects.json`과 `projects/projects.json`의 차이.
- `shortform/projects.json`에서 `clips: []`인 프로젝트가 보이는 이유.
- `promotedProjectId`, `shortform_project_*`, `shortform_*`, `shortform_render_*`,
  `source.shortform_project_*`의 관계.
- Template Builder 템플릿을 수정한 뒤 예전 shortform project를 다시 편집으로 열 때,
  기존 output 영상과 편집 preview가 달라질 수 있는 문제.
- 현재까지 남은 큰 작업 목록 정리와 문서화.

확인한 저장소:

```text
~/Library/Application Support/Clipper2/shortform/projects.json
~/Library/Application Support/Clipper2/projects/projects.json
~/Library/Application Support/Clipper2/templates/template-builder.json
~/Library/Application Support/Clipper2/projects/files/local/shortform_<renderProjectId>/
```

파일 역할:

- `shortform/projects.json`
  - shortform 제작/편집 원본 project store.
  - `source`, `clips`, `renderSettings`, `previewTimeline`, `mainTitle1`,
    `mainTitle2`, `promotedProjectId` 등을 저장한다.
  - `POST /projects/shortform/projects` 직후에는 의도적으로 `clips: []`,
    `status: editing`이다.
  - `POST /projects/shortform/projects/:projectId/clips`가 성공하면 clips가 채워지고
    `status: ready`가 된다.
  - 실제 앱 데이터 기준 총 38개 중 `clips: []`는 3개였고, 모두 2026-06-16 초기에
    생성만 되고 clip generation이 완료되지 않은 `editing` project였다.
- `projects/projects.json`
  - `/projects` 작업 보관함/완료 project store.
  - `projectId`, `jobId`, `pluginName`, `status`, `sourceAssets`, `outputRoot`,
    `params`, `result.video_path`, `result.thumbnail_path`, `result.manifest`,
    `artifacts`, `completedAt` 등을 저장한다.
  - 완료 card, 재생, output file resolve에 쓰인다.
- `templates/template-builder.json`
  - Template Builder family 최신본 store.
  - 현재 shortform project는 이 최신 template을 `renderSettings.templateId`로만
    참조한다.
- `projects/files/local/shortform_<renderProjectId>/render-jobs/*.clipper1-render-payload.json`
  - 실제 render job payload/recipe snapshot.
  - `legacy_payload.template_builder_render_contract`에는 렌더 당시 Template Builder
    contract snapshot이 들어 있다.

ID 관계:

```text
shortform_project_1781755507534
= shortform 제작/편집 원본 project id

shortform_1781755534088
= 보관함/렌더 산출물 project id
= projects/files/local/shortform_1781755534088/ 폴더명

shortform_render_1781755534088
= queue/render job id

source.shortform_project_1781755507534
= completed manifest/sourceAssets에서 원본 shortform project를 가리키는 source asset id

promotedProjectId
= shortform 원본 project에서 연결된 보관함/렌더 project id
```

현재 구조 판단:

- 렌더 결과물 보존은 괜찮다.
  - 완료 render payload에는 `legacy_payload.template_builder_render_contract`가 있어
    생성 당시 Template Builder contract snapshot으로 render된 결과가 보존된다.
- 편집 재진입 관점은 부족하다.
