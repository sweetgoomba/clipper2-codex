## Plugin Runtime Memory Management Initial Implementation

2026-06-23 세션 후반에 plugin/runtime memory pressure 완화를 위한 1차 구현을 진행했다.
이 작업은 완료 판정 전 단계이며, 사용자는 아직 실제 앱에서 수동 테스트하지 않았다.

관련 문서:

- `.codex/design/PLUGIN_RUNTIME_MEMORY_MANAGEMENT_2026-06-23.md`
- `.codex/standards/GIT_COMMIT_MESSAGE_POLICY.md`

앱 repo 상태:

```text

  branch: feature/plugin-runtime-memory-management
  pushed:
    dded94b chore(template-builder): remove legacy template families and S3 storage
    a978ea7 feat(plugin-runtime): add Python runtime lifecycle policy

desktop/clipper_angular:
  branch: feature/plugin-runtime-memory-management
  pushed:
    652bc44 chore(template-builder): remove legacy template builder UI paths

desktop/clipper_python:
  branch: feature/plugin-runtime-memory-management
  pushed:
    84a1d44 chore(clipper1): remove legacy template assets

  branch: feature/plugin-runtime-memory-management
  no new memory-management commit in this session
```

NestJS 구현 요약:

- `PythonRuntimeLifecyclePolicy` 추가.
- env 기반 lifecycle option 추가:
  - `CLIPPER_PLUGIN_RUNTIME_EXCLUSIVE_GROUP`
  - `CLIPPER_PLUGIN_RUNTIME_IDLE_SHUTDOWN_MS`
  - `CLIPPER_PLUGIN_RUNTIME_HEALTH_TIMEOUT_MS`
- `PluginsModule`에서 `PYTHON_RUNTIME_LIFECYCLE_OPTIONS` token을 통해 ConfigService 기반 옵션 주입.
- `PythonPluginWorkflowExecutor`가 `start()`/`run()` 전에 idle exclusive peer cleanup을 수행하고,
  `run()` 이후 idle stop을 예약한다.
- `/health`의 `active_jobs` 또는 `activeJobs`가 0이고 manifest가
  `safeToEvictWhenIdle`인 plugin만 stop 후보로 본다.

검증:

```text
desktop/clipper_nestjs npm run build
desktop/clipper_nestjs node --test test/python-runtime-lifecycle-policy.test.js
desktop/clipper_nestjs node --test test/*.test.js
desktop/clipper_nestjs git diff --check
```

결과:

- build pass
- lifecycle policy test 3/3 pass
- 전체 Node test 148/148 pass
- diff check pass

아직 남은 것:

- local/devapp/packaged에서 실제 plugin process가 종료되는지 확인 필요.
- Python plugin `/health` payload가 active job 수를 실제로 제공하는지 확인 필요.
- Electron packaged mode의 `PluginHost.stop()`이 child process를 실제로 종료하는지 확인 필요.
- OS memory pressure 감지 또는 RSS 기반 eviction이 필요한지 판단 필요.
- Angular에는 runtime cleanup 상태 UI가 아직 없다.

이번 세션 중 legacy template cleanup 작업도 별도 브랜치에서 처리했고,
`cleanup/remove-legacy-templates` worktree는 제거했다. 해당 cleanup commit들은 위 feature 브랜치에도 반영되어 있다.

원칙 추가:

- `.codex/standards/GIT_COMMIT_MESSAGE_POLICY.md` 추가.
- 모든 앱 repo와 `.codex` repo 커밋 메시지는 Conventional Commit 형식을 따른다.
- type 없는 `Add ...`, `Remove ...`, `Update ...` 메시지는 금지한다.
