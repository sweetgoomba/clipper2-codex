- Clipper에서 개선할 점:
  - 프록시 설정은 가능하면 config-as-code로 관리한다.
  - 실제 secret, env, runtime state를 Git에 넣지 않는다.
  - DB 포트는 필요한 서버에서만 접근 가능하게 제한한다.
  - 서버에서 source build를 반복하기보다 CI image build와 server pull/up을 우선 설계한다.
  - 백업은 생성뿐 아니라 restore drill로 검증한다.
  - web client/admin/API/DB host port는 환경별로 예약하되, desktop plugin별 고정 port/env 방식과 혼동하지 않는다.

- 사용자 추가 설명으로 확정된 1차 출시 전제:
  - Windows 설치형 앱 빌드는 사무실의 정해진 Windows PC에서 수행한다.
  - Windows code signing 인증서가 해당 PC에 설치되어 있으므로, GitHub-hosted Windows runner가 아니라 이 Windows PC를 self-hosted CI runner로 삼는다.
  - macOS 설치형 앱 빌드는 별도 Mac mini self-hosted runner에서 수행하는 방향이다.
  - 설치파일 저장소는 기존처럼 S3를 유지한다.
  - 개발팀은 개인 로컬에서 기능 개발/버그 수정/로컬 테스트를 하고, 준비된 변경을 stage에 배포한 뒤 prod로 배포한다.
  - GitHub Actions 같은 CI/CD 시스템을 쓰더라도 실제 빌드는 사무실 Windows PC와 Mac mini runner에서 실행되게 한다.
  - dev/stage/prod 서버는 설치형 앱을 빌드하는 서버가 아니라 다운로드 페이지, API, release metadata/update feed, DB/proxy/monitor를 운영하는 서버다.
  - 코드 push/main merge만으로 설치파일 release가 되면 안 된다.
  - Windows release는 Windows PC runner에서 `npm run build:app:win:x64`, macOS release는 Mac mini runner에서 `npm run build:app:mac:arm64` 같은 명시적 release build trigger로 실행한다.
  - Windows/macOS release와 version/update metadata는 플랫폼별로 따로 관리한다.
