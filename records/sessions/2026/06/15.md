## Preview Engine Decision

The user clarified that the shortform preview cannot remain a static square or
ratio box. The target preview is a Vrew-like browser timeline preview:

- It must play generated clips as if they were a video.
- It must not pre-render a temporary FFmpeg preview file for normal editing.
- It must compose selected media assets, generated TTS audio, BGM audio,
  `main_title1`, `main_title2`, and active captions in the browser.
- It must react when caption text is edited and TTS regeneration updates
  `ttsAudioUrl` or `durationMs`.
- It must react when clips are added, deleted, reordered, or when selected media
  changes.
- It must consume the same template runtime contract that final render consumes.

The agreed sequence is:

1. Lock the shortform template runtime contract.
2. Simplify Template Builder so Builder-created templates produce that runtime
   contract and real 9:16 card thumbnails.
3. Replace the temporary simplified built-in template catalog with
   Builder-produced templates.
4. Build the browser timeline preview engine after Builder-created templates are
   flowing through the catalog.

## Template Builder Thumbnail Capture And Local Browser Guard

After user inspection, the active `/templates` page still had two product
issues:

- The new simplified Template Builder page allowed create/edit work to start in
  a plain localhost browser even though that environment does not have
  `window.clipperBridge.capture`, so saving a real card thumbnail could not
  work.
- New template creation and edit saving had to capture the actual left preview
  frame as the list thumbnail, not a procedural fallback image.

Committed Angular fix:

```text
clipper_angular: 41e884e fix: harden shortform template builder thumbnails
```

Implementation:

- Gallery and empty-state `새 템플릿` buttons now receive `canCreate` and are
  disabled when live preview capture is unavailable.
- `TemplateBuilderPageComponent.openCreateFamilyForm()` and
  `handleCreateFamily()` also guard against missing capture so direct method
  calls cannot create a template in a non-capture environment.
- The page shows a shared capture warning when localhost/browser dev-server
  lacks `window.clipperBridge.capture`.
- Edit start and edit save remain blocked without capture; save can no longer
  be the first time a user discovers the environment cannot capture a thumbnail.
- Card thumbnail refresh now uses the currently selected family preview element
  when available and does not fall back to procedural canvas generation for the
  active preview path.
- `previewCanvasElement()` prefers the left preview frame:
  `.template-workspace__preview-cell .phone-canvas`.
- New template creation inserts/selects the created family, closes the create
  modal, waits for paint, then captures/uploads the thumbnail and upserts the
  updated family.
- `createCardThumbnailFromPreview()` no longer waits for text preview artifact
  regeneration before capture. The card thumbnail captures the current DOM
  preview directly.
- `waitForBrowserPaint()` now has an 80ms timeout fallback. In packaged Electron
  app automation, the page can be `document.visibilityState === 'hidden'` and
  `requestAnimationFrame` may not fire; thumbnail capture still proceeds.
- Product-visible copy was aligned further: `메인 타이틀` became `타이틀`, and
  `캡션` became `자막` in the simplified Builder UI.
- Removed the inspector action `나머지 비율에 적용`.
