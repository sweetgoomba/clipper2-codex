## Template Simplification And Shortform Preview Direction

The user changed the Template Builder product direction before starting the
shortform template/layout work.

Recorded in:

- `design/TEMPLATE_SIMPLIFICATION_AND_SHORTFORM_PREVIEW_2026-06-12.md`

Decisions:

- Preserve the existing full Template Builder implementation on archive branches
  before simplifying the active branches.
- Replace the active Template Builder model directly after archival; do not keep
  a second product-visible full Template Builder route.
- New templates keep only `main_title1`, `main_title2`, and `caption`.
- `sub_title`, `bottom_title`, and `logo` are removed from new templates and
  from the shortform production page.
- Main title remains two lines.
- A template has exactly one ratio, either `1:1` or `4:3`.
- Existing official legacy templates are not shown in the new shortform template
  picker.
- The shortform production page should rename `레이아웃` to `템플릿`, remove ratio
  selection, remove title visibility checkboxes, and use a template picker.
- The selected template's ratio drives preview and final render.
- The new preview should be a timeline-style preview with TTS, BGM, selected
  media, main title lines, and active caption.
- Browser preview should be treated as fast interactive preview, not
  pixel-identical proof. Final parity should use a render-engine preview path.

## Clipper2 Modal Inventory

The user asked where Clipper2 currently uses modals and which pages/features
they belong to before deciding whether to migrate them to the shared
confirmation modal.

Findings were recorded in:

- `design/CLIPPER2_MODAL_USAGE_INVENTORY_2026-06-12.md`

Summary:

- The new shared confirmation modal is appropriate for simple destructive or
  blocking confirmations.
- Shortform regenerate-clips confirmation is the current shared-modal use case.
- Strong future candidates:
  - Template Builder dirty edit-session cancel prompt currently using native
    `window.confirm`.
  - Template Builder delete template confirmation overlay.
- Conditional future candidate:
  - Dashboard plugin runtime admission dialog, after the shared modal supports
    richer detail rows or custom body content.
- Not recommended for the current simple shared modal:
  - ffmpeg/model consent overlays.
  - shortform clip generation progress dialog.
  - Template Builder sample render overlay.
  - Projects clip video preview overlay.
  - Dance member image preview overlay.
  - Template Builder create/rename/clone/admin password form overlays.

Current decision: do not migrate additional existing modals now. Keep the
inventory linked from `README.md` and `handoff/NEXT.md` so later modal cleanup
can start from a known list.
