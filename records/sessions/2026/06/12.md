# 2026-06-12

## Clipper2 Modal Inventory

The user asked where Clipper2 currently uses modals and which pages/features
they belong to before deciding whether to migrate them to the shared
confirmation modal.

Findings were recorded in:

- `design/CLIPPER2_MODAL_USAGE_INVENTORY_2026-06-12.md`

Summary:

- The new shared confirmation modal is appropriate for simple destructive or
  blocking confirmations.
- Shortform regenerate-clips confirmation is the current shared-modal use case.
- Strong future candidates:
  - Template Builder dirty edit-session cancel prompt currently using native
    `window.confirm`.
  - Template Builder delete template confirmation overlay.
- Conditional future candidate:
  - Dashboard plugin runtime admission dialog, after the shared modal supports
    richer detail rows or custom body content.
- Not recommended for the current simple shared modal:
  - ffmpeg/model consent overlays.
  - shortform clip generation progress dialog.
  - Template Builder sample render overlay.
  - Projects clip video preview overlay.
  - Dance member image preview overlay.
  - Template Builder create/rename/clone/admin password form overlays.

Current decision: do not migrate additional existing modals now. Keep the
inventory linked from `README.md` and `handoff/NEXT.md` so later modal cleanup
can start from a known list.
