## Actual Runtime Checks

`clipper1_video_render`를 사용해 local/devapp/packaged runtime smoke를 진행했다. 이 plugin은
heavy runtime lifecycle group에 포함되어 있고 model preload 없이 실제 Python plugin process lifecycle을
검증할 수 있다.

확인 결과:

- local NestJS mode:
  - `/health.active_jobs`는 idle 상태에서 `0`.
  - dry-run job 완료 후 idle stop이 실행됨.
  - Python `/shutdown` 호출 후 process가 exit code 0으로 종료됨.
  - PID probe는 `ESRCH`.
- devapp mode:
  - `/health.active_jobs`는 idle 상태에서 `0`.
  - dry-run job 완료 후 idle stop이 실행됨.
  - Python `/shutdown` 호출 후 process가 exit code 0으로 종료됨.
  - PID probe는 `ESRCH`.
- rebuilt packaged Electron app:
  - idle stop 경로에서 child process가 exit code 0으로 종료됨.
  - explicit `POST /plugins/clipper1_video_render/stop` 경로에서도 child process가 exit code 0으로 종료됨.
  - Electron bridge -> bundled NestJS -> Python plugin `/shutdown` 경로를 로그로 확인함.
- 사용자 요청으로 `dance_highlight`, `dialog_highlight`, `tts_supertonic` actual sequential smoke도 이어서 실행했다.
  - local: `dance_highlight -> dialog_highlight -> clipper1_video_render -> tts_supertonic -> dance_highlight`
  - devapp: `dance_highlight -> dialog_highlight -> clipper1_video_render -> tts_supertonic -> dance_highlight`
  - rebuilt packaged: `dance_highlight -> dialog_highlight -> clipper1_video_render -> tts_supertonic -> dance_highlight`
  - `dance_highlight`, `dialog_highlight` actual job 중 `/health.active_jobs > 0`을 관찰했고, 완료 후 `0`으로 돌아왔다.
  - 각 다음 plugin start가 이전 idle peer를 Python `/shutdown`으로 종료했고 `lastExitCode=0`을 확인했다.
  - packaged mode에서도 Electron bridge 경유로 같은 결과를 확인했다.

추가 발견:

- `tts_supertonic`은 manifest상 `safe_to_evict_when_idle=true`지만 default exclusive group 밖이었고,
  `TtsPluginClient`가 `PluginHost.ensureStarted()`를 직접 호출해 lifecycle policy를 우회했다.
- 실제 smoke에서 `tts_supertonic`이 `dance_highlight` 시작 뒤에도 남는 것을 확인했다.
- `ef1b23a`에서 default exclusive group에 `tts_supertonic`을 포함하고, TTS synthesis 경로가 lifecycle policy를 거치도록 수정했다.

## Implemented

`desktop/clipper_nestjs`:

- `LocalPluginProcess.stop()`이 SIGTERM 전에 Python plugin `/shutdown`을 먼저 호출하도록 변경.
- `/shutdown` 실패 또는 timeout 시 SIGTERM, 이후 SIGKILL로 fallback.
- SIGKILL 후에도 exit event가 오지 않으면 error를 던지도록 명확화.
- stop helper 단위 테스트 추가.
- default Python runtime exclusive group에 `tts_supertonic` 추가.
- `TtsPluginClient`가 synthesis 전 `prepareForRun()`, 완료 후 `scheduleIdleStop()` 호출.

Commit:

```text
fbf7b41 fix(plugin-runtime): gracefully stop local Python runtime
ef1b23a fix(plugin-runtime): include TTS runtime in lifecycle policy
```

`desktop/clipper_electron`:

- Electron main `PluginProcess.stop()`도 Python plugin `/shutdown`을 먼저 호출하도록 변경.
- packaged mode `PluginHost.stop()`이 bundled runtime child process를 exit code 0으로 종료하는지 확인.
- stop helper 단위 테스트 추가.

Commit:

```text
b18f424 fix(plugin-runtime): gracefully stop Electron-hosted Python runtime
```

Python production code는 변경하지 않았다. Python SDK에는 이미 `/shutdown`과 `/health.active_jobs`가 있었고,
이번 변경은 host가 그 lifecycle API를 실제 stop 경로에서 사용하도록 하는 것이다.
