- 결정:
  - 다음 서버 Codex 세션의 첫 접속지는 `m2-proxy`로 한다.
  - 첫 세션 목적은 배포가 아니라 read-only inventory/preflight다.
  - 첫 실제 Clipper 배포 대상 환경은 `dev`로 한다.
  - `stage`는 dev health와 DB/backup/proxy route가 확인된 뒤 진행한다.
  - `prod`는 stage 검증과 release/update feed 정책이 확정되기 전에는 건드리지 않는다.
- 이유:
  - Nginx Proxy Manager는 `m2-proxy`에서 실행 중이고 실제 route/cert 설정은 Git에 없다.
  - ipTIME 포트포워딩과 외부 80/443 진입점도 `m2-proxy` 기준으로 확인해야 한다.
  - dohit 문서상 현재 서버 역할은 `m2-proxy` = edge/prod, `m2-stage` = dev/stage app, `m2-db` = DB/backup이다.
  - Clipper의 첫 배포는 dohit과 공존해야 하므로 NPM route, 현재 host port, Docker network, LAN IP, firewall 상태를 먼저 확인해야 한다.
- 다음 서버 세션에서 `m2-proxy`에서 직접 확인할 것:
  - `hostname`, macOS computer/local host name, LAN IP.
  - `docker ps` 기준 `nginx-proxy-manager`, dohit prod app, monitor 상태.
  - Nginx Proxy Manager compose 위치와 `proxy-server/data`, `proxy-server/letsencrypt` 존재 여부.
  - Nginx Proxy Manager route 목록, 인증서 상태, upstream host/port 방식.
  - ipTIME에서 80/443 포트포워딩이 어느 LAN IP로 향하는지.
  - 81 관리 UI가 LAN/admin-only인지, 외부 공개가 아닌지.
  - `m2-proxy`, `m2-stage`, `m2-db`의 실제 LAN IP.
