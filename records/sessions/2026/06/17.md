## URL Backend Implementation

NestJS 이전 상태:

- URL mode project creation은 가능하다.
- 클립 생성 시에는 `current.source.url` 문자열을 그대로 LLM prompt로 넘긴다.
- Python legacy처럼 URL 본문 파싱, 원본 이미지 추출, 원본 이미지 우선 미디어 배정은
  아직 없다.

Python legacy 기준:

- `input_type == 1`이면 URL을 파싱한다.
- Naver Blog / Tistory / Brunch는 Selenium + BeautifulSoup로 제목, 본문 HTML,
  이미지 URL을 추출한다.
- 그 외 URL은 news scraper로 제목/본문을 가져온다.
- GPT에는 URL이 아니라 `parsed_content`를 넘긴다.
- 추출 이미지는 S3 업로드 후 클립 순서대로 먼저 배정하고, 부족할 때만 이미지 검색
  API를 사용한다.

NestJS 구현:

- `ShortformUrlContentExtractor` provider를 추가한다.
- URL 타입 판별과 본문/이미지 추출을 service로 분리했다.
- 지원 대상은 Naver Blog, Tistory, Brunch, generic/news HTML fallback이다.
- Naver Blog는 `mainFrame` iframe을 follow하고 `se-image-resource` 이미지를
  `?type=w966`으로 정규화한다.
- URL mode `generateClips()`는 파싱된 본문을 LLM prompt로 사용한다.
- `ShortformProject.source`에 `parsedHtml`, `parsedText`, `sourceImageUrls`,
  `sourceType`, `parsedAt`을 보존한다.
- 추출 이미지는 clip media asset으로 순서대로 우선 사용하고, 부족하면 기존 Naver
  image search fallback을 사용한다.
- mock HTTP fixture 기반 테스트로 URL 원문이 아닌 파싱 본문이 prompt로 들어가고,
  첫 clip media가 원본 이미지가 되는지 검증했다.

## Shortform Render Queue Follow-Up

추가 작업 커밋:

```text
clipper_angular: 98612db feat: route shortform renders to project queue
clipper_nestjs:  4b79992 feat: queue shortform renders through python worker
```

사용자 지적:

- 기존 `숏폼 생성하기` 경로가 실제 작업 보관함 큐와 연결되지 않았다.
- `VideoRenderJobsService` 요청 시점에 synthetic completed project가 보일 수
  있었고, 이는 “렌더 완료 후 완료 목록으로 이동” 플로우가 아니었다.
- `clipper1_video_render` worker가 adlight_python `VideoService.py`와 완전 parity인지
  확인이 필요했다.

확인 결과:

- `clipper_python/plugins/clipper1_video_render`는 실제 Python plugin worker지만,
  `local_render_adapter.py`가 명시하듯 legacy `VideoService`의 conservative subset이다.
  완전 parity 포팅은 아니다.
- 기존 shortform render API는 `VideoRenderJobsService`와 `ProjectRepository.upsert()`를
  직접 호출해 완료되지 않은 shortform render를 completed project처럼 기록할 수 있었다.
- 작업 보관함 실행 큐는 `/jobs` / `JobsService` / `JobQueue` 경로이며,
  완료 프로젝트 생성의 정상 지점은 `ProjectsService.recordCompletedJob()`이다.

구현:

- Angular `ShortformWorkflowPageComponent.startRender()`는 현재 edit state를 저장한 뒤
  render API 응답의 job id로 `/projects?plugin=clipper1_video_render&job=...` 이동한다.
- NestJS `ShortformProjectService.startRender()`는 shortform manifest, render recipe,
  legacy Clipper1 payload를 만든 뒤 `JobsService.start()`에
  `pluginName: clipper1_video_render`로 enqueue한다.
- 기존 `VideoRenderJobsService.start()`와 render 요청 시점의
  `ProjectRepository.upsert()` 경로를 제거했다.
- `JobsService.publish()`는 shortform render job 완료 결과에 `render_manifest`를
  `manifest`로 보존한다.
- `ProjectsService.recordCompletedJob()`도 completed project result에 같은 manifest를
  보존하므로 완료 후 project detail/manifest 재구성이 가능하다.
- source ingest가 `text_prompt`를 새 입력 소스로 오해하지 않도록 render job params에는
  공통 `source` 대신 `input_source`와 `source_assets`를 둔다.
- API 테스트 mock TTS는 가짜 ID3 header 대신 ffmpeg/ffprobe가 읽을 수 있는 짧은 WAV
  buffer를 반환한다.

제약:

- 이번 작업은 Project-first / Plugin / Queue 전체 재정리가 아니라 shortform render
  submit path를 기존 `/jobs` 큐에 붙인 focused fix다.
- simplified shortform template은 Clipper1 legacy payload render 대상이 아니다.
  실제 render path는 legacy Clipper1 또는 Template Builder custom preset을 기준으로
  검증한다.
