## 2. 프로모션 기능의 최신 범위

### 회원가입과 크레딧 지급

- Google 로그인 후 실제 신규 회원에게 보이는 필수 동의 화면 아래에 선택 프로모션 코드 입력란을 둔다. 코드는 대문자로 정규화한다.
- Google에서 돌아온 계정에 연결된 서명된 가입 대기표로 가입 완료를 요청한다. 코드를 Google 서버에 맡겨 보관하는 구조가 아니다. 서버가 실제 가입 흐름을 판정하며 일반 회원 요청이 신규 여부를 지정할 수 없다.
- 최초 가입 혜택과 프로모션 혜택은 **별도의 지급 출처·수량·만료일**로 남는다. 사용 가능 총량은 유효 잔액의 합계다. 가입400+행사200=600은 시험 예시이며 운영값 하드코딩이 아니다.
- 서로 다른 user/admin DB 사이의 가입·혜택 처리는 내구성 있는 작업/멱등 키와 복구 경로로 연결한다. 중복 요청·응답 유실·동시 가입에서도 중복 지급을 막고, 지급 미완료를 완료된 로그인처럼 안내하지 않는다.
- 신규 가입 전용 코드를 입력하지 않고 가입을 완료한 회원은 나중에 일반 등록으로 해당 신규 가입 전용 혜택을 소급 적용하지 않는다.

### 캠페인과 코드

- 관리자 메뉴는 **프로모션**, 목록의 단위는 **캠페인**이다. 먼저 캠페인을 만들고 상세에서 하나 이상의 고유 프로모션 코드를 발급한다. 캠페인 생성 시 코드·추천인을 함께 요구하지 않는다.
- 캠페인은 지급 혜택·기간·참여 조건·코드별 등록 인원 제한을 공유한다. 추천인·개별 상태·등록 인원은 코드별 값이다.
- 한 회원은 **한 캠페인에서 코드 하나만** 등록한다. 회수된 성공 등록도 이력에 남는다. 다른 캠페인 참여 이력 자체로 새 캠페인 참여를 제한하지 않는다.
- 캠페인에서 정한 최대 인원은 **각 코드마다 독립 적용**한다. 2명 제한/코드2개라면 코드마다2명이며 캠페인 전체2명이 아니다.
- 문자열은 영문 대문자·숫자·밑줄·하이픈5~20자다. 소문자는 입력부터 대문자로 변환한다. 옛 개발 코드만 길이 제한을 풀어 주는 실행 예외는 두지 않는다.
- 캠페인 활성·코드 활성·시작/종료일·상한이 함께 실제 등록 가능 여부를 결정한다. 캠페인을 비활성화해도 개별 코드 설정을 전부 중지로 덮어쓰지 않는다. 화면은 실제 등록 불가 사유를 반영한다.
- 관리자 이메일·코드·추천인 중심 참여 조회와 회원의 여러 참여 내역은 유지한다. 내부 캠페인 이름을 회원에게 불필요하게 노출하지 않는다.

### 지급 혜택과 참여 가능 조건

혜택 종류와 가입 시점 조건은 별개다. 크레딧 지급이 반드시 신규 가입 전용인 것은 아니다.

| 설정 | 최신 동작 |
| --- | --- |
| 크레딧 지급 | 수량·유효일수 입력. 두 입력은 한 줄 반반. 자체 만료일까지 사용 |
| 이용권 지급 | 활성 등급·이용 개월 선택. 월 크레딧은 해당 등급에서 결정하며 별도 유효일수 입력 없음 |
| 이용권형 크레딧 만료 | 일반 유료와 같은 월별 이용 기간. 마지막 기간도 이용권 종료를 넘지 않음 |
| 참여 대상 | 회원가입하는 신규 회원만 / 기존 회원만 / 신규·기존 회원. 필수, 기본은 신규 |
| 추가 조건 | 현재 활성 이용권 없음 / 과거 유료 이용권 결제·사용 이력 없음. 선택한 조건 모두 충족 |
| 신규 회원만 선택 | 추가 조건을 해제하고 보이는 채로 비활성화. 별도 참여 시점/상단 단계 탭 없음 |

Free는 추가 조건의 ‘활성 이용권’으로 취급하지 않는다. 현재 유료·프로모션·관리자 지급 이용권은 활성 검사 대상이다. **관리자 지급의 과거 이력·무료체험 이력·다른 캠페인 이력은 추가 조건 선택지에 없다.**

일반 크레딧형은 별도 참여 조건에 걸리지 않으면 기존 Pro 이용권을 유지하면서 받을 수 있다. 이용권형은 중복 이용권 지급을 막는 현재/예정 이용권·진행 중 첫 구독 검사를 계속 적용한다. 참여 대상 선택만으로 그 구조적 중복 검사를 해제하지 않는다.

### 생성 확인·수정·삭제·회수

- 저장을 누르면 기존 공통 확인창에 설정 요약을 표시하고 **확인 후 생성**에서만 요청한다. 돌아가면 입력을 보존한다. 확인 표는 두 열 모두 왼쪽 정렬, 가로·세로 구분선, 왼쪽 레이블은 약한 글자색이다. 열별 배경색 시안은 채택하지 않았다.
- 생성은 비활성 상태다. 상세에서 코드를 발급한 뒤 활성화한다. 수정 저장은 변경이 없으면 비활성화한다.
- 종료일은 미정(null)일 수 있다. 시작 이후 활성 상태인 동안 운영자가 비활성화할 때까지 등록할 수 있다. 크레딧 만료일과 별개다.
- 등록 이력이 있어도 종료일 날짜↔미정, 단축/연장 가능(시작일 이후). 기존 지급분의 만료일은 소급 변경하지 않는다. 종료일 수정만으로 캠페인을 자동 재활성화하지 않는다.

| 성공 등록 이력이 생긴 후 | 변경 가능 여부 |
| --- | --- |
| 캠페인 이름 | 가능 |
| 종료일 | 가능: 시작일 이후로 단축/연장/미정 전환 |
| 코드별 등록 인원 제한 | 추가/해제/증가/감소 가능. 각 코드의 기존 등록 인원보다 작게 설정 불가 |
| 시작일·혜택 종류·지급량/유효기간·등급/개월·참여 대상·추가 조건 | 변경 불가 |
| 활성·비활성 | 별도 조작 가능. 새 등록만 통제, 기존 지급 유지 |
| 삭제 | 불가. 성공 등록 이력이 없을 때 연결 코드와 함께 삭제 가능 |

잠금 문구는 **“이미 코드를 등록한 회원이 있어 시작일·지급 혜택·참여 대상·추가 조건을 변경할 수 없습니다.”**처럼 대상을 명시한다. 모호한 ‘지급 조건’으로 모든 설정을 뭉뚱그리지 않는다.

회수는 해당 등록으로 받은 이용권을 종료하고 해당 등록의 미사용 크레딧을 함께 회수한다. 사용 기록·사용한 수량·다른 구매/가입/관리자 지급분은 보존한다. 정상 만료는 회수와 다르며 자체 유효기간이 남은 별도 크레딧을 임의 회수하지 않는다. 별도 복구/재발급 기능은 추가하지 않았고, 잘못 회수했을 때 기존 관리자 지급 기능을 이용한다.

### 현재 범위에서 제거한 초기 기능

**프로모션 종료 후 유료 예약, 레퍼럴 결제 귀속/성과 측정, XLSX 내보내기는 현재 출시 브랜치에서 제거했다.** 결제·크레딧의 원본 장부와 일반 구독/카드/재시도/환불 기능을 제거한 것은 아니다. 과거에 수락한 결제 약속을 임의 삭제하는 작업도 하지 않는다.

초기 구현은 각 제품 저장소의 `archive/promotion-access-referral-20261102`로 보존했다. 나중에 레퍼럴을 재개할 때는 새 요구로 설계한다. 첫 코드/최근 코드 귀속·성과 인정 기간·자동 정산 등을 현재 미결정 필수사항으로 다시 올리지 않는다.

## 3. 프로모션과 별개로 구현한 Free·플러그인·요금제 UI

### 이용 상태와 크레딧

- 유료 판매 상품은 Basic/Pro/Business3등급, Free를 포함한 기본 이용 상태는4가지다. Free는 결제할0원 정기 구독을 만드는 방식이 아니다.
- 활성 주 이용권이 없으면 Free다. 가입 크레딧을 소진·만료하거나 유료 이용권이 끝나도 Free 상태는 유지된다.
- 기존 최초 가입 크레딧은1회만 지급한다. Free로 돌아올 때 재지급하거나 매월 지급하지 않는다. 화면도 **가입 시1회 N크레딧·가입일부터D일 유효**로 표시해 Free 상태의 종료처럼 보이지 않게 한다.
- 사용 가능한 플러그인은 **실행 시점의 현재 등급**을 따른다. 크레딧 구매 당시 등급이 크레딧에 붙어 유지되지 않는다.
- 정기 지급분의 월별 만료·연간 구독의 월별 지급·기존 차감 순서/FIFO·환불 원칙은 변경 지시 없는 부분 그대로다.
- 추가 크레딧 신규 구매는 활성 유료·프로모션 이용권에서만 허용한다. 이용권 종료 후 남은 구매분은 원래 만료일까지 현재 등급에서 허용한 플러그인에 사용한다.

### 관리자 /plans와 공통 표시·실행

- 등급별 편집 버튼 대신 **요금제별 플러그인 관리** 버튼 하나로 전체 등급을 비교하는 공통 모달을 연다. 모달 밖에서도 자동 포함의 켜짐/꺼짐 상태를 표시한다.
- 공통 자동 포함 ON이면 Free를 포함해 하위 등급의 허용은 상위에도 포함된다. OFF이면 등급별 독립 설정이 가능하다.
- 최신 UI는 잠금 없이 **체크→상위까지 체크 / 해제→하위까지 해제**한다. 모두 체크된 상태에서 Pro의 스토리보드를 해제하면 Free/Basic/Pro는 해제되고 Business는 유지된다.
- 자동 포함 토글·등급 순서·연동 안내는 목록 스크롤 중에도 고정된다. 변경 없으면 저장 불가, 확인/취소/오류 시 초안 보존, 저장 중 중복 조작 차단을 적용했다.
- 전역 정책+전체 허용 목록을 단일 트랜잭션으로 저장하고 revision으로 오래된 초안 덮어쓰기를 막는다. 서버가 등급/플러그인 집합과 포함 관계를 다시 검사한다.
- Free 상태는 **항상 활성**으로 고정 표시한다. 등급 수정의 업그레이드 순위와 크레딧 유효일수 입력 높이를 맞췄다.
- `/#price`와 `/pricing`은 제안F 기반 공통4카드를 재사용한다. 가격·지급량·Free 혜택 기한·허용 플러그인은 API/관리자 설정에서 읽고 목업 숫자나 조합을 고정하지 않는다.
- 앱은 스토어 표시·설치·준비/편집을 허용하고, 실제 권한 제한이 필요한 새 실행은 서버에서 현재 등급을 먼저 확인한 뒤 크레딧을 확인·차감한다. 버튼 표시만으로 제한하지 않는다.

### 최신 변경 이력 표시
