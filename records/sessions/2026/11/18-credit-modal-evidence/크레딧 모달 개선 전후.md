## 단계별 관측

- Electron만 바꾼 실험용 앱에서 정상 Nest 주소 조회는 99.8–109.7ms에서 0.0–0.3ms로 줄었다. 원본 앱과 실험용 앱의 ASAR는 컴파일된 NestManager 한 파일만 달랐다.
- Electron 단독 실험에서 해외영상 모달은 최초 검토 277.5ms에서 33.8ms로 줄었다. 텍스트 숏폼은 4장면 중앙값 241.9ms, 12장면 중앙값 626.7ms였다. 12장면의 사전검사 표본에 1,461.0ms가 한 번 나와 최종 전후 비교는 위의 동일 렌더링 설정 두 번을 사용했다.
- 모달을 표시한 양쪽 표본 중 34개는 가격을 포함한 선택 버튼의 문구가 일치했다.
- 공통 견적 HTTP를 양쪽에서 관측한 24개 경로의 응답 중앙값은 5.9→5.2ms였다. 브라우저에서 데스크톱 Nest와 웹 API를 거쳐 응답을 받기까지의 시간이다.
- 인물 하이라이트의 모달 전 자원 평가 HTTP는 2→1회였다.
- 최종판 숏폼의 모달 전 순서는 편집 저장, 렌더 사전검사, 견적이다. 이 표본에서 렌더 사전검사 HTTP는 22.4–30.7ms였다.

## 우선순위별 반영 내용

1. Electron이 실행 중인 Nest 주소를 곧바로 반환한다. 최초 기동, 비정상 종료 또는 종료 후 재기동에는 Python 사전검사를 수행한다.
2. 견적, 숏폼 편집 저장과 렌더 사전검사, 홈 재시도 사전검사, 도구 상태, 플러그인 상태 및 자원 평가, 안무 참고 이미지 사전검사에 현재 Nest 주소를 요청 컨텍스트로 전달한다. 인증 인터셉터가 주소와 경로를 확인한 뒤 토큰을 붙인다. 기존 호출부에는 기존 주소 확인 경로를 유지했다.
3. 숏폼 미디어와 WAV는 요청 안에서 파일 식별자·크기·수정 시각이 같은 경우 FFmpeg 검사를 한 번 수행한다. 새로 받은 원격 소재나 교체된 파일은 다시 검사한다. 실제 렌더 실행은 새 요청에서 과금 전에 검증한다. 공유 파일을 쓴 회귀 테스트의 디코딩 횟수는 4장면 15→3회, 12장면 47→3회였다.
4. 인물 하이라이트에서는 설치·기동 상태를 먼저 확인하고, 모달 경고에 쓰는 평가를 견적과 함께 한 번 읽는다. 확인창을 띄우기 전에도 상태표시줄의 직전 평가를 보존하고, 새 평가가 더 최근이면 갱신한다.
5. 안무 외부 이미지 다운로드를 요청당 최대 3개로 제한해 겹쳐 처리한다. Python 모델 재초기화가 겹치지 않도록 얼굴 판정은 Nest 프로세스당 한 번에 하나씩 보낸다. 외부 사진 6장에 고정 지연과 모의 응답을 사용한 서버 시험의 중앙값은 564→211ms였다. 설치형 버튼 표는 로컬 참고 사진 세 장을 사용했다. 큐레이션은 쓸 수 있는 긴 이미지 조각 하나를 찾는 시점에 다음 단계로 진행한다. 원격 미리보기의 유효성은 생성 버튼을 눌렀을 때 다시 확인한다.
6. 같은 세션·Nest 주소·작업 키·입력의 진행 중 견적을 합친다. 견적이 끝나면 다음 요청은 새로 확인한다. 확인창을 띄울 때 스피너를 내리고 승인 뒤 복원하는 동작을 공통화했다.
7. 웹 API의 견적은 기존 사용 가능 지급분 조건으로 잔액 합계만 조회한다. 회귀 테스트에서 견적의 크레딧 관련 SQL이 3회에서 1회로 줄었다. 권한과 실행·차감·환불은 기존 검증을 사용한다.
