# Clipper Studio 크레딧 모달 지연 검토

2026-11-17 KST · macOS Apple Silicon · 로컬 웹 API `127.0.0.1:3000`

## 결론

가장 큰 공통 병목은 설치형 Electron의 **NestJS 주소 조회가 이미 실행 중인 서버에도 Python 가상환경 전체 검사를 다시 수행하는 것**이다. 실제 앱에서 주소 IPC 6회가 **99.8–109.7ms** 걸렸다. 토큰 IPC와 FFmpeg 설치 확인은 각각 **0–0.2ms**였다. 일반적인 과금 견적 HTTP는 **5–9ms**에 응답했다. Angular의 기능 서비스와 로컬 인증 인터셉터가 주소를 연달아 조회하므로, HTTP 1회 앞에 약 200ms의 준비 시간이 추가된다. 랭킹에서 견적 요청은 클릭 **216.6ms** 후 시작했고 **6.8ms** 만에 끝났다.

숏폼 4종에는 별도 병목이 있다. 프로젝트 저장, 렌더 사전검사, 견적을 차례로 실행한다. **4장면 텍스트 숏폼 866ms, 12장면 1,182ms**였다. 그중 렌더 사전검사는 **171ms → 508ms**로 늘었다. 두 프로젝트에 같은 로컬 MP4와 WAV를 사용했으며, 장면 수에 비례해 FFmpeg 검사가 반복되는 구조를 확인했다.

## 빌드와 측정 기준

- 원격의 `refs/heads/dev`를 직접 조회한 뒤 각 커밋에서 별도 detached Git worktree를 만들었다. Angular `d7dc973f`, Electron `b2f53db5`, 데스크톱 NestJS `136e38a4`, Python `53c7fccc`, 웹 API `1e230818`.
- Node 24.19.0, Electron 43.3.0, uv 0.9.18. `build:app:mac:arm64:local-api`로 생성된 `.app`을 `hdiutil`로 DMG에 묶었다. 해당 번들에서 직접 실행했다. 개발판 QA 프로필 `credit-modal-qa`, 자동 업데이트 비활성. 신규 로컬 공개키와 격리된 PostgreSQL 3개 DB를 사용했다. DMG 체크섬과 마운트한 `app.asar`·런타임 설정의 바이트 일치를 확인했다. 패키징·Nest 기동 관련 기존 테스트 53개가 통과했다.
- 실제 패키지 렌더러에 Chrome DevTools Protocol로 버튼 클릭을 전달했다. 클릭 이벤트의 단조 시각부터 해당 확인 창 DOM이 표시된 첫 관찰까지 기록했다. 일반 모달은 금액이 표시된 상태로 열린다. 스토리보드는 창과 금액 버튼 활성화를 따로 기록했다. 수치는 개별 표본이며 한 프레임 정도의 관찰 오차가 있다.
- 테스트 계정에 로컬 전용 플랜과 가상 크레딧을 발급했다. 합성 미디어, 기존 얼굴 테스트 픽스처, 앱의 저장 데이터 형식을 따르는 QA 프로젝트·실패 잡을 사용했다. 스토리보드에서 OpenAI·네이버는 로컬 DB의 자격증명 존재 조건만 채웠다. 측정 종료점은 확인 창 표시다. 재료 다시 만들기 창을 닫는 과정에서 자동화 입력이 유료 선택을 한 번 발동했다. 격리 QA 계정의 가상 120 크레딧이 차감됐고, 임시 키를 쓴 제공자 요청이 401로 실패한 뒤 120 크레딧이 자동 환불됐다. 최종 순차감은 0이다.
- 분류 기준은 앱 스토어의 현재 유료 기능 14개와 코드에서 찾은 추가 차감 확인 진입점이다. 서버에 남은 `shortform_explainer.script`와 `shortform_explainer.video`는 구버전 키다. 현재 단계별 과금은 `create`, `visuals`, `video_seconds`를 사용한다.
- 초기 대사 하이라이트 표본은 스토어 설치 종료 부근에 얻었다. 백그라운드 설치, 계정 갱신, 상태 폴링 요청은 모달 대기의 필수 경로에서 제외했다. 창이 가려져 프레임 관찰이 누락된 시도와 입력 검증에서 막힌 시도는 대표값에서 제외했다.

변화 그림의 재생성은 변화 방식으로 완성된 영상이 남아 있는 경우에 `confirmPictureChange`를 거친다. 완성된 3초 영상과 시작 그림이 있는 QA 프로젝트에서 15.1ms였다. 기존 영상이 없는 경우에는 확인 없이 유료 그림 요청으로 이어질 수 있다. 실패 그림 카드의 버튼은 같은 `redo`를 호출하며, 보존된 영상 자산이 있는 별도 예외 상태로는 실측하지 않았다.

홈의 공통 재시도는 실패·취소 상태와 정산 상태를 확인한다. 숏폼은 `POST /jobs/:id/retry/preflight`에서 소유자, 상태, 정산, 중복 재시도, 실행 권한을 검사하고 등록된 숏폼 사전검사를 거친 다음 새 견적을 요청한다. 다른 모듈의 홈 재시도는 로컬 상태 판정 다음에 바로 새 견적을 요청한다. 하이라이트는 기존 소스 길이, 베리에이션은 1개를 견적에 전달한다. 베리에이션은 보관함 카드에서 결과 화면을 연 뒤 개별 결과의 `다시 만들기`를 사용한다.

생성형 AI의 재료·장면·영상 편집은 현재 단가와 첫 생성 묶음 상태를 화면에서 읽는다. 이미 만든 결과를 밀어내는 경우에는 기존 자산·연쇄 수량을 판단해 확인 창을 연다. 재료 재생성·요청 수정은 참조하는 장면 그림이 있을 때 재료만 그릴지 함께 그릴지 선택하는 창을 쓴다. 장면 그림 재생성·요청 수정·변화 그림 재생성은 만들어 둔 영상이나 변화 그림에 영향이 있을 때 확인한다. 영상 재생성·요청 수정은 기존 영상이 준비된 경우 가격을 표시한 확인 창을 쓴다. 첫 그림·첫 영상 만들기 등 즉시 실행하는 경로는 버튼에 가격을 표시하며, 클릭 후 견적 창을 여는 경로와 별개다. 최종 합성 렌더는 무료이고 첫 생성 묶음의 남은 무료 작업을 닫는 경우에만 묶음 종료 확인이 붙는다.

## 버튼 클릭 후 일어나는 작업

### 공통 견적

1. Angular가 입력과 연타 잠금을 확인하고 기능별 준비를 수행한다. 출발점은 기능별 버튼 핸들러다.
2. API 서비스가 Electron IPC로 번들 NestJS 주소를 조회한다. 로컬 인증 인터셉터가 URL 일치 여부를 보려고 같은 주소를 다시 조회한다. 이후 Electron의 토큰 조회, 필요 시 갱신·재시도, `Authorization` 및 `x-trace-id` 첨부를 거친다.
3. 각 주소 조회에서 `NestManager.doStart()`가 `isRunning`보다 먼저 `ensureVenv({ onlyIfMissing: true })`를 호출한다. 그리고 Python 버전, `python -m yt_dlp --version`, `yt-dlp-ejs` 패키지 버전의 **세 자식 프로세스**와 콘솔 스크립트·마커를 확인한다. 정상 견적 HTTP 1회 앞에 기존 상태에서도 이 검사가 두 번 발생한다. 여러 HTTP가 동시에 시작되면 진행 중인 `startPromise`를 공유할 수 있다.
4. 데스크톱 NestJS가 로컬 요청을 인증하고, 동일한 작업 키와 입력을 웹 API `POST /operations/:key/quote`로 전달한다. 웹 API는 RS256 JWT 검증, 회원·세션 조회, 작업 정책 조회, 입력 길이·개수·초 기반 계산, 유효 플랜/기능 권한 조회, 잔액 집계 및 차감 후 잔액 계산을 수행한다. 잔액 집계는 현재 지급분을 종류별로 합친 뒤 현재 혜택을 찾기 위해 유효 접근권과 지급분도 읽는다. 스토리보드는 수량과 견적 ID를 함께 돌려준다.
5. Angular가 작업 키·잔액·금액을 검증하고 유료 확인, 이용권 안내, 크레딧 부족 중 해당 UI를 연다. 정상 확인에서 기존 스피너 덮개를 닫는다. 잡 예약, 실제 차감과 렌더/분석 호출은 승인 뒤에 시작한다.

## 수정 후보와 검증 기준

1. **가장 먼저 Electron의 정상 서버 주소 조회에서 Python 검사를 제거한다.** `NestManager.doStart`의 정상 프로세스/포트 확인을 `preflight` 앞에 둔다. 최초 준비와 종료 후 재기동에서만 검사를 실행한다. 자식 프로세스 종료 중/헬스 실패·재시작·동시 호출을 기존 `startPromise`와 함께 검증한다. 이 변경 한 가지를 적용한 뒤 설치형 동일 기기에서 다시 잰다. 현재 데이터 기준 견적만 있는 경로에 약 200ms, 숏폼의 세 순차 HTTP에 약 600ms에 해당하는 제거 대상이 있다.
2. **로컬 API 주소 조회를 한 요청당 한 번으로 정리한다.** 주소 확인과 토큰 주입을 공통 진입점으로 모으거나 요청 컨텍스트에 해석된 주소를 전달한다. 일반 외부 요청에 토큰이 붙지 않는 조건과 재기동 시 동적 포트 갱신은 유지한다. 1번 뒤에 남은 IPC 비용을 재고 우선순위를 정한다.
3. **숏폼 사전검사에서 같은 WAV·로컬 소재의 재검사를 없앤다.** 현재 `assertReady`가 원격 구체화 전·후에 로컬 파일과 오디오를 모두 검증한다. 유효성/파일 존재 확인과 디코딩을 나누거나, 한 요청 안에서 파일 경로와 변경 정보로 검증 결과를 공유한다. 원격 소재만 내려받은 뒤 검사한다. 최종 렌더 시작은 파일 변경 가능성과 비용 차감을 위한 검증을 유지한다. 4·12장면, 원격 포함, 누락·손상 파일, 저장된 최신 발음으로 재검증한다. 프로젝트 업데이트와 렌더 사전검사 순서는 연관이 있으므로 단순 병렬화하지 않는다.
4. **인물 하이라이트의 자원 평가를 한 번만 계산해 재사용한다.** readiness와 모달 경고가 같은 플러그인 평가 결과를 각각 조회한다. 요청 스냅숏을 전달하고 오래된 결과는 갱신한다. 경고에 쓸 조회가 실패하더라도 견적 성공·권한 규칙을 독립적으로 보존한다. 디스크 경고는 이미 비차단이므로 중복 제거와 구분한다.
5. **안무 외부 참고 이미지와 큐레이션 원격 이미지의 최악 지연을 줄인다.** 안무는 선택·업로드 단계에서 이미 검증된 로컬 자산을 우선 사용한다. 외부 참조를 준비할 때는 멤버/이미지 수, 재시도, 캐시 히트, 네트워크와 Python 수행 시간을 계측한 뒤 제한된 동시성을 적용한다. 큐레이션은 선택·미리보기 중 확인한 이미지 상태를 사용하고, 이미 사용할 수 있는 긴 이미지 조각이 있으면 나머지 응답을 기다릴 필요가 있는지 검토한다. 서버의 다운로드 안전성·파일 제한, 추출에 필요한 장수, 사용자 경고는 유지한다.
6. **견적과 모달 공통화는 의도가 같은 부분부터 적용한다.** 현재 `OperationChargeGuardService`가 일반 모달을 이미 공통화한다. 동일 작업 키·동일 입력의 *진행 중인* 버튼 가격 조회를 클릭 견적과 합치고, 이미 끝난 견적은 가격·권한·잔액 최신성 규칙을 정한 뒤 재사용 여부를 판단한다. `BlockingProgress` suspend/resume과 홈/결과 재시도의 견적 옵션 구성처럼 실질적으로 반복되는 코드만 공통화한다. 수량 선택이 가능한 스토리보드와 정액/재작업 조건이 있는 생성형 AI의 전용 UI는 각각의 흐름을 유지한다.
7. **웹 API의 읽기 비용은 마지막에 재측정한다.** 견적의 접근권 판정과 전체 잔액 요약이 유효 접근권을 각자 조회한다. 견적에 실제 필요한 잔액·권한 조회만 공유하거나 요약 조회를 줄이는 편이 타당하다. 견적·실행·환불의 동시성, 정산 트랜잭션과 권한 규칙은 유지한다. 현재 수 ms 응답에서는 Electron·렌더 사전검사가 우선이다.

검증은 같은 macOS 설치형과 Windows 설치형에서 각각 정상 기동/재기동을 구분해서 수행한다. 대표 입력과 네트워크 조건을 고정하고 첫 클릭 및 반복 표본을 저장한다. 클릭·각 HTTP 발사/응답·모달 표시·유효 견적 표시 타임스탬프와 작업 중 프로세스 생성 횟수를 남긴다. 견적 비용·잔액·권한·취소 결과가 같은지도 확인한다.
