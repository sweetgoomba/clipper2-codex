# 2026-10-01 — W14 성공 기준 확인

W14 UI 피드백: 기존 Angular의 `source-input`/`source-confirm-card`, 홈 대기열·실행 카드, 완료 카드 `결과 보기`, 안무·대사 결과 열 카드, 기존 `clip-trimmer` 핸들/숫자 병행 구현을 읽기 전용으로 확인했다. 인물 목업은 진입→홈 큐→완료 결과를 분리하고, 결과를 인물/클립/원본 미리보기 3열로 수정했다. 사용자 요청에 따라 숫자 경계 입력을 목업에서 제거하고 드래그 시작·끝 핸들, 읽기 전용 시각, 원래 경계·저장 동작으로 바꿨다. [W14 제안 §3](../../../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md)과 [W14 카드](../../../../handoff/tasks/person-highlight.md)에 제안 상태로 기록했다. 실제 제품 코드·ML·사용성 검증은 하지 않았다.

추가 UI 교정: 플레이어 바로 아래에 별도 이동 막대와 편집 타임라인을 번갈아 두지 않고 동일한 구간 타임라인 하나를 사용한다. 기본 상태는 선택 구간의 재생·구간 내 seek만 가능하며 경계 핸들은 조절 불가다. `구간 편집` 중에만 핸들이 활성화되고 저장/취소로 보기 상태에 돌아온다. 이는 목업/제안 변경이며 실제 앱 구간 편집 코드는 건드리지 않았다.

사용자가 위 수정 목업을 확인했다. 출력 방식·MVP 전체 스펙 및 실제 구현/평가 착수의 승인으로 해석하지 않는다. 다음 선택은 개별 MP4/복수 ZIP에 더해 선택 구간을 하나로 잇는 MP4를 첫 버전에 넣을지다.

후속 다운로드 UI 요청을 결과 목업에 반영했다. 현행 안무 인물 행의 hover ZIP 버튼과 대사 클립 행의 hover MP4 버튼을 확인했다. 인물 행에는 해당 인물 전체 ZIP, 클립 행에는 개별 MP4 버튼을 추가하고 체크박스·선택 내보내기 영역을 제거했다. 아이콘은 hover 외에 키보드 포커스와 터치에서도 표시한다. 실제 파일 생성·과금·작업 큐·임의 다중 선택/합친 MP4 범위는 검증/결정 전이다.

사용자는 목업을 확인하고 **이어 붙이는 기능은 없다**고 결정했으며 설계 진행을 지시했다. [Superpowers W14 MVP 서면 설계](../../../../features/highlights/records/2026/10/2026-10-01-person-highlight-mvp-design.md)를 작성했다. 클립 MP4·인물 ZIP·전체 ZIP 직접 요청, 임의 다중 선택 UI/이어 붙인 MP4 제외, 공통 얼굴 API·다중 관측/track/group·다대다 Scene·review revision·export job·평가와 실행 gate를 통합했다. 기존 [9/30 제안](../../../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md), [W14 카드](../../../../handoff/tasks/person-highlight.md), [평가 manifest](../../../../features/highlights/records/2026/09/30-w14-evaluation-manifest.yaml), [W13 계약 인계](../../../../features/highlights/records/2026/09/30-w14-to-w13-face-contract-handoff.md), [WORKBOARD](../../../../handoff/WORKBOARD.md)를 갱신했다. 서면 설계 사용자 리뷰 전이라 구현 계획/제품 코드·ML/다운로드·fetch/commit/merge는 진행하지 않았다. 과금/원본 보존 정책·GT 원본/라벨·모델 실제 hash·W13 상호 확인은 남는다.

사용자가 인물·등장 구간 누락 최소화와 서로 다른 인물의 오합침 최소화가 **둘 다 중요하다**고 확인했다. W14 [설계 제안](../../../../features/highlights/records/2026/09/30-w14-person-highlight-design-proposal.md), [평가 manifest](../../../../features/highlights/records/2026/09/30-w14-evaluation-manifest.yaml), [인물 카드](../../../../handoff/tasks/person-highlight.md), [WORKBOARD](../../../../handoff/WORKBOARD.md), [W13 공통 계약 인계](../../../../features/highlights/records/2026/09/30-w14-to-w13-face-contract-handoff.md)에 동등한 1차 기준을 반영했다. 배경·단역 포함 correctly grouped interval recall과 false merge를 각각 보고하고, 한쪽 악화를 다른 쪽 개선으로 상쇄하지 않는다. 불확실한 관측은 확인 필요로 보존하며 false split/수정 부담도 분리해 보고한다. 수치 목표·GT 입력·MVP 합친 MP4 여부·과금/보존 정책과 W13 계약 상호 확인은 남아 있다. 이번 후속은 문서만 수정했고 제품 코드·ML·모델 다운로드·유료 호출·fetch·commit/push/merge/deploy는 실행하지 않았다.

## W13 — metadata 평가 adapter 선택·준비

사용자는 W13의 평가 도구 준비까지 선택하고 구체 설계를 승인했다. W13 작업에서는 Python `origin/dev`를 fetch해 `4778295`로 조사 HEAD와 동일함을 확인하고, 별도 브랜치·worktree에 분석 결과만 반환하는 경로를 구현했다. 기존 제품 `run()`의 분석 판단을 공유하며 clip/thumbnail/제품 meta는 평가 경로에서 만들지 않는다. 가짜 입력 안무 테스트 34개 통과. 비 e2e 전체 487 passed/1 skipped/5 setup errors(이 환경의 localhost bind 거부). 실제 영상·모델 평가, 모델 다운로드, 과금, Build5, commit/push/merge/deploy는 하지 않았다. [코드·검증·한계](../../../../features/highlights/records/2026/10/01-w13-evaluation-adapter.md), [W13 카드](../../../../handoff/tasks/dance-highlight.md), [평가 manifest](../../../../features/highlights/records/2026/09/30-w13-experiment-manifest.yaml)를 갱신했다. W14 공통 얼굴 계약 승인이나 W14 파일 수정으로 간주하지 않는다.

같은 날 사용자가 첫 영상 후보로 `https://youtu.be/yFTAYXDTjqI`를 지정했다. manifest에 URL과 ID만 반영했다. 원본 YouTube metadata는 이 환경에서 접근 실패했고 로컬 동일 ID 파일도 확인되지 않았다. 원본 다운로드·영상/모델 분석 0회. 정확한 구간·원본 파일/hash와 나머지 실행 범위 확정 대기.

### W13 후속 — 기존 앱 입력 발견과 전체 영상 선택

사용자가 이 영상은 현재 앱에서 이미 안무 작업을 완료했고, 기존 다운로드 원본의 **전체 구간**을 쓰라고 지정했다. 앞 문단의 로컬 파일 미확인은 프로젝트 트리만 검색한 결과였으며, 앱 사용자 데이터 폴더 조사로 정정했다. `Clipper Studio Dev`와 일반 `Clipper Studio`의 동일 video ID 원본 두 사본은 SHA-256 `7f23b9ad8dd6873d8c39a8369083626de5e1807468d083247f0545c3299688d4`로 같다. `ffprobe` 길이 133.654059초, 1920×1012, 60000/1001 fps, 79,098,114 bytes. 9/29 Dev와 9/10 일반 앱 완료 프로젝트의 `dance_meta_v1`에서 `config/stats/lists/persons`가 같고, 최신 결과는 메인 19개·그룹 1개·main 1개 얼굴 표본 단계 탈락이다. 정답 라벨 없이 정확도나 회귀는 판단하지 않았다.

최신 프로젝트의 참조 URL 24개 중 로컬 파일은 23개(하니 `ref_00` 없음)이며 기존 YOLO pose·YuNet·SFace weight도 확인해 각 hash를 [입력 목록](../../../../features/highlights/records/2026/10/01-w13-existing-app-input-inventory.json)에 기록했다. [쉬운 설명](../../../../features/highlights/records/2026/10/01-w13-first-video-static-review.md)과 [manifest](../../../../features/highlights/records/2026/09/30-w13-experiment-manifest.yaml), [W13 카드](../../../../handoff/tasks/dance-highlight.md), [WORKBOARD](../../../../handoff/WORKBOARD.md)를 갱신했다. 기존 3개×120초 제안은 이 영상에 한해 전체 133.654초로 대체했다. 새 다운로드·새 영상/모델 평가·과금·Build5·commit/push/merge/deploy는 수행하지 않았다. 라벨·참조 사용 범위/권한·비교 변수·실행 SHA/device/횟수/시간·자원 한도/출력 위치를 사용자와 정해야 한다.

후속으로 기존 원본을 초당 1프레임으로 샘플링해 임시 contact sheet 7장을 육안 확인했다. 약 0~5초 출연 전 무대, 5~113초 안무, 113초~끝 종료 화면이라는 예비 관찰만 남겼다. 메인/멤버 정답 라벨과 정확도 수치는 아직 만들지 않았고 새 모델 추론은 0회다. 위 문단의 "새 영상 평가 0회"는 이 간단한 육안 선별 전 상태를 가리킨다.

기존 Dev 실행 로그를 추가로 확인했다. 그룹 중첩으로 메인 후보 `20.487~30.030`초와 `30.030~34.835`초가 제외됐지만 그룹 clip은 `23.357~33.433`초이므로 양옆에 출력 공백 2.870초와 1.402초가 남는다. 얼굴 표본 탈락 1건의 시점은 이 로그에서 확인되지 않는다. 로그는 포즈 분석 2002프레임·55.8초, 전체 기존 앱 작업 77.0초를 기록하지만 새 평가 실행 시간의 보증값으로 쓰지 않는다.

### W13 후속 — 사용자 정정: 공동 메인·보류 보존

사용자는 분명한 단독 리드는 한 명으로 보되 **공동 메인은 여러 명**, 같은 장면의 여러 인물 배정 허용, 불확실한 안무 장면의 **보류 보존**을 요구했다. 앞서 제가 제안한 의상 색↔멤버 이름 확인 질문은 필요하지 않은 부담이었으므로 철회했다. 메인/장면 보존 라벨은 영상 내 익명 인물 ID로 가능하고, 멤버 신원 정확도는 독립적으로 확인된 이름이 있는 구간에서만 계산한다.

코드 재확인: Python `MainSelector.select`/`FrameRec`는 프레임당 main 하나만 남기고 그룹 중첩은 main 구간을 제거한다. 얼굴 표본 부족도 main clip 생성 전에 제거한다. Nest `dance_clip_assignments[clipId]`는 목적 `personId` 한 명만 저장한다. [다중 메인·보류 설계 정정](../../../../features/highlights/records/2026/10/01-w13-multi-main-retention-design.md)을 작성하고 [비교 설계](../../../../features/highlights/records/2026/09/30-w13-investigation-evaluation-design.md), [manifest](../../../../features/highlights/records/2026/09/30-w13-experiment-manifest.yaml), [W13 카드](../../../../handoff/tasks/dance-highlight.md), [WORKBOARD](../../../../handoff/WORKBOARD.md)를 고쳤다. 제품 코드와 기존 앱 결과는 변경하지 않았고 새 모델 추론·다운로드·과금·Build5·commit/push/merge/deploy는 실행하지 않았다.

### W13 후속 — 전체 영상 독립 육안 검토 초안

사용자가 계속 진행을 지시해 기존 다운로드 원본 전체 133.654초를 ffmpeg **2fps 정지 장면 실제 267장/17개 contact sheet**로 읽었다. [쉬운 시간순 검토표](../../../../features/highlights/records/2026/10/01-w13-full-source-review-guide.md)와 [당시 16개 연속 구간 JSON 초안](../../../../features/highlights/records/2026/10/01-w13-full-source-label-draft.json)을 작성했다. 무대 첫 등장 약 5.5초, 종료 카드 약 113초와 그 사이 리드 교체·동기화 안무를 임시 표시했다. 익명 시각 표식 `V1`~`V5`는 멤버 이름이나 확정 track이 아니고, scoring용 `main_track_ids`는 비워 두었다. 2fps 정지 장면으로 정확한 경계·사람 연속성·공동 메인·안무 종료·얼굴 신원을 확정하지 않는다.

기존 앱 JSON을 다시 계산해 메인 clip 19개/그룹 1개, 20.487~34.835초의 인물별 main 부재, 그 안의 그룹 clip 23.357~33.433초와 결과 공백 2.8695초/1.4014초를 확인했다. 원본 장면에는 이 시간에 출연자와 앞사람 교체가 보여 우선 검토 대상으로 지정했다. 이 정적 대조를 모델 정확도나 예전 대비 회귀라고 주장하지 않는다. manifest에는 초안 경로/hash만 반영하고 scoring용 frozen label·새 실험 실행 조건은 미확정으로 유지했다. 기존 영상/clip·제품 코드는 변경하지 않았고 새 ML/모델 다운로드/유료 호출/Build5·commit/push/merge/deploy는 하지 않았다.

### W13 후속 — 교체 구간 촘촘한 확인과 첫 비교 변수

사용자가 이어서 진행하라고 지시했다. 같은 원본의 15~38.75초·50~65.75초를 **4fps 정지 장면**으로 추가 확인하고 보존했다. 기존 16구간 초안을 **19개 연속 임시 구간**으로 좁혔다. 15.5~20.5초 V1, 21.25~27.5초 V2, 28.5~33.5초 V3, 53.5~57.5초 V4, 58.5~61.75초 V5를 단독 메인 **후보**로, 사이사이는 교체/공동 메인 보류로 기록했다. 이는 연속 영상·독립 track/멤버 확인 전의 초안이며 scoring 라벨은 아니다. [쉬운 검토표](../../../../features/highlights/records/2026/10/01-w13-full-source-review-guide.md)와 JSON hash를 갱신했다. ffmpeg `showinfo`로 2fps 최종 표본은 133.0초·267번째, 집중 표본은 각각 96장/64장임을 다시 확인해 초기 장수·끝 시각 표기를 정정했다.

### W13 후속 — 첫 보존 지표와 실행 전 한 장 요약

### W13 후속 — 사용자 승인 실영상 MoveNet 3회 평가

사용자가 고정 [실행 범위](../../../../features/highlights/records/2026/10/01-w13-movenet-execution-scope-one-page.md)에 `해`라고 답했다. 승인 manifest의 원본/모델/라벨 hash·코드/런타임/장치·3회/시간/RSS/출력 한도·빈 출력 위치 사전 검사를 통과한 뒤 격리 W13 worktree에서 원본 전체의 CPU MoveNet pose metadata **3회**를 실행했다. [실행·표본 결과](../../../../features/highlights/records/2026/10/01-w13-movenet-first-real-metadata-evaluation.md)에 회당 56.75~60.90초, 최대 worker RSS 937.42MiB, 전체 출력 20.62MiB, 세 pose JSON 동일 해시를 기록했다. 원본 9프레임의 45명 중 33명 검출, 일부 가림 3/9명, 메인 위치 4프레임 중 1개 일치·3개 다른 인물 선택이었다. 틀린 메인 3프레임에서 정답 인물은 모두 검출됐다. 6.0~112.5초 공연 창의 프레임 셀 기준 raw 후보 공백은 0.267초다. 최종 clip 공백과 단계가 다르며 현행 YOLO와 같은 입력 pose A/B도 아니다. 채점기는 7개 테스트를 실패→통과로 확인하고 모델 재실행 없이 적용했다. raw segment 끝의 포함 시각 때문에 보존 계산 규칙을 실행 후 보정한 사실을 기록했다. manifest는 `completed_scoped_metadata_run`으로 재실행을 차단했다. 새 YOLO pass·얼굴/참조 이미지/clip export/제품 모델 교체·W14 공통 얼굴 파일 수정·commit/push/merge/deploy는 없다.

### W13 후속 — 저장 metadata의 메인 규칙 비교

사용자의 `진행해`는 새 추론이 아니라 직전 제안한 **저장 pose의 메인 선택/전환 규칙 비교**로 해석했다. [읽기 쉬운 원인·조건 비교](../../../../features/highlights/records/2026/10/01-w13-main-selector-offline-rule-comparison.md)에 SHA 고정 입력, 현행 선택기 2,002프레임 재생 불일치 0건, 네 솔로 앵커의 순간 점수 순위와 이전 인물 유지 조건을 적었다. 틀린 세 장 중 두 장은 정답이 순간 점수 3·4위, 한 장은 1위이나 +6% 후보 점수 문턱에 미달했다. 즉시 최고 점수 대안은 앵커 1/4→2/4이지만 공연 창의 bbox 불연속 대리 지표 230→380; 후보 점수 여유만 제거하거나 실제 `skip4` 시간에 맞춰 streak만 줄인 대안은 1/4로 그대로다. group 플래그는 명확한 솔로 창 222/269프레임에서도 켜져 있어 공동 메인 자동 배정의 근거로 부적합하다. `top-k` 포함 수만 올리면 네 단독 정답 표본에서 오배정도 늘어난다. 라벨을 확장하기 전에는 전환 지연·공동 메인 precision/recall 또는 모델 우위를 주장하지 않는다. 제품 코드·기존 앱 프로젝트·W14 공통 얼굴 파일은 변경하지 않았고 새 ML/clip export/commit/push/merge/deploy는 없다.

### W13 후속 — 세 오선택 전후 원본 전환 확인

사용자의 `진행해`에 따라 동일 원본의 20.0~23.5초·26.5~31.0초·51.5~59.5초를 원본 6프레임 간격(약 0.1001초) 이미지로 확인하고 세 오선택과 동일한 원본 프레임 1320·1740·3356을 전체 해상도로 확인했다. [쉬운 원본 검토 기록](../../../../features/highlights/records/2026/10/01-w13-transition-source-review.md)과 [잠정 구간표](../../../../features/highlights/records/2026/10/01-w13-transition-source-review-v2.json)에 교체 검토 시간대를 남겼다. 기존 P2·P3·P4 단독 앵커와 충돌하는 장면은 찾지 못했다. 그러나 작성자가 모델 결과를 이미 보았으므로 이번 표는 새 독립 정답이 아니며, 공동 메인이나 전환 지연을 수치로 판정하지 않는다. 기존 동결 라벨/hash와 MoveNet 3회 metadata 결과는 그대로 유지했다. 이번에는 원본 읽기·이미지 추출·문서 갱신만 했고 새 ML·제품 코드 변경·commit/push/merge/deploy는 없다.

### W13 후속 — 독립 원본 전환 라벨과 저장 결과 재채점

사용자 요청에 따라 앞선 원본 전용 독립 검토자가 앱·MoveNet 출력과 오프라인 비교 기록을 보지 않고 네 교체 시간대를 약 10fps와 정확한 원본 프레임으로 다시 봤다. [라벨 v2](../../../../features/highlights/records/2026/10/01-w13-blind-transition-labels-v2.json) hash `9b871c05833731ea20789cc4af0a0bc31bb8f2096ca00f8d9f4ca2768274cbe8`에 엄격 단독 메인 6프레임과 약한/경계 2프레임, 인계 보류 구간을 **저장 pose 확인 전에 고정**했다. 기존 `run-01/pose.json`을 새 추론 없이 대조한 [결과](../../../../features/highlights/records/2026/10/01-w13-blind-transition-audit-and-rescore.md)는 새 표본 **2/6 일치, 4/6 오선택**이다. 네 오선택에서 모두 정답 인물은 검출됐고, 순간 점수 4·2·2위 셋과 1위지만 미선택 하나로 나뉜다. 6장 모두 group 플래그가 참이나 원본 정답은 단독이다. 공동 메인 후보와 인계는 보류했고 전체 영상/전환 지연 수치로 확대하지 않았다. 기존 v1 라벨과 3회 pose 결과·manifest는 그대로이며 제품 코드·공통 얼굴 파일·clip export·새 ML·commit/push/merge/deploy는 없다.

### W13 후속 — 새 고정 표본 재채점·탈락 장면 보존 설계

사용자 지시에 따라 작은 단계마다 멈추지 않고 기존 원본/저장 pose/artifact의 읽기·오프라인 비교를 이어갔다. 원본 프레임 27개를 [표본 계획](../../../../features/highlights/records/2026/10/01-w13-holdout-source-sample-plan.json)에 예측 확인 전 고정하고, 별도 원본 검토자가 앱·MoveNet 결과를 보지 않은 채 [단독 18·그룹 4·빠른 인계 5 라벨](../../../../features/highlights/records/2026/10/01-w13-holdout-source-labels-v1.json)을 고정했다. 저장된 2,002프레임을 현행 `MainSelector`에 재생했을 때 저장 bbox/group과 불일치 0건이다. [오프라인 결과](../../../../features/highlights/records/2026/10/01-w13-selector-holdout-evaluation.md)는 새 단독 표본 현행 6/18, 정답 검출 후 다른 사람 선택 9, IoU≥0.30 정답 대응 실패 3이다. `skip4` 전환 streak 보정 또는 정적 관절 거리 계수 제거만 한 조건은 각 4/18로 낮았다. 그룹·빠른 인계는 단독 정확도에 넣지 않았고 전체 영상·YOLO 대비 정확도·전환 지연·공동 메인 수치로 일반화하지 않았다. 새 모델 추론은 없다.

[첫 제품 범위 설계](../../../../features/highlights/records/2026/10/01-w13-review-candidate-preservation-contract.md)는 `group_overlap`과 얼굴 표본 부족으로 탈락한 main 후보를 별도 sidecar와 원본 타임라인의 `확인 필요` 읽기 전용 항목으로 남기는 안이다. 기존 MP4 102.229/106.5초에 두 탈락 후보 시간을 더하면 clip이 전혀 없던 4.271초가 검토 가능해진다는 **기존 artifact 정적 계산**이며 실제 화면·새 MP4·정확도 개선이 아니다. 현행 `Segment.end`의 다음/마지막 관측 혼합 의미와 ffmpeg export 경계의 불확실성을 기록했다. [W14 공통 얼굴 API 소비자 검토](../../../../features/highlights/records/2026/10/01-w13-face-core-consumer-contract-review.md)는 W14 공통 파일 초기 소유·W13 Dance 정책 소유를 확인했지만, 현재 미커밋 API의 PTS/실패 관측/embedding 공간 지문 차이를 실제 Dance 이식 전 과제로 남겼다. 공통/제품 코드·기존 완료 프로젝트는 건드리지 않았고 clip export·commit/push/merge/deploy 없음. 다음 사용자 결정은 읽기 전용 검토 화면/sidecar를 첫 제품 범위로 선택할지다.
