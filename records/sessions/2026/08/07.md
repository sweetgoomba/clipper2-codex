## 조사와 영상 후보 흐름

### 조사 근거와 레퍼런스 분석 분리

- 신규 조사 주제는 시장 자료를 중심으로 생성한다.
- YouTube 검색 결과는 시장 반응을 파악하는 조사 자료로 남길 수 있지만, 조사 단계에서
  레퍼런스 영상을 선택하고 정밀 분석하는 절차는 기본 흐름에서 제거했다.
- 영상 정밀 분석 구현과 기존 artifact는 삭제하지 않았다. 향후 별도의 `쇼츠 분석` 플러그인
  또는 선택형 시청자 반응 분석 기능으로 재사용할 수 있다.
- 특정 레퍼런스 영상의 제작 공식을 조사 주제 생성에 강하게 반영하지 않는다. 영상 공식은
  주제를 고른 뒤 영상 후보와 스토리보드를 만드는 단계에서 사용하는 방향으로 정리했다.

### 결과 중심 UI

- 운영 프로필을 선택하면 조사 실행 기록이 아니라 해당 프로필의 조사 주제가 최신순으로
  바로 보인다.
- 각 주제에는 좁힌 키워드, 조사 시각, 조사 ID, 시장 근거 수와 조사 상세 진입점을 표시한다.
- `주제 추가 생성`은 기존 조사 하나를 선택해 그 저장 근거로 더 만들거나 새 조사를 시작한다.
  여러 조사를 합치는 기능은 넣지 않았다.
- 한 번의 주제 종합은 정확히 8개의 서로 다른 주제를 요구하도록 계약을 변경했다.
- 영상 후보 화면도 생성 실행 목록보다 후보 카드 전체 내용을 먼저 보여준다.
- 추가 후보 생성은 기존 후보와의 중복을 함께 검사한다.
- 후보 생성과 조사 응답의 잘못된 근거 ID, 예상보다 적은 결과, provider projection 오류를
  복구하거나 안전하게 실패로 저장하는 경계를 보완했다.

## 스토리보드 UX와 데이터 구조

- 스토리보드는 더 이상 후보 프로젝트에 하나만 덮어쓰지 않는다.
- 후보 하나에 여러 스토리보드를 저장하고 최신 스토리보드 전체를 기본 화면에 표시한다.
- 이전 스토리보드는 상단 이력 메뉴에서 선택한다.
- 새 스토리보드를 만들 때마다 영상 모델과 제작 방식을 다시 선택할 수 있다.
- 한 의미 장면은 모델 최대 길이에 맞춰 여러 생성 영상 쇼트로 나뉠 수 있다.
- 스토리보드 첫 화면의 기술적인 생성 조건은 기본 콘텐츠보다 뒤로 이동했다.
- 좌측 단계 사이드바는 제거했다. 상단 breadcrumb는 운영 프로필명 → 조사 주제명 →
  영상 후보명처럼 실제 선택 계보를 표시한다.
- 프로젝트 보관함의 AI 숏폼 디렉터 결과에서 `상세`를 누르면 일반 모달이 아니라 해당
  스토리보드 경로로 이동한다.
- 화면 진입에 필요한 운영 프로필·주제·후보 context가 URL과 저장 데이터에서 복구되도록
  route guard와 archive deep link 경계를 추가했다.

## 내레이션과 타이밍

- 목표 영상 길이는 운영 프로필에서 숫자로 수정할 수 있다. 기본값은 30초다.
- 스토리보드의 장면별 내레이션을 Clipper TTS로 합성한다.
- 계획 시간을 맞추기 위해 TTS를 몰래 빠르게 만들지 않는다. 실제 TTS 길이에 영상 타임라인과
  컷 길이를 맞춘다.
- TTS 재생 시간이 원래 목표보다 길면 전체 영상 길이도 실제 내레이션 길이만큼 늘어난다.
- 첫 장면에서 후보 hook을 붙인 뒤 비슷한 문장을 다시 생성하던 중복을 제거했다.
  문장부호 차이만 있는 hook도 중복으로 판정한다.
- 장면 내레이션에는 화면 연출·카메라·효과음 지시를 섞지 않고 실제로 들려줄 문장만 둔다.

## 생성형 영상 모델과 제작 방식

사용자에게 다음 모델을 선택지로 노출했다.

- `Gemini Omni`
  - 장면 쇼트 최대 10초
  - 720×1280, 9:16
- `Seedance 2.0`
  - fal.ai 공급자
  - 장면 쇼트 최대 15초
  - 720×1280, 9:16
- `Veo 3.1 Lite Generate`
  - 장면 쇼트 최대 8초
  - 지원 길이로 provider 요청을 반올림하되 계획 타임라인은 보존
- `Veo 3.1 Fast Generate`
  - 장면 쇼트 최대 8초
  - Lite와 같은 스토리보드 길이 경계를 사용

두 제작 방식도 유지했다.

- `Clipper 템플릿 방식`
  - 생성 영상은 화면 소재를 담당한다.
  - 음성은 Clipper TTS, 정확한 대사 자막과 메인 타이틀은 Clipper 템플릿이 담당한다.
  - 생성 영상의 source audio에 들어 있는 ambient sound effect는 최종 믹스에 포함할 수 있다.
- `AI 통합 제작 방식`
  - 공급자가 영상·음성·장면 내 텍스트를 함께 만들 수 있다.
  - Clipper TTS·자막·타이틀·BGM을 중복 합성하지 않는다.

Veo는 장면 안의 글자를 안정적으로 만들지 못하는 실제 결과를 반영해 text-free 생성 정책을
사용한다. Veo 프롬프트는 글자·숫자·로고·UI 문구·자막을 요청하지 않고, 장면 의미를
구체적인 피사체·행동·공간·카메라 진행으로 표현한다.

## provider 작업 복구와 로컬 저장

- Gemini Omni, Veo, Seedance 작업을 Web API에서 제출하고 상태와 결과를 조회한다.
- Web API 재시작 뒤에도 원격 provider job 식별자와 요청 정보를 잃지 않도록 영상 작업을
  PostgreSQL에 영속화했다.
- provider 결과는 S3를 도입하지 않고 인증된 Web API stream으로 Desktop에 전달한다.
- Desktop은 결과를 `CLIPPER_DATA_DIR` 아래 프로젝트 자산으로 영구 저장한다.
- 다운로드 중단, 같은 provider 결과 재다운로드, 파일 검증 실패와 provider 재생성을
  구분한다. 파일 검증 재시도만으로 새 유료 provider 작업을 만들지 않는다.
- provider HTTP 상태, 안전한 오류 코드와 정제된 메시지를 저장해 앱 재시작 뒤에도 컷의
  실패 이유를 표시할 수 있게 했다.
- 생성 결과 MP4는 해상도·길이·오디오 정책을 검증한 뒤 원자적으로 로컬 파일로 승격한다.

## 기존 Clipper 렌더 파이프라인 수렴

- AI 숏폼 디렉터 전용으로 별도의 최종 합성기를 유지하지 않고 기존
  `ShortformProjectService`와 Clipper 작업 큐를 사용한다.
- 최종 렌더 요청은 큐에 들어가므로 페이지를 떠나도 서버 작업이 계속된다.
- 상태 전달은 기존 큐 이벤트 경계를 재사용하며 1초 polling을 새로 추가하지 않는다.
- 완료된 결과는 프로젝트 보관함의 `AI 숏폼 디렉터` 분류에 나타난다.
- AI 숏폼 디렉터 상세 화면에서도 현재 스토리보드의 렌더 이력과 결과를 확인한다.
- 재렌더는 이전 최종 영상을 덮어쓰지 않고 버전으로 누적한다.
- 새 스토리보드에는 이전 스토리보드의 최종 영상 상태가 섞이지 않는다.

### Full 기본 템플릿

- archive 브랜치의 첫 번째 레거시 template family에서 Full 비율 템플릿과 gradient,
  thumbnail, font, 크기·색·위치 데이터를 가져왔다.
- 기존 사용자 템플릿은 여전히 템플릿 하나에 비율 하나만 가진다.
- Full 템플릿은 AI 숏폼 디렉터 영상 제작을 위한 읽기 전용 시스템 preset으로 예외 제공한다.
- 템플릿 페이지에서도 `Clipper 기본 Full 템플릿`을 실제 데이터와 미리보기 자산으로
  확인할 수 있다.
- AI 숏폼 디렉터의 Clipper 템플릿 방식은 기존 렌더 경계로 메인 타이틀 1·2줄, 대사 자막,
  TTS, source effect를 전달한다.

## Nano Banana 구현 상태

### Task 1 — 완료

`Generated-media config and backward-compatible project persistence`

- `generated-video`와 `generated-image`를 구분하는 strict union을 추가했다.
- 새 프로젝트는 `generatedMediaProductionConfig`를 저장한다.
- 기존 `aiVideoProductionConfig` 프로젝트는 저장 JSON을 바꾸지 않고 읽을 때 영상 branch로
  변환한다.
- Nano Banana 2는 `clipper-template`만 허용하며 다른 조합은 사전 단계에서 거부한다.
- 이미지·영상 설정은 서로 다른 approval ID를 만든다.
- 집중 검증: 43/43 통과, 독립 검토 CLEAN.

### Task 2 — 완료

`Multi-image storyboard contract, prompt, compiler, and TTS alignment`

- scene media decision에 조건부 `imageBriefs` 계약을 추가했다.
- 의미 장면별로 하나 이상의 이미지 프롬프트를 만들고 전체 이미지 수 범위를 검증한다.
- 30초·5장면 fixture는 10~12개를 허용한다.
- image shot narration range는 대사 전체를 빈틈과 중복 없이 나눈다.
- TTS 재정렬 뒤에도 승인된 이미지 쇼트 ID와 개수를 유지한다.
- 전역 motion preset 순서를 고정했다.
- 스토리보드 생성만으로 이미지 provider job을 만들지 않는다.
- 집중 검증: Web 47/47, Desktop 58/58 통과, 독립 검토 CLEAN.

### Task 3 — 완료

`Web API Nano Banana capability and raw Gemini transport`

- Web API capability catalog에 Nano Banana 2를 추가했다.
- 기존 `GoogleAiCredentialService`로 키를 해석한다.
- Gemini Developer API의 `/v1beta/interactions` raw REST transport를 추가했다.
- 요청은 `aspect_ratio: "1:1"`, `image_size: "1K"`, `store:false`로 고정한다.
- PNG/JPEG/WebP만 허용하고 base64, MIME, 32 MiB 경계, provider 오류, timeout과 usage를
  안전하게 파싱한다.
- 집중 검증: 19/19, TypeScript와 ESLint 통과, 독립 검토 CLEAN.

### Task 4 — 완료

`Persisted Web AI image job, result blob, ACK, migration, and OpenAPI`

- `shortform_director_ai_image_jobs` PostgreSQL 테이블과 TypeORM repository를 추가했다.
- `(owner_subject_id, idempotency_key)`를 unique 경계로 사용한다.
- 원본 결과 bytes는 `bytea result_blob`에 저장하고 일반 metadata 조회에서는
  `select:false`로 제외한다.
- Desktop 저장 완료 전까지 결과를 유지하고 ACK 뒤 정리할 수 있다.
- 5분 동안 상태를 확정하지 못하면 unknown 경계를 사용하고, ACK되지 않은 결과는 7일
  만료 정책을 가진다.
- owner-scoped metadata/result route, migration, datasource 등록과 OpenAPI를 추가했다.
- 로컬 PostgreSQL integration을 포함한 집중 검증: 64/64 통과, 독립 검토 CLEAN.

운영 중 처음 Web API를 실행했을 때 migration이 적용되지 않아
`relation "shortform_director_ai_image_jobs" does not exist`로 부팅이 실패했다. 이후
`CreateShortformDirectorAiImageJobs1786100000000` migration을 로컬 user DB에 적용했고,
pending migration 없음과 Web API 정상 부팅을 확인했다.

### Task 5 — 완료

`Desktop image job domain and exact local image validation`

- Desktop용 strict `AiImageJobV1` 상태·전이·retry lineage를 추가했다.
- 기존 영상 작업과 독립된 `aiImageJobs` 배열을 production state에 보존한다.
- 결과 이미지는 비어 있지 않고 최대 32 MiB여야 한다.
- PNG, JPEG, WebP container를 dependency 없이 bounded parsing하고 MIME/signature와
  정확한 1024×1024 크기를 확인한다.
- 저장 경로는 다음과 같다.

```text
shortform-director/projects/<projectId>/assets/generated-images/
  <shotId>/<revisionId>.<ext>
```

- `.part` streaming, SHA-256, revision lock, stale lock 복구, atomic rename과 overwrite
  방지를 구현했다.
- 집중 검증: 최종 59/59 통과, 독립 검토 CLEAN.
