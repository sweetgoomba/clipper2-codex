## 실제 Vira DB 조회를 실행하지 않은 이유

사용자 승인 gate까지 갔지만 현재 로컬 환경에는 `DATABASE_URL`이 없었다. 이후 사용자가
더 근본적인 전제를 바로잡았다.

- Vira는 아직 완성된 서비스가 아니다.
- 현재 DB는 폭넓은 카테고리의 대표 corpus가 아니라 소량의 테스트 데이터다.
- 고정 주제의 row 부재는 시장 신호 부재가 아니라 수집 coverage 부재다.

따라서 기존 DB를 조회해도 `V` 입력 축의 품질을 판단할 수 없고 사례 간 비교를 왜곡한다.
실제 Vira DB read는 취소했다. offline SQL과 normalizer는 통합 계약·보안·원자성 fixture로만
보존한다.

## 다음 설계에서 고려할 외부 제약

- Data API `videoDuration=short`는 실제 Shorts가 아니라 4분 미만 영상이다.
- 실제 Shorts는 최대 3분이며 정사각형 또는 세로 화면비 판별이 추가로 필요하다.
- 2026년 공식 quota 문서와 Vira의 기존 `search=100 units` bookkeeping이 다르다.
- 비인가 API data의 30일 refresh/delete와 파생 지표 정책을 반영해야 한다.
- yt-dlp는 PO Token, rate limit, cookie·계정 제한 때문에 주 discovery provider로
  부적합하다.
- 최신 검색어는 `V` 시장 신호에는 필요하지만 당일 급등어보다 최근 30일 coverage와 채널
  다양성이 충분한 주제가 중요하다.

공식 문서 링크와 접근별 trade-off는 위 corpus options 문서에 기록했다.
