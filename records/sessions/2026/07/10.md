## Auth/Session/License/Credit/Provider Integration

`feature/auth-session-license-provider-20260707` 작업은 dev merge용 브랜치에서 정리 후 각 repo `dev`에 반영됐다.

주요 완료 상태:

- desktop OAuth는 one-time code exchange + server-side session + refresh rotation 구조로 동작한다.
- user access JWT와 operator/admin JWT는 분리됐다.
- user JWT는 비대칭키 기반이고, desktop local NestJS는 public key로 1차 검증한다.
- legacy `JWT_SECRET` user/operator fallback은 제거됐다.
- Electron은 token bundle을 안전 저장하고, access 만료/401 흐름에서 refresh한다.
- web client도 stale session 401/403에서 refresh 실패 시 로그인 화면으로 이동한다.
- operator/admin session table과 refresh rotation 기본 흐름이 구현됐다.
- `/operators` 접근은 super-admin 계정만 허용하도록 제한했다.
- admin nav profile action에 "로그인 세션" 진입점을 추가했다.
- user license/current summary와 credit ledger는 desktop Settings, web client, web admin member detail에 연결됐다.
- operation policy admin은 `크레딧 정책` 페이지로 제공된다.
- Highlight/Shortform/Variation billing quote/start/refund 흐름이 구현됐다.
- OpenAI runtime은 DB credential만 사용한다.
- provider usage log/admin page는 보류로 되돌렸고, provider call 자체를 사용자 과금 단위로 보지 않는 정책을 유지한다.

## Environment And Secret Boundary

이번 세션에서 정리한 runtime/env 원칙:

- provider key는 desktop/local NestJS/Python plugin에 넣지 않는다.
- OpenAI/Naver runtime key는 web_api DB credential 경계를 따른다.
- user JWT private key는 web_api만 가진다.
- user JWT public key는 secret이 아니며 packaged app resource로 포함 가능하다.
- desktop local NestJS packaged mode는 packaged resource의 user JWT public key를 사용한다.
- devapp/local 실행에서는 repo별 ignored env 파일로 public key path/base URL/mode만 관리한다.
- HF token 계열은 현재 desktop env 문서/파일에서 제거하는 방향으로 정리했다.
- 실제 secret 파일 경로, 값, token 내용은 문서화하지 않는다.
