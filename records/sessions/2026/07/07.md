## Key Decisions

### Auth/session

- Google OAuth 단독 로그인 유지
- 앱 메인 화면 진입 전 로그인 필요
- short-lived JWT access token + long-lived opaque refresh token + server-side session table 채택
- refresh token rotation 사용
- desktop OAuth callback은 token URL 전달을 폐기하고 one-time code exchange로 변경
- access JWT는 RS256
- web_api만 private key로 signing
- local NestJS/web_api는 public key로 verification
- MVP에서 local NestJS public key는 앱 resource PEM으로 포함
- refresh token 원문은 클라이언트에만 저장하고 서버 DB에는 hash만 저장
- Electron은 token bundle을 safeStorage로 저장
- user JWT와 operator JWT는 분리
- logout blocklist 중심 모델은 비채택

### Local NestJS

- local NestJS는 최종 auth truth가 아니다.
- local NestJS JWT 검증은 localhost 이상 요청을 초기에 거르는 1차 필터다.
- 최종 session revoke/license/credit/operation 판단은 web_api가 한다.
- refresh token과 provider key는 local NestJS/Python plugin에 넘기지 않는다.

### License/credit

- 한 user의 active license는 최대 1개
- active license가 있으면 새 승인 license는 queued
- credit 소진 시 active license는 active_depleted
- queued license는 자동 active 되지 않음
- 사용자가 "다음 이용권 시작"을 눌러야 queued license가 active
- 기존 credit/기간 흡수/병합 없음
- MVP에서 credit top-up은 만들지 않음
- `charge_then_refund`: 시작 시 차감, 성공 시 유지, 실패 시 refund ledger
- stale running operation은 MVP에서 자동 환불보다 admin review가 안전

### Operation policy

- 크레딧 차감 단위는 provider API 호출이 아니라 사용자-facing 제품 operation
- `operation_key`를 안정 식별자로 사용. 예: `dance_highlight.extract`
- DB 내부 id는 코드에서 직접 참조하지 않음
- `operation_id`, `execution_mode`, `enabled` 기반 설계는 MVP에서 제거
- `OperationBillingStrategy`, `OperationRunStatus`, `CreditLedgerType`, `CreditLedgerReason`, `ProviderScope` enum을 사용
- `OPERATION_DEFINITIONS` code registry + 명시적 seed/upsert로 `operation_policies` row 생성
- seed는 `ON CONFLICT (operation_key) DO NOTHING`
- 관리자 수정값을 배포 seed가 덮어쓰지 않음
- 관리자 CRUD는 Read + 제한적 Update만 허용
- Create/Delete는 일반 관리자 CRUD로 열지 않음

### Plugin store

- MVP에서 플랜별 플러그인 노출/잠금/상위 플랜 유도 정책은 제외
- MVP에서 플러그인 스토어 목록은 web_api DB가 아니라 로컬 앱 manifest/catalog/Angular visible list 기준 유지
- web_api는 플러그인 표시 여부가 아니라 실제 제품 실행 허용 여부를 판단

### Provider credential

- provider key는 설치형 앱에 넣지 않음
- provider credential은 DB 암호화 저장 중심으로 통일
- OpenAI env fallback은 migration 기간에만 허용하고 안정화 후 제거
- provider endpoint는 user JWT + operationRunId 소유권 + provider scope enum 확인
- provider_usage는 audit/rotation 분석용이며 사용자 credit 추가 차감 단위가 아님

Phase 4 구현 내용:

- local NestJS `CLIPPER_AUTH_MODE=jwt`에서 user access JWT를 RS256 public key로 1차 검증한다.
- local verifier는 `iss=clipper-web-api`, `aud=clipper-user`, `typ=user`, `sub`, `sid`, `exp` claim과 signature를 확인한다.
- public key는 inline PEM 또는 resource path에서 읽고 캐시한다. public key는 secret이 아니지만 실제 private key/env 값은 다루지 않았다.
- local `AuthContext`에 `sessionId`와 `accessToken`을 보존해 web_api relay에 사용할 수 있게 했다.
- `WebApiClient.postJson()`은 호출별 bearer token 전달을 지원한다.
- Shortform web_api script generator는 현재 user bearer token을 `/llm/script` 호출에 relay한다.
- Angular HTTP interceptor는 local NestJS `/v1/*` 요청에만 bearer token을 붙이고, web_api auth/`/me` 요청은 건드리지 않는다.
- Angular WebSocket은 token을 URL query가 아니라 `Sec-WebSocket-Protocol`로 전달한다.
- Electron local NestJS process env에 packaged public key resource path 기본값을 주입한다. `CLIPPER_AUTH_MODE=jwt`는 자동 강제하지 않는다.

- `web/clipper_web_api`

  - `authTokenInterceptor`가 일반 API 401/403을 받으면 `/auth/refresh`를 interceptor 우회 HTTP client로 1회 호출하고, 성공하면 원 요청을 새 access token으로 재시도한다.
  - refresh 실패 또는 retry 후 인증 실패 시 local token/user state를 지우고 `/login?returnUrl=<현재 app 경로>`로 이동한다.
  - `/me`, `/auth/refresh`, `/auth/logout`, handoff preview/exchange는 각 caller가 직접 처리하도록 전역 redirect 대상에서 제외했다.
