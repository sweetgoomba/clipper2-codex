## 실제 E2E 결과

- 사용자가 실제 등록 credential과 앱 화면의 비용 승인을 사용해 다음 흐름을 끝까지 실행했다.
  - 운영 프로필
  - 최신 조사
  - Shorts 선택과 레퍼런스 정밀 분석
  - 조사 주제
  - 최소 10개 영상 후보
  - 후보 선택
  - 상세 영상 기획
  - 장면 소재 준비
  - 최종 렌더
- 코딩 프로필과 엔터테인먼트 프로필에서 각각 최종 영상을 만들었다.
- 조사 근거, 대본, 영상에서 전달할 내용은 이전보다 좋아졌지만 장면 시각 구성 품질 문제가
  확인됐다.

## 확인된 시각 문제와 원인

1. 코딩 영상은 대부분 도식 장면이었고, 내부 매체 선택 이유가 도식의 화면 문구로 노출됐다.
2. 엔터테인먼트 영상은 다수 장면이 빈 배경처럼 보였다.
3. 실제 저장 결과를 확인하니 코딩 영상은 5개 장면에 외부 시각 소재가 1개뿐이었고,
   엔터테인먼트 영상은 외부 시각 소재가 0개였다.
4. Naver 이미지 검색 실패가 아니라 장면 선택 LLM이 `programmatic-diagram` 또는
   `kinetic-typography`를 장면의 유일한 매체로 선택해 이미지 검색 자체가 호출되지 않은
   것이 원인이었다.
5. `decision.rationale`이 도식 layer의 headline/content로 컴파일돼 내부 설명이 최종
   영상에 노출됐다.
6. 기존 도식 variant들이 최종 렌더에서 모두 같은 3단계 카드로 축약됐다.

## 확정한 보완 설계

- 신규 장면 결정 계약은 단일 `medium` 대신 다음 두 축을 사용한다.
  - `baseMedium`: official source, image search, generated image, generated video
  - `overlayMode`: none, kinetic typography, programmatic diagram
- 모든 신규 장면은 외부 기본 시각 소재를 정확히 하나 갖는다.
- 도식과 kinetic typography는 기본 시각 소재를 대체하지 않고 그 위에 올라가는 overlay다.
- 내부 `rationale`은 감사 기록에만 남기고 시청자에게 보이는 문자열로 사용하지 않는다.
- 도식은 비교·순서·루프·수치 4개 의미별 레이아웃을 사용한다.
- 도식은 전체 장면의 `ceil(sceneCount / 3)`개 이하이고 연속 장면에 배치할 수 없다.
- 기존 저장 프로젝트의 3단계 카드 계약은 호환을 위해 유지한다.

## 장면 미디어 준비 실제 실패와 보완

새 앱에서 만든 프로젝트
`shortform_director_project_2e526ca7-b590-4934-901e-273845c1e7de`의 소재 준비를 실제
실행했으며, 6개 source layer가 모두 retryable failure가 됐다.

확인한 원인:

1. source layer의 `content`에 실제 검색 설명이 아니라
   `production-source-naver-...` 내부 ID가 저장됐다.
2. 자동 준비가 운영 프로필 문맥과 내부 ID를 합친 뒤 뉴스 도메인 `site:` 조건을
   덧붙였다.
3. 여러 내부 ID가 들어간 검색어는 Web API의 100자 제한을 넘어 HTTP 400이 됐다.
4. 짧은 검색어는 요청은 성공했지만 내부 ID 검색이라 결과가 없었다.
5. 뉴스 본문 이미지가 별도 CDN 도메인에 있는 정상적인 경우도 기사 도메인과 다르다는
   이유로 제거됐다.

수정:

- 신규 VideoPlan source layer에는 내부 ID 대신 실제 출처 제목을 저장한다.
- source fallback은 실제 출처 제목과 안전한 장면 문맥으로 검색한다.
- Web API 요청 전체를 100자 이내로 제한하고 내부 production source ID는 검색어에서
  제거한다.
- 검색 자체는 기사 도메인으로 제한하되, 그 기사의 실제 이미지가 CDN 호스트에 있어도
  후보로 허용한다.
- 검색으로 받은 이미지는 기존과 동일하게 권리 확인 전에는 렌더할 수 없다.
- 기존 실패 acquisition은 retryable 상태이므로 새 앱에서 같은 프로젝트의 소재 준비를
  다시 실행할 수 있다. VideoPlan을 다시 만들 필요는 없다.
