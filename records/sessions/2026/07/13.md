## Packaged Local API JWT Public Key

`npm run build:app:mac:arm64:local-api`는 deployment public key가 아니라 local-api 전용 public key source를 선택하도록 수정했다.

- local-api source: `resources/auth/user-jwt-public.local.pem`
- 일반 package source: `resources/auth/user-jwt-public.pem`
- electron-builder에는 선택된 파일을 `build/generated/auth/user-jwt-public.pem`이라는 안정적인 package 내부 이름으로 전달
- key 내용은 출력·문서화하지 않고 source/output 파일 동일성만 검증

## yt-dlp EJS Runtime

첫 packaged 검증에서 다음 경고가 재현됐다.

```text
No supported JavaScript runtime could be found
```

원인:

1. 기존 `clipper_electron` 의존성은 `electron ^33.1.0`, lockfile 실제 버전은 `33.4.11`이었다.
2. 해당 Electron 실행 파일의 내장 Node.js는 `20.18.3`이었다.
3. 패키지 앱은 yt-dlp `--js-runtimes`에 개발 셸의 `.nvmrc` Node.js가 아니라 Electron `process.execPath`를 전달한다.
4. 세 desktop repo의 `.nvmrc`는 모두 Node.js 22지만 Electron 내장 Node.js와는 별도 런타임이다.
5. 기존 관리 venv에는 plain `yt-dlp`만 설치되어 `yt-dlp-ejs`가 포함되지 않았다.

수정:

- Electron을 exact `35.7.0`으로 올림
- 설치된 Electron 실행 파일의 내장 Node.js `22.16.0` 확인
- 관리 venv install target을 `yt-dlp[default]>=2025.12.8`로 변경
- `.clipper-ytdlp-ejs-v1` marker가 없는 기존 venv는 다음 패키지 앱 실행에서 한 번 보강
- package build script 자체는 dependency install을 하지 않으므로 새 checkout/runner는 `npm ci` 후 package build 필요

검증 구성:

```text
web/clipper_web_api: npm run start:dev
desktop/clipper_electron: npm run build:app:mac:arm64:local-api
Clipper Studio packaged app: 개발자 모드 > YouTube 인증 디버그
```

실측 결과:

1. 전체 초기화 후 기본 공개 URL을 `인증 없음 + 메타데이터 확인`으로 실행해 성공했다.
2. raw metadata는 4K/24fps/SDR, AV1 video, Opus audio와 yt-dlp `2026.07.04` 정보를 반환했다. `_filename`은 예상 파일명이며 `--skip-download` 때문에 metadata 단계에서는 파일이 생성되지 않는다.
3. 같은 URL을 `인증 없음 + 실제 다운로드`로 실행해 종료 코드 `0`, 약 `3.9초`, 약 `97.6 MB`로 성공했다. 임시 결과 파일은 크기 확인 후 정리된다.
4. 회원 전용 영상 ID `k_TGyt6E29w`는 `인증 없음 + 메타데이터 확인`에서 종료 코드 `1`과 `Join this channel to get access to members-only content` 오류를 반환했다.
5. 아동용(`Made for Kids`) 공개 영상은 metadata/download 모두 성공했다. 이는 접근 제한이 아니라 콘텐츠 분류이므로 기대 동작이다.

해석:

- 기본 공개 URL은 현재 환경에서 Google 로그인 필요 흐름을 재현하지 않는다.
- 회원 전용 URL은 제한 실패를 재현하지만 성공 검증에는 해당 채널 멤버 계정이 필요하다.
- 외부 브라우저 열기만으로 앱 쿠키가 만들어지지 않는다. 로그인 후 선택한 브라우저의 cookie strategy를 별도로 실행해야 한다.
- Electron 내장 로그인은 관리 쿠키 파일 전략과 함께 검증해야 한다.
- `Made for Kids`와 `Age-restricted`는 다른 상태다.

## Confirmed Gap

현재 `authRequired` 정규식은 anti-bot, sign-in confirmation, cookies 안내, 연령 확인 문구를 감지하지만 다음 회원 전용 문구를 분류하지 않는다.

```text
Join this channel
members-only
member-only
```

따라서 회원 전용 URL은 실패와 stderr는 정확히 표시하지만 `로그인 + 채널 멤버십 필요` 상태로 구조화되지 않는다. 성공 metadata JSON의 `availability`와 `age_limit`도 현재 raw stdout에만 있고 UI 요약 필드에는 없다.

후속 방향:

- `availability`, `age_limit`, format count를 metadata 결과에 구조화
- `auth_required`, `members_only`, `age_verification`, `bot_verification`, `browser_cookie_error`처럼 제한 원인을 구분
- 단순 boolean `authRequired`는 호환을 위해 유지하더라도 회원 전용은 별도 entitlement 설명 표시
- private/member/premium 오류 문구 unit test 추가
