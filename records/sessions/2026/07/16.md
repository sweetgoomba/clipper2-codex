- derivation은 `planningContextId`, `contentStrategyId`, `matrixEntryId`, `hypothesisId`를 desktop Nest가 부여한다.

- Beat의 narration에서 narration cue를 결정적으로 조립한다.

### grounding과 copy 품질 규칙

- Beat는 선택 hypothesis의 evidence/claim id만 grounding할 수 있다.
- 전체 Beat 합집합은 선택 hypothesis의 모든 참조를 최소 한 번 포함해야 한다.
- 첫 scene은 hook이고 선택 hook을 narration 또는 text에 포함해야 한다.
- 마지막 scene은 cta이고 programmatic CTA layer에 선택 CTA를 포함해야 한다.
- prohibited expression은 strategy copy와 plan intent/narration/layer content에서 거부한다.
- 정규화 결과가 같은 ContentStrategy hook은 중복으로 거부한다.
- 전략 재생성 성공 시 이전 strategy에서 파생된 plan은 새 empty plan으로 무효화한다.

```text
  → AssetRequirement
     ├─ programmatic → resolved
```

## 열 번째 vertical slice — Supertonic cue-level 실측 타이밍 정렬

현재 TTS 구현을 다시 감사한 결과 Python `tts_supertonic`은 WAV 경로만 반환하고, Nest `SupertonicShortformTtsProvider`가 파일 전체 duration과 checksum을 측정한다. word/sentence timestamp는 현재 계약에 없다.

따라서 이번 단계는 단어 정렬이 아니라 narration cue 1개와 측정된 WAV 1개를 연결하는 순수 domain alignment로 구현했다.

```text
estimated VideoPlan 45,000ms
  + cue별 artifact id / checksum
  + narration text fingerprint
  + measured WAV duration
                ↓ exact-set validation
Scene → Beat → Shot → Layer reflow
                ↓
tts_aligned VideoPlan 41,200ms
```

계약:

- input schema: `video-plan-tts-alignment-input.v1`
- output metadata: `tts-timing-alignment.v1`

- 파일 경로/URL/provider credential은 입력과 저장 metadata에 없음
- missing, duplicate, unknown cue, stale text, unsafe artifact id, invalid checksum/duration은 all-or-nothing 실패
- 실패 fallback은 원본 estimated plan을 변경하지 않음
- 이미 aligned인 plan과 stale alignment metadata는 재정렬하지 않음

재배치:

- Beat와 narration cue duration은 측정 WAV 길이
- Scene과 plan duration은 aligned Beat 합
- Shot은 기존 duration 비율과 최소 250ms를 보존
- Layer는 Shot 안의 상대 시작/끝 비율과 최소 1ms를 보존
- id/order/copy/grounding/asset strategy는 불변

- 7개 cue: `4600 + 6400 + 6900 + 7200 + 5000 + 4900 + 6200 = 41200ms`

## 열다섯 번째 vertical slice — Render input 재검증과 immutable staging

RenderRecipe compile preview와 실제 renderer 사이에 파일 검증·고정 경계를 추가했다.

```text
current Director project
  → strict RenderRecipe compile

  → narration WAV 재검증

  → temporary copy + copied checksum 검증
  → immutable ready stage rename
  → future renderer adapter
```

bind snapshot:

- 새로 연결하는 project artifact는 `project-artifact-snapshot.v1`의 artifact kind, media type, size와 SHA-256 checksum을 AssetRef에 저장한다.

## 열여섯 번째 vertical slice — Private renderer adapter와 operation foundation

renderer/provider를 정하지 않은 상태에서 immutable stage 이후의 내부 실행 계약을 고정했다.

```text
immutable render-input stage
  ├─ public-safe stage metadata
  ├─ exact RenderRecipe in private manifest
  └─ checksum-verified staged files
              ↓

  ├─ recipe

  ├─ explicit id / claim / availability 검증
  └─ production adapter 0개
              ↓
future JobsService executor
  └─ opaque stage/recipe checksum reference only
```

stage와 execution bundle:

- private `stage.json`에 exact `render-recipe.v1`을 저장한다.
- canonical recipe checksum이 public stage의 `recipeChecksum`과 다르면 hydration을 거부한다.

- bundle metadata에는 original project path, source path, URL이 없으며 renderer는 `sourceId`로만 staged copy를 해소한다.
- source 원본을 stage 이후 변경해도 resolver는 immutable copy를 반환한다.
- unknown source id, recipe 변조, staged bytes 변조, input set 변조를 거부한다.
- recipe 없는 기존 private stage는 execution bundle로 읽지 않는다.

adapter registry:

- `ShortformDirectorRendererAdapter`는 execution bundle과 operation id/AbortSignal/progress callback만 받는다.
- adapter는 Director project repository, original ProjectManifest와 original source path를 받지 않는다.
- explicit adapter id는 존재, recipe claim, availability를 모두 검증한다.
- id가 없으면 등록 순서에서 claim 가능하고 available인 첫 adapter를 고른다.
- production module의 Director adapter token은 빈 배열이다.
- 기존 generic `VideoRenderProviderRegistry`와 provider는 자동 포함하지 않았다.

operation/retention:

- future persisted job params용 `shortform-director-render-job-reference.v1`은 project/stage/recipe id, recipe checksum, adapter id만 가진다.
- retry는 같은 immutable reference를 복사해 새 JobsService job과 `retryOf`를 만들 수 있다.
- JobsService status retention class는 다음으로 고정했다.
  - waiting/starting/running → `active-job`
  - failed/cancelled → `retry-source`
  - completed → `completed-source`
- cleanup duration, stage 삭제 worker, 별도 queue 저장소를 추가하지 않았다.

Vite development server는 실행하지 않고 trusted repository source를 offline build하는 데만 사용한다. 렌더 asset은 method/Host/random token/source id를 검증하는 별도 loopback server가 제공하고 browser outbound network를 차단한다. upstream compatibility가 열리면 patched Vite로 올려야 한다.

### Headless application renderer

추가한 source 경계:

- isolated package
  - `src/project.ts`, Director scene, frame bridge, render client/state
  - RenderRecipe projection
  - static bundle cache
  - process-tree RSS monitor
  - actual worker와 representative benchmark
  - minimal editor fixture
- Nest application
  - `ShortformDirectorMotionCanvasWorker`
  - `ShortformDirectorMotionCanvasRendererAdapter`
  - registry order `[motionCanvas, remotion]`
- tests
  - license/projection/cache/RSS PoC
  - adapter success/cancel/registry isolation
  - opt-in actual H.264/AAC integration

실행 흐름:

```text
exact execution bundle
  → staged input size/checksum 재검증
  → Motion Canvas source revision SHA-256
  → static bundle cache created | reused
  → strict token-protected 127.0.0.1 server
  → Puppeteer/installed Chrome
  → frame별 PNG stream
  → FFmpeg image2pipe + aligned narration mix
  → MP4/H.264/AAC
  → FFprobe contract
  → existing atomic Director output storage
```

- bundle source fingerprint는 runtime source/config/package manifests의 canonical hash다.
- cache miss는 temporary build 뒤 검증하고 fingerprint directory로 원자 승격한다.
- 같은 revision은 Vite를 다시 실행하지 않고 static bundle을 재사용한다.
- browser는 loopback origin 외 request를 abort한다.
- staged image/video는 exact source token과 byte-range를 사용하고 TTS track은 frame timing에 맞춰 delay/mix한다.
- progress, AbortSignal, SIGTERM 뒤 bounded SIGKILL fallback, sanitized failure를 기존 adapter 계약에 연결했다.
- 취소 시 output workspace를 폐기하고 finalize하지 않는 회귀를 추가했다.
