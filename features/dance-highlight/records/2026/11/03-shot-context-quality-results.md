## 구현한 증거 계약

이름 판정, 메인 역할, 단체 출력 자격을 분리했다. 새 규칙은 특정 영상 시간이나 멤버 이름을 하드코딩하지 않는다.

1. **전경 유지:** 원래 확인된 같은 이름의 양쪽 근거와 현재 얼굴·몸통 우위, 경쟁자 관측, 몸 대응, 컷·교대 보호가 모두 필요하다. 정확히 중앙선을 몸통이 덮는 조건을 숫자로 넓히는 방식은 쓰지 않았다. 원래 group run 전체가 전경 근거를 만족할 때만 group 출력을 해제한다.
2. **샷별 이름 복원:** 최종 같은 이름 양쪽 구간은 후보만 지목한다. 각 샷의 원래 body-owned 얼굴이 신원을 따로 확립하며, 컷을 가로질러 몸 track으로 이름을 전달하지 않는다. 새 이름 시간 전체가 현재 main 역할과 같은 샷의 유효한 얼굴 지지를 가져야 한다. 원래 primary, accepted joint, 직접 secondary reference 근거를 쓰되, window/video 재복원 결과를 새 seed로 쓰지 않는다.
3. **역할 유지:** 이미 양쪽에서 확립된 같은 메인을 현재 얼굴·몸통 구도와 모든 경쟁자 관측으로 보존한다. 전 표본에서 원래 확정 이름과 body-owned 직접 joint 결과가 일치해야 한다. 원래 source cut, handoff, camera episode, identity 경계를 넘지 않는다. 기존 context 루프가 끝난 뒤 frozen 입력만 읽으므로 복원된 구간이 다른 복원의 앵커가 되지 않는다. 이 경로의 군무 출력은 보존한다.

샷별 추가 원본 검사는 영상당 **최대12개 경로·240개 source frame read 예약**으로 제한한다. 이는 디코더 내부 keyframe preroll을 포함한 벽시계 상한은 아니다. 한도 초과, 미관측 시간, 인물 교대, 얼굴 충돌이 있으면 미확인을 남긴다. 원래 확정 이름과 얼굴 gallery는 수정하지 않는다. 임의 최소/최대 클립 길이, 3초 제한, 모든 짧은 클립 흡수는 추가하지 않았다.

무거운 **SAM mask tracking·joint 재검증 호출은 계속 주석 상태**다. 이번 복원 경로에 새 ML 추론을 추가하지 않았다. 기존 저장 pose 대응과 필요한 짧은 원본 영상 검사는 사용한다. Person·공용 SDK·공유 얼굴 모델의 동작은 변경하지 않았다. Windows용 기존 가속 경로도 바꾸지 않았으며, 이번 실제 앱 측정은 Mac에서만 했다.

## 독립 검증에서 막은 오류

Astra xhigh 검증 세션과 구현 에이전트를 분리했다. 반례가 나오면 먼저 재현하고 수정한 뒤 원본 양성이 유지되는지 다시 확인했다.

- 기존 context가 군무의 일부를 먼저 복원한 뒤 나머지만 보고 전체 group을 지우는 문제: 원래 group 경계를 먼저 동결한다.
- handoff의 한 시점만 보아 관측 사이 교대를 놓치는 문제: `previous_time–time` 닫힌 구간과 복원 구간의 겹침을 검사한다.
- 새 source 시간이 있으나 sampled unknown row가 없는 샷을 named-only로 오인하는 문제: 실제 새 시간을 먼저 검사하고 관측이 없으면 0복원·0read로 보류한다. `.91/.95/.99` 경계 반례를 추가했다.
- 화면 가장자리의 큰 인물이 얼굴·몸통 관측을 잃으면 경쟁에서 빠지는 문제: 위치와 무관하게 신뢰 torso를 요구하며, 얼굴 없는/repeated 경쟁자는 더 작은 실측 torso·전체 bbox와 비클리핑 조건이 필요하다.
- 경로의 median에 의존하는 검사 실패를 더 큰 경로에 무조건 재사용하는 문제: 해당 실패는 정확히 같은 경로에만 캐시한다.
- 새 판정 근거의 `numpy.bool_` JSON 저장 문제: 기본 bool로 저장하고 일반 `json.dumps` 회귀를 추가했다.
