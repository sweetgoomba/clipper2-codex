## 이번에 구현한 구조

`performance_parts.py`를 최종 개인 클립 조립 지점으로 분리했다. 얼굴 인식이 뒷받침하는 입력 구간과, 화면 분류·교대·검증된 연속성으로 구성한 최종 공연 파트를 별도로 기록한다. 입력 신원 구간과 얼굴 관측은 동결하고, 교정된 출력이 다시 얼굴 근거가 되지 않게 했다. 원본 구간 투영 → 미확인 교대 분리 → 얼굴 경계 복원 → 기존 검증된 동명 병합 → 이름 경계 조정 순서는 보존한다. preparation 출력은 별도 경로로 유지한다.

이 추출 자체는 동작 보존 리팩토링이다. 같은 멤버의 6초 구간을 강제로 나누지 않으며 **3초 상한을 추가하지 않았다**. 반대로 양끝 이름이 같다는 이유로 관측 없는 공백 전체를 이름 붙이거나 짧은 클립을 일괄 병합하지 않는다. `performance_parts_v1` 진단에는 입력 구간, 최종 구간, 출처 구간 ID, 기존 조립 과정에서 새로 이름이 붙은 시간이 구분된다. 이 마지막 값에는 이전 버전부터 있던 복원이 포함되므로 이번 개선량으로 계산하면 안 된다.

## 실제로 바뀐 두 곳

- **ANT 146.613133–146.880067초:** 군무 구간인데 잠깐 홍은채 0.066733초와 미확인 0.2002초로 남던 부분을 기존 단체 구간에 연결했다. 최종 단체 구간은 146.613133–149.149초다. 짧은 미확인 두 조각이 사라졌다.
- **NEON 143.676867–144.077267초:** 실제 원경 군무가 관측 누락 때문에 미확인 두 조각으로 남아 있었다. 이를 연결하며 양쪽 단체도 142.4423–144.3442초 한 구간이 됐다. 미확인 두 개와 짧은 단체 한 개가 줄었다.

이 범위 밖의 분류 변화는 없다. MMN의 최종 구간·분류는 기준과 같다. 원본 얼굴 구간, pose 측정값, reference 선택·바이트·임베딩, 영상 SHA, 설정 SHA는 세 영상 모두 동일하다. 메인 판정 내용도 실행 시간과 최종 출력 번호 재배열을 제외하면 같다. 기존 사용자 피드백 14구간의 결과를 보존했다는 것은 **그 14구간을 모두 올바르게 고쳤다는 뜻이 아니다**.

원본 시각과 분류가 같은 421개 클립의 썸네일은 모두 동일했다. 변경된 3개 클립의 썸네일을 직접 확인했다. 구간별 변화와 파일 이름 재번호를 구분해 비교했다.

## 시간상 단체 판정의 제한과 이유

새 compact 군무 증거는 기존에 확정된 단체 구간과 관측상 이어질 때만 확장한다. 고립된 단체 조각을 새로 만들지 않는다. 지속되는 중앙 몸, 실제 편집 컷, 메인 교대, 카메라 전환 구간, 관측 누락은 보호한다. 화면이 잠깐 넓어졌다는 이유만으로 단체로 바꾸는 규칙은 아니다.

한 샘플 누락을 보완하는 경로는 기존 0.6초 이하 공백 조건 안에서 바로 앞뒤 관측만 쓴다. 이것은 **클립 길이 상한이 아니라 검증 가능한 관측 공백의 상한**이다. 실제 사람으로 검증된 몸이 최소 두 개 있고 각각 양끝에서 유일하게 대응해야 한다. 큰 전경 인물·중앙 몸·잘린 몸·누락된 자세는 보류한다. native 관측을 쓸 때에는 정확한 같은 프레임, 저장 group 박스와 같은 좌표, 실제 전신 관절 관측이 모두 필요하다. 불완전한 native 박스를 일반 박스로 대체하지 않는다.

NEON에서는 8608/8616 프레임의 실제 몸 두 개를 사용해 8612 프레임만 보완했다. 무대 조형물 박스 한 개는 사람 근거에서 제외했다. 이 처리에는 새 모델이나 SAM 추론이 없다. 이미 계산된 몸 관측의 대응을 읽는 것과 비싼 SAM 몸 추적을 다시 실행하는 것은 구분한다.

## 실패한 시도도 보존

첫 compact 제안은 여섯 범위에서 단체 후보를 넓혔다. 실제 앱 첫 실행에서 1초 미만 클립이 245 → 247개로 오히려 늘었고 MMN/NEON에 3~4프레임 미확인 조각이 생겼다. 미확인 시간이 줄었다는 이유로 채택하지 않았다.

고립된 compact 단체 구간을 막은 뒤에도 NEON의 한 샘플이 남았다. 여러 프레임의 일반 몸 박스를 모으던 초안은 조형물 박스를 새 전경 인물의 근거로 재사용하거나 pose 누락을 통과시키는 반례가 있었다. 실제 reliable-body 관측과 바로 양끝의 native/full 근거로 제한해 수정했다. 독립 검토의 양성 1개와 음성 23개를 통과했다. 첫 실패한 앱 결과와 반례는 최종 결과로 덮어쓰지 않았다.

## 실행 시간 해석

NEON 로그의 `segment_build` 65.161초는 구간 구성 전체이며, 그 안의 `native_scene`은 44.885초다. 둘을 합산하면 중복 계산된다. 기준 native는 39.518초였고 요청 프레임 수와 측정 결과는 전후 모두 같았다. MMN/ANT/NEON의 native 관측 수는 각각 135/299/541개로 동일하다.

이번에 추가한 `group_context` 연결 비교는 실제 앱에서 각각 0.000468/0.000521/0.001545초였다. 이 값은 공백 연결 함수만의 시간이며 compact 분류 전체를 대표하지 않는다. 전체 저장 관측의 분류 재생에서는 compact 처리 증가가 영상별 약 0.2–0.4초였다. 수정하지 않은 YOLO·얼굴 단계에서도 시간 증가가 관측됐다. 각 한 번씩의 실행만으로 55.873초 증가의 원인이나 일관된 속도 회귀를 확정할 수 없으며, 반대로 이를 무시하고 빨라졌다고 주장할 수도 없다.

## 검증·격리

- 최종 Dance 테스트 1,010개 통과(7.67초).
- 전체 Python 2,601개 통과, 6개 skip, 기존 renderer 실패 6개(196.11초). 전체 성공으로 표현하지 않는다. 실패는 annotation counter/chip/arrow 관련 5개와 ranking fadeblack 1개다.
- Astra 독립 검토: 최종 함수 양성 1개·음성 23개, 기존 body predicate 전체 9,266관측 변화 0, 저장된 세 영상 재생에서 최종 두 범위만 변경. 최종 앱 산출물 감사는 별도 보고서에 기록한다.
- 지정 npm 빌드 성공. 패키지 Dance 55개 소스 SHA가 검증 소스와 일치하며 최종 실행 이후에도 소스가 바뀌지 않았다.
- 이번 차이는 기존 파일 4개와 새 파일 5개다(실제 관측 JSON fixture 두 개 포함). Person/shared/SDK 변경 없음. 기존 미커밋 작업을 보존했고 커밋·푸시·병합은 하지 않았다.
- SAM `mask_continuity`와 `joint_identity`는 실제 세 실행에서 모두 0초, reason은 `disabled_runtime_cost`다. 기존 가벼운 pose/appearance 비교는 그대로다. 새 Windows 기기 실측은 하지 않았다.

## 남은 핵심 과제

1. **이름이 붙은 짧은 클립 73개는 그대로다.** 이번 단체 교정으로 멤버 파트 분절을 해결했다고 말하지 않는다. 새 조립 계층은 다음 수정의 경계와 근거를 분리한 기반이다.
2. 얼굴을 놓친 짧은 시간에도 같은 사람이 계속 메인인지, 실제 교대인지 구별하는 양성 근거가 부족하다. 양끝 이름만 같은 연결, 중앙 위치만으로의 main 확정은 반례를 통과하지 못했다. 기존 사용자 확인 구간(ANT 4.57–6.14, ANT 9.91–10.28, MMN 38.20–39.34 등)을 우선 평가한다.
3. 실제 컷과 카메라 움직임을 구별하지 못해 올바른 연결을 막는 곳이 남는다. MMN 49.9초 실험에서 특정 사례에 맞춰 cut 임계값을 바꾸지 않았다. 다양한 진짜 컷·줌 반례와 함께 검증해야 한다.
4. 같은 메인의 얼굴 공백을 복원하는 변경과 단체 판정을 분리해 평가한다. 새로운 조립 기록으로 왜 경계가 생겼는지 원인을 집계한 후 한 종류씩 고친다. 미확인 0초나 클립 개수만을 목표로 삼지 않는다.
5. 선택적 SAM은 여전히 미채택이다. 기존 얼굴/몸/역할 근거로 해결할 수 없는 짧은 후보만 대상으로 준비·추론·종료 전체 예산과 실제 강제 종료를 먼저 검증해야 한다. 이전처럼 광범위하게 켜지 않는다.
6. 실행 시간은 얼굴·메인 처리의 같은 입력 반복 측정으로 안정적인 차이를 먼저 분리해야 한다. 이번 결과를 성능 최적화 완료로 취급하지 않는다.

## 최종 실제 앱 독립 감사

Astra가 부모 비교와 별도로 최신 세 프로젝트를 감사해 **71개 산출물 조건을 모두 통과**했다. 제품 단위 테스트 71개를 새로 실행했다는 의미는 아니다. 이름 교체·새 main·기존 group 손실과 새 0.1초 미만 잔여는 없었다. 기존 0.1초 미만은 24 → 23개다.

시작/끝까지 같은 421개 외에 끝점만 달라진 기존 썸네일도 추적하면 423장이 바이트까지 같다. ANT group 시작점이 바뀌어 갱신된 한 장은 앱 FFmpeg로 원본에서 다시 추출해 일치함을 확인했다. 진단 얼굴 이미지 역시 재번호화를 따라 대조했고 삭제된 미확인 4클립의 9장만 제거됐다. 총 이미지 수는 1776 → 1762이며 이 감소를 얼굴 인식 손실로 해석하지 않는다. native 요청과 실제 관측은 합계 975회로 동일하다.

### 진단 지도 표시의 예외
