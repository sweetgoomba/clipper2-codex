# Astra 검증 반영: 이름 경계 교정·실제 앱 비교·SAM 비용 검토

2026-11-02 · 원본 `desktop/clipper_python` · `fix/dance-gpu-performance-20261102`

상태: 개선안 구현, 독립 재검토, 회귀 테스트, 원본 저장소 앱 빌드, 같은 세 YouTube 영상의 실제 앱 비교를 완료했다. 커밋·푸시·병합은 하지 않았다. 새 앱과 세 완료 프로젝트를 열어 둔다.

## 결론

실제 적용한 품질 개선은 ANTIFRAGILE의 사쿠라→홍은채 경계 한 곳, **0.283617초**다. MMN과 NEON의 분류·경계는 그대로이며, 세 영상의 **1초 미만 클립 245개와 미확인 39.577초는 줄지 않았다.** 전반적인 품질 문제를 해결한 결과가 아니다.

몸 추적 SAM의 두 호출은 계속 주석 처리되어 실제 실행 시간도 모두 0초다. 인물 하이라이트·공유 얼굴 코어·SDK의 제품 코드는 변경하지 않았다. 이번 추가 검사는 영상당 약 0.01–0.16초였다. Windows 실기 측정은 하지 않았다.

## 실제 적용한 수정

새 `named_boundaries.py`는 이미 이름이 있는 인접 A→B 클립의 경계만 검사한다. 경계 앞뒤의 원본 얼굴 관측 두 개가 A를 독립적으로 지지하면 원본 픽셀, 선택된 몸의 소유, 경쟁 인물, 단체/교대와 다른 확정 얼굴을 검증한다. 마지막으로 확인된 원본 프레임의 끝까지만 A를 연장한다. 원래 출력 경계가 얼굴 근거의 검색 범위까지 잘라 버리던 문제를 고쳤다.

- ANT 기존 경계: 사쿠라 110.977533–117.317200 / 홍은채 117.317200–119.686233.
- 새 경계: 사쿠라 110.977533–117.600817 / 홍은채 117.600817–119.686233.
- 원본 7028/7048 프레임의 동일인 근거와 그 사이 몸 경로를 검증했다. 7052 프레임의 다음 다른 이름 너머로 확장하지 않는다.
- 실제 앱에서도 이 경계 한 곳만 이동했다. 홍은채 클립의 썸네일 한 장은 시작점 변경에 맞춰 갱신됐고, 나머지 썸네일은 동일하다. 총 main 범위와 클립 수는 보존됐다.
- 얼굴 pair의 0.15–0.6초는 근거 사이 간격 조건이다. 클립 최대 길이가 아니며 3초 강제 분할을 다시 넣지 않았다.

교정된 결과를 다음 교정의 얼굴 근거로 재사용하지 않는다. unknown이나 group를 이름 있는 main으로 승격하지 않는다. 원본 얼굴·참조 갤러리는 읽기 전용이다. main-role 선택 자체의 정답을 새로 입증하는 기능도 아니다.

메인 판정에서 이미 계산한 **모든 관측의 선택 몸과 경쟁 후보·위치·크기·이유**를 진단 파일에 추가했다. 선택 변경 프레임만 남기는 기존 기록으로는 단순 fallback과 실제 구도 근거를 분리하기 어려웠다. 이 추가 기록은 다음 역할 판정 검증용이며 선택 동작·모델 호출 수를 바꾸지 않는다.

## 적용하지 않은 시도와 이유

Astra 검토의 한쪽 얼굴 pair를 이용한 미확인 복원안을 구현하고 저장 원본으로 재현했다. 4개 신원 후보, 합계 2.636초가 연결됐지만 2개는 원경 군무 또는 두 명이 앞에 있는 장면이라 메인 역할이 불명확했다. 중앙의 큰 몸으로 제한한 후속 실험은 한 후보 0.234초만 통과했으나, 비슷한 크기의 두 전경이 있는 반례도 통과했다.

따라서 이 자동 복원과 새 구도 임계값은 제품에서 제거했다. 신원 연결만 맞다고 메인 분류까지 정확해진 것으로 처리하지 않았다. 실험 소스와 독립 검토의 반례를 증거 폴더에 보존했다. 후보 2.636초를 이번 미확인 개선량으로 보고하지 않는다.

독립 재검토는 새 이름 경계 함수에서 detector 0.8–0.9의 유효한 반대 이름을 누락하는 결함도 발견했다. seed 선정만 0.9 이상으로 제한하고, 모든 유효한 확정 이름은 경로 중단·충돌 검사에 포함하도록 수정했다. 실패 재현 → 수정 → 재검증을 완료했다.

## 몸 추적이 필요한 경우와 비용 상한

몸 추적은 얼굴이 안 보이거나 카메라 전환이 있는 구간에서 **이름이 확인된 얼굴과 같은 몸이 이어지는지** 추가로 증명할 수 있다. 누가 무대의 메인인지 판단하는 문제를 대신 해결하지는 않는다. 이번 117초 경계처럼 기존 얼굴·원본 근거만으로 고칠 수 있는 곳에는 SAM이 필요하지 않았다.

과거 최적화된 SAM 실행 기록을 다시 집계했다. 이것은 이번 실행의 비용이나 새 제한 모드 실측이 아니다.

|영상|과거 SAM 전체|통과 시도 시간 합|실패 시도 시간 합|최종 main에 추가된 이름 시간|
|---|---:|---:|---:|---:|
|MMN|77.968초|37.363초|40.174초|2.386초|
|ANT|234.226초|82.251초|151.517초|7.842초|
|NEON|1163.121초|111.714초|1050.835초|4.738초|

NEON은 주변 얼굴까지 넓게 탐색하는 경로에 1014.037초를 썼다. 이를 제외해도 main/joint face 경로가 148.513초였다. 이미 tiny 모델, 512 입력, 이미지/mask 캐시, 실패 조기 종료가 적용돼 있었으므로 이를 새 해결책으로 다시 제안하지 않는다.

짧은 경로의 실제 성공 기록도 있다. MMN 38초의 사쿠라 복원은 19개 관측·양방향 검증 한 경로가 3.596초, ANT 10초의 김채원 복원은 7개 관측·경계 얼굴 대응 한 경로가 2.324초였다. 반면 ANT 4.57초의 홍은채 경로는 19.105초였다. MMN 후보의 전체 탐색 비용은 실패까지 합쳐 14.253초다. **빠른 성공 시도만 골라 전체 비용처럼 제시할 수 없고, 모델 준비를 포함한 최적 5초/10초 예산은 아직 검증되지 않았다.**

선택적으로 재도입한다면 다음 방식이 필요하다.

1. 원본 얼굴 근거·대상 몸·메인 역할은 이미 확인됐지만 짧은 연결만 불확실한 후보를 먼저 고른다. 긴 context 전체 탐색을 하지 않는다.
2. 가장 가까운 원본 seed에서 짧은 경로만 검사하고, 후보 수·경로 길이에 상한을 둔다. 두 SAM 단계가 하나의 총예산을 공유한다.
3. 부모가 별도 SAM 프로세스의 초기화·decode·추론·양방향 검증·종료까지 포함한 deadline을 관리한다. `Future.timeout`만으로는 실행 중 추론이 종료되지 않는다.
4. 제한 내 모든 검증이 끝난 후보만 적용한다. 미완성 결과는 버리고 기존 출력을 유지한다. 시간 초과 뒤 자식 프로세스·장치 작업·공유 상태가 남지 않는지 Mac/Windows에서 확인한다.

현재는 이 취소 구조와 cold-start 비용을 실제 검증하지 않았으므로 **SAM OFF를 유지**한다. 기존의 가벼운 pose/appearance 연속성 검사와 무거운 SAM 추적을 구분한다.

## 테스트·빌드·격리

- 최종 변경 관련 111개 테스트 통과. Astra가 독립적으로 관련 37개를 재실행해 통과하고 실제 저장 3영상의 제품 함수를 재생해 같은 경계 교정 한 곳만 확인했다.
- 전체 Python: 2565 통과 / 6 skip / 기존 렌더 테스트 6 실패. 전체 실행은 마지막 detector conflict 보강 직전이며, 보강 후 관련 111개와 독립 37개를 다시 통과했다. 전체 통과로 표현하지 않는다.
- 기존 실패: annotation renderer의 counter/chip/arrow 4개 및 byte-identical 1개, ranking transition의 fadeblack 1개. 이번 변경 범위 밖의 동일한 기존 실패다.
- 지정 명령 `npm run build:app:mac:arm64:local-api`, Node 24.19.0으로 원본 Electron 저장소에서 빌드 성공. 패키지 안무 Python 소스 54개 해시 일치. 실행 중 로드한 수정 모듈의 해시도 원본 소스와 일치했다.
- 작업 시작 스냅샷 109개와 비교하면 제품 수정은 안무 `pipeline.py`, `face_evidence.py`, `observed_main.py` 및 새 `named_boundaries.py`다. 기존의 큰 미커밋 변경은 보존했다. 인물/SDK의 스냅샷 56개 파일과 실행 중 공통 AuraFace 해시가 동일하다.
- `git diff --check` 통과. Windows 기기에서 새 분석을 실행하지 않았으므로 Windows 속도·품질 수치는 없다.

## 남은 과제

- 실제 메인 역할과 얼굴 신원을 분리해서 평가해야 한다. 얼굴 연결 성공만으로 원경 군무·공동 전경을 단독 main으로 만들지 않는다. 새 전체 관측 기록이 이 구분의 근거가 된다.
- 사용자 확인 공백 ANT 4.57–6.14(홍은채), ANT 9.91–10.28(김채원), MMN 38.20–39.34(사쿠라)는 그대로 남는다. 현재 source-cut veto를 넘을 수 있는 짧고 독립적인 얼굴 소유/경계 대응을 우선 실험해야 한다.
- 1초 미만 245개를 일괄 병합하지 않는다. 실제 교대·짧은 파트와 인식 공백 때문에 분절된 조각을 구분해야 하며, 이번 수정으로 이 문제를 해결하지 못했다.
- 선택적 SAM은 빠른 성공 경로의 재현, cold 준비 비용, 예산 초과 실제 종료 검증 후 채택 여부를 판단한다. 현재 자료로 품질을 최대로 만드는 총시간 상한을 확정할 수 없다.

## 완료 후 독립 앱 산출물 감사

Astra 세션이 실제 앱의 기준·새 프로젝트 6개를 직접 읽고, 부모 비교 스크립트와 별도로 재계산했다. 429개 클립, 1,776개 이미지, 9,266개 진단 프레임, 사용자 14구간에 대한 70개 불변 조건이 모두 통과했다. 이는 제품 단위 테스트 70개 추가 실행이 아니라 저장 산출물 감사다. ANT 경계 이동 0.283617초(원본 17프레임), 그에 따른 몸 표본 4개 재배분과 썸네일 1개 이외의 변경은 없었다. 바뀐 썸네일은 원본에서 새 시작 시각으로 재추출해 앱 파일과 바이트까지 일치함을 확인했다. SAM OFF와 실제 로드 소스 일치도 독립 확인했다.

실행시간 합계 1219.419→1132.067초가 독립 재계산과 일치한다. 위 표는 대기열 제외 시간이다. 제출부터 완료까지의 대기 포함 시간은 앞 작업의 남은 시간이 달라 ANT 481.064→602.064초, NEON 539.285→958.290초였다. 따라서 실행시간 감소를 제출 후 전체 대기시간 감소로 표현하지 않는다. 미확인·짧은 클립의 기존 문제는 그대로 남으며 모든 장면의 메인 역할 정답을 새로 검증한 것은 아니다.
