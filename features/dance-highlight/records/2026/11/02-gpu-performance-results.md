## 측정 조건과 근거

- 기존 세 유튜브 URL을 앱 UI에서 다시 입력하고 새 프로젝트로 실행했다. 기존 프로젝트는 보존했다.
- 저장된 아티스트·대표 이미지 선택과 이미지 파일 바이트가 모두 같다. 원본 영상, 모델, 설정 해시도 비교했다.
- 실제 앱에 패키징된 안무 제품 소스와 작업 브랜치 소스의 해시가 일치한다. [소스 해시](02-gpu-performance-app-evidence/source-hashes.json).
- 기존 유튜브 원본 캐시를 정상 앱 경로로 재사용했다. 새 다운로드에 걸리는 네트워크 시간은 측정하지 않았다.
- 앱 작업의 실제 started 시각부터 프로젝트 completed 시각까지다. 대기열 시간은 제외했다. Python pipeline TOTAL도 별도로 보존했다.
- Apple M4, 24 GiB, macOS 27.0. 한 차례의 순차 실행 비교이며 서로 다른 날짜의 기존 실측과 비교한 결과다. 통계적 반복 벤치마크는 아니다.
- 이전 기준 실행은 2026-10-29. 기존 메인 판정 시간은 독립 타이머가 없어 로그 간격으로 추산한 값이다. 위 전체 시간 표와 얼굴/cluster 단계는 실제 로그 기반이며, 이번 메인 판정 시간은 새 타이머로 직접 측정했다.
- 세 실행에 표시된 총 차감은 120크레딧. 사용자 승인을 받고 진행했다.

## 구현 범위

- 안무 전용 AuraFace 세션 주입: Mac CoreML(CPUAndGPU), Windows DirectML, CUDA 제공자가 있는 경우 CUDA 우선, 초기화/추론 실패 시 CPU 복구.
- 같은 입력의 얼굴 검출·임베딩 재사용, 검증된 원본 장면 전환 목록 재사용, 완전히 동일한 SAM 프레임 순서·프롬프트의 완료 결과 재사용. 메모리 상한과 출력 복사, 세션 잠금 포함.
- 임계값, 샘플 간격, 모델 가중치, 클립 병합/분리 로직은 변경하지 않았다.
- SAM MPS와 이미지 인코더만 MPS로 옮기는 실험도 일부 소유 인물 판정이 달라져 제품 경로에는 적용하지 않았다. 몸 추적은 CPU다.
- 공유 얼굴 코어와 인물 하이라이트 제품 코드/의존성은 변경하지 않았다. 전역 uv.lock 해시 변경으로 인물 환경 재동기화가 발생할 수 있으나, 인물의 의존성 선택과 CPU 기본값은 유지한다.
- Windows dance 의존성은 onnxruntime-directml 1.24.4. 패키지별 frozen exact uv sync가 이전 CPU ORT 설치를 대체한다. Windows YOLO/PyTorch CUDA 설치 및 최적 GPU 어댑터 선택은 이번 구현에 포함되지 않는다.

## 검증과 남은 제약

- 안무/공유 얼굴/인물 관련 테스트 1,255개 통과. 독립 구현 리뷰에서 조치할 결함 없음.
- 넓은 저장소 테스트에서는 권한 제한 관련 실패·오류와 렌더링 실패가 있었다. 권한 관련 일부 재실행 31개 통과; 렌더링 6개 실패와 다른 플러그인 부팅 검사 일부는 이번 변경과 분리해 남겨 두었다. 전체 저장소 테스트가 모두 통과했다고 주장하지 않는다.
- Mac 실제 앱의 CoreML 제공자와 CPU fallback 횟수를 기록했다. 모델별 제공자 정보는 [runtime 증거](02-gpu-performance-app-evidence/quality-and-runtime.json)에 있다. 얼굴 통계 원본은 주 파이프라인 얼굴 세션의 누적값이므로 영상별 차분도 함께 저장했다. 별도로 생성되는 보조 얼굴 세션의 연산을 모두 합친 값은 아니다.
- Windows 실제 GPU 기기에서의 설치·추론 정확도·성능은 미검증이다. 선택/fallback/동시성/의존성 격리 테스트만 완료했다.
- CPU 얼굴 위치 검출, 보조 얼굴 검증, SAM 몸 추적이 남은 비용이다. NEON은 몸 마스크 연속성에 21분 20초, Python 전체 분석의 약 57.3%를 쓴다. 완전히 같은 SAM 시퀀스 캐시 적중은 영상별 0/2/2회여서 반복 검증의 큰 비용을 없애지는 못했다. 다음 개선의 중심은 SAM 추적 비용이며, GPU 전환은 실제 판정 동등성을 먼저 확보해야 한다.
- 현재 소스는 미커밋이며 dev에 병합하거나 푸시하지 않았다.

## 추가 조사: NEON 몸 마스크 검증 21분 20초의 원인

사용자가 21분 20초의 필요성·무한 반복 여부를 질문하여 실제 실행의 후보별 비용과 코드를 대조했다. 이번 추가 조사는 제품 코드/결과를 바꾸지 않았다.

- 이 단계는 기본 YOLO 인물 검출·메인 판정이 아니라, 이름이 없는 구간에 기존 얼굴 근거의 이름을 연결하는 **추가 복원**이다. `recover_mask_names`는 이미 이름이 있는 구간을 건너뛴다. 별도의 확정 이름 재검증은 NEON에서 약 0.78초다.
- SAM2.1 tiny를 CPU에서 실행하며, 기준 얼굴의 몸부터 목표 구간까지 몸의 픽셀 영역을 추적한다. 순방향 검사가 통과하면 반대 방향도 추적해 몸 영역과 소유 인물이 일치하는지 검증한다. 구간별·이름 후보별로 이 작업이 반복된다.
- 48개 미확인 후보 구간에 146회 시도. 13회는 직접 얼굴 충돌로 사전 거절했고, 133회의 추적 시도에 1,279.13초가 기록됐다. 단계 전체는 1,279.73초다.
- 성공 시도 22회는 119.72초, 거절 시도는 1,159.41초(약 19분 19초), 측정된 시도 시간의 90.64%다. 실패를 확인하는 검증도 품질에 기여할 수 있으므로 이 전부가 안전하게 삭제 가능한 시간이라는 뜻은 아니다.
- 같은 카메라 장면에 등장한 다른 멤버의 얼굴을 기준으로 삼는 context/joint-context 후보가 약 1,119.56초(87.53%)를 차지한다. 기준 얼굴과 목표 사이의 최대 시간 거리, 후보 수, 구간/전체 처리 시간에 명시적인 서비스 상한이 없다. 10–19초 떨어진 기준 얼굴까지 연결한다.
- 복원한 내부 구간은 총 8.64초이며, 당시 출력 가능한 메인 구간에 겹치는 이름 복원 변화는 **4.74초**다. 이후 장면 문맥·병합이 이 근거를 사용할 수 있으므로, 4.74초를 이 단계 제거 시 최종 결과 차이로 해석하면 안 된다. 제거 전후 전체 파이프라인 비교는 아직 하지 않았다.

무한 반복은 없다. 유한한 구간·후보·프레임 목록을 처리하며, 특정 실패 조건에서 지지 구간 확장 또는 실패 전 부분 구간 재검증을 각각 조건부로 추가한다. NEON 기록에는 부분 재검증 8회, 짧은 지지 구간 재검증 1회가 있다. 복원된 이름을 다시 새 기준 얼굴로 삼아 재귀적으로 반복하지 않는다. 그러나 후보 선택과 종료 조건이 느슨해서 유한한 작업도 지나치게 커진다. 특히 기존 context 후보는 가까운 앞뒤에서 같은 이름을 확인한 뒤에도 계속 검사하며, 역방향 검증은 이미 불일치가 발생해도 전체 경로를 계산한 뒤 판정한다.

기본 인물 추적은 필요하지만 현재의 비싼 전수 복원 방식은 필수 구성요소가 아니다. 후속 검토는 (1) 판정이 확실히 실패할 때 안전한 조기 종료, (2) 가까운 동일 몸 근거 우선 및 먼/경쟁 후보의 사전 선별, (3) 이름 후보마다 긴 몸 경로를 다시 추적하는 구조 개선, (4) 서비스 처리 예산과 미확정 종료 정책 순이다. 이 중 후보 축소·시간 예산은 결과 변화 가능성이 있으므로 사용자 확인 사례와 세 영상의 최종 클립을 비교해야 한다. 모든 SAM 복원을 끄면 기존에 확인한 홍은채/사쿠라 구간 등의 이름 복원이 사라질 수 있다. 인물 하이라이트는 변경 대상이 아니다.
