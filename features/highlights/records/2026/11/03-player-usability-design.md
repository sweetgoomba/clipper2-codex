# 하이라이트 플레이어 사용성 설계

사용자 승인: 2026-11-03, “제안대로 진행”. 최신 origin/dev에서 UI와 Web API의 feat/highlight-player-usability 브랜치를 만들었다.

## 동작
- 장면 모달에서 스페이스바는 재생/일시정지이며 포커스가 다음 장면 버튼에 남아 있어도 장면을 넘기지 않는다. 키 반복은 무시하고 입력·체크박스 편집은 보호한다.
- 음량 슬라이더와 음소거 버튼을 제공한다. 음량과 음소거는 장면을 넘겨도 유지하고 실제 video volumechange와 동기화한다.
- 일반 미리보기는 해당 클립 범위를 재생한다. 구간 편집 중에는 원본 전체에서 선택한 위치를 재생하고, 편집 구간 바깥이라는 이유로 되감거나 멈추지 않는다. 탐색 중 재생 요청도 탐색이 끝나면 이어간다.
- 기본 미리보기와 편집은 기존 화면 구조·토큰을 사용한다. 다른 워크플로의 플레이어 교체는 범위 밖이다.
- 아티스트 탐지는 후보와 순서를 유지하며 제목에 포함되지 않은 별칭의 정규식 실행을 건너뛴다. API·인증·DB 계약은 유지한다.

## 접근 비교
기존 플레이어에 필요한 조작과 이벤트 처리를 추가하는 방식 채택. 브라우저 controls 전면 사용은 장면 시간 대신 원본 전체 시간을 노출하고, 공유 플레이어 전면 교체는 변경 범위를 불필요하게 넓힌다.
검색 인덱스/캐시 재설계보다 부분 문자열 선검사가 작고 기존 결과를 보존한다.

## 증거와 검증
최신 초기 카탈로그 7,468명에서 detectArtists 계산 6.4~18.2초, 직접 이름 검색 약 19~30ms. UI onTimeUpdate는 editMode && video.paused일 때만 외부 위치를 허용한다. 문서 키보드 핸들러에 Space 처리가 없다.
회귀 테스트: 버튼 포커스·키 반복·입력 보호, 음량/음소거·장면 변경 유지·fallback, 편집 중 경계 전후 재생·탐색 대기. 실제 카탈로그 탐지 성능과 한글/영문/별칭/경계 결과 검증. UI/Web API 빌드 및 관련 테스트와 UI 런타임 스모크.
