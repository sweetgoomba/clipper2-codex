# W14 — 신규 얼굴 인식 후보의 비교시험 설계

후속: 사용자에게 실행 범위와 정답 의미를 설명한 뒤 동의를 받아 격리 모델 준비·CPU실행·확인 화면을 만들었다. [실행/실패/남은 GT와 배포 검증](14-w14-candidate-runtime-and-face-review.md). 아래는 실행 전 설계 이력이며 제품 채택 또는 정확도 개선을 선언하지 않는다.

2026-10-14 KST. 상태: **조사·설계, 실행 전**. 사용자의 외부 조사 전달 및 `응. 진행하자. 내가 뭐 정해줄거있어?`에 따라 기존 구현/평가 자료를 읽고 시험안을 구체화했다. 이 승인을 신규 모델 다운로드·설치·추론·제품 코드 수정 승인으로 확대하지 않는다. Superpowers 설계 절차를 이어가며 공통 API 변경은 구현 전에 별도 서면 설계/계획에 반영한다.

## 1. 목표와 고정 범위

- W13이 선택한 메인 인물의 얼굴을 사용자 등록 멤버와 비교하여 **다른 멤버 오확정과 식별 가능한 얼굴의 과도한 거부를 함께 줄인다**.
- 메인 선택·몸 추적·안무 구간 분리는 W13 소유. W14는 관측별 인식 성능과 같은 사람의 증거 결합을 나눠 평가한다.
- macOS는 **Apple Silicon arm64만**, Windows는 x64. Intel Mac 제외. `face-reidentification-retail-0095`의 제공자 이름 Intel은 지원 CPU 제한을 뜻하지 않는다.
- 로컬 CPU, Python 3.11/uv, 플러그인별 선택 의존성/venv/모델 준비, 공통 API의 플러그인 비종속성을 유지한다.
- 기존 앱·공통 core·v1~v5 결과·사용자 편집·다른 세션 변경은 보존한다. v5의 기각된 점수 규칙을 새 기준선으로 채택하지 않는다.

작업 경로는 기존 `.worktrees/shared-reference-face-matching-20261013`을 유지한다. 평가 입력은 그 아래 `evaluation-output/comparison-review-20261013/segments-v4/manifest.json`, 참조는 `evaluation-output/reference-replay-v1/dataset.json`에서 출발한다.

`evaluation/segment_review/owned_replay.py`는 저장 `face_candidates`의 15개 값과 `selected_face_index`, `roi_box`, `frame_index`를 사용한다. 얼굴 bbox/5점은 ROI 기준이므로 source 좌표로 바꿀 때 ROI 원점을 더한다. 정렬은 원본 frame의 ROI에서 수행했다. **비교 화면의 JPEG 얼굴 이미지를 신규 모델 입력으로 재활용하지 않는다.** 새 입력 묶음을 만들 때 각 관측의 원본/좌표/선택 인덱스 존재와 유효성을 확인해야 한다. 이는 아직 실행하지 않았다.

공통 `OpenCvFaceBackend.detect()`는 검출·정렬·SFace 특징 추출이 결합되어 있고 공개 결과에 5점이 없다. 평가 파일에는 5점이 있다는 사실과 공개 API가 이미 분리되어 있다는 주장을 혼동하지 않는다.

## 3. 접근 선택

1. **권고: 같은 단일 얼굴의 인식 모델 비교 → 같은 사람의 구간 결합 → W13 통합.** 변경 원인과 오답을 구분하기 쉽다. 별도 영상 정답 준비가 필요하다.
2. 새 모델을 기존 전체 파이프라인에 바로 넣기: 화면 결과는 빨리 나오지만 몸 선택/표본/정렬/판정 영향이 섞여 모델 우열을 설명하기 어렵다. 이번에는 선택하지 않는다.
3. 모델 추가 없이 SFace 판정 규칙만 계속 조정: 변경량은 작지만 같은 자료에 대한 반복 조정과 알려진 회귀 위험이 크다. 신규 후보 비교의 대체안으로 삼지 않는다.

## 4. 1차 후보와 보류 조건

| 후보 | 첫 비교 역할 | 준비 단계의 통과 조건 |

| `landmarks-regression-retail-0009` | 후속 정렬 효과 분리 | 1차 결과 후 필요할 때, 인식 모델을 고정한 별도 대조 |

AuraFace의 공식 파일 페이지 SHA는 `a7933ea5330113b01c9b60351d8f4c33003f145d8470ac5f0e52ee2effe25c60`, LICENSE를 포함하는 저장소 revision 후보는 `af6d057c9b0ec4071d4c49c80e3539258798b609`이다. 이 값은 앞선 공식 웹 조사 기록이며 로컬 다운로드 검증이 아니다. 전체 FaceAnalysis pack을 받지 않는다.

0095는 `2023.0/models_bin/1/face-reidentification-retail-0095/FP32/`의 XML/BIN 쌍이다. 공식 manifest의 checksum은 96자리이므로 SHA-256 필드로 복사하지 않는다. 제공 checksum 알고리즘을 확인하고, 향후 승인된 준비 단계에서 실제 파일 SHA-256을 별도로 기록한다.

앞선 조사 근거: [AuraFace 카드](https://huggingface.co/fal/AuraFace-v1), [LICENSE](https://huggingface.co/fal/AuraFace-v1/blob/main/LICENSE.md), [가중치](https://huggingface.co/fal/AuraFace-v1/blob/main/glintr100.onnx), [0095 manifest](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/intel/face-reidentification-retail-0095/model.yml), [0009 manifest](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/intel/landmarks-regression-retail-0009/model.yml). 공개 성능/학습 데이터 설명은 제공자 주장, Clipper 성능은 미검증이다. 이번 턴에는 이 웹 조사를 반복하지 않았다.

기존 시험 ArcFace는 회귀 참고만 보존한다. 배포 권한 관계가 해소되지 않아 기본 제품 후보로 채택하지 않는다. 다른 보류 후보를 이번 시험에 추가하지 않는다.

## 5. 정답과 통제 조건

정답 기록은 모델 출력과 분리하고 모델 결과를 보기 전에 고정한다.

- 키: source hash + frame/PTS/timebase + observation ID/version + body/track/scope + bbox/5점 좌표계.
- 라벨: 실제 선택 얼굴의 reference ID 또는 등록 외 인물, 메인 몸과의 연결 confirmed/ambiguous/wrong, crop 자체 식별 가능 여부, 얼굴 크기·각도·흐림·가림·조명, bbox/특징점 유효성.
- 출처: 사용자 확인/독립 검토/미확인, 확인자·버전·근거. `unlabelled`, `unidentifiable`, `out_of_gallery`를 다른 상태로 둔다.
- 기존 시간대 main 정답으로 잘못 선택된 얼굴에 목표 멤버 이름을 붙이지 않는다. 모델 출력을 정답으로 역입력하지 않는다.
- 판단 가능한 관측과 모호한 관측을 모두 보존한다. 정답 미확인 수를 공개하고 정확도 채점 범위를 명시한다. 실패/미확인 사례를 삭제해 분모를 줄이지 않는다.
- 23참조 사진 및 멤버별 개수는 모델 간 동일. 먼저 기존 centroid 결합 방식을 통제한다. 최대유사도 등 참조 결합 변경은 별도 대조로 둔다.
- 원본 시점/얼굴 선택/검출 bbox/YuNet 5점은 동일. 모델별 필요한 크기·채널·정규화·정렬 template은 올바르게 적용하고 기록한다. 0095는 ‘모델+필수 정렬’ 비교로 표시한다.

## 6. 단계별 시험안 — 미실행

### A. 기존 자료 비교 준비

기존 20구간을 개발/회귀 집합으로 고정한다. 451시점 전체 목록과 406개 얼굴 선택 근거를 검토하고, 얼굴 정답을 확인한 것과 아직 확인하지 못한 것을 분리한다. 반복·명확 사례까지 사용자에게 일괄 재라벨링시키지 않고, 불확실한 대표 사례를 모아 필요한 것만 요청한다. 사람 이름을 확실히 판단할 수 없는 자료는 미확인으로 남긴다.

### B. 모델 준비 후 단일 얼굴 비교

별도 실행 승인을 받은 뒤 exact file/license/runtime/preprocessing 검사를 통과한 두 후보의 참조23+영상406개 특징을 각 1회 수집하는 것이 첫 제안이다(모델별 최대429개, 두 후보858개; 부팅 smoke/실패/추가 타이밍 측정은 별도 횟수 기록). SFace는 입력·공간 동일성이 검증된 캐시만 재사용한다. 새로운 표본이나 정렬 조건은 별도 실행으로 센다.

초기 자원 상한 제안은 worker별 CPU 1 thread, batch1, 10분/4GiB RSS, 후보 순차 실행, 새 출력 합계2GiB다. 측정 전에 정확한 장비/OS/runtime 버전·입력/코드 hash·출력 경로·호출 수를 실행 manifest로 잠근다. 상한 초과 시 실패를 기록하고 자동 반복/임의 증량하지 않는다. 이는 실행 승인이나 성능 예상치가 아니다.

### C. 개발 기준과 독립 평가

기존 영상에서 모델별 거리/1·2위 차이/거부 기준을 정하고 별도 영상에 고정 적용한다. 참조 사진 leave-one-out만으로 영상 threshold를 확정하지 않는다. 이미 본 영상의 인접 프레임을 개발/독립 평가에 나눠 넣지 않는다.

별도 영상은 같은 등록 멤버가 등장하되 다른 촬영 조건의 사례를 우선하고, 초기 검증은 최대3개×120초 이하를 제안한다. 링크가 달라도 같은 촬영/재편집/참조 사진과 중복되는 프레임이면 독립으로 보지 않는다. 새 영상은 threshold tuning에 사용하지 않으며, 보고 난 뒤 기준을 바꾸면 개발 자료로 재분류한다. 이 작은 집합으로 매우 낮은 FAR나 일반 제품 성능을 입증했다고 쓰지 않는다.

사용자가 다음 두 평가 영상을 제공했다. 영상 구성은 사용자 설명이며, 실제 전 프레임 검토/멤버·배경 얼굴 라벨링을 마친 것은 아니다.

| 평가 ID / URL | 사용자 설명 | 주요 평가 목적 |
| --- | --- | --- |
| `holdout-backup-dancers` / [J9DlrnNlgfE](https://www.youtube.com/watch?v=J9DlrnNlgfE) | 매우 많은 백댄서와 함께하는 무대 | 등록 외 인물을 멤버로 오확정하는지, 혼잡·가림에서 실제 멤버를 놓치는지, 메인 몸 주변의 다른 얼굴을 선택하는지 |
| `holdout-members-only` / [6bVUjsUi9sw](https://www.youtube.com/watch?v=6bVUjsUi9sw) | 백댄서 없이 멤버5명만 나오는 무대 | 멤버 간 오분류와 식별 가능한 멤버의 거부율, 각 멤버별 편차 |

기존 `yFTAYXDTjqI`는 개발/회귀, 새 두 영상은 독립 평가 **후보**로 예약한다. 새 영상은 각120초 이하·합계240초 이하로 시작하는 계획이며 정확한 구간은 모델 결과를 보기 전에 원본/중복/난이도 검토로 고정한다. 지금 단계에서는 길이·해상도·format ID·hash·시작/끝을 추측해 기입하지 않는다. 세 번째 새 영상은 당장 추가 요청하지 않는다. 기존133.65초 회귀 자료는 이 신규 영상240초 예산과 구분한다.

주평가는 W13이 이미 선택한 메인 얼굴이다. 백댄서 영상에서는 별도 정답을 붙인 등록 외 얼굴 표본도 거부 검사용으로 두되, 이를 메인 인물 정답이나 메인 선택 성능과 섞지 않는다. 멤버 인식 성능과 등록 외 얼굴 거부 성능을 별도 분모로 보고한다. 백댄서를 실제로 등록 외 인물이라고 라벨링하지 않은 채 위치·의상만으로 확정하지 않는다.

페이지 확인 범위(후속 갱신): 브라우저에서 둘 다 정상 재생됨을 확인했다. 첫 영상은 Super Shy/SBS 2023-07-16/표시3:35, 둘째는 OMG/KBS 2023-01-27/표시3:51이다. 둘째의 앞선 웹 fetch 오류는 해소했다. 각 영상의 `[30,60)`, `[80,110)`, `[125,155)`, `[165,195)`초를 모델 결과를 보지 않고 평가 창으로 선정했다. [직접 관찰·시간 창·정답 준비안](14-w14-holdout-input-preparation.md). 실제 파일/PTS/hash/참조 사진 중복 검증과 정답 라벨링은 남아 있다. 두 영상의 실제 스트림/색공간/HDR 여부를 확인하고 모델 간 동일 디코딩 경로를 고정해야 한다.

이번 URL 제공은 평가 자료 지정으로 반영했다. 영상 파일 다운로드·모델 다운로드/설치/실행은 수행하지 않았다. 남은 작업은 원본 확보를 포함한 실행 범위 확정 후, 정확한 구간/선택 얼굴/정답을 모델 결과와 독립적으로 잠그는 것이다.

### D. 시간 결합과 W13 통합

관측별 비교 뒤, 실제 동일인 범위가 확인된 자료로 track/구간 집계를 평가한다. 얼굴 인식 교체 효과와 표본 수집/결합 변경 효과는 기존/수정 파이프라인×기존/신규 모델로 분리한다. 수동 7범위 표시는 진단 대조이며 제품 규칙으로 넣지 않는다. W13 최신 출력은 SHA와 동일인 scope 계약을 따로 확인한 뒤 사용한다. 옛 MoveNet 결과를 최신 W13 품질로 설명하지 않는다.

## 7. 지표·화면·채택 판단

- 관측: 다른 멤버 오배정 건수/분모, 식별 가능한 등록 인물의 거부율, 처리율, 확정 결과 정확도, 등록 외 인물 오수락, 멤버별 혼동표와 크기/각도/흐림별 결과.
- 원인: `not_sampled`, `no_face`, `association_error/ambiguous`, `alignment_invalid`, `inference_error`, `recognition_rejected`, `wrong_identity`, `scope_invalid`, `segment_conflict`. 모델 실행 오류를 정상 미매칭으로 집계하지 않는다.
- 시간축: 유효한 동일인 범위의 track/구간 정답. 잘못된 몸 선택과 얼굴 이름 오류 별도 집계.
- 실행: cold/warm 분리, 모델 로드/전후처리 포함 여부, p50/p95/RSS/전체 시간. 샘플 수와 타이밍 반복 수 명시. 공개 GFLOPs/파일 크기를 실제 지연시간으로 대체하지 않는다.
- 결과 화면: 멤버 카드 → 클립 → 원본의 메인 위치/선택 얼굴/정답 확인 상태/모델별 결과와 거부 이유. 같은 클립의 전후 이동을 추적하고 no-face/오류도 남긴다. 기존 v5를 덮어쓰지 않는다.
- 채택: 개발 단계에서 고정한 비교 지점에서 오배정이 같거나 줄면서 올바른 매칭이 늘어나는지, 같은 처리율에서 오배정이 줄어드는지 함께 본다. 상충하면 우승 모델로 선언하지 않고 수치·사례를 제시한다. 작은 표본에서 오배정0이어도 ‘실제 오류율0’이라고 쓰지 않는다. 제품 수치 목표는 독립 자료 규모와 결과를 보고 별도 제품 결정으로 남긴다.

## 8. 최소 변경과 배포 전 조건

후속 구현은 기존 공통 match/gallery/consensus 계약을 재사용하고, bbox/5점 관측과 인식 adapter를 분리하는 작은 호환 확장을 우선한다. legacy `detect()` 소비는 보존한다. 모델 hash/정렬/전처리/정밀도/출력 정규화/거리 정의가 다르면 다른 embedding 공간이며, 참조 cache에도 이미지 hash/version을 연결한다.

ORT/OpenVINO는 필요한 평가·소비자 venv에만 둔다. lock에 ORT가 있다는 사실을 Dance venv에 설치돼 있다는 뜻으로 해석하지 않는다. 기본 SDK import에 ML 로딩을 추가하지 않는다. 제품 통합 때 Electron의 공통 패키지 source fingerprint/재설치 누락을 별도로 처리한다.

정확한 code/weight/runtime/재배포/별도 조건을 구분한다. OpenCV wheel의 LGPL 구성요소는 실제 배포물 기준으로 검토하며 headless나 NOTICE만으로 의무가 해소됐다고 가정하지 않는다. native DLL/코드서명/한글 경로/캐시 권한/모델 미준비·오프라인/개발도구 없는 환경을 Mac arm64와 Windows x64에서 검증한다. wheel 존재는 모델 실행 증거가 아니다.

macOS 최소 버전은 아직 제품 정책이 확인되지 않았다. 현재 Mac에서의 후보 비교 설계는 진행하되 최소 지원 버전을 모델 때문에 임의로 올리지 않는다. 필요하면 런타임 선택 시 지원 범위와 변경 비용을 제시해 한 번에 결정한다.

## 9. 이번 작업의 실제 검증과 인계

이번 작업은 저장 문서/JSON/코드 읽기와 이 설계·작업보드·W13 공통 계약 인계의 문서 갱신만 수행했다. **신규 다운로드0, 설치0, 모델 추론0, 벤치마크0, 제품/평가 코드 수정0**. 앞선 테스트 통과 수를 이번 후보의 실행 검증으로 재사용하지 않는다.

W14 소유: 공통 관측/인식 adapter 설계, 참조 비교, 입력/실패/공간 계약, 공정한 평가. W13 소유: main/몸 추적/구간/crop 및 Dance adapter 소비. 병합은 W14 공통 API·고정 fixture → W13 최신 출력 compatibility → 소비 adapter/venv 순서이며, 이번에는 파일 소유 변경·merge·다른 세션 메시지·새 세션 생성이 없다.

남은 입력: 제공된 두 영상의 원본/촬영·참조 중복 여부와 정확한 평가 구간, 실제 선택 얼굴 identity/ownership의 독립 정답, exact runtime 의존성/OS 범위와 최소 macOS 정책. 추가 영상 URL 요청은 사용자 제공으로 해결했다. 모델별 파일/전처리 실물 검사는 후속 준비 단계다. 지금 사용자에게 threshold·모델 우승자·참조 재선택을 요구하지 않는다.
