# 10/15 안무 하이라이트 빌드 범위 점검 — W14 얼굴 매칭

사용자는 오늘 안무 하이라이트의 앱 적용·빌드·보고가 필요하므로 평가를 계속하는 대신 제품에 넣을 수 있는 범위를 판정해 달라고 했다. 아래 최초 판정은 이후 사용자가 **이 세션의 얼굴 매칭 변경을 시험 빌드에 넣어 직접 검증**하겠다고 명확히 한 뒤 바뀌었다. 설치 파일 생성·실제 영상 정확도 확인 완료를 뜻하지 않는다.

## 후속 결정 — 공통 얼굴 매칭의 안무 시험 빌드 연결

- **실제 코드 위치:** Python `test/dance-highlight-merge-20261015` HEAD `e636a5f`, Electron 같은 이름의 별도 repo HEAD `b162592`. 별도 격리 feature에서 구현·검증한 뒤 깨끗한 병합 테스트 작업 트리에 각각 merge했다. 빌드 입력은 `/Users/jina/project/adlight/.worktrees/dance-merge-test-20261015/desktop/clipper_electron`과 형제 `clipper_python`이다. 원래 W14 donor와 다른 세션의 Angular/Nest 변경은 덮어쓰지 않았다.
- **바뀐 동작:** `clipper_face_core` 0.2.0을 안무 플러그인의 선택 의존성으로 설치한다. Dance의 기존 메인 구간과 메인 몸 추적에서 최다 표를 얻은 클러스터의 얼굴 특징만 등록 사진과 구간별 비교해 `person_id`를 기록한다. 같은 멤버가 여러 구간에 반복 등장할 수 있다. 한 구간의 얼굴 근거가 다른 멤버를 지지하면 보류한다. 서로 다른 클러스터가 같은 멤버로 붙을 때는 기존의 추가 거리 제한 `min(0.45, 주 클러스터 거리+0.08)`을 적용한다. 무효 참조 특징은 유효 사진 수에서 제외하고, 유효 gallery가 없으면 멤버 이름을 강제하지 않는다. 결과 `stats.reference_matching=shared_reference_v1`과 상태별 건수를 남긴다.
- **유지한 입력:** 얼굴 검출 YuNet 2023mar, 특징 SFace 2021dec, 기존 참조 사진, 메인 인물·구간 생성 경로. AuraFace/Intel/Seeta 모델 교체, 다른 촬영 참조 추가, 시간 이웃 이름 전파, W13 72번 메인 판정은 이 빌드에 포함하지 않았다. 얼굴이 메인 몸의 ROI에서 선택됐다는 가정은 실제 얼굴 소유 정답과 다르다.
- **실제 검증:** 병합 작업 트리에서 Dance+core 테스트 **115 통과**, Electron TypeScript 빌드와 선택 venv 테스트 **12 통과**. 격리 Python venv에서 앱과 같은 `uv sync --frozen --no-dev --no-editable --offline` 옵션으로 Dance·core·SDK wheel 설치와 설치본 import를 확인했다. 안무 로컬 서버/작업 API smoke **4 통과·1 skip**. 리뷰의 다수 트랙·중복 클러스터·불량 참조 3건을 수정하고 후속 읽기 전용 리뷰에서 중요 문제 0건을 확인했다. Python 전체 suite의 최초 실행은 756 통과/3 skip/로컬 포트 권한에 따른 4 fail·16 error였고, 이 전체 suite는 최종 수정 뒤 재실행하지 않았다.
- **아직 확인하지 않은 것:** 설치형 Electron 앱 빌드·실행, 사용자 영상의 새 클립과 기존 결과 비교, 잘못된 멤버 확정/미매칭의 실제 개선율, Mac/Windows 패키징 결과. 사용자가 새 빌드에서 동일 영상·동일 참조 사진으로 재실행한 결과가 다음 판정 입력이다. 이 연결은 시험용이며 정확도 개선 완료나 배포 승인 주장이 아니다.

## 연결 이전 확인 상태 — 보존 이력

- W14 `feature/shared-reference-face-matching-20261013` Python 작업 트리에 공통 `clipper_face_core` 0.2.0 구현이 있지만, Dance 제품 adapter·플러그인 설치·Mac/Windows 앱 실행까지 연결되지는 않았다. 작업 트리 변경은 미커밋 상태다.
- 기존 앱의 얼굴 검출/인식은 YuNet 2023mar + SFace 2021dec이다. AuraFace 교체, 참조 사진 8장 추가, 시간 이웃의 이름 자동 전파는 저장 정답에서 회귀 또는 오배정 위험이 확인돼 제품에 채택하지 않았다. [회귀 결과](14-w14-face-evidence-regression-result.md).
- W13 72번 메인 선정 결과는 평가 노트북에만 있다. 사용자 확인에서 15.816초의 오선택과 149.883초 세 인물 공유 배정 요구가 남았다. W13 세션도 이 후보를 오늘 제품 개선으로 보고할 수 없다고 확인했다. [W13 확인 기록](15-w13-stage-focus-five-review-and-shared-clips.md).
- 별도 `test/dance-highlight-merge-20261015` 작업 트리에는 안무 진입·참조 사진·아티스트 목록 등 사용성 기능 브랜치가 병합돼 있다. 확인한 HEAD는 Python `47e8c3b`, Nest `6bc3496`, Angular `1b1379e4`, Electron은 `origin/dev`와 동일했다. 이 병합은 W13 메인 선정이나 W14 얼굴 매칭 정확도 후보를 포함하지 않는다. 해당 앱 빌드·관리자 화면 실행은 `안무 하이라이트 사용성 개선` 세션에서 진행 중이므로 여기서 중복 수정하거나 완료로 기록하지 않는다.

## 최초 제품 판정 — 위 시험 빌드 결정으로 대체

1. 오늘 빌드의 안무 개선 범위는 병합된 **사용성 기능**으로 명확히 한정한다. 기존 YuNet/SFace와 기존 메인·구간 판정은 그대로 설명한다.
2. 공통 얼굴 모듈, 신규 인식 모델, 참조 추가, 시간 자동 배정, W13 72번 후보, 세 인물 공유 배정은 오늘의 검증된 앱 정확도 개선으로 발표하지 않는다.
3. 실제 앱 빌드 완료와 설치 후 실행 결과는 빌드 세션의 산출물·로그가 나와야 기록할 수 있다. 이 문서 작성 시점에는 이 세션에서 설치 파일·실제 개선 클립을 생성하지 않았다.

## 최초 후속 순서 — 보존 이력

W13이 메인 몸·구간·공유 장면 계약을 제품 코드로 고정하고, W14는 그 출력에서 얼굴 소유·참조 매칭을 분리 평가한다. 기존 정답 손실과 타인 오확정이 없는 설정을 골라 Dance adapter에 연결한 뒤 실제 클립 생성, Mac arm64/Windows x64 설치 검증을 거쳐 제품 판정을 바꾼다. 평가에서 관측한 회복만으로 출시 가능하다고 판단하지 않는다.
