선정 근거는 시간대 분산과 다음 직접 관찰이다. 영상 전체의 얼굴 품질/멤버 정답을 주석한 결과는 아니다.

## 정답 자료 준비 순서

1. 원본 파일과 format ID·해상도·fps/timebase·색공간/HDR·hash를 고정한다. 원본 얼굴을 인위적으로 저해상도화하거나 기존 정렬 JPEG에서 다시 정렬하지 않는다.
2. 창당 정수 source-second의 1fps를 최초 정답용 표본 일정으로 제안한다. 30시점×4창×2영상=240시점이다. 실제 frame은 해당 시각 이상인 첫 source PTS로 선택하고 requested time/actual PTS를 모두 기록한다. 표시 fps로 PTS를 만들어내지 않는다.
3. 모델 출력/점수를 보지 않고 얼굴 존재·가림·식별 가능성·등록 인물/등록 외/미확인 상태를 기록한다. 이름이 확실하지 않으면 사용자에게 대표 사례만 모아 묻고, 검토 전까지 미확인으로 남긴다.
4. W13이 제공한 메인 몸/track/source가 있으면 동일 시점의 선택 얼굴 소유를 대조한다. 새 두 영상에는 아직 고정된 W13 메인 출력이 없으므로, **현재 이 자료로 안무 메인→멤버 분류의 전체 정확도를 계산할 수 없다.** 별도의 단일 얼굴 인식 평가를 전체 안무 평가로 이름만 바꾸지 않는다.
5. 백댄서의 등록 외 얼굴 거부 시험은 별도 표본 집합과 분모로 기록한다. 모든 검출 얼굴을 메인으로 취급하지 않는다. 모델마다 성공한 얼굴만 따로 고르지 않는다.
6. 입력/정답/개발 threshold를 잠근 뒤 후보별 같은 관측을 처리한다. 판정 기준은 새 영상 결과를 본 뒤 수정하지 않는다. 수정한다면 해당 자료는 개발 자료로 전환하고 별도 평가가 필요하다.

1fps는 초기 정답/인식 비교 표본 일정이며 생산 파이프라인 추적 주기나 interval 정확도를 보장하지 않는다. 240시점의 동시 얼굴 수가 정해지기 전에는 신규 특징 추출 호출 수를 임의로 확정하지 않는다. 얼굴 없는 표본과 연결 불확실/모델 오류를 남긴다.

## 필요한 정답 필드

`source_id/hash, window_id, requested_seconds, actual_pts, time_base, frame_index, observation_id/version, bbox_px/coordinate_space, landmarks/landmark_schema, selected_body_id, physical_identity_scope, ownership_status, reference_id_or_out_of_gallery, identity_label_status, identifiable_from_crop, size/blur/pose/occlusion/light, reviewer/provenance/version`.

구분 규칙:

- `unlabelled`: 아직 사람이 정답을 붙이지 않음. 모델 거부와 다르다.
- `unidentifiable`: 해당 crop만으로 판단할 근거가 부족함. 시간축 맥락으로 실제 identity를 알더라도 crop 식별 가능성은 별도다.
- `out_of_gallery`: 등록5명 외 인물임을 검토한 라벨. 단순 모델 미매칭은 이 라벨의 근거가 아니다.
- `ownership_wrong/ambiguous`: 검출 얼굴과 선택 몸의 연결 문제. 인식 정답률/메인 선택 성능과 별도 집계.
- `scope_invalid`: 같은 track으로 주어진 표본이 동일인이라는 근거가 성립하지 않음.

## 후속 실행 범위 초안과 남은 확인

현재는 조사·설계만 승인된 상태다. 사용자에게 한 번에 확인할 후속 범위는 다음과 같다.

- 제공2영상 로컬 확보·해시/메타데이터·표본/정답 준비.
- 공식 AuraFace의 인식 ONNX1개 및0095의 FP32 XML/BIN2개와 라이선스 확보. 0009/부속 얼굴·나이/성별 모델은 이 범위에서 제외.
- 기존 W14 격리 경로의 별도 평가 venv에서 필요한 CPU 런타임 준비와 최소 평가 adapter 작성. 기본 SDK·앱·W13·기존 plugin venv를 바꾸지 않는다.
- 정확한 파일/전처리/실행 manifest 확인을 통과하면, 기존23참조+406얼굴을 같은 조건으로 비교한다. 단일 worker CPU1/batch1/10분/4GiB RSS, 새 산출물2GiB 상한을 우선 제안한다. 설치/모델 보관 공간과 미디어 보관 공간은 추론 산출물 상한과 구분해 실행 전에 고정한다.
- 새 영상은 정답/관측 목록과 호출 수를 먼저 잠근 뒤 평가한다. 정답이 부족하면 동작 확인/점수 표만 만들고 정확도 개선을 선언하지 않는다. Windows 실행 장비 확보 전에는 Mac 결과를 Windows 검증으로 표시하지 않는다.
- 제품 통합/기존 결과 교체·빌드 배포·유료 API는 후속 별도 범위다.

정확한 runtime 버전/실제 weight 텐서·정규화·파일 hash·독립 정답은 아직 미확인이다. 위 초안은 실행 권한을 스스로 부여하는 문서가 아니다. 앞서 사용자가 “조사·후보 선정이며 이 메시지만으로 다운로드/설치/실행/코드 수정하지 말라”고 지정했으므로 실행 단계로 전환하는 확인이 필요하다. 영상 URL 제공/준비 진행의 `응`을 모든 모델 실행 승인으로 확대하지 않았다.
