# W14 — 같은 얼굴의 입력 위치·정렬 변화와 오확정 충돌 진단

작성: 2026-10-14. 사용자 “진행해줘”에 따른 기존 모델·승인된 로컬 얼굴 평가의 연속 작업. Superpowers systematic-debugging의 evaluation spike로 실행했다. 제품 적용이나 모델 교체 완료 보고가 아니다.

## 1. 쉬운 결론

- 얼굴이 다른 사람에게 잘못 연결되는 문제만으로 현재 혼동을 설명할 수 없다. 조사한 충돌 시점에서 기존/새 얼굴 상자는 같은 메인 머리를 가리키며, 인식 단계의 점수는 입력 상자·5점 변화에 따라 크게 달라진다.
- 4K 원본에서 YuNet이 얼굴 위치·눈·코·입을 다시 찾게 하면 일부 결과가 좋아진다. 같은 정답 얼굴34개 중 확정정답 SFace16→18, Aura18→19, Intel7→10. 세 모델 모두 이34개에서 잘못된 멤버 확정0이다.
- 그러나 전면 교체는 채택하지 않는다. Aura의57–63초 충돌은 해소됐지만 다른21.889–27.294초 구간에서 새 충돌이 생겨 다니엘 배정이 보류됐다. SFace의57–63초 혼동도 계속된다. 4개 얼굴은 새 연결 기준에서 추가 보류됐다.
- 현재 단계는 **입력에 민감한 실패를 구체적으로 재현하고 개선/악화를 분리한 상태**다. 전체 안무 품질 개선·최종 모델 선택·제품 통합은 미완료다. 사용자에게 새 라벨 입력을 요구하지 않는다.

[변경 전후 멤버·클립·얼굴 비교](http://127.0.0.1:58261/native-face-input-v1/index.html). 첫 화면은 AuraFace/57–63초이며, ‘다니엘 배정 보류 사례’ 버튼으로 나빠진 사례도 바로 볼 수 있다. 확인 내용을 입력하거나 내보낼 필요가 없는 읽기 전용 화면이다.

## 2. 고정한 것과 바꾼 것

W13-35의 저장 main/segments/pose snapshot을 읽었다. 현재 W13-40 결과에 대한 평가가 아니다. 안무 메인·몸·구간·참조23장·인식 가중치·모델별 gallery·threshold·시간 선택은 동일하다. 제품/core/W13 코드와 사용자 원문 정답을 변경하지 않았다.

기존: 1920×1012에서 찾은 YuNet bbox/5점을 3840×2026 좌표로 축별 변환해 실제4K 픽셀에서 정렬·인식.
시험: 동일 YuNet 가중치로3840×2026 전체 프레임에서 bbox/5점을 다시 찾고 같은4K 픽셀에서 정렬·인식.

따라서 bbox와5점이 함께 바뀐 대조다. ‘랜드마크만의 효과’, 새로운 모델의 효과, 단순 확대의 효과로 부르지 않는다. 새 얼굴도 같은 pose-head 연결 규칙을 통과하고 기존 선택얼굴과 IoU≥0.5여야 한다. 기존 GT가 있으면 정확한frame/label ID도 같아야 한다. 정답은 선택·임계값 조정에 사용하지 않고 동일 얼굴 비교 확인에만 쓴다.

먼저43표본(기존 이름GT34+이름없는기존답변1+진단8)을 고정해 시험했다. 이후 특정 사례만 좋아지는지 확인하기 위해 이전243표본 전체로 확장 계획을 고정하고 실행했다. 세 선택법은 각99슬롯 그대로다. 기존 unavailable28개를 복원하는 실험이 아니며 검출 recall 향상은 측정하지 않았다.

## 5. 채택 여부·남은 작업

1. 4K 얼굴 입력과 표본 간격 선택은 조사 후보로 유지한다. 이번 ‘전체프레임4K재검출’은 전면 적용하지 않는다. 개선 얼굴과 손실/새충돌을 모두 보존한다.
2. 다음은 **같은 메인 얼굴의 작은 입력 변화가 다른 멤버 확정으로 뒤집히는 불안정성**을 고정된 성공/실패 세트에서 평가한다. 모델을 또 바꾸거나 이번 두 시점만 맞추도록threshold를 조절하지 않는다. 입력 변화가 큰/상충하는 근거를 언제 보류할지, 실제 다른 사람이 섞였을 때는 반드시 충돌로 남길지를 함께 검증한다. 강한다수만 남기는 임의규칙을 제품에 넣지 않는다.
3. 인식가능 메인얼굴을 가진 별도촬영자료, 독립된 개발/평가분리와메인범위정답이 있어야 최종모델/제품연결 판단을 할 수 있다. 현재 작은/흐린배경얼굴에 이름을 억지로 추가하지 않는다. 사용자추가입력은 지금필수가아니다.
4. 모델이 완벽하지 않아도 안전하게 보류하는 정책과, 식별가능한 얼굴의 과도한미매칭을 함께 비교해야 한다. 단일얼굴·track·메인범위·제품실행 성공을 분리한다.
5. Macarm64/Windowsx64 패키징, 깨끗한사용자환경, 모델/런타임license고지, cold/warm/p50/p95는 제품채택 전 남은 gate다. 이번에 새 license판정/최신모델조사를 수행하지 않았다.
