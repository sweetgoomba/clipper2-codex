## 1. 얼굴 모델 교체의 정확한 범위

**SFace → AuraFace v1 교체는 공통 얼굴 특징 추출기에 적용됐고, 인물과 안무 하이라이트가 모두 사용한다.**

| 단계 | 현재 구현 | 범위 |
| --- | --- | --- |
| 얼굴 위치·5개 특징점 검출 | OpenCV YuNet | 유지 |
| 얼굴 정렬·특징 벡터 추출 | 공통 `clipper_face_core.auraface.AuraFaceRecognizer` | SFace에서 AuraFace v1으로 교체 |
| 모델 파일·검증 정보 | 공통 `clipper_face_core.face_models` | 같은 `glintr100.onnx`, SHA-256·크기 사용 |
| 실행 런타임 | ONNX Runtime 1.31.0, CPUExecutionProvider | 두 플러그인 의존성에 고정 |
| 사람·포즈 검출 | YOLO 계열 기존 경로 | 얼굴 모델 교체와 별개로 유지 |
| 인물별 묶기·구간 구성 | 각 플러그인의 후속 로직 | 전부 동일한 파이프라인으로 합친 것은 아님 |

호출 경로:

- 인물: `person_highlight/app.py:load_models` → 공통 `OpenCvFaceBackend` → 공통 `AuraFaceRecognizer`.
- 안무: `services/pipeline.py:create_default_pipeline` → `FaceClusterService` → 같은 `AuraFaceRecognizer`. 영상 얼굴과 참조 인물 사진 모두 여기서 특징을 추출한다.
- 안무 참조 매칭 adapter는 공통 `build_gallery`, `match_reference`, `combine_reference_matches`를 사용한다. 모델 SHA와 정렬·전처리 버전도 AuraFace 기준으로 전달한다.
- 인물은 공통 `group_observations` 뒤에 인물 전용 추적·얼굴/몸 연결·`identity_refinement`를 수행한다. 이번 인물 과분리 개선 전부가 안무에 자동으로 적용된 것은 아니다.
- NestJS 카탈로그·설치 확인과 Electron 모델 경로·용량 표시도 두 플러그인을 AuraFace로 변경했다.
- 가중치를 다시 학습하거나 사용자의 인물 사진으로 파인튜닝한 작업은 아니다. 배포된 모델을 교체하고, 정렬·비교·추적·그룹 연결을 개선했다.
- 기존 완료 프로젝트를 자동 재분석하지 않는다. 새 실행의 결과와 기존 저장 결과를 구분해야 한다.
- 안무에도 바뀐 임베딩이 들어가므로 실제 안무 영상의 인물 배정 품질·문턱 적합성은 병합 전에 별도 점검해야 한다. 단위테스트 통과는 정확도 개선의 증거가 아니다.
- macOS Apple Silicon 실행은 확인했고, Windows 실기 검증은 사용자가 하기로 했다. 인텔 Mac은 요구 범위 밖이다. 라이선스 우려 설명 후 사용자가 AuraFace 사용을 승인했으며, 법적 무결성 보증으로 기록하지 않는다.

## 2. 인물 분석·장면 구성

- 원본 영상 → 얼굴/몸 관측 → 추적 및 인물 그룹 → 공통 음성 분석 → 인물별 재생 구간 구성 → 대표/장면 이미지와 메타데이터 저장 순서다.
- 여러 각도의 얼굴 근거를 보존하고, 시간적으로 연속된 얼굴 연결·조명 변화에 의한 거짓 컷·짧은 조각의 기존 인물 연결을 개선했다. 동시 등장·경쟁 인물·약한 근거는 합침을 제한한다.
- 잘린 장면을 무조건 합치거나 유사도만 일괄 완화하지 않는다. 최종 refinement는 얼굴/몸 reconciliation 뒤에 한 번 수행하고, 후보를 실제 관측 근거로 다시 확인한다.
- 대사 하이라이트와 음성 분석을 공통화한 현재의 문맥 기반 장면 구성을 유지한다. “잠깐 박수치는 순간도 놓치지 않는다”는 요구와 현재 구간 구성의 완전한 일치는 미검증이다.
- 한 인물이 잠깐 나온 뒤 다른 인물만 오래 나오는 문제를 줄이도록 인물별 구간을 먼저 구성한다. 서로 다른 인물은 재생 시작·끝이 정확히 같을 때에만 가상 장면을 공유한다.
- 기본 앞뒤 패딩은 각각 **0.25초**이고, 인정된 인접 컷 경계를 넘지 않도록 제한한다. 관측 간격에 따른 등장 끝 추정과 별개다.
- 카드의 시간과 길이 표시는 실제 재생 구간 기준으로 통일했다. 여러 appearance span의 합을 재생 길이처럼 표시하지 않는다.
- 분석 완료 시 모든 장면 MP4를 미리 생성하지 않는다. 구간 편집 저장은 범위 메타데이터 변경이며, 다운로드·숏폼 생성 시 필요한 구간을 영상으로 만든다.
- 동일 인물 과분리·오합침·비얼굴 대표 문제는 개선했지만 종결 판정하지 않는다. 후보 수 감소만으로 정확도 향상을 단정하지 않는다.

## 3. 성능·메모리

- 낮은 점수/크기 등 기존 조건으로 제외될 얼굴에는 불필요한 AuraFace 추론을 생략한다. 얼굴 존재 확인에는 검출만 사용한다.
- GPU 몸 추론과 CPU 얼굴 추론은 한 프레임·한 worker 범위에서 겹쳐 실행하며, 결과는 원래 순서로 추적기에 전달한다. CPU 또는 가용 메모리 부족/조회 실패 시 직렬 실행한다.
- 시각 단계 이후 모델과 가속기 캐시를 해제한다. 취소/예외 때 worker와 예외 프레임이 모델을 붙잡지 않도록 정리한다.
- 동일 시각 썸네일 재사용, 한 프레임씩 처리, JSON 스트리밍과 별도 float32 NPY 저장으로 중복 디코딩·직렬화 비용을 줄였다.
- 잡별 `json/performance.json`에 단계 시간·개수·RSS·장치를 기록한다. 중첩·병렬 시간은 합산하면 안 된다.
- 10/22 기록: 동일 22:25 원본에서 이전 앱 실행 10:37과 최적화 오프라인 파이프라인 7:06을 비교했다. 캐시/앱 준비 비용 차이가 있어 완전히 동일한 E2E 비교는 아니다. 제어된 120초 분석 비교는 56.666→35.381초였다.
- 병렬 추론의 peak RSS 감소는 입증하지 못했다. 메모리 보관/직렬화 개선과 추론 peak 개선을 구분한다.
- 상세 근거: Python 저장소 `docs/superpowers/plans/2026-10-22-person-performance-results.md`, `docs/superpowers/reviews/2026-10-23-person-fragmentation-v3-results.md`.

## 4. 결과 화면·편집·내보내기

- 인물 후보는 장면 수 내림차순, 최초 선택은 가장 위 카드. 기본 Person 이름은 ‘인물’로 표시한다.
- 장면 2개 이하 후보를 일괄 숨기는 규칙은 철회했다. 미확인 인물 bucket은 UI에서 숨기는 결정을 유지한다.
- 후보 카드 이미지는 100×100px, 생성 대표 이미지 256×256px. 별도 인물 섹션·대표 변경 버튼은 현재 화면에서 제거했다.
- 카드 아이콘은 hover 시 표시하고 세로 중앙 정렬한다. 인물 삭제와 장면 소속 제거에는 공통 확인 모달을 사용한다.
- 체크박스는 장면 선택, 카드 본문 클릭은 원본 구간 미리보기. 모달 자동 재생·구간 상대 시간(0부터)·이전/다음·선택 동기화·구간 편집/취소를 지원한다.
- 모달을 닫으면 카드의 열림 강조가 해제된다. 선택하지 않은 카드의 썸네일/문구를 어둡게 하지 않는다.
- 체크된 장면은 곧바로 최종 숏폼 미리보기에 반영하지 않는다. 상단 더보기에서 선택 ZIP, 숏폼 구성, 현재 인물에서 제거, 다른 인물로 이동을 실행한다.
- 선택 카드 드래그는 체크된 장면 묶음을 이동한다. 미선택 카드를 끌면 그 카드만 선택해 이동한다. 드래그 이미지에 장면 개수를 표시한다. 개별 카드 이동 버튼으로 한 장면만 옮길 수도 있다.
- 인물 카드 드래그 병합 후 스낵바를 표시한다. 장면/인물 제거는 다른 인물의 소속과 원본 영상을 지우지 않는다.
- 숏폼 구성 모달: 큰 16:9 원본 미리보기, 전체/한 장면 재생, 가로 스크롤 장면 순서, 드래그 정렬. 재생 장면을 자동 강조하고 보이는 위치로 스크롤한다. 순서 변경 시 바꾼 장면부터 다시 재생한다. 적용 전에는 기존 미리보기 순서를 바꾸지 않는다.
- 템플릿/타이틀·출처/전환 효과는 기존 공통 숏폼 UI를 재사용한다. 결과 화면 원본 YouTube URL 복사도 지원한다.
- 인물 하이라이트의 과금 확인과 큐 진입 전 중복 클릭 방지는 기존 공용 과금 흐름에 연결했다. 이번 체크포인트에서 실제 결제망은 검증하지 않았다.

앱 빌드: `npm run build:app:mac:arm64:local-api`. 결과는 Electron 저장소 `dist-app/mac-arm64/Clipper Studio (dev).app`. 실행 중 앱의 산출물 디렉터리를 재빌드로 삭제하면 lazy chunk/리소스 오류가 생길 수 있으므로 정상 종료 후 교체하거나 별도 출력 경로를 사용한다.
