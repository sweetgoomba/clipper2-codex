## 코드 수정

- Python Person adapter는 같은 프레임에서 작은 box의 75% 이상을 포함하고 IoU가 0.2 이상인 중첩 얼굴을 한 관측으로 보존한다. 모든 별개 얼굴은 남긴다. 밝기 변화가 작아도 색 분포가 크게 바뀐 컷을 잡도록 shot 판정을 넓혔다. 원본 앞 20초를 **추론 없이 읽어** 새 판정이 `2.5, 5, 6.5, 8, 10, 11.5, 12.5, 13.5, 16, 16.5, 19.5`초를 자르는 것을 확인했다. 전체 영상 컷 정답/오탐은 검증하지 않았다.
- 분석 결과 clip은 한 shot 안에서 겹치는 관측 window를 하나로 합치고 `person_ids`를 합집합한다. 같은 scene ID라도 겹치지 않는 source 경계는 별도 clip으로 남기며, Nest의 사용자 편집 경계는 변경하지 않았다. **기존 artifact의 interval만 새 clip 규칙에 대입한 오프라인 시뮬레이션**은 1,301→580개, 중앙값 2→3초, 3초 미만 944→280개였지만 shot ID는 이전 것이어서 새 전체 결과의 예측값이 아니다. 이전 shot ID를 그대로 쓰면 최대 54초/28그룹 clip도 만들어져 새 컷 판정과 실제 영상 검증이 중요하다.
- 공용 얼굴 관측 DTO에 선택적 `sharpness`를 추가하고 OpenCV Laplacian 선명도 값을 전달한다. 대표 관측과 후보는 선명도를 더 반영해 순위를 매긴다. 원본 자체가 작고 흐린 경우 복구할 수 없다. 단일 관측 그룹은 숨기지 않고 `needs_review`로 표시한다. 기존 결과/사용자 지정 대표 이미지는 자동으로 덮어쓰지 않는다. W13 기존 소비자는 새 선택 필드를 읽지 않아도 된다.
- Angular 결과에서 `함께 등장 n명` badge와 표시 전용 코드를 제거했다. 장면의 다대다 `personIds`는 실제 소속·export에 필요하므로 유지한다. 공통 trimmer에 선택적 viewport를 추가해 Person의 짧은 장면을 최소 12초 폭으로 확대하고 75%씩 좌우 이동한다. 기존 편집기는 viewport 없이 전체 길이를 쓴다. 보기에서는 핸들 없이 선택 구간 재생, 편집에서는 핸들 및 저장/취소, 일시정지 중 경계 밖 프레임 확인이 가능하다.

## 검증과 남은 입력

먼저 실패하는 회귀를 확인한 뒤 Python Person/core 14개 테스트 통과, ruff 통과. Angular Person/trimmer 집중 18개, 전체 Chrome Headless 5,449개 통과; `CI=1 NG_BUILD_CACHE_STORE=sqlite` devapp 빌드 통과, TypeScript `--noEmit` 통과. 빌드와 테스트를 동시에 실행하거나 `CI=1` 없이 실행하면 Angular compiler cache 오류가 있었고, 순차 `CI=1` 빌드에서 통과했다. 사용자 완료 artifact는 이전 코드의 결과이며 **새 코드로 37분 영상 재분석·GT 정확도 측정은 하지 않았다**. 새 결과의 인물/interval recall, false merge/split, 대표 이미지 개선량, 실제 clip 수·길이, 편집 UX 실사용, Windows/패키징은 미검증이다.

특히 사용자 지정 동일인 5/6/8/13은 중첩 검출 한 사례만 직접 완화했다. 작은/측면 얼굴에서 같은 사람을 자동으로 모두 합친다는 보장은 없다. 이 사례의 익명 GT와 다른 사람 동시 출연 라벨을 함께 고정해 누락과 오합침을 따로 측정해야 한다. 향후 실제 ML 비교는 기존 [평가 manifest](../09/30-w14-evaluation-manifest.yaml)의 경로/hash·최대 3×120초·모델/OS/device/시간/자원/출력 상한을 확정한 뒤 진행한다. 새 모델 다운로드·외부 유료 API·Build5는 별도 범위다. W13 소유권/호환성 검토도 대기 중이다.
