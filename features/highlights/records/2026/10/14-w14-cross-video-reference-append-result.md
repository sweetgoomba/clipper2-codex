## 4. 시행착오·검증·공통 계약

1. 첫 요약 스크립트에서 정답 없는 관측의 None을 정답처럼 다뤄 gains/losses 목록에 포함한 문제를 발견했다. 예측/known 수치에는 영향 없음. `attempt1-*` 보존 후 known 정답만 집계하도록 수정, 회귀 테스트 실패→통과. 첫 비교 계획 rev2로 재잠금했다.
2. 기존 확정 보존의 첫 진단에는 invalid 관측 하나가 run 전체를 거부하는 과도한 veto가 들어갔다. 독립 리뷰에서 발견. 첫 결과 SFace13/Aura12 배정은 이 추가 veto의 결과이며 충돌 증가 탓으로 해석하면 안 된다. `preserve-attempt1-*` 보존.
3. 기존 합의의 이름 배정 원칙에 맞춰 invalid 관측은 별도 기록하고 근거에 보태지 않되, 유효한 충분한 근거를 막지 않도록 수정했다. 실패1/통과11→통과12. 이것은 몸 경로 사이의 이름 전파 허용이 아니다.
4. 최종 관련 테스트109통과. 원래353×2 + 외부34×2 =774얼굴 판정 재현. 독립 리뷰에서 첫 계획78입력 hash, 모델별387관측의 source 제외/space/policy/evidence 일치, 서로 다른 gallery fingerprint 보존, 지표와 35대상 이름 전후 재집계 확인.
5. 두 gallery 결과를 하나의 공통 `ReferenceMatch`인 척 만들지 않았다. 별도 `evaluation_two_gallery_evidence_v1` 결과에 둘 다 저장. core의 gallery 일치 검사 우회/공개 API 변경 없음. 원래 core와 이 평가 wrapper의 사유 문자열 전체가 동일하다는 주장도 하지 않는다.
