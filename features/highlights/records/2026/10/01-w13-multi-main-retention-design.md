# W13 메인 여러 명·보류 보존 설계 정정 — 2026-10-01 KST

상태: **사용자 원칙을 반영한 설계안**. 제품 코드와 기존 앱 결과는 변경하지 않았다. 새 모델 평가도 실행하지 않았다.

## 사용자가 정한 원칙

- 한 사람이 분명히 앞에서 주도하면 그 사람을 메인으로 본다.
- 같은 구간에 주도하는 사람이 여러 명이면 **메인을 여러 명** 둘 수 있다. 같은 원본 장면이 여러 인물 카드에 들어가도 된다.
- 누구인지 또는 누가 메인인지 확실하지 않은 장면은 **보류 목록에 남겨 검토**한다. 불확실하다는 이유로 장면을 조용히 버리지 않는다.

제가 먼저 물었던 **의상 색과 멤버 이름의 대응은 현재 결정할 일이 아니다**. 의상 색은 특정 무대에서 사람을 눈으로 따라가는 임시 단서일 수 있을 뿐, 멤버 신원의 정답이나 사용자에게 제출받을 필수 정보가 아니다. 메인 선정/장면 보존 평가에서는 동일 인물을 구분하는 임시 ID(`P1`, `P2` 등)를 쓸 수 있다. 실제 멤버 이름의 정확도는 독립적으로 확인된 신원 라벨이 생긴 구간에서만 계산한다.

## 현재 코드와 충돌하는 지점

Python `MainSelector.select()`는 프레임마다 한 사람만 반환하고 `FrameRec`도 `main_id/main_bbox` 하나를 저장한다. 나머지 출연자의 위치 경로는 평가 adapter나 최종 `dance_meta_v1`에 남지 않는다. 그룹 표시가 있어도 `_filter_group_like_main_segments()`는 겹침이 큰 **메인 구간 전체를 제거**한다. 얼굴 평균을 만들지 못한 남은 메인 구간도 clip 생성 전에 제거한다. Nest의 `dance_clip_assignments[clipId]`는 목적 `personId` 하나만 저장하며 기존 UI의 이동은 한 사람에게 옮기는 동작이다. 현재 제품에는 한 장면을 동시에 여러 인물에게 배정하는 계약이 없다.

기존 영상 `yFTAYXDTjqI`에서는 그룹 겹침 때문에 `20.487~30.030`초와 `30.030~34.835`초 메인 후보가 제외됐고, 실제 그룹 clip은 `23.357~33.433`초만 차지한다. 이 사실은 **보존/보류 필요성을 보여주는 사례**이며, 그 구간의 정답 메인 인원·이름은 아직 확인되지 않았다.

## 제안하는 분석·편집 계약

장면에는 안정적인 `scene_id`와 원본 시간 `[startMs,endMs)`를 부여한다. 메인 판단은 단일 `person_id`가 아닌 **후보 사람/track ID 집합**으로 남긴다. `group`은 별도 표시이며 메인 집합과 동시에 참일 수 있다. 사람별 bbox/track, 각 후보의 근거·불확실성, 자동 판정 revision과 사용자 수정 revision을 분리해 기록한다.

| 관측 | 저장/화면 처리 |
|---|---|
| 메인 한 명이 분명함 | 그 한 명에 배정 |
| 두 명 이상이 분명히 공동 메인 | 확인된 사람 모두에 배정, 같은 장면을 여러 카드에서 참조 |
| 출연자는 보이나 메인 또는 신원이 불확실함 | 원본 구간·후보·이유를 `확인 필요`에 보존; 자동으로 모든 멤버에게 붙이지 않음 |
| 출연자 없는 도입/종료 화면 | `비안무`로 명시; 누락 장면으로 세지 않음 |

**장면 보존과 신원 확정은 별개다.** 얼굴 표본이 없어도 장면/track 후보는 보류 목록에 남는다. 사람 이름을 모르는 후보에게 임의의 기존 멤버 이름을 붙이지 않는다. 사용자가 여러 인물에 배정하면 `scene_id → person_id 집합`을 edit revision에 기록하고 한 번에 되돌릴 수 있어야 한다. 같은 trim/화면이면 MP4 하나를 여러 카드가 참조하는 방식부터 검토하고, 인물마다 다른 follow crop이 필요할 때에만 별도 렌더 필요성을 판단한다. 다른 사람에게 배정했다고 그 사람의 crop track이 자동으로 생기지는 않는다.

## 비교 평가의 변경

정답표는 시간 구간마다 `dance_active`, `main_track_ids[]`(0명·1명·여러 명), `group`, `needs_review`, `candidate_track_ids[]`, 각 사람 bbox와 신원 확인 상태를 분리한다. `P1` 같은 임시 ID는 **같은 영상 안에서의 사람 연속성**을 뜻하며 멤버 이름이 아니다. 한 장면에 두 명이 정답이면 현행 1명 예측은 맞힌 한 명을 인정하면서 다른 한 명의 누락도 기록한다. 완전 오답 하나로 뭉개지 않는다.

- **메인 선정:** 사람별 시간 가중 recall(놓친 메인), precision(불필요하게 붙인 사람), 집합 일치, 추가/제거 전환 지연을 나눠 기록한다. 그룹 판단은 별도 지표다.
- **보존:** 정답상 안무 구간 중 `자동 배정됨`, `확인 필요로 남음`, `어디에도 보이지 않음`의 시간을 따로 기록한다. 보류는 보존 성공이지만 인물 판정 성공은 아니다. 보류량과 사용자 수정 부담도 표시한다.
- **신원:** 멤버 이름이 독립적으로 확인된 사람/구간에서만 조건부 identity precision·unknown 오배정률을 낸다. 임시 ID나 기존 앱의 예측 이름을 정답 이름으로 대체하지 않는다.
- **중복 배정:** 같은 장면을 여러 명에게 배정한 경우, 맞는 사람을 더 살렸는지와 잘못 붙인 사람을 늘렸는지를 동시에 본다.

첫 단계는 기존 앱 artifact와 원본 전체 구간을 이 기준으로 **읽기 전용 검토**하는 것이다. 현재 평가 adapter는 1명 main과 탈락 구간을 관측할 수 있지만 다른 출연자의 track을 재구성하지 못한다. 다중 메인 자동 판정/인물별 crop/다중 카드 배정은 별도 제품 계약·구현 범위다. 한 번에 모델·tracker·UX를 모두 바꾸지 않고 보류 보존과 다중 메인 판정을 따로 비교한다. 실제 ML 실행 전에는 기존 manifest의 입력·라벨·weight·장치·횟수·시간/자원 상한·출력 위치를 확정한다.
