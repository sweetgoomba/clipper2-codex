# W14 — SeetaFace6 일반형 얼굴 매칭 비교 결과

2026-10-14. 사용자가 승인한 제한 범위에서 SeetaFace6 일반형 `face_recognizer`를 기존 SFace 및 AuraFace와 비교했다. **안무 영상의 일부 얼굴에서는 개선됐지만, 다른 두 영상에서 기존 SFace보다 정답을 더 많이 놓쳐 사전 통과 기준을 충족하지 못했다. 제품에는 연결하지 않는다.** 제품 기본 모델은 YuNet + SFace이고 AuraFace는 비교 후보로 남긴다. 인물 하이라이트 기능 개발과 W13 안무 제품 코드는 이번 작업에서 변경하지 않았다.

## 1. 승인 범위와 파일 출처

승인된 공식 `sf6.0_models.zip` 301,479,618바이트와 고정 revision `3cefcf6896a2e7268add82ea89f720271a825157`의 ONNX 102,530,399바이트를 받아 총 404,010,017바이트를 전송했다. 상한은 450 MiB였다. 압축에서는 `face_recognizer.csta` 한 파일만 추출했다. 공식 압축 안의 파일과 변환 저장소가 제공하는 원본 CSTA의 Git blob SHA-1이 바이트 단위로 일치한다. 다른 Seeta 모델은 추출하거나 실행하지 않았다.

| 파일 | SHA-256 | 실제 확인 |
|---|---|---|
| 공식 압축 | `57d339895915b73f19b986f1def66eed8b51975e8b0e74eeb12c656277230800` | 공식 링크에서 수신 |
| 원본 `face_recognizer.csta` | `3cefce29d2ceb6fd95153d67c11f24ce08746e1877478bacaa5ae5d333a0a670` | 압축 멤버와 고정 원본 미러 일치 |
| 변환 `face_recognizer.onnx` | `1225ab4edd7b677df724e013a2eddb35d5ce1bb0d2ef4d0f4d50243ef21f9389` | 고정 revision과 Git blob 확인 |

원본 설정은 256 × 256 BGR 얼굴 정렬, 중앙 248 × 248 crop, float32 CHW, 외부 255 나눗셈 없음, 1,024차원 출력의 제곱근 1회 및 L2 정규화다. 실제 ONNX 입력은 `[1,3,248,248]`, 출력은 `[1,1024,1,1]`이며 마지막 연산은 ReLU다. 임의 입력과 첫 참조 사진에서 원본 CSTA 그래프의 NumPy 실행과 ONNX Runtime 출력 차이의 최대 절댓값은 각각 `0.0000434`, `0.0001221`이었다. 두 입력 모두 음수 출력이 없고 정규화 벡터의 cosine 차이는 `0.000001` 미만이었다. 이는 **제3자 변환과 해석기 사이의 대조**이며 원래 TenniS 런타임이나 픽셀 샘플러와의 독립 일치 검증은 아니다.

공식 프로젝트의 상업 이용 및 BSD 2-Clause 안내와 변환 코드의 MIT 조건을 실행 전 조사에서 확인했다. 이번 결과는 특정 파일의 출처와 시험 가능성을 뒷받침하지만, Mac·Windows 설치 앱에 넣을 때 필요한 고지, 네이티브 의존성, 두 운영체제의 실제 패키징까지 확인한 것은 아니다. [실행 전 출처·라이선스 검토](14-w14-standard-recognition-probe-preflight.md).

## 2. 고정 입력과 결과

원래 참조 사진 23장, 개발 자료 135행, 안무 얼굴 관측 353행, 다른 두 영상의 얼굴 34행을 사용했다. 모두 같은 원본 프레임, YuNet 얼굴 상자와 5점, 안무 메인 몸과 몸 경로·구간을 유지했다. 총 545행에서 499행의 특징을 계산했다. 나머지는 기존 연결 실패 44행과 정렬 불가 2행으로 각각 기록했다. 이번 인식 모델의 새 추론 오류는 0건이다. 모델마다 필요한 입력 전처리는 각각 적용했고, 특징·참조 캐시·거리 기준은 서로 섞지 않았다.

| 확인 자료 | SFace 정답 / 오확정 / 보류 | AuraFace | SeetaFace6 일반형 |
|---|---:|---:|---:|
| 안무 얼굴 34개 | 18 / 0 / 16 | 19 / 0 / 15 | 20 / 0 / 14 |
| 그중 식별 가능한 28개 | 15 / 0 / 13 | 17 / 0 / 11 | 19 / 0 / 9 |
| 다른 두 영상에서 식별 가능한 19개 | 15 / 0 / 4 | 17 / 0 / 2 | **13 / 0 / 6** |
| 별도로 확인한 메인 인물 2시점 | 1 / 0 / 1 | 0 / 1 / 1 | 2 / 0 / 0 |

일반형은 안무의 식별 가능한 얼굴에서 SFace보다 4개를 더 맞혔고 1개의 기존 정답을 놓쳤다. 다른 두 영상에서는 1개를 새로 맞혔지만, 기존 SFace가 맞혔던 3개를 놓쳤다. 이 3개는 일반형에서도 정답 멤버가 점수 1위였으나, 개발 자료에서 고정한 거리 기준을 넘어서 보류됐다. 사후에 이 자료에 맞춰 기준값을 바꾸지 않았다. 개발 자료의 이름 있는 128행에서는 SFace 59개, AuraFace 34개, 일반형 32개가 정답으로 확정됐다. 일반형의 기준 `최대 거리 0.2967339754`, `최소 후보 차이 0`은 개발 자료의 잘못된 확정 0건 조건에서 고정했다. 이 수치는 제품용으로 검증된 기준이 아니다.

일반형은 확인된 105.105초 해린과 25.759초 다니엘을 각각 맞혔다. 61.6616초 혜인도 맞혔으며, 해당 안무 구간의 뒤쪽 몸 경로에서는 혜인 근거를 보존했다. 등록 후보 밖 인물 얼굴 5개와 비얼굴 1개에는 이름을 붙이지 않았다. 안무의 35개 메인 대상 중 이름이 붙은 수는 SFace 16개, AuraFace 13개, 일반형 18개다. 이 수는 **전체 구간 정답률이 아니다.** 확인된 얼굴 및 두 메인 시점에서 일반형의 몸 경로·구간 모순은 0건이었다.

## 3. 사전 기준 판정

실행 전에 정한 기준은 식별 가능한 안무 28개와 추가 영상 19개에서 각각 SFace 이상의 정답을 유지하고, 적어도 한쪽에서 정답을 늘리되 오확정을 늘리지 않는 것이었다. 105.105초 해린, 등록 외 인물 거부, 확인된 몸 경로 충돌도 유지해야 했다. **추가 영상은 13개 대 SFace 15개이므로 불통과다.** 다른 조건의 통과를 이유로 제품에 연결하지 않는다. AuraFace 역시 독립 검증 전까지 비교 후보일 뿐 제품 모델 교체 결정은 없다. SeetaFace6 Light는 별도 가중치이며 앞선 실험에서 미채택됐다. 이번 일반형 결과를 Light 결과와 혼합하지 않는다.

안무 34개 얼굴 라벨은 개발 자료와 같은 프레임이므로 독립 평가가 아니다. 다른 두 영상의 34개 얼굴도 이미 확인한 회귀 자료다. 28개와 19개를 독립적인 많은 표본으로 취급하거나 전체 영상의 매칭률 향상으로 일반화할 수 없다. 다음에 제품 교체를 검토하려면 새 촬영 영상의 독립적인 식별 가능 메인 얼굴·몸 경로·구간 정답과 Mac Apple Silicon 및 Windows x64 패키징 검증이 필요하다. 현재 사용자에게 추가 라벨이나 파일 내보내기를 요청하지 않는다.

## 5. W13 인계와 다음 범위

W14는 공통 얼굴 API, 검증 입력과 격리 비교를 소유하고 W13은 안무 메인 몸, 추적 경로, 구간, 멤버 연결, crop과 제품 adapter를 소유한다. 일반형의 원본/변환 SHA, single 256 정렬, 248 BGR 입력, 제곱근 후처리, L2, 거리 정의를 별도 embedding 공간과 참조 캐시 키로 취급했다. 기존 SFace/Aura/Light 특징, 캐시 또는 기준값과 섞지 않는다. 이번에는 공통 API나 선택 의존성을 바꿀 근거가 없다.

다음 작업은 모델 기준을 이 회귀 자료에 맞춰 반복 조정하는 것이 아니다. W13의 실제 메인/몸 경로/구간에 대해 **독립 영상의 식별 가능한 얼굴과 구간 정답을 먼저 고정**하고, 기존 SFace의 표본 수집·얼굴 연결·보류 원인과 모델 자체의 오류를 분리해야 한다. 그 결과로 후보가 다시 유효해질 때 계약 확인 → 기존 소비자 호환성 검증 → 선택 가상환경·모델 준비 → Apple Silicon / Windows x64 설치 검증 → 합의한 순서의 병합으로 진행한다. Mac Intel은 이번 지원 범위 밖이다. 다른 채팅으로 메시지를 보내거나 새 세션을 만들지 않았다.
