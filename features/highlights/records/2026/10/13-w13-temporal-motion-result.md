### 저장 코드·결과에서 확인한 사실

- `tools/w13_temporal_pose.py:55`의 군무는 움직임 참여 인원 신호다. 각 사람의 motion이 `max(motion_floor, 가장 큰 motion×relative_floor)` 이상인지 센다. 최소 3명이 보이고 참여 인원이 `max(3, 검출 인원×fraction)` 이상인 상태가 0.35초 지속되면 켜진다. 끌 때도 반대 증거가 0.35초 필요하다.
- MoveNet512 설정은 floor0.16/relative0.4/fraction0.8, YOLO26s는0.06/0.4/0.6. 5명 검출 시 각각4명/3명이 문턱을 넘으면 군무다. motion은 몸 높이로 정규화한 관절 동작80%+공통 이동을 뺀 몸통 이동20%를 약0.67초 평균한 특징값이며 확률이 아니다.
- **메인 점수의 우세·분포·집중도를 군무 조건에서 검사하지 않는다.** 움직임 방향/박자 일치도 검사하지 않는다. 몇 명이 함께 움직여도 특출난 메인이 있을 수 있으므로 사용자 정의와 맞지 않는다.
- `select_main()`은 검출 인물이 있는 한 반드시 한 명을 선택한다. 군무 신호를 입력으로 받지 않는다. 군무로 표시된 MoveNet1031/YOLO1144관측 전부에 메인 상자가 남았다.
- 두 모델의 메인 점수는 중앙0.36+상대 크기0.24+상대 움직임0.40. 이전08은 중앙0.45+상대 크기0.35+정적 관절길이0.20이다. 선택 전환은 현재 사람보다0.04 높은 후보가0.2초 유지하면 발생하고, 현재 track이 검출되지 않으면 즉시 새1위를 선택한다. 동률에 가까운 군무에도 강제1위가 생기므로 순위 변화/검출 잡음/추적 변경이 튐을 만들 수 있다. 각각의 기여량을 모든 전환에서 분해한 것은 아니다.
- `tools/w13_temporal_experiment.py:127`에서 군무 F1 최고 설정을 선택했고 단독 메인 오표시 상한/최종 메인 없음 검증이 없었다. 군무를 많이 찾는 효과가 큰 오표시에도 설정 채택을 허용했다. 이는 평가 설계의 한계다.

### 다음 설계 기준 — 아직 구현하지 않음

1. 여러 명의 움직임 참여 신호와 최종 '메인 없는 군무' 판정을 구분한다. 메인 후보 점수의 우세·분포와 시간 지속성을 함께 확인한다.
2. 명확한1명은 단독 메인, 소수의 명확한 우세 집합은 공동 메인, 여러 인물이 비슷하게 춤추고 특출난 집합이 없으면 군무+메인 없음. 가림·검출 실패·동작 정보 부족을 곧바로 군무로 바꾸지 않는다. 해당 구간은 판정 불충분으로 보존한다.
3. 군무 오표시로 단독·공동 메인을 지우지 않는지와 군무 속 강제 메인 비율, 잦은 전환, 실제 인계 지연을 분리해서 평가한다. F1 하나로 통과시키지 않는다. 장시간 이전 메인 유지로 진짜 인계를 늦추는 부작용도 확인한다.
4. 기존 정답표 원본은 보존한다. 중첩556관측을 새 군무 정책에서 자동으로 '메인 없음 정답'으로 변환하지 않고 별도 채점/의미 검토 대상으로 분리한다. 사용자가 정답표를 다시 작성해야 하는 상태로 되돌리지 않는다.
5. MoveNet512·YOLO26s를 계속 비교하고 제한된 위치 표본만으로 모델 우승을 선언하지 않는다. 이번 응답에서는 저장 결과를 읽어 원인을 확인했으며 새 추론·규칙 재평가·후보 코드 변경은 하지 않았다.
