# W14 인물·공통 얼굴 매칭 작업 총정리와 모델 선택 준비 상태

작성 기준: 2026-10-14 KST. 범위: 9/29 조사부터 10/14 추가 영상 22개 얼굴 비교까지. 사용자의 요청에 따라 후속 실험에 앞서 작업을 정리한 문서다. 이번 문서화에서는 새 추론·다운로드·설치·제품 코드 변경을 하지 않았다.

## 1. 먼저 결론

**공통 얼굴 매칭 모듈과 비교 도구는 구현됐고, 잘못된 얼굴 선택·표본 누락·판정 방식의 구체적인 문제를 찾고 일부 수정했다. 그러나 사용자가 원하는 안무 구간의 멤버 분류 품질은 아직 충족하지 못했다.**

현재 할 수 있는 결정은 **YuNet + SFace를 비교 기준으로 유지하고, 시험한 대체 모델을 지금 제품에 교체 적용하지 않는 것**이다. 이것은 SFace의 품질이 충분하다는 판단이 아니다. AuraFace·Intel0095가 실제 문제를 더 잘 해결한다는 근거를 얻지 못했고, 기존 ArcFace ONNX도 일부 성공 사례 외에 전체 개선과 배포 권리 확인이 부족하다.

| 사용자가 궁금한 것 | 현재 답 |
| --- | --- |
| 재사용 가능한 공통 모듈을 만들었나? | **예.** 독립 `clipper-face-core 0.2.0`에 참조 준비·얼굴별 비교·같은 사람 범위의 근거 결합과 실패 계약이 있다. |
| 안무 앱이 그 개선판을 실제로 쓰고 있나? | **W14 작업에서는 아직 아니다.** 저장된 W13 출력에 연결한 평가 adapter까지 만들었다. 제품 소비 adapter 연결·병합·설치형 배포는 남았다. |
| 얼굴 매칭이 얼마나 좋아졌나? | 특정 오확정 방지와 일부 표본의 개선은 확인했다. **전체 구간 정확도가 몇 % 향상됐다고 말할 수 있는 대조 결과는 없다.** |
| 새 모델을 실행했나? | **예.** SFace 외에 ONNX Zoo ArcFace, AuraFace-v1, Intel0095를 실제 실행했다. 조사만 한 후보와 구별해야 한다. |
| 지금 최종 모델을 선택할 수 있나? | **아직 아니다.** 시험한 후보의 즉시 교체를 보류할 근거는 있지만, 장기 채택 모델을 확정할 검증은 부족하다. |
| 가장 먼저 필요한 것은? | 실제 안무 메인 범위에서 **그 사람에게 연결된 식별 가능한 얼굴을 여러 시점 확보**하고, 구간별 정답으로 모델·표본 선택 효과를 나누어 비교하는 것. |

아래 수치는 당시 저장 기록과 결과 파일을 대조한 것이다. 과거의 테스트 통과를 이번에 재실행했다고 표현하지 않는다. 예전 문서 제목의 ‘최신’은 **당시 고정한 snapshot**이며 현재 W13 최신 버전 전체를 뜻하지 않는다.

## 2. 목표가 어떻게 바뀌었나

### 처음 목표: 인물 하이라이트 자체

참조 사진을 미리 지정하지 않고 영상 안의 같은 사람을 익명 Person 그룹으로 묶는 기능이었다. 기존 영상 선택 → 홈 작업큐 → 완료 카드 → 인물별 결과 흐름, 대표 이미지·장면 목록·원본 재생·수정·개별 MP4/인물 ZIP 등을 구상하고 시험용 앱에 구현했다.

사용자 결정은 다음과 같이 유지한다.

- 결과 화면은 왼쪽 인물 목록, 중앙·오른쪽 클립/원본 영역. 분석은 작업큐에서 수행한다.
- 인물 카드와 개별 클립의 hover 다운로드, 클립 체크박스 없음. **이어붙인 MP4/쇼츠 없음.**
- 같은 재생 막대를 보기 모드에서는 재생에만 사용하고, 편집 모드에서 시작·끝 핸들을 조절한다. 긴 원본의 짧은 구간은 주변 확대·좌우 이동으로 검토한다.
- 이름·대표 사진·재배정·병합·제외/복원·경계 편집은 사용자 overlay로 보존한다. 기본 인물 목록을 자동 배경 필터로 줄이지 않는다.
- ‘함께 등장 n명’ 표시는 제거했다. 실명 검색·얼굴=화자 판단·자동 BGM/타이틀/crop·body ReID는 기본 범위에 넣지 않았다.
- 이후 몸 실험에서 **얼굴 앵커가 전혀 없는 몸 상자만으로 인물 카드나 이름을 만들지 않는다**고 명확히 했다. 검출된 얼굴 기반 그룹 표시와 몸만의 진단값은 구별한다.

10/1 실제 사용자 영상에서 과분할·동일인 과분리·오검출·대표 이미지 품질 문제가 드러났다. 이 제품 기능의 품질은 합격하지 않았다.

### 10/13 이후 우선순위: 안무의 참조 기반 얼굴 매칭

사용자가 인물 플러그인 기능 확장을 보류하고 안무 품질을 우선하라고 결정했다. 현재 목표는 다음 경로다.

> W13이 구간과 메인 몸을 선택 → W14 평가/소비 adapter가 그 몸의 얼굴을 연결 → 공통 얼굴 모듈이 등록된 5명과 비교 → 같은 사람임이 보장되는 범위에서 근거를 결합 → 멤버 또는 미매칭/확인 필요 반환.

메인 선정·몸 추적·구간 분리는 W13 책임이다. 얼굴 매칭 모델이 이 문제들까지 해결하는 것으로 평가하지 않는다. 향후 인물 하이라이트에서도 공통 모듈을 재사용한다. [우선순위 전환 기록](13-w14-face-matching-priority-reset.md)

## 3. 모델 목록 — 실제 시험과 조사만 한 후보

### 3.1 얼굴 모델

| 모델/정확한 파일 | 역할 | 이번 세션에서 실제 한 일 | 현재 판단 |
| --- | --- | --- | --- |
| **YuNet 2023mar** / `face_detection_yunet_2023mar.onnx` | 얼굴 검출·5점 특징점 | Person·Dance의 실제 영상 검출, 크기/점수 조건 및 확대 재검출 대조 | 기존 검출 기준 유지. 작은 얼굴·비얼굴 오검출·특징점 오류는 남음. |
| **SFace 2021dec** / `face_recognition_sface_2021dec.onnx` | 얼굴 특징 128차원 | 기존 대조군. 익명 그룹화, 등록 멤버 비교, 입력·정렬·참조·합의 실험 | **당분간 기준선 유지. 품질 합격 아님.** |
| **ONNX Model Zoo LResNet100E-IR** / `arcfaceresnet100-8.onnx` | 얼굴 특징 512차원, 약 261MB | 10/1 Person 영상, 10/13–14 같은 Dance 얼굴 비교. OpenCV DNN CPU 실행 | 드라마 일부와 클립10 개선, 다른 자료에서 개선 불충분. 권리 관계 미해소로 제품 배포 보류. |
| **AuraFace-v1** / `glintr100.onnx` | 얼굴 특징 512차원, 약 261MB | 10/14 ORT CPU 실제 실행. 같은 참조·영상 얼굴·추가 두 영상 비교 | 실행 가능성 확인. SFace 대비 일관된 품질 개선 없음, 교체 미채택. 경량 대안은 아님. |
| **Intel face-reidentification-retail-0095** / FP32 XML+BIN | 얼굴 특징 256차원, 가중치 약 4.67MB | 10/14 OpenVINO CPU 실제 실행·같은 얼굴 비교 | 실행은 가볍지만 이 자료의 매칭 품질이 부족. 교체 미채택. ‘Intel’은 개발사명이며 Intel Mac 지원을 뜻하지 않음. |
| **Intel landmarks-regression-retail-0009** | 선택 얼굴의 정렬용 5점 | 공식 명세·도입안 조사 | **다운로드·추론 미실행.** 인식 모델을 고정한 별도 정렬 실험 후보. |
| **InsightFace buffalo_l** | 과거 안무의 검출·인식 pack | 과거 코드/교체 이력 조사 | 이번 W14 신규 비교에서 재실행하지 않음. 복귀 결정 없음. |

**ArcFace는 하나의 파일명이 아니다.** ONNX Zoo의 `arcfaceresnet100-8.onnx`와 AuraFace의 `glintr100.onnx`는 서로 다른 체크포인트·전처리·임베딩 공간이다. 512차원이라는 이유로 특징/참조/기준을 섞지 않았다.

과거 buffalo_l → YuNet/SFace 교체는 Windows의 InsightFace 소스 빌드/개발 도구 요구로 앱 기동이 막힌 문제와 가중치 이용조건이 주요 이유였다. 당시 Mac 실행 기록은 있지만 동일 입력의 old/new 정확도 우위가 입증되어 교체했다는 근거는 찾지 못했다. [역사 조사](../09/29-face-change-detail.md)

조사만 하고 W14에서 실행하지 않은 얼굴 예비 후보: dlib ResNet v1, EdgeFace-XS, CVLFace AdaFace IR18 WebFace4M, GhostFaceNet, LVFace, RetinaFace 대체 검출기, Intel face-detection-retail-0004. 가중치 권리 불명확/비상업 경로/배포 부담/현재 입력에 대한 개선 근거 부족 등으로 기본 시험군에 넣지 않았다. 이는 각 프로젝트 전체의 영구 금지 판정이 아니다. [후보별 당시 검토](14-w14-recognition-candidate-evaluation-design.md)

### 3.3 파일 식별·라이선스·실행 환경

아래는 **당시 정확한 파일을 확인한 상태의 기록**이다. 이번 문서화에서 최신 공식 약관을 다시 조사하거나 배포 승인을 내린 것이 아니다.

| 파일 | SHA-256 |
| --- | --- |
| YuNet | `8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4` |
| SFace | `0ba9fbfa01b5270c96627c4ef784da859931e02f04419c829e83484087c34e79` |
| ONNX Zoo ArcFace | `f0a2e278b430372d308fef67c1aea308c2baf37f32e8908d9bfce035c26a3fb4` |
| AuraFace | `a7933ea5330113b01c9b60351d8f4c33003f145d8470ac5f0e52ee2effe25c60` |
| Intel0095 XML | `6cf60c341452155e35c467510c6c50a96ade5b2bd8f88c5a90902e905d8a80c3` |
| Intel0095 BIN | `21319b95e54181857f99e22dc32ec89770eca2969a1432cfa1594bffc94edd62` |

- YuNet 폴더 MIT, SFace 폴더 Apache-2.0 확인 이력. Aura는 고정 revision의 모델 카드·Apache-2.0 LICENSE를 보존했다. Intel0095는 공식 manifest의 파일 URL·checksum·Apache-2.0 연결을 확인했다.
- ONNX Zoo ArcFace는 Zoo 표기와 원 가중치 권리 관계를 해소하지 못했다. 10/1의 Apache 표기만으로 상업 배포 가능하다고 결론내리지 않는다.
- ORT/OpenVINO/OpenCV의 본체 라이선스와 실제 wheel의 제3자 구성요소는 별도다. LGPL/FFmpeg 등을 포함한 실제 앱 패키징 의무, LICENSE/NOTICE 배포 경로는 미완료다.
- 실제 후보 실행 장비는 **Apple M4, RAM 24GiB, macOS 27 arm64, Python 3.11.12**. 전용 uv venv에서 OpenCV 4.13.0.92, ORT 1.24.4, OpenVINO 2026.4.1 등을 사용했다. 이 버전을 제품 기본값으로 채택한 것이 아니다.
- ORT의 해당 arm64 wheel tag는 macOS 14.0, OpenVINO는 11.0이었다. wheel 존재·M4 1대 실행은 최소 OS/Windows x64/클린 설치 보장이 아니다. macOS Intel은 범위 밖이다.
- OpenVINO 초기 smoke에서 telemetry 초기화 경로를 발견했다. 전송 성공 여부는 미확인이고 얼굴 전송 경로는 사용하지 않았다. 후속 본 실행에는 공식 `CI=true` 옵트아웃을 적용했다. 제품 도입 전 startup 제어가 필요하다.

### 공통 모듈의 실제 API와 경계

`build_gallery()`는 등록 사진의 특징으로 참조 집합을 만든다. `match_reference()`는 얼굴 하나를 모든 후보와 독립 비교한다. 다른 구간에 같은 이름이 붙었다는 이유로 이 얼굴의 이름을 바꾸지 않는다. `combine_reference_matches()`는 소비자가 **같은 사람이라고 선언한 범위**의 근거를 결합하고, 강한 다른 멤버 근거가 충돌하면 확인 필요로 남긴다.

- UI/job/Dance Segment/PersonGroup 객체에 종속되지 않는다. 기본 의존성은 NumPy이며, 선택적 OpenCV import와 모델 로딩을 분리했다. SDK 기본 시작에 ML 다운로드를 추가하지 않았다.
- source/model/config hash, 좌표와 시간 기준, 관측/분석/범위 ID, 모델 공간·정렬·정규화·거리·정책 지문을 검사한다. 중복 관측으로 지지 수를 늘리지 않는다.
- 몸의 주인 판단, 물리적 동일인 추적, 구간 분리는 소비자의 책임이다. `association=confirmed`는 소비자의 입력 주장이지 GT 인증이 아니다.
- 기존 Person 관측/grouping/대표 후보 API도 보존했다. 기존 Person의 시간·정규화 계약이 새 참조 계약으로 자동 전환되지는 않는다.
- **영속 임베딩 캐시 서비스를 새로 완성한 것은 아니다.** 공간/입력 지문 계약과 평가 캐시를 만들었고 제품 캐시 invalidation 연결은 후속이다.

## 7. 현재 수치를 정확히 읽는 법

### 서로 다른 세 가지 정답

1. **원래 메인이어야 할 사람**: W13의 춤/구간 평가 정답.
2. **실제로 선택된 몸/얼굴은 누구인가**: W14 얼굴 매칭의 입력 정답. W13이 다른 사람을 골랐더라도 그 선택된 사람의 얼굴을 맞혔는지 따로 평가한다.
3. **얼굴 crop만으로 식별 가능한가**: 이름을 주변 영상으로 알 수 있어도 작은 얼굴 사진만으로 구별하기 어려울 수 있다. `identity`와 `identifiable`을 별도 저장했다.

### 지표도 서로 다르다

- **점수1위 정답**: 등록 후보 중 가장 가까운 사람이 맞는지. 거부 기준을 무시한 순위 검사다.
- **올바른 확정 / 잘못된 확정 / 보류 / 처리 오류**: 거리·1/2위 차이 등의 기준을 적용한 결과. 보류는 정답 인식 성공이 아니다.
- **구간 최종 정답**: 같은 메인 범위의 얼굴 근거를 결합해 해당 클립에 올바른 멤버가 붙었는지. 얼굴1장의 정답을 구간 전체로 자동 복사하지 않는다.
- 테스트 통과·거리 검산·파일 hash 일치는 **계산과 기록의 정확성**을 검사한다. 실제 인물 정답률과 다른 증거다.

### 평가 방식 자체에서 고쳐야 할 점

최근 추가 영상 검토는 고정8프레임의 얼굴을 폭 작은/중간/큰 순서로 고른 뒤 남은7개를 채웠다. **안무가 선택한 메인의 유효한 얼굴 근거를 먼저 확보한다는 우선순위가 부족했다.** 그 결과 사용자는 작고 흐린 얼굴·백댄서를 반복 확인했고, 실제로 원하는 메인 멤버 인식 문제에 대한 정보는 적었다.

따라서 다음에는 이 검토를 그대로 늘리지 않는다.

- 알아볼 수 있는 메인 얼굴은 올바른 매칭/과도한 거부를 평가하는 주 자료로 둔다.
- 작은·흐린·가린 얼굴은 그 메인 범위에서 다른 시점의 유효 얼굴을 확보할 수 있는지 먼저 본다. 끝까지 입력이 부족하면 그 이유를 분리한다.
- 등록 외 인물·비얼굴·식별불가는 잘못된 확정을 막는 보조 시험으로 유지한다. 이를 인식 개선 성과로 보고하지 않는다.
- 나쁜 입력을 전체 분모에서 숨기지는 않는다. 다만 **식별가능 얼굴의 인식률**, **전체 범위의 입력 확보율**, **불확실 입력의 거부**, **최종 클립 결과**를 별도로 보고한다.
- 현재 GT/결과를 이미 본 후의 반복 실험은 개발·진단이다. 같은 자료를 계속 ‘새 독립 평가’라고 부르지 않는다.

전역 grouping threshold 완화, detector 점수/큰 상자 필터, 단순2배 확대/재검출, ±2px 정렬 평균, 참조42px 축소, 두눈 정렬, 가까운 참조2장, 단순 margin 완화, 자동 영상참조 확대는 **시험한 조건에서 두 목표를 함께 해결하지 못했다.** 모든 가능한 변형이 불가능하다는 뜻은 아니지만 같은 조건을 새 해결책처럼 반복하지 않는다.

## 10. 최종 선택 전에 남은 작업 — 실행 순서

아래는 후속 우선순위다. 이번 문서화에서 실행하지 않았고, 구체적인 허용 오류율·시간 예산 수치를 합의한 것처럼 만들지 않았다.

### 1) 평가 입력을 실제 사용 흐름에 맞추기

고정할 W13 출력 버전·source hash·구간·메인 위치를 하나로 잠근다. 이미 평가한 iteration27과 이후 W13 변경을 섞지 않는다. 메인 역할, 몸 관측, 물리적 동일인 범위, 공동 메인의 여러 사람, 얼굴 연결 실패를 구별한다.

그 범위 안에서 얼굴이 제대로 보이는 시점을 확보한다. 이미 구현한 첫/중간/끝·reserve 표본 보충과 구별하여 **선명한 시점을 고르는 효과**를 대조한다. 모델 점수나 정답 멤버를 보고 유리한 얼굴만 고르는 방식은 피한다. 유효 얼굴이 끝내 없는 범위도 수와 이유를 남긴다.

### 2) 정답과 평가 세트를 보완하기

- 실제 선택된 사람/얼굴의 멤버, 연결이 맞는지, crop 식별 가능성, 등록 외 여부를 기록한다.
- 다른 촬영에서도5멤버를 포괄하고, 현재 부족한 **혜인·식별가능 하니**를 포함한다.
- 구간 전체가 한 사람의 근거인지와 최종 클립 이름의 정답을 확보한다. 얼굴34개만으로42범위 전체 정답을 만들지 않는다.
- 기존135답변·22답변은 보존한다. 이미 여러 번 살펴본 부분은 개발/회귀용으로 취급하고 평가용 표본은 촬영·시간 인접성을 고려해 분리한다.

### 4) 두 목표를 동시에 채점하기

주 지표는 **다른 멤버로 잘못 확정한 비율**과 **식별가능 메인을 올바르게 확정한 비율/보류율**이다. 같은 오배정 수준에서 더 많이 맞히는지, 같은 확정 범위에서 덜 틀리는지 비교한다. 멤버별 편차와 실제 구간 결과를 함께 낸다.

실패를 `not_sampled`, `no_face`, `association_error/ambiguous`, `alignment_invalid`, `inference_error`, `recognition_rejected`, `wrong_identity`, `segment_conflict`로 분리한다. 관측 없음·정상 거부·처리 오류를 한 종류의 미매칭으로 합치지 않는다. 등록 외 거부는 별도 보고하고 소수 사례의0오배정을 FAR0으로 확대하지 않는다.

### 5) 품질을 통과한 후보만 제품 준비

정확한 파일 권리와 배포 의무 → 공개 backend/manifest → 플러그인별 선택 의존성·uv venv·모델 준비 → 참조 캐시 무효화 → W13 소비 adapter/compatibility → Apple Silicon/Windows x64 설치형 실행 순서로 확인한다.

필요한 실제 확인은 clean install, 개발 도구/시스템Python/CUDA 불필요, 최소 macOS와 Windows native DLL, 서명·격리·한글 경로·cache 권한, 모델 미준비/오프라인, cold/warm·thread·RSS·Electron 영향이다. 현재 M4 평가 실행으로 이 항목들이 통과된 것은 아니다.
