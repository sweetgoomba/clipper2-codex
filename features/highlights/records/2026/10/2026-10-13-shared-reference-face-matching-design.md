## 목적과 성공 기준

사용자가 멤버별로 선택한 참조 얼굴 사진을 기준으로, 안무에서 선택된 사람의 얼굴을 해당 참조 인물에 정확히 연결한다. 이 기능을 독립 Python 패키지로 만들어 향후 Person 등 다른 플러그인도 소비하게 한다. 실명 자동 식별을 하지 않으며 ID/표시 이름은 소비자가 제공한 참조 라벨이다.

사람 선택·추적·구간 경계는 W13, 얼굴 관측·비교·참조 매칭 공통 기능은 W14가 담당한다. 현재 Person 자체 UI·출력·몸 검출/등장 interval 개발은 보류한다.

정확한 참조 매칭을 늘리면서 다른 참조 인물에 잘못 배정하는 경우를 늘리지 않는 것이 첫 성공 기준이다. 미배정/모호 결과와 멤버별 편차를 별도로 측정한다. 이름을 전부 붙여 매칭률만 높이는 것은 성공으로 판단하지 않는다.

## 실제 진단이 보여 준 문제

- 기존 참조 사진 23장은 자기 사진을 제외한 나머지 참조들과의 비교에서 입력 라벨과 23/23 일치했다. 새로 계산한 멤버별 평균 특징은 저장된 W13 값과 정확히 같았다. 이는 이 참조 집합의 일관성 진단이며 영상 정확도가 아니다.

- 원본 정답 몸 영역 18개에서 직접 비교는 입력 라벨 일치 14, 다른 라벨 2, 기준 미달 2였다. 위 얼굴 선택 문제 외에 참조와 영상 얼굴의 비교 문제도 남았다. 단일 프레임 비교를 항상 더 좋다고 볼 수 없다. 저장 256의 올바른 몸 선택 6개에서는 직접 비교 일치 4, 기존 구간 결과 일치 5였다.

| 접근 | 얻는 것 | 한계 |
|---|---|---|
| **참조 매칭을 공통 API로 분리하고 얼굴/track별 근거를 보존 — 권고** | 같은 입력으로 단계별 차이를 확인하며, 이미 참조와 맞는 얼굴이 전역 군집 때문에 다른 이름으로 바뀌는 문제를 다룰 수 있음 | 대상 얼굴의 선택과 애매한 track의 판단을 별도로 검증해야 함 |

| 인식 모델부터 교체 | 영상 얼굴과 참조 사진 간 특징 차이가 줄어들 가능성 | 옆 얼굴 선택·서로 다른 사람의 구간 혼합·후단 이름 덮어쓰기는 따로 남음. 새 모델 공간/참조 재계산과 검증 비용 발생 |

첫 구현은 권고 접근을 따른다. 기준 모델은 현재의 YuNet/SFace이며, 모델 교체 실험은 동일 관측과 매칭 계약이 준비된 뒤 별도로 비교한다.

## 첫 구현 범위

공통 패키지 `clipper_face_core`에 **참조 갤러리 준비와 query 비교 결과**를 명시적으로 추가한다. 기존 Person UI·익명 grouping 소비를 이 단계에서 변경하지 않는다.

흐름:

```text
소비자가 제공한 참조 ID + 참조 얼굴 특징
  → 공간/유효성 검증 → 참조 갤러리

소비자가 지정한 대상의 얼굴 관측/track 표본
  → 갤러리와 비교 → 후보 순위·거리·격차·판단 근거
  → 소비자의 같은-person 표본 범위 안에서 합의/충돌 결과
  → Dance adapter가 해당 구간의 참조 ID/미배정으로 반영
```

1. **갤러리 준비:** 여러 참조 이미지를 하나의 opaque `reference_id`에 연결한다. 첫 비교의 평균/L2 계산은 현재 Dance 방식과 동일하게 유지한다. 참조 이미지별 유효/실패·원본 ID와 갤러리 지문을 보존한다.
2. **query별 비교:** 동일 embedding 공간의 모든 참조 ID에 대한 cosine distance, 1·2순위와 격차를 반환한다. 서로 다른 query가 같은 참조 ID를 선택할 수 있다. 다른 query가 먼저 배정됐다는 이유로 차순위 참조 ID를 대신 배정하지 않는다.
3. **판정:** 명시적 정책에 따라 `matched`, `ambiguous`, `unmatched`, `invalid`를 반환한다. 거리/격차 기준은 정책 입력이며 metric 단위를 함께 고정한다. 새 기본 수치는 설계만으로 확정하지 않는다. 평가 baseline은 현재 Dance의 distance 0.60과 현재 동작을 대조군으로 보존한다.
4. **표본 결합:** 소비자가 같은 사람이라고 지정한 하나의 track/구간 안에서 개별 표본의 근거를 유지한다. 서로 다른 참조 ID를 강하게 지지하는 표본이 섞이면 충돌을 반환하며, 조용히 한 이름으로 평균내지 않는다. 이 모듈이 사람 track의 물리적 동일성을 보장하거나 구간을 자르지는 않는다.
5. **추적 가능성:** 최종 결정이 어떤 얼굴 후보·표본·참조 비교를 사용했는지 관측 ID로 역추적할 수 있어야 한다. query별 결과와 집계 결과를 함께 내므로 전역 익명 cluster 결과가 참조 이름을 덮어쓰지 않게 한다.

대상 ROI의 최고 검출 점수 얼굴 하나를 곧바로 대상 인물로 확정하는 문제는 별도 하위 계약으로 다룬다. 공통 얼굴 관측은 후보를 모두 반환하고 위치/점수/실패 근거를 보존한다. 몸 상자 안의 얼굴 중심 하나만으로 소유를 확정하지 않는다. 실제 진단에서 정답 몸 상자 안에도 복수 얼굴 후보가 남는 프레임이 있었다. 첫 구현의 매칭 API는 **선택된 관측 ID와 선택 상태**를 입력받고 모호한 연결은 표시한다. 얼굴 후보 선택 규칙을 제품에 적용하려면 독립 얼굴 위치/대상 연결 라벨 검증이 먼저 필요하다.

### 판정과 결합의 명시적 규칙

- 비교 정책은 `max_distance`, `min_margin`, `minimum_support`를 명시적으로 받으며 숨은 제품 기본값을 두지 않는다. 거리 작은 순서로 정렬하고 `margin = second_distance - first_distance`로 정의한다. 1위가 최대 거리보다 멀면 `unmatched`, 거리는 통과하지만 동률 또는 격차 미달이면 `ambiguous`, 두 조건을 통과하면 `matched`다. 참조 ID가 하나뿐이면 2위/격차는 null이며 거리 조건만 평가했다는 사유를 남긴다.
- 대상 얼굴 연결 상태가 모호하면 거리 순위는 제공하되 `matched`로 승격하지 않는다. 유효 특징이 없거나 공간/차원이 다르거나 NaN·무한대·영벡터이면 `invalid`와 이유를 반환한다. 무효 참조 표본은 실패 목록에 남기고, 유효 참조가 없는 ID는 갤러리 비교에서 제외한다. 비교 가능한 참조 ID가 하나도 없으면 갤러리 실패를 반환한다.
- 첫 표본 결합은 명시적으로 같은 사람에 속한다고 소비자가 지정한 표본만 받는다. 개별 `matched`가 서로 다른 ID를 지지하면 집계는 `ambiguous/conflicting_references`다. 하나의 ID만 지지하고 유효 지지 표본 수가 `minimum_support` 이상이면 그 ID를 반환한다. 지지 부족은 `ambiguous/insufficient_support`, 유효 비교가 모두 거리 미달이면 `unmatched`, 전부 무효이면 `invalid`다. 다른 모호/실패 표본도 결과에서 삭제하지 않는다. 지지 수는 중복 observation ID를 제거한 뒤 센다.
- 참조 평균/L2와 위 정책은 각각 버전을 가진다. 기존 강제 배정/전역 군집 경로는 평가 대조군으로만 재현하며 이 독립 API의 기본 동작에 섞지 않는다. 새 정책의 제품 수치와 적용 여부는 평가 결과로 결정한다.

## 공개 계약 경계

| 개념 | 필수 의미 |
|---|---|
| `EmbeddingSpace` | 인식 weight SHA, 정렬/색상/입력 처리·출력 정규화 버전, dimension, backend 버전, 거리 정의. 빈 지문이나 다른 공간 비교를 거부 |
| `ReferenceSample` | 소비자 제공 reference ID, 이미지/관측 ID, 이미지 hash, 특징 또는 실패 상태. Dance 멤버/UI 타입을 요구하지 않음 |
| `ReferenceGallery` | 공간 지문, 참조 표본 목록/상태, 집계 방식 버전과 갤러리 hash |
| `QueryEvidence` | 관측 ID, 특징 또는 실패, 품질 근거, 소비자가 제공한 track/구간 연결 ID와 유효 범위. source/model/config 및 시간·좌표 provenance와 연결 가능 |
| `ReferenceMatch` | 후보 ID별 거리, 1·2순위/격차, 상태, 적용 정책 지문, 사용·제외한 관측 ID와 이유. 소비자가 표시 이름을 붙임 |

관측 시간/좌표와 비교 공간은 별개로 기록한다. 검출 모델/config와 인식 공간 지문을 혼동하지 않는다. video source의 PTS/time base, pixel/normalized bbox, 회전/원점 계약은 W13 adapter와 고정한다. 기존 frameIndex/FPS의 파생 초만 있는 자료는 그 한계를 명시하고 원본 PTS라고 표기하지 않는다.

공용 입력은 Dance `Segment`, `PersonGroup`, Angular UI, job/과금 타입에 의존하지 않는다. numpy 기반 비교와 모델 backend의 import 경계를 구분하며 OpenCV는 선택 backend로 준비한다. 기본 SDK/app 시작 경로에 얼굴 모델 설치·초기화를 추가하지 않는다. 각 소비 플러그인의 venv·모델 준비 정책을 유지한다.

## 통합과 소유권

- W14: 공통 패키지, 공개 계약, 참조 매칭 fixture/평가 adapter. 현재 Person MVP의 광범위한 미커밋 변경을 통째로 안무에 옮기지 않는다.
- W13: Dance의 사람 선택·track·구간·군무·crop 및 기존 제품 adapter 통합. 이 세션이 W13의 작업 파일을 직접 수정하지 않는다.
- 순서: 고정 fixture/공개 API → W14 격리 평가 adapter로 이전 동작 재현과 새 경로 비교 → W13 adapter의 실제 소비 검증 → 제품 적용 판단.
- 새로운 제품 코드 작업 전에는 최신 `origin/dev` 및 진행 중 작업 의존성을 확인한 격리 checkout을 준비한다. 필요할 때만 Electron의 공통 패키지 설치/fingerprint를 다루며 Person 등록·Nest/UI·Web API 변경은 이 범위에 없다.

## 검증 및 적용 기준

첫 자동 검증은 ① 다른 query 추가가 기존 query의 참조 순위를 바꾸지 않음, ② 동일 인물의 여러 query가 같은 참조 ID를 가질 수 있음, ③ 다른 공간/무효 특징/참조 실패의 명확한 처리, ④ 충돌하는 표본 근거 보존, ⑤ 기존 갤러리 평균 특징 재현, ⑥ 기본 SDK의 선택 ML 의존성 경계를 다룬다.

실영상은 검출·대상 얼굴 선택·특징 비교·표본 결합·최종 배정을 분리한다. 올바른 얼굴을 제공한 조건과 실제 Dance 선택을 제공한 조건을 별도로 채점한다. 10/13의 18개 표본은 이미 열람한 진단 자료이므로 새 독립 성능으로 재사용하지 않는다. 제품 적용 판단에는 모델 결과를 보기 전에 고정한 별도 얼굴/연결 라벨과 멤버별 오배정·미배정 검증이 필요하다. source/참조/model/config/hash·정답·자원·출력 위치는 실제 실행 전 manifest로 고정한다.

현재 자료에서 인정할 수 있는 완료는 **공통 API 구현·고정 fixture 통과·W13 소비 호환 확인**과 **각 평가 범위의 수치**다. 전체 영상·다른 영상·Windows 품질을 검증 없이 완료라고 하지 않는다. 같은 영상의 전체 시간 겹침 점수를 순수 얼굴 매칭률로 사용하지 않는다.

## 검토 상태

의도·담당 범위는 사용자 방향 전환에 따른다. 사용자가 이 설계의 쉬운 설명을 요청해 읽은 뒤 `진행해줘ㅗ`라고 답해 다음 단계 진행을 승인했다. 이에 Superpowers 구현 계획을 작성했다. 계획의 파일·테스트·실행 순서는 별도 검토 대상이며, 실행 방법은 이 세션에서 직접 구현하는 방식을 권고한다. 현재 제품 수정·공통 API 이식·모델 교체·배포는 수행하지 않았다.
