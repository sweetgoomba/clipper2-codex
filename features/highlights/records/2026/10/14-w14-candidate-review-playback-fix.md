# W14 — 후보 비교 화면 사용 안내와 재생 보완

2026-10-14. 사용자 피드백: 목록 기준 4가지/451관측/멤버별 0건의 의미가 불분명하며, 20개 클립 재생이 검은 화면과 고정 박스로 보임.

## 확인한 사실

- 기본 목록 `직접 확인한 정답`은 사람이 입력한 얼굴 identity를 집계한다. 아직 입력 0건이므로 멤버별 0, 미확인 451은 정상이다. 모델 실패 451건이라는 뜻이 아니다.
- 기존 무대 20구간에서 저장한 451시점 = 선택 얼굴406 + 미검출36 + 연결보류9. 신규 두 무대의 결과가 아니다.
- 최초 요청은 클립1~19에서 시간순 중앙의 선택 얼굴 1개씩, 총19개. 클립20은27시점 모두 미검출이어서 최초 얼굴 확인에서 제외한다. 이는 전체 정확도를 입증하는 GT 완성이 아니다.
- 사용자 탭의 검은 화면을 재현했다. 당시 media error 없음/readyState4. 페이지 reload 뒤 영상이 나타나고 실제 재생도 확인했다. 검은 화면의 브라우저 내부 원인까지 특정하지 않았으며, 파일이나 모델 오류라고 단정하지 않는다.
- 고정 박스 숨김에는 실제 코드 오류가 있었다. SVGElement에 `hidden` property만 대입하여 HTML hidden attribute가 생성되지 않았다. 재생 중에도 과거 시점의 박스가 남았다.
- 구간 끝의 재생 버튼은 시작 위치로 되돌리지 않았고 play rejection/로딩/오류 안내도 없었다.

## 변경

`evaluation/candidate_comparison`의 평가 화면만 변경했다.

- SVG hidden attribute를 직접 제어. 재생/seek/로딩 중 및 선택한 시점 밖에서는 박스를 숨긴다. 박스는 저장된 한 시점의 몸·얼굴 위치이며 연속 추적 오버레이가 아니다.
- 재생/일시정지 버튼 상태, 구간 끝에서 재시작, 선택 얼굴 시점 복귀, 영상 다시 불러오기, 로딩/재생 실패 메시지 추가.
- ‘관측’을 ‘분석 시점’으로 풀어 쓰고 최초19개 입력 순서, 정답 목록과 모델 점수1위 목록의 차이, 현재 자료가 기존20클립이라는 설명 추가.
- 기존 URL/localStorage key/사용자 정답/노출 이력 형식 유지. 추론 결과/거리/모델/정답을 수정하지 않음.

## 검증

- 신규 playback Node 테스트: 선택 시점, SVG attribute, 구간 끝 멈춤/재시작, 다른 시점의 박스 숨김, play reject, 로딩/재시도 통과.
- 기존 정답 노출 이력 Node5 assertions 통과.
- `python -m pytest evaluation/candidate_comparison -q`: 16 passed.
- 실제 브라우저: 클립1/3 원본 표시 및 시간 진행, 재생 중 박스 숨김, 클립3 끝20.34초에서 멈춤 후 재클릭10.78초 재생, 선택15.348666초 복귀와 박스 표시 확인. `timeupdate` 기반 재생 정지라 프레임 단위 export 경계를 보증하는 플레이어는 아님.
- ‘영상 다시 불러오기’ 후 동일 선택 시점 복구 확인. Aura 목록72/82/184/36/29, 처리보류48 표시 확인. 이 값은 성능 점수가 아니다.
- 기존 artifact-manifest의 data/result/npz12개 SHA 동일. 새 ML0. 제품/core/W13/원본/서버 프로세스 변경 없음.
- 검증 메타데이터: `.worktrees/shared-reference-face-matching-20261013/evaluation-output/candidate-comparison-20261014/metadata/ui-playback-fix-verification.json`.
- 화면 증거: 같은 출력 폴더 `review-playback-proof.png`. 이전 UI는 `metadata/ui-before-playback-fix`에 보존.

## 사용자 입력 순서

1. 목록 기준 `직접 확인한 정답`, 왼쪽 `전체` 유지. 모델 점수는 최초 입력 뒤 비교용으로 본다.
2. 아래 선택 얼굴의 실제 멤버 이름/등록 외 인물/판단 어려움 선택.
3. 얼굴 이미지 자체로 알아볼 수 있는지 선택. 영상 문맥으로만 알아봤다면 이미지 자체 식별은 ‘어려움’으로 기록 가능.
4. `다음 확인 표본 →` 반복. 우선19개만 확인하며 모든451시점을 요구하지 않는다.
5. `확인 내용 내보내기` JSON 전달. 이후 개발용 정답 검토 및 모델별 기준 보정, 독립 영상 평가가 남는다.

왼쪽 멤버 카드는 필터이며, 얼굴 아래 멤버 버튼이 정답 입력이다. 19개 입력을 마쳐도 나머지 미확인 시점이 남는 것은 정상이다.
