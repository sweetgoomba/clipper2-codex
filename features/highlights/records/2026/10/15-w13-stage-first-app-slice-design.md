# W13 — 무대 하이라이트 첫 앱 적용 범위

## 목적과 출하선

사용자가 결과에서 각 클립의 역할을 `단독 메인`, `공동 메인`, `함께 등장`으로 읽고, 같은 원본 장면을 실제 등장한 여러 인물의 목록에 넣어 각 인물 ZIP·숏폼에 사용할 수 있게 한다. `함께 등장`은 춤 여부와 무관한 표현이다. 영상에 나오지 않은 멤버에게 자동 배정하지 않는다.

**첫 빌드 범위:** 현행 Python이 이미 만든 `lists.main`과 `lists.group` 파일을 Nest 결과 상세에서 모두 노출한다. 기존 main은 `단독 메인`, group은 `함께 등장`으로 시작한다. group의 멤버는 자동 식별 결과가 없으므로 `배정 대기` 목록에 먼저 놓고 사용자가 화면을 보며 여러 명을 선택한다. 메인 클립도 여러 명으로 변경할 수 있고 그때 `공동 메인`으로 표시한다. 한 물리적 MP4를 여러 인물 목록에서 참조하며 추가 인코딩은 하지 않는다. 기존 클립 이동·숨김·되돌리기와 기존 프로젝트 읽기를 유지한다.

**다음 빌드 범위:** 72번의 화면 주목 판정을 제품에 넣기 전 15.816초 오선택을 고치고 43.911초 및 사용자 확인 9구간 회귀를 통과한다. RTM/YOLO 두 모델의 배포·속도·사용권 문제와 새로운 영상의 일반화는 별도 게이트다. 이번 첫 빌드가 자동 메인 선정 정확도 향상을 입증하지는 않는다.

## 계약

- 원본 클립 ID·파일 경로는 하나다. 결과 `ProjectClipItem`에 `stageRole: 'single'|'joint'|'together'`, `personIds: string[]`를 추가한다. 기존 `personId`는 단일 인물 소비자를 위한 호환 필드로 보존하며 새 인물 소속 판단은 `personIds`를 쓴다.
- `lists.group`의 초기 `personIds=[]`. 이 클립은 `배정 대기`에 보이지만 어떤 멤버 ZIP·숏폼에도 들어가지 않는다. 모든 멤버가 나온 것으로 추측하지 않는다. `lists.main`의 초기 `personIds=[기존 personId]`이고, 미분류 ID도 보존한다.
- 새 결과 overlay는 클립별 `stageRole`과 `personIds` 전체를 원자적으로 저장한다. 하나를 추가/제거하는 연산보다 현재 선택 집합 전체를 제출해 새로고침과 되돌리기를 명확히 한다. 잘못된 클립 ID와 존재하지 않는 인물 ID는 거부한다. 기존 단일 클립 이동 overlay는 그대로 읽되 새 overlay가 있는 클립에서만 새 값이 우선한다.
- 역할과 배정은 구분한다. `joint`는 사람 2명 이상, `single`은 1명, `together`는 1명 이상 또는 아직 배정 대기 상태를 허용한다. `together`는 인원 수가 아니라 ‘특정 메인이 없는 함께 등장 장면’을 뜻한다.
- Nest `persons[].clipIds`는 `personIds` 소속으로 채우고, 인물 ZIP·전체 ZIP·숏폼 선택 검증도 같은 소속을 사용한다. 전체 ZIP은 같은 MP4를 인물별 폴더에 각각 넣을 수 있다. 비디오의 원본 파일은 한 번만 보존한다.
- Angular 결과에서 뱃지와 다중 인물 선택을 제공하고 변경 뒤 목록을 새로 읽는다. `배정 대기`는 다운로드·숏폼 생성 대상에서 제외한다. 기존 프로젝트는 새 필드가 없어도 단일 인물 목록이 동일하게 보인다.

## 검증과 남는 한계

Nest는 구형 `dance_meta`, 그룹 클립 노출, 다중 소속, ZIP 중복 경로, 숏폼 소속 검증, overlay 저장/되돌리기를 검사한다. Angular는 뱃지, 다중 선택, 배정 대기, 선택된 인물의 클립 목록을 검사하고 두 저장소를 빌드한다. 테스트용 결과에서 `a` 단독, `b+c` 공동, `a+b+c` 함께 등장, 미등장 `d` 제외를 확인한다.

이 빌드는 기존 YOLO 기반 판정과 얼굴 이름 매칭을 바꾸지 않는다. 따라서 메인 오선택, 분절, 멤버 오매칭, 새 장면 자동 다중 배정은 남는다. 사용자에게 새 자동 정확도가 입증됐다고 보고하지 않는다. 실제 설치형 앱 통합·원본 영상 새 분석·배포는 각각 별도 실행 결과로 기록한다.
