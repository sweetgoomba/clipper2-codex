# W13 메인 판정 후속: 저장 자세 검증과 512 입력 평가 준비

이 문서는 512 실행 **전** 준비 기록이다. 사용자가 범위를 확인한 뒤 실제 1회 실행한 결과와 채택 기각 근거는 [512 실행·추가 탐색 결과](02-w13-movenet-512-result-and-selector-probe.md)에 있다. 현재 manifest는 완료 상태로 재실행을 막는다.

2026-10-02 KST. 사용자가 새 MoveNet 결합 클립을 이전보다 나쁘다고 평가한 뒤, 자동 메인 판정 원인을 더 좁혔다. 제품 기본 모델·메인 선택 규칙·W14 공통 얼굴 파일·기존 결과 카드는 변경하지 않았다.

## 저장 자세만으로 규칙을 바꿀 수 있는가

동일 원본 `yFTAYXDTjqI`의 다른 프레임 22장을 원본 화면에서 표기했다: 명확한 단독 메인 17장, 그룹 4장, 보류 1장. [표본 계획](02-w13-followup-source-plan.json)·[원본 기준 표기](02-w13-followup-source-labels.json)·[저장 pose 재채점](02-w13-saved-pose-followup-probe.json)을 보존했다. 검토자는 이전 실패 구간을 알고 있었고, 정확히 같은 인덱스 5장은 과거 원본 관찰/점수 파일에도 등장했다. **새로운 독립 홀드아웃이나 영상 전체 정확도 추정이 아니다.** 단독 인물 상자는 사람이 대략 그려 IoU≥0.30 비교에 사용했다.

| 같은 저장 MoveNet 256 입력의 단독 프레임 | 현행 선택 | 20원본프레임 간격 관절 움직임 단독 선택 |
| --- | ---: | ---: |
| 이번 전체 17장 | 7/17 | 10/17 |
| 과거 파일과 같은 인덱스를 제외한 14장 | 6/14 | 9/14 |
| 앞서 별도로 고정했던 개발용 15장 | 6/15 | 5/15 |

이번 17장에서는 정답 사람이 모델 출력에 있는 것은 15장이다. 움직임 단독 규칙은 왼쪽에서 낮게 움직이는 파랑 `P4` 세 장을 모두 회복했으나 연보라 `P5` 두 장을 모두 틀렸다. 과거 15장에서는 전체가 악화됐다. 이번 그룹 4장은 모두 기존 `is_group=true`였지만, 단독 메인 17장 중 **14장도 `is_group=true`**라 그 플래그로 단독/그룹을 가를 수 없다. **움직임 단독·그룹 플래그를 제품에 채택하지 않는다.** 두 표본을 합쳐도 다른 영상의 품질이나 기존 YOLO 대비 우위를 뜻하지 않는다.

## 같은 모델, 입력 크기 하나만 바꾸는 다음 대조

현재 `MoveNetPoseAnalyzer`가 화면을 **256×256으로 줄여** 넣는 점을 확인했다. [Google 모델 카드](https://storage.googleapis.com/movenet/MoveNet.MultiPose%20Model%20Card.pdf)는 입력 높이/너비가 32의 배수인 동적 크기라고 설명하고, 로컬 SavedModel 서명도 `int32 [1,None,None,3]`이다. 따라서 **기존 로컬 가중치는 그대로 두고 512×512 입력 1회**를 통제된 다음 후보로 둔다. 고해상도 입력이 검출이나 메인 정확도를 개선한다는 결과는 아직 없다.

격리 평가 adapter에 `input_size=256|512`를 추가하고 기본값 256을 유지했다. manifest가 입력 크기를 명시하지 않거나 다른 값을 내면 runner가 거절한다. 기존 18장 holdout과 추가 원본 라벨도 경로·SHA-256·원본 SHA-256을 검사하게 했다. 합성 좌표 역변환과 manifest 잠금 테스트는 **실패→수정→34개 통과**했다. [새 실행 범위 초안](02-w13-movenet-512-manifest.yaml)은 **`pending_user_scope_confirmation`**으로 두었고, CLI `--execute`가 승인 상태 미비로 거절하는 것을 확인했다. 읽기 전용 preflight는 복사한 설정에서 기존 원본·로컬 모델·라벨·코드·런타임 hash와 빈 출력 위치를 통과했다. **512 실영상 추론·얼굴 분석·새 MP4 export는 0회**다.

이전 256 입력의 사용자 승인 3회는 모두 소진됐다. 512 입력은 새 실행 조건이므로 사용자 첫 요청의 “실제 ML 전에 입력/hash·모델·장치·횟수·시간·자원·출력 위치 확정” 조건에 따라 새 범위 확인이 필요하다. 초안은 같은 원본 전체 0–133.654059초 SHA-256 `7f23b9ad8dd6873d8c39a8369083626de5e1807468d083247f0545c3299688d4`, 같은 로컬 MoveNet SavedModel tree SHA-256 `ea71312368f39053ed7b9b2e4fac3bcecd94c667f679830a0a999b31ccaf705c`, Mac mini M4 CPU, 512 입력, `skip4`, **1회 / 최대 600초 / worker RSS 12,288MiB / metadata 250MiB**, 격리 출력 `output/evaluation/yFTAYXDTjqI/movenet-512-v1/`이다. 외부 다운로드·비용·새 YOLO 실행·얼굴/클립 생성은 포함하지 않는다.

실행 승인이 오더라도 결과의 사람 검출·단독 메인·그룹 오판을 **256 저장 결과와 같은 고정 표본에서 따로** 비교한다. 낫지 않으면 새 앱 결과로 만들지 않는다. 나아져도 한 영상의 선택 프레임만으로 제품 모델을 교체하지 않으며 전환/멤버 identity/최종 클립 품질은 별도 gate다.

평가 전 판정 규칙을 잠근다. 기존 18장 단독 표본의 메인 선택은 6/18·정답 사람 대응은 15/18이고, 추가 17장에서는 각각 7/17·15/17(이 중 과거 동일 인덱스를 뺀 14장은 메인 6/14)이다. 512 입력은 **기존 18장과 새 비중복 14장 모두에서 메인 일치 수가 늘고**, 각 집합의 정답 사람 검출 수가 줄지 않아야 후속 후보로 남긴다. 그룹 표본 8장의 단독 메인 선택·그룹 플래그는 별도 표로 공개하고, 새로운 자동 인물 배정이나 MP4 생성의 채택 근거로 합산하지 않는다. 특히 이전 새 결과의 그룹 출력이 84.15초였던 문제를 해결했다고 볼 수 없으면 최종 앱 결과로 승격하지 않는다. 512가 이 최소 조건을 통과해도 이전 YOLO 앱을 이겼다는 뜻은 아니며, 전체 구간·멤버 얼굴·클립 품질은 실제 별도 비교가 필요하다.
