# W13 동일 영상의 새 완료 클립 실험

> **사후 판정: 품질 미달·채택 안 함.** 사용자가 실제 클립을 본 뒤 이전보다 나쁘다고 평가했다. 고정 단독 18프레임의 메인 인물 일치는 6/18, 그룹 출력은 10.08→84.15초다. 이 페이지의 `새 결과`는 실패 실험의 증거이며 추천 결과가 아니다. [원인과 별도의 보수적 비교본](02-w13-user-quality-feedback-and-conservative-result.md)을 보라.

2026-10-02 KST. 사용자는 기존 결과에서 빠진 장면의 읽기 전용 검토보다, **같은 영상으로 새 버전이 실제 생성한 클립**을 앱에서 빨리 보고 비교하기를 원했다. W13 격리 앱 미리보기의 **별도 두 번째 프로젝트**로 실험 결과를 만들었다. 기존 설치본과 9/29 완료 프로젝트는 보존했다.

## 직접 확인

- [새 완료 결과](http://localhost:4201/#/projects/1790950000001): 제목 `W13 새 실험 결과 · MoveNet · 누락 구간 보존`. 멤버별 클립을 클릭하면 실제 MP4가 열린다. `미분류`에는 얼굴을 확인하지 못한 1개가 있다.
- [9/29 기존 완료 결과의 격리 복사본](http://localhost:4201/#/projects/1790659628130): 같은 원본·참조 이미지를 쓴 이전 결과. 두 Chrome 탭을 열어 두었다.
- **20~35초**를 먼저 비교한다. 기존에는 그 15초 창의 개별 메인 클립이 0.65초뿐이고, 새 결과에는 **15.0초**가 있다. 새 클립은 대략 20.2~30.4초(`민지` 자동 배정)와 30.4~45.4초(`하니` 자동 배정)에 걸친다. 이름 배정의 정답 여부는 확인되지 않았으므로 화면을 보고 판단해야 한다.

## 무엇을 바꿔 실행했나

9/29 기존 앱 출력은 YOLOv8s Pose 관측, 메인/그룹 중첩 필터, YuNet/SFace 매핑, MP4 export였다. 이번 실험은 사전 승인·저장된 MoveNet MultiPose Lightning TF2 v1의 2,002개 자세 관측을 **다시 실행하지 않고 재생**했고, 나머지는 같은 W13 Python 파이프라인의 얼굴 분석·매핑·MP4 export를 실제 수행했다. 두 옵션을 실험적으로 켰다: 그룹 판정과 겹친 메인 후보도 개별 클립으로 남기기, 얼굴 표본 없는 메인을 `unknown`으로 export하기. 그룹 clip도 유지했다. 제품 기본값은 바꾸지 않았다. 기존 23장 참조 이미지를 로컬 복사해 사용했고 URL 다운로드는 하지 않았다. W14 공통 얼굴 파일은 수정하지 않았다.

따라서 아래 숫자는 **MoveNet 교체 + 메인 보존 옵션을 함께 적용한 결과**다. 모델 단독 효과 또는 이전 버전보다 인물 판정이 정확해졌다는 주장은 할 수 없다.
