## 참조 집합의 일관성

23장 모두 얼굴 특징을 얻었다. 각 사진을 자기 멤버의 참조 평균에서 제외한 leave-one-out 비교에서 **23/23이 입력 멤버 라벨과 일치**, 기존 distance0.60 아래였다. 재계산한 5개 평균 특징은 저장 W13 값과 원소별 정확히 같았다.

이것은 참조 집합 자체/전처리 재현 진단이며 영상 얼굴 정확도가 아니다. 서로 비슷한 촬영 조건의 참조 사진이 있을 수 있고 참조 소유 라벨을 독립 검증하지 않았다. 7장에서는 복수 얼굴 '후보'가 나왔지만 모두 실제 얼굴이거나 올바른 대상을 뜻하지 않는다. [사진별 후보·거리](evidence/13-w14-face-matching-baseline/reference-gallery/reference-result.json).

## 저장 결과의 재현과 매핑 규칙

저장256/512의 실제 매핑 함수와 구간 점수 함수를 읽어 모델 추론 없이 재생했다. 두 조건 모두 저장 mapping 및 점수를 재현했다. 각 조건의 한 cluster가 가장 가까운 하니 대신 차순위 혜인으로 배정됐다. 다른 cluster가 이미 하니에 배정된 뒤 1차 일대일 배정 규칙이 작용한 사례다.

같은 관측에서 이 규칙만 없애고 가장 가까운 라벨로 배정하는 반사실 계산은:

| 조건 | 기존 메인 이름 시간 겹침 | 최근접만 적용 |
|---|---:|---:|
| 저장256 | 25.808초 | 22.996초 |
| 저장512 | 29.312초 | 30.913초 |

따라서 **최근접만 무조건 적용하는 수정은 채택하지 않았다.** 이 점수는 사람 선택·경계·그룹화가 섞인 전체 출력의 시간 겹침이며 순수 얼굴 정확도가 아니다. [재현 코드·프레임별 추적](evidence/13-w14-face-matching-baseline/cache-audit.json), [읽기 전용 계산기](evidence/13-w14-face-matching-baseline/cache_audit.py).

## 원본 정답 몸과 실제 선택 몸을 구분한 18프레임

기존 원본 우선 익명 몸 상자 정답 중 strict_solo 18개를 사용했다. P1~P5와 사용자 멤버 이름은 같은 시각의 사용자 main 라벨로 연결했다. 이는 이전에 사용한 같은 영상의 표본이며 얼굴/가림/소유를 새로 독립 주석한 표본이 아니다. 모든 검출 bbox와 결과를 보존했고 선택된 대상의 네 진단 이미지를 직접 확인했다.

| 입력 ROI | 입력 라벨 일치 | 다른 라벨 | 기준 미달 |
|---|---:|---:|---:|
| 원본 정답 사람의 몸 영역 | 14/18 | 2 | 2 |
| 저장256이 선택한 몸 영역 | 4/18 | 12 | 2 |
| 저장512가 선택한 몸 영역 | 7/18 | 8 | 3 |

모든 조건은 같은 현재 얼굴 모델/참조·동일18프레임을 썼다. 실제 선택 몸이 원본 몸 상자와 IoU≥0.30인 표본은 각6개다. 그6개에서 저장512의 개별 ROI 직접 매칭은 **6개 일치**, 기존 구간 이름은 **3개 일치**였다. 저장256은 직접 **4개**, 기존 구간 **5개**였다. 소수 같은 영상 진단이므로 직접 매칭의 일반 우위를 주장하지 않는다. [54개 영역별 입력/검출/후보 순위](evidence/13-w14-face-matching-baseline/selected-face-trace/trace-result.json).

## 확인한 구체적인 오류 위치

1. **참조와 맞는 특징이 후단 군집에서 다른 이름으로 바뀜.** 저장512의 10.6106~20.2202초 track 평균은 해린 distance0.451950, 하니0.638148이었다. 전역 cluster1에 들어간 뒤 최종 이름은 하니였다. 17.2172/18.2182/19.2192초 실제 선택 ROI를 직접 비교하면 세 장 모두 해린과 일치했다. 모델 특징 생성 후의 그룹/이름 배정도 오류원이다.
2. **검출 점수로 옆 얼굴을 선택함.** 30.4971초 정답 몸 상자는 `[655,398,1003,899]`, 확장 ROI는 `[602,222,1055,949]`다. 현재 선택은 source face `[600.930,416.015,29.896,52.813]`, score0.917240이다. 원본 목표의 중앙 얼굴 후보 `[855.474,414.279,45.557,55.673]`의 score0.913369보다 조금 높았다. [초록=선택, 주황=다른 후보 이미지](evidence/13-w14-face-matching-baseline/selected-face-trace/1828_annotated_target.jpg)에서 확장 영역 왼쪽 사람을 선택한 것을 확인했다. 그 결과 query는 다니엘에 가까웠다. 대체 후보를 새로 특징 추출해 개선을 검증한 것은 아니다.
3. **올바른 대상 영역에서도 참조 비교 실패가 남음.** 원본 P5 몸의59.526/60.527/60.994초는 얼굴 후보가 있으나 사용자 혜인 라벨에 배정되지 않았다(해린1, 기준미달2). 이미지에서 선택 위치를 확인했지만 독립 얼굴 landmark/소유 정답이나 모든 참조의 타당성을 검증한 것은 아니다. 이 사례를 후단 군집 문제만으로 해결했다고 주장하지 않는다.

또한 얼굴 중심이 몸 상자 안에 있어야 한다는 조건만으로는 충분하지 않다. 18개 정답 몸 중5개(1152·1408·1528·1948·3568프레임)에서 몸 상자 내부에 복수 얼굴 후보가 남았다. 후보 선택은 얼굴별 소유/가림 GT와 함께 별도 검증한다.

## 다음 구현 제안과 미검증

권고는 **참조 우선 매칭의 공통 API와 query/track별 근거 보존**이다. 먼저 현행 기준선 재현과 공통 비교 기능을 분리하고, W13에서 사람/track/구간을 제공하도록 한다. 모호한 얼굴 또는 서로 다른 참조를 지지하는 표본은 강제 배정 대신 상태와 근거를 반환한다. UI/클립 길이/몸 모델/새 인물 플러그인 기능 확장은 보류한다.

공통 모듈 이식·새 matching 정책의 제품 정확도·다른 영상·Windows·앱 결과 개선은 아직 검증하지 않았다. 이번 진단은 설계의 원인을 좁힌 것이며 제품 수정 완료가 아니다. 다음은 [서면 설계안](2026-10-13-shared-reference-face-matching-design.md)의 검토 후 구현 계획이다.
