# 2026-10-23 공통 얼굴 변경의 무대 하이라이트 이식 검토

## 판정과 범위

이 문서는 `feature/person-highlight-w14-20261020`의 네 desktop 저장소를 읽고, **얼굴 매칭 관점에서** 무대 하이라이트에 실제 적용된 변경과 인물 전용 변경을 구분한 검토다. 기준 HEAD는 Angular `7a453546`, Electron `25022554`, NestJS `0ec0822a`, Python `ef9ae0df`다. 네 작업 트리 모두 `origin/feature/person-highlight-w14-20261020`을 추적했고, Python·Angular·NestJS의 tracked 변경은 없었다. Electron의 `dist-app-person-*` 디렉터리는 기존 untracked 빌드 산출물이다. 원격 `dev` 병합 여부와 앱 실영상 정확도는 이 코드 검토로 확인하지 않았다.

**핵심 판정:** 새 실행에서 두 플러그인이 같은 YuNet 검출기와 AuraFace v1 특징 추출기를 사용하도록 연결돼 있다. 그러나 안무의 메인 몸 선정, ROI 얼굴 소유, track 평균, 익명 클러스터, 참조 배정, group 수신자와 클립 경계는 기존 안무 경로다. 인물에서 만든 다각도 근거·관측 전수 비교·시간 연속성·짧은 조각 연결은 안무에 자동 적용되지 않는다. 기존 안무 문턱값도 AuraFace에서 재보정되지 않았다. 따라서 통합 빌드는 **실험 가능한 새 입력**이지 정확도 개선 판정이 아니다.

10/16의 SFace 유지·AuraFace 미채택·Person MVP 보류는 당시 결정이다. 이후 사용자 승인과 10/23 구현 상태는 [현재 체크포인트](/Users/jina/project/adlight/.codex/features/highlights/records/2026/10/23-person-highlight-checkpoint-and-shared-face-model.md)를 따른다. 과거 W14의 오확정·기존 정답 손실 사례는 새 모델과 규칙을 평가할 회귀 입력으로 보존한다.

## 3. 통합 전 반드시 확인할 위험

1. **AuraFace 문턱 미보정.** feature diff에서 안무 `cluster_distance_threshold=.42`, `member_match_threshold=.60`, duplicate `.45/.08`은 그대로다([`config.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/config.py:111)). group 얼굴은 별도 하드코딩 거리 `.60`, margin `.05`, 반복 수신 거리 `.55`를 쓴다([`pipeline.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/pipeline.py:841)). SFace와 AuraFace의 거리 분포가 같다는 근거가 없으므로 기존 수치를 통과 기준으로 취급하지 않는다. 문턱을 새 모델에 맞게 추정하더라도 개발 입력과 잠근 검증 입력을 분리한다.
2. **몸↔얼굴 소유.** 안무는 확장 ROI의 최고 점수 얼굴을 쓰고, 두 얼굴 이상인 group은 몸 박스에 중심이 든 얼굴을 받는다([`face_cluster.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/face_cluster.py:66), [동일 파일](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/face_cluster.py:129)). 겹치는 몸 박스·작은 얼굴·손/배경 상자에서 타인 얼굴을 메인에 연결할 수 있다. `confirmed_group_recipients`는 반복 얼굴과 절반 이상 겹치는 매칭 메인 구간으로 수신자를 추가한다([`pipeline.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/pipeline.py:71)); 잘못된 메인 이름이 group에도 전파될 수 있다.
3. **모델/캐시·설치.** Python은 다운로드 파일의 크기·SHA를 확인하고 임시 파일에서 교체한다([안무 `face_models.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/dance_highlight/dance_highlight/services/face_models.py:80), [인물 `model_assets.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/plugins/person_highlight/person_highlight/model_assets.py:34)). 공통 `EmbeddingSpace`는 모델 SHA/정렬/전처리/차원을 포함하고 불일치 벡터 비교를 거부한다([`contracts.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/clipper_face_core/clipper_face_core/contracts.py:59), [`matching.py`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_python/clipper_face_core/clipper_face_core/matching.py:14)). 현재 안무 참조는 재계산되므로 SFace 캐시 혼용 경로는 보이지 않는다. 반면 Electron/Nest의 설치 상태 화면은 일반 모델 파일 **존재 여부**와 `.ready`만 확인하고 내용 SHA는 확인하지 않는다([Electron `plugin-install-state.ts`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_electron/src/main/plugin/plugin-install-state.ts:134), [Nest `plugin-asset-install-state.ts`](/Users/jina/project/adlight/.worktrees/person-highlight-w14-20261020/desktop/clipper_nestjs/src/modules/plugins/infrastructure/plugin-asset-install-state.ts:102)). 모델이 손상돼도 UI는 설치됨으로 보일 수 있으나 Python이 모델을 준비할 때 검증·재다운로드가 실행된다. 오프라인 설치 실패, 오류 표시, 공유 파일 삭제/재설치는 설치 앱에서 확인해야 한다. SFace로 조용히 대체하는 경로는 없다.

## 4. 동일 입력 A/B와 채택 기준

1. **입력 고정:** 대표님께 전달한 설치본의 desktop 네 SHA, 원본 영상 SHA, 참조 사진별 SHA, 모델 SHA, OS/CPU, 현재 `dev`와 feature SHA를 기록한다. 이미 본 뉴진스·ANTIFRAGILE 라벨은 회귀용으로 쓰고, 새 촬영의 원본 우선 라벨을 별도 잠금 검증으로 둔다. 기존 릴레이 18구간은 내부 메인 교대 때문에 단일 이름 GT로 재사용하지 않는다.
2. **변수 하나씩:** W13 pose·메인 몸 bbox/track·shot·구간을 고정한다. 같은 YuNet 후보/ROI에서 SFace와 AuraFace의 **참조와 영상 얼굴을 각각 같은 모델로 재임베딩**한다. 모델 교체 비교와 얼굴 선택/시간 규칙 추가 비교를 분리한다. 거리·margin은 개발 표본에서만 선택해 검증 표본에 고정 적용한다.
3. **분리 채점:** (a) 원본 얼굴 검출·비얼굴, (b) 얼굴 한 장의 신원/보류/등록 외, (c) 메인 몸↔얼굴 소유, (d) track·클러스터 동일인 분리와 다른 사람 오합침, (e) main 클립 이름·group 수신자·구간 경계, (f) 분석 wall time·peak RSS·모델 다운로드/초기화 시간을 각각 기록한다. 배정 수 증가나 후보 수 감소만으로 합격시키지 않는다.
4. **회귀 gate:** 기존 정답 손실과 신규 오배정은 사례별 원본에서 확인한다. 특히 동시에 등장하는 서로 다른 멤버, 교대 직전/직후, 작은·흐린 얼굴, 등록 외 인물, group 공유를 포함한다. 하나의 잘못된 확정이 클립 이름과 group 소속을 연쇄 변경하는지 확인한다. 독립 표본 없이 새 기본 문턱이나 인물의 후처리 규칙을 제품값으로 채택하지 않는다.
5. **앱 확인:** 무대 세션이 통합한 별도 빌드에서 사용자가 같은 영상으로 새 프로젝트를 실행한다. 입력/결과와 소스 SHA를 함께 보존하고, 기존 완료 프로젝트와 구별한다. Windows 실기는 사용자 담당이며 이 검토에서 실행하지 않았다.
