## 실제 검증과 한계

- 평가용 테스트를 먼저 작성했고 구현 전에는 모듈 부재 `ImportError`가 났다. 구현 후 `unittest` 7개(이번 3개+기존 관측 4개), Ruff, compileall 통과. [독립 검산](../../../../../../.worktrees/shared-reference-face-matching-20261013/evaluation-output/antifragile-holdout-20261014/sface-embeddings-v1/audit.json) SHA `ea4de0e252996b269ddf41bcc9aaa32cfb540cf0038d28c211989bb0a12f86ea`: 계획·원본·모델·참조 해시, 특징/점수 파일 해시, 후보 ID 일치, 영상 `(3450,128)`·참조 `(24,128)` 유한 벡터, 최대 단위길이 오차 `1.19e-7`, 점수 `(3450,21)`의 **전항목 재계산 일치**를 확인했다.
- **3,450개가 실제 얼굴 3,450개 또는 인식 성공 3,450건이라는 뜻은 아니다.** 앞 단계 약 112초 손 오검출 후보를 포함하며, 얼굴 크기/흐림/가림 때문에 특징이 만들어졌어도 식별 가능한지는 별도 라벨이 필요하다. 사진 21장의 선택도 새 영상의 멤버 정답을 제공하지 않는다.
- 다음 필수 연결: W13이 **동일 원본 SHA**에서 구한 메인 몸 bbox/track·역할(메인/공동/군무/없음)·교대/구간 경계의 frame index 또는 PTS를 받는다. 얼굴 후보가 메인 몸에 실제로 속하는지 별도 검토하고, 관측 없음·연결 모호·인식 점수 부족/충돌·잘못된 멤버 확정을 나눠 채점한다. 그 후 동일한 연결 얼굴과 참조 사진으로 AuraFace 등 후보를 별도 embedding 공간/전처리에서 공정하게 비교한다. W13 출력, 독립 새 영상 GT, SFace/Aura 우열, 전체 clip 정확도, 제품/Windows 통합은 **미검증**이다. 사용자에게 현재 추가 라벨 작업을 요청하지 않는다.
