# W14 — 입력 안정성으로 잘못된 충돌과 실제 타인 혼입을 구별할 수 있는가

2026-10-14. 이전 입력 민감성 진단에 이은 사용자 “진행해줘” 범위. Superpowers 원인 진단·evaluation spike. 제품 코드가 아닌 평가 전용 가설 검사다.

## 1. 결론부터

**두 입력에서 모두 확정되지 않은 얼굴을 버리는 방식은 채택하지 않는다.** AuraFace의 문제 구간은 혜인으로 배정되지만, 실제로 다른 사람인 얼굴을 한쪽 입력이 맞힌 근거도 함께 버리는 반례가 확인됐다.

대표 반례: 사용자 정답이 해린인14.147초·14.615초 얼굴 두 개와, 민지인103.704초 얼굴 하나를 조합했다. 앞의 두 얼굴은 양쪽 입력 모두 해린이다. 민지는 기존 입력에서 보류, 새 입력에서 민지 정답 확정이다. “둘 다 확정” 규칙을 적용하면 민지가 제외되어 세 얼굴 전체가 해린으로 배정된다. 이 세 얼굴은 모두 기존 사용자가 식별 가능하다고 답한 얼굴이다.

이것은 실제 영상에서 세 얼굴이 같은 메인 구간에 들어 있었다는 주장이 아니다. **정답이 다른 실제 얼굴로 만든 혼입 검사**다. 잘못된 얼굴 제외가 무엇을 놓칠 수 있는지 확인한다.

[규칙·안전장치·반례 비교 화면](http://127.0.0.1:58261/face-input-stability-v1/index.html). 기본은 AuraFace/양쪽확정/충돌보존 끔. 체크박스로 원래 근거를 보존하면 반례는 확인 필요가 되지만 실제57–63초도 다시 보류가 된다. 입력이나 내보내기 작업은 필요 없다.

## 2. 고정 조건과 비교안

- 이전243관측,3모델의 저장된 두 입력 결과만 사용. 두 입력은 모두 실제4K 인식 픽셀이고, YuNet의bbox/5점 검출 해상도만 달랐다.
- 기존36개 안무 메인 범위,3개선택법×99슬롯, 원본/참조/모델/거리/임계값 고정. 새 모델 추론·검출·다운로드·설치·pose0.
- 같은 시점의 두 입력은 한 관측이다. 지지2개로 세지 않는다. 새로운 정답·인접얼굴 정답전파 없음.
- 이름GT34개(식별가능28/어려움6), 다니엘GT0. 전체36범위 중11에 일부 얼굴GT,25범위는GT없음. 현재분석은W13-35고정snapshot이며 최신W13-40평가가 아니다.

두 방식 각각에 ‘원래 충돌 보존’을 끄고/켜서 총4정책을 평가했다.

1. **양쪽 확정**: 같은 얼굴의 두 입력 모두 동일 멤버로 확정되어야 얼굴 근거로 채택.
2. **1위 일치**: 양쪽 점수1위가 같고 최소한 한쪽이 그 멤버로 확정해야 채택. 두 입력 모두 보류이면 새확정을 만들지 않는다.
3. **원래 충돌 보존(각 방식의 안전장치)**: 채택되지 않은 얼굴이라도 어느 입력에서 다른 멤버로 확정되었다면 범위를 확인 필요로 유지. 단순 미관측/보류는 반대멤버 표가 아니다.

원래 모델별 거리/차이 기준을 조절하지 않았다. 조건은 결과 계산 전에 manifest에 고정했다. 이미 이전 실패를 본 개발자료의 사후가설 검사이며 독립평가나사전등록 연구가 아니다.

### 얼굴 정답34개 중 올바른 확정

이34개에서 모든 방식의 오확정0. 나머지는 보류. 식별가능28개만 보면 기존/새/양쪽/1위는 SFace13/15/12/16, Aura16/17/16/17, Intel6/9/6/9다. 전체범위 정확도나실제배포 성능 개선으로 해석하지 않는다.

### 실제 문제 구간57–63초의 전체87시점

- Aura 양쪽확정: 혜인. 원래충돌보존을 켜면 보류. 1위일치는 보존 여부와 관계없이 보류.
- SFace: 네정책 모두 보류. 입력 안정성만으로 현재문제를 해결하지 못했다.
- Intel: 양쪽확정은 지지부족으로 보류,1위일치는 혜인. 다른시점의정답으로 구간전체를정답판정하지 않는다.
- Aura에서 제외된 해린판정 시점은 직접GT가 없으며 이를 ‘확인된 오답을 수정했다’고 표현하지 않는다.

### 서로 다른 정답 얼굴을 섞은 검사

GT34에서 같은멤버 두얼굴(서로다른관측,≥0.25초차)+다른멤버 한얼굴을 모두 조합:2,941묶음. 동일멤버만 있는 세얼굴 대조230묶음. 동일face재사용이 많으므로2,941독립표본/FAR/실제혼입영상성능이 아니다.

|모델|양쪽확정에서 이미 알아본 타인의 증거를 지운 조합|그중 모두식별가능|해당 타인의 고유얼굴 수|
|---|---:|---:|---:|
|SFace|88|50|4|
|AuraFace|19|15|1|
|Intel0095|18|11|5|

- 양쪽확정+원래충돌보존은 위타인증거삭제를 모두막았다. 대신Aura의원래문제도보류로남는다.
- 1위일치는 이번조합에서 이미알아본타인의증거삭제0이었다. 그러나Aura/SFace원래충돌을해결하지못해완성안으로채택하지않는다.
- **0은 ‘타인혼입을모두검출’이라는뜻이아니다.** 원래양쪽모델입력에서다른사람을못알아보면두기준얼굴만으로이름이붙는사례가남는다. 전체단일이름배정수·새입력대조·기준얼굴지지확보여부·타인식별여부를별도로보존했다.
- 1위일치의기존새입력대비단일배정증가중에는타인증거삭제가아닌기준얼굴의지지증가로발생한경우가있다. 이를모두‘충돌삭제오류’로계수하지않는다.

## 4. 얼굴 특징만 비교하면 구별할 수 있는가

식별가능28얼굴로, 동일인물84쌍(0.25초미만인접제외)과다른인물284쌍의저장embedding cosine거리를비교했다. 모델/입력별로같은사람거리와다른사람거리가모두겹쳤다.

진단상한: 정답을미리안상태에서동일인물84쌍을전부유지하는거리한계(max positive)를잡아도, 새입력의다른사람284쌍중 SFace119/Aura247/Intel185쌍이같은편에남는다. 이는배포할threshold가아니며평가GT를사용한oracle진단이다. 기존입력은각212/256/234쌍이다.

따라서지금저장된특징에서거리한계하나만정해동일인물을모두연결하면서타인은모두분리하는것은불가능했다. 이결론은현재표본·cosine단일기준에한정한다. 모든알고리즘/모델의불가능성을뜻하지않는다.

## 6. 다음 방향·남은 입력

- **불안정한 얼굴이라는 이유로 반대 멤버의 근거를 삭제하는 접근은 중단한다.** 원래 관측·실패·타인 후보는 보존한다.
- 다음 검증 단위는 안무가 정한 메인 몸의 연속 경로다. 그 안에서 여러 시점의 얼굴 근거가 어떻게 이어지는지 확인한다. 같은 몸에 연결된 일시적인 얼굴 혼동과, 실제 다른 몸/사람으로 연결이 전환된 경우를 구분해야 한다. 몸/track ID만으로 동일인이라고 확정하거나 다수표로 타인 근거를 지우지 않는다.
- 기존 충돌 시점과 고정된 성공/실제 다른 사람 대조에서 시간적 근거를 먼저 검증하고, 이후 다른 촬영 영상으로 평가한다. 모든 배경 얼굴을 더 라벨링하는 방향이 아니다. 지금 사용자의 추가 입력은 필수가 아니다.
- 독립 촬영의 식별 가능한 얼굴·main 범위 정답, 모델별 기준 교정과 고정 평가, 실제 혼입/메인 전환, Mac arm64/Windows x64 패키징은 여전히 미검증이다. 모델 선택이나 제품 통합 준비가 끝난 상태는 아니다.
