# W13 첫 비교 범위 제안 — 장면 보존부터

상태: **기존 파일의 정적 대조 완료 / 새 모델 실행 전 제안**. 사용자가 지정한 원본은 `yFTAYXDTjqI` 전체 133.654059초다. 제품 코드·기존 결과는 바꾸지 않았다.

## 원본을 더 본 뒤 확인한 것

기존 앱은 메인 후보 두 구간 `20.487~30.030`초, `30.030~34.835`초를 그룹 구간과 많이 겹친다는 이유로 **얼굴 분석 전에 제외**했다. 합계 약 14.348초다. 저장된 그룹 clip은 그중 23.357~33.433초(10.077초)만 덮는다. 따라서 결과 clip이 전혀 없는 시간은 양끝 합계 **4.271초**다. 원본의 [19~34.75초 촘촘한 장면 모음](01-w13-full-source-review-guide.md#장면-모음-보는-방법)에는 한 사람이 계속 주도하는 대신 앞에서 움직이는 사람이 차례로 바뀌는 모습이 보인다. 독립 신원/track 검증 전에는 누구의 clip인지 단정하지 않는다.

같은 방식으로 53.5~57.5초와 58.5~61.75초도 서로 다른 단독 메인 **후보**로 좁혔다. 이 두 구간은 기존 결과에서 main clip으로 남았지만, 기존 clip 경계가 실제 교체와 일치하는지는 미검증이다. [전체 19구간 초안](01-w13-full-source-label-draft.json)에 명확한 후보와 보류 구간을 나눠 적었다.

## 첫 비교에서 바꿀 변수 하나

**제안 변수는 `탈락 장면의 보존 정책`이다.** 모델·tracker·얼굴 판정·멤버 이름·crop·UX는 이 비교에서 바꾸지 않는다.

| 항목 | 지금 앱 | 비교할 정책 |
|---|---|---|
| 그룹과 겹친 메인 후보 | 메인 처리에서 제외; 그룹 clip이 덮지 않는 양끝은 결과에서 사라짐 | 원본 시간·현행이 선택한 단일 후보 track·`group_overlap` 이유를 **확인 필요** 장면으로 남김 |
| 얼굴 표본 부족 메인 후보 | clip 생성 전 제외 | `insufficient_track_samples` 등 사유와 원본 구간을 **확인 필요**로 남김 |
| 그룹 clip | 1개로 유지 | 그대로 유지하며, 검토 후보와 시간상 공존 허용 |
| 인물 카드 | 한 clip → 한 명 | 이 단계에서는 자동 배정을 추가하지 않음. 공동 메인 판정은 별도 비교에서 검증 |

기존 결과만으로 가능한 **정적 가정 계산**: 두 `group_overlap` 후보를 검토 목록에 기록하면, 기존 그룹 clip과 중복되는 10.077초도 사람별 검토 대상으로 보이고, clip이 없는 **4.271초**도 원본에서 찾아갈 수 있다. 이는 새 MP4 4.271초 생성, 정확도 개선, 실제 사용자 검토 완료를 뜻하지 않는다. 후보 두 개가 여러 리드 교체를 가로지르므로 이를 그대로 한 사람에게 붙이는 방식은 제안하지 않는다. 얼굴 표본 탈락 1건은 현재 로그에 시간이 없어 정적 계산에 넣지 않았다.

## 이후 실제 metadata 비교를 한다면

기존 [평가 adapter](01-w13-evaluation-adapter.md)는 `smoothed_main`, `group_filtered_main`, `dropped_main`, 프레임별 선택 main bbox/track을 별도 기록한다. 그래서 같은 추론 결과에 **현행 drop 처리와 검토 목록 보존 처리**를 나란히 적용할 수 있다. 첫 비교는 현행 모델 분석 **최대 3회**만 제안한다. 대조 정책은 그 metadata에 오프라인 적용하므로 별도 모델 3회를 반복할 이유가 없다. 원래 제안한 최대 6회 상한보다 적다. 제품 변경 없이 분석 결과에서 다음을 계산한다.

1. 원본상 안무라고 확인된 시간 중 `인물 카드`, `확인 필요`, `어디에도 없음`의 시간. 검토 목록을 만든 만큼의 사용자 수정 부담과 거짓 검토 후보도 따로 센다.
2. 메인 사람 집합의 recall/precision·전환 지연은 **사람별 box/track이 확정된 라벨 구간에서만** 계산한다. 보존 성공을 메인 판정 성공으로 바꿔 쓰지 않는다.
3. 멤버 신원 정확도는 별도 평가다. 이번 보존 비교에는 멤버 이름이나 참조 이미지를 요구하지 않는다. 기존 앱의 예측 이름을 정답으로 쓰지 않는다.

첫 **보존** 지표에 한해 [공연 장면 가시성 라벨](01-w13-retention-visibility-label-v1.json)을 6.0~112.5초로 보수적으로 고정했다. 출연·종료 경계의 각 1초는 점수에서 제외한다. 이 라벨은 춤 동작 여부나 **사람별 메인 정답이 아니다**. 메인 정확도·전환 지연·공동 메인 평가에는 원본 연속 검토와 익명 사람별 위치/교체 라벨을 별도로 고정해야 한다. 현재 2fps 전체·4fps 두 부분의 정지 장면은 그 **후보 초안**이다. Python worktree의 실제 실행 코드 fingerprint, CPU/device, 기존 weight 사용 조건, 반복 횟수·시간/메모리 상한·출력 디렉터리를 [manifest](../09/30-w13-experiment-manifest.yaml)에 함께 고정한다. 지금 새 ML·모델 다운로드·유료 호출은 하지 않았다. 사용자에게 보여줄 실행 범위는 [한 장 요약](01-w13-first-evaluation-one-page.md)에 정리했다.
