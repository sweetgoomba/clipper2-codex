## 병합 후 표시·대표 이미지 보존 회귀

Nest `PersonProjectDetailBuilder`가 `rawGroups.filter(...).map(index)`로 기본 이름을 부여해 병합 후 다른 카드의 `Person N`이 바뀌고, 대표 그룹 한쪽의 이미지 후보만 남기는 문제를 재현했다. 원본 manifest의 index를 유지하고, 대표 그룹의 사용자 지정 이름·이미지를 우선한 다음 병합된 원본 그룹의 사용자 지정값을 사용하며, 모든 병합 그룹의 기본 이미지·후보를 중복 없이 제시하도록 고쳤다. 사용자 지정값은 기존 `person_highlight_edits` overlay에 그대로 둔다.

실패를 먼저 확인한 회귀와 Nest 빌드 후 관련 18개 테스트가 통과했다. 실제 저장된 37분 manifest(554그룹/1,301클립)에 사용자 확인 관계 `person_006`, `person_008`, `person_013`→`person_005`와 `person_008` 대표 이미지 선택을 **프로세스 메모리에서만** 대입한 읽기 전용 dry run은 표시 551그룹, `person_007`의 `Person 7`, 병합 대표 이미지 경로, 병합 후보 12개를 확인했다. 저장된 프로젝트에는 해당 병합/대표 선택을 기록하지 않았다. Job JSON은 failed 4/completed 1/active 0이었고, 같은 Nest worktree의 서버를 새 빌드로 정상 재시작한 뒤 `/v1/app/info` HTTP 200을 확인했다. 얼굴 추론·영상 재분석·실제 UI 조작·37분 정확도 측정은 하지 않았다. 이번 변경은 수정 결과의 표시 계약에 한정되며 동일인 자동 grouping의 불합격 상태는 그대로다.

## 10/1 후속 승인과 다음 평가 순서

사용자는 앞선 “추가 얼굴 추론 횟수 소진” 안내에 대해 **「그냥 얼굴 추론 계속 몇번이고 해도 돼. 승인할게」**라고 답했다. 따라서 기존 YuNet/SFace를 이용한 후속 **얼굴 추론 실행 횟수 제한은 해제**한다. 이 말은 새 모델 다운로드, 외부 유료 API, Build5, 자동 과금·권한 변경, 기존 완료 프로젝트 덮어쓰기를 승인한 것으로 해석하지 않는다. 개별 실행의 입력·GT·코드/모델 hash·자원 상한·출력 위치는 실행 전에 계속 고정한다.

다음 원인 분리 평가에서 원본 SHA `29101ea9…b16ecdea3`로 먼저 고른, 지금까지 라벨·튜닝하지 않은 `[985,1015)`, `[1526,1556)`, `[1623,1653)`초 세 창(합계 90초)을 사용한다. 선택은 `random.Random(int(source_sha256[:16],16)^20261001)`로 30초 창을 뽑고 기존 `[0,20)`, `[180,210)`, `[1140,1170)`초 창에서 30초 이상 떼는 규칙이다. 5 fps 전체 artifact에는 이 창에 각각 291/222/108관측과 11/13/8개 clip이 있으나, **원본 얼굴/배경/동시 출연·컷/연속 장면 경계 라벨을 먼저 고정하기 전에는 후보 품질을 채점하거나 규칙을 조정하지 않는다**. 원본/기존 YuNet·SFace SHA를 다시 확인했고 장치는 macOS 27.0 arm64, OpenCV 4.13.0 CPU다. 실제 새 추론은 이 결정을 기록하는 동안 **0회**다.

우선 원본만으로 명확한 익명 인물·배경/단역·동시 출연·컷과 연속 등장 경계·판정 불가를 라벨한다. 이어 기존 5 fps 결과를 보수적 기준으로 채점해 검출 누락/오검출, 같은 사람의 그룹 분리/다른 사람 오합침, shot과 사용자가 기대한 scene의 차이, 대표 crop 흐림을 분리한다. 이후 저장 관측만으로 grouping·구간 후보를 **한 변수씩** 대조하고, 추가 얼굴 추론이 구체적인 미해결 가설을 검증할 때만 같은 hash/격리 폴더/회당 시간·RSS·출력 상한을 정해 실행한다. 작은 개발 창의 개선만으로 전체 결과를 교체하지 않으며, 기존 카드와 사용자 수정은 보존한다.

후속 가설의 근거로 새 전체 결과의 P3 라벨 A는 1145초와 1155초에 `person_006`, 1160초에 `person_316`이었다. 1155초/1160초 두 얼굴의 저장 SFace cosine은 **0.1861**이고 다른 shot이다. 따라서 전역 cosine threshold만 낮춰 자동 병합하는 방식은 근거가 약하며, 이 사례만으로 두 큰 그룹 전체가 같은 사람이라고 판정할 수도 없다. 홀드아웃의 다른 인물 오합침을 우선 확인한다.
