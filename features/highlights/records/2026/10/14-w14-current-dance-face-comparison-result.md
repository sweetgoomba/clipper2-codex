# W14 · 현재 안무 메인 출력과 SFace/Aura 연결 비교

## 결정

**AuraFace로 제품 기본 모델을 바로 교체하지 않는다.** 추가 영상의 선명한 12얼굴에서 Aura12/SFace10 정답이었지만, 실제 안무 메인 소비 결과까지 일관된 우위는 아니다.

[클립·멤버·원본 비교](http://127.0.0.1:58261/dance-main-comparison-v1/index.html). 사용자가 추가 라벨을 작성할 필요는 없다. 얼굴 모델을 앱에 연결했다는 뜻이 아니라, 고정된 안무 출력에 공통 매칭 모듈을 연결한 **평가 consumer**다.

## 무엇을 실제로 했나

- W13 현재 유지 후보40B의 `joint_onset-{segments,observed,pose}.json`을 읽기 전용으로 복사·해시 고정했다. W13 최신 실패49나 다른 세션 파일은 수정하지 않았다.
- 58구간: 단독33, 공동1, 군무6, 미정18. 매칭 대상은 단독33명+공동2명=35개이며, 계획된 몸 경로37개를 모두 포함한다.
- 저장된 두 native4K 평가 자료243+238=481행에서 동일 관측127개를 제거하고, 현재 군무가 된11.678초의 옛 메인1개를 제외했다. 최종353개 관측을 양쪽 모델에 동일하게 사용했다.
- 재사용은 같은 원본hash·frame·실제 몸 상자·동일 pose 후보 풀로 확인했다. 예전 segment/track ID가 같다는 이유만으로 연결하지 않았다. 중복 관측은 두 모델 벡터와 검출/연결 정보를 비교했다.
- 구간/track 변경에 맞게 evidence provenance를 새로 만들고 기존 벡터로 다시 매칭했다. 참조23사진·모델별 공간·threshold·정렬·per-run minimum_support2는 고정했다. 모델 간 공간/캐시를 혼합하지 않았다.
- 모든 기존 관측을 보존했다. 작은 충돌을 지워 결과를 좋게 만들지 않았고, 한 경로의 이름을 다른 경로로 전파하지 않았다.

## 실제 결과

| 지표 | SFace | AuraFace |
|---|---:|---:|
| 메인 대상 이름 배정 /35 |16|13|
| 확인 필요 /35 |19|22|
| 사용자 정답이 연결된 얼굴 관측 /34: 정답 |18|19|
| 같은34얼굴: 다른 멤버로 확정 |0|0|
| 같은34얼굴: 보류 |16|15|

Aura는 SFace가 보류한3개에 이름을 붙이고, SFace가 이름을 붙인6개를 보류했다. 다른 이름으로 직접 바뀐 구간은 없다. **배정 수는 정확도가 아니며, 34얼굴 GT는 구간 전체 GT가 아니다.** 이전 개발 진단의 불균등한 표본을 재사용했으므로 새로운 독립 평가도 아니다.

1. **13.814–15.482초 (클립29)**: SFace 해린13+하니1 근거 충돌 → 보류. Aura 해린17 → 해린. 이 결과만으로 SFace의 하니1이 오답이었다고 단정하지 않는다.
2. **21.889–27.294초 (클립32)**: SFace 두 경로에서 다니엘44/30 → 다니엘. Aura 앞 다니엘44, 뒤 다니엘28+해린2 → 보류. 25.759/25.826초의 해린판정 때문에 보류되는 기존 문제가 현재 소비자에서도 남는다.
3. **53.387–57.257초 (클립42)**: SFace 민지5 → 민지. Aura 민지4+하니1 → 보류.
4. **57.257–63.063초 (클립43)**: 앞33관측은 두 모델 모두 확정0. 뒤54관측은 SFace 하니4+혜인2 충돌, Aura 혜인28. Aura도 앞 경로가 뒷받침되지 않아 전체구간은 보류. 뒷부분 혜인 근거를 앞부분으로 빌려 쓰지 않았다.

## 검증과 시행착오

- 새 검출·인식·몸 추론0. 재생2.186초·RSS171,278,336B, 상한180초/4GiB 안에서 완료. 현재 Mac CPU 환경만 해당한다.
- manifest revision2의58입력hash 일치. 기존 얼굴 점수/순위/거부사유706개가 재계산과 정확히 일치한다. exact body/pose pool 확인480행.
- 독립 리뷰가481→353, 중복127 벡터/이미지, 군무제외1, 35scope/37run 시간·track 소속, 배정수 및 GT34 채점을 재검산했다. 중요한 결함 없음.
- 관련 `test_run_scoped_matching.py`, `test_quality_sampling.py` 29개 통과. 제품 전체 suite/Windows/설치형 앱 통합 검증은 이번 실행에 포함하지 않았다.
- 첫 replay는 기존 `load_context` 반환 tuple 인덱스 착오로 예측 저장 전에 실패. 초안 코드/manifest를 보존하고 수정한 revision2를 고정했다. 모델 실행이나 결과 선별 실패가 아니다.
- 브라우저에서1920×1012 원본 영상/얼굴이미지 로딩, 모델 전환, 멤버 필터, 빈 목록, 사례 전환과 클립 재생을 확인했다. UI 경계에서 초과 재생을 끝 시점으로 되돌리고 빈 목록의 이전 영상을 숨겼다.

## 한계 및 다음 구현의 우선순위

1. 제품 기본 SFace 유지. Aura 후보/공통 모듈은 보존한다. Intel은 이번 두 모델 소비자 비교에 추가하지 않았다.
2. **얼굴 추출 입력과 최종 합의를 별도 작업으로 분리한다.** 실제 다른 얼굴 연결·위치점 오류·모델 인식 불안정을 구별할 수 있도록 동일 시점의 원본/선택 얼굴/정렬/점수를 근거로 사용한다. 이미 해본 전체 재검출·참조 최근접·수동 위치점·단순 안정성 필터를 다시 성능 개선처럼 보고하지 않는다.
3. 다음 변경의 주 대상은25.759/25.826초의 순간 충돌과57.257–59.459초의 무확정이다. 전체 투표/threshold 완화/다른 run 이름 전파는 기본 해결책으로 채택하지 않는다. 실제 타인 전환 반례를 보존하면서 입력 또는 판정을 바꾸는 근거가 있어야 한다.
4. 685개 현재 메인 시점 중353개 저장 관측을 사용했고332개는 이번에 새 얼굴을 추론하지 않았다. 새 공동 시작의8개(4시점×2명)도 여기에 포함된다. 모든 프레임을 분석한 결과라고 표현하지 않는다. 각 run은 관측을 갖지만 연속 물리적 동일성은 안무 consumer의 가정이며 독립 GT로 확정되지 않았다.
5. 새 두 영상에는 W13 main/segment 결과가 없어, 그12얼굴 결과를 이번 클립 GT나 독립 구간 정확도로 합산하지 않았다. 제품 적용 판단에는 고정 소비자+충분한 구간 정답, Macarm64/Windowsx64 packaging과 런타임 검증이 남는다.

W14 평가/API/fixture 소유, W13 main/몸/구간/mapping/crop/제품adapter 소유 유지. 계약 상호확인→시간/좌표/scope/실패 호환→선택venv/consumeradapter→양OS→합의merge 순서 유지. 이번은 읽기 소비자 검증이며 W13의 새 수락이나 제품 연결 승인 완료가 아니다. 채팅 발신·새세션·commit/push 없음.
