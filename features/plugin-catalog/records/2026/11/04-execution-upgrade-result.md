# 플러그인 실행 요금제 제한과 업그레이드 연결 결과

2026-11-04. 사용자 요청에 따라 별도 새 채팅 **플러그인 요금제 제한·업그레이드 독립 검증**(01a1a3a2-09dd-7d73-bbe0-8c100795ae9e)의 읽기 전용 검증을 먼저 완료한 뒤 구현했다.

## 반영한 동작

- 신규 실행의 서버 권한 검사와 기존 승인 attempt 재사용은 유지했다. 견적에서도 요금제 허용 여부를 잔액 조회보다 먼저 판단하고 제한 사유를 우선한다. 기존 숫자 응답 계약은 유지한다.
- 공통 앱 안내와 스토리보드·설명형 숏폼의 개별/재시도/비동기 실패에서 정확한 허용 요금제와 웹 이동을 제공한다. 기존 상위 연속 집합에만 “이상” 표현을 사용하고 비연속 허용 집합은 개별 이름으로 안내한다.
- 웹은 현재 유효 이용권과 실제 구독을 구분한다. Free는 신규 구독, 활성 유료 구독은 기존 /my 견적·명시 동의·차액 결제·변경 흐름을 재사용한다. 현재 상품, 결제 주기 변경, 상향, 하향 예약, 예약 상품, 금지된 연간→월간을 구분한다.
- 프로모션·관리자 이용권과 의미 있는 미완료/비활성 구독은 기존 정책에 따른 관리 경로를 안내한다. 새로운 유료 전환 정책을 만들지 않았다.
- 로그인/desktop handoff의 안전한 /pricing?plugin=... 복귀 주소를 양쪽 allowlist에 추가했다. 판매 상품과 별도로 플러그인 권한 카탈로그를 확인해 판매 중단/상품 없는 허용 등급을 구매 가능 상품으로 오인하지 않는다.
- 웹 결제 후 앱 재시도는 최신 서버 견적과 실제 실행 권한/크레딧 검사를 사용한다. 캐시된 잔액으로 동의를 미리 차단하는 경로를 제거했고 기존 가격 확인·과금·큐·환불·복구 정책은 유지했다.

## 구현 후 독립 검토와 수정

독립 코드 검토에서 나온 4건 모두 회귀 실패 재현 후 수정했다.

1. 업그레이드 이동 모달의 결과를 과금 동의 Promise와 분리했다. 두 종류 모달이 겹쳐도 업그레이드 버튼이 실행 동의가 되지 않는다.
2. 이미 유료 생성이 끝난 설명형 숏폼의 무료 최종 렌더 재시도에 영상 생성 요금제/잔액 검사를 적용하지 않는다.
3. 과거에 보관된 다른 장면의 제한 오류가 최신 허용 재시도에서 다시 뜨지 않도록 실패 변화를 구분한다. 새로 조회한 유효 권한이 이미 허용하면 낡은 업그레이드 안내를 숨기되 실제 실행 검사를 생략하지 않는다.
4. 스토리보드 제한 견적에도 “다시 확인”을 제공한다. 수량은 유지하고 최신 견적을 조회하며 별도의 명시적 크레딧 동의 전에는 생성하지 않는다.

후속 경계 확인에서는 서버가 과금하지 않는 0장/이미 완료된 그림·영상 단계 전환도 보존했다. 실제 계획과 준비된 자산이 새 작업이 없음을 증명할 때만 전환·일괄·자동 이어가기의 유료 단위 견적을 생략한다. 미완료 변화 그림·아직 차감하지 않은 대기 영상과 개별 다시 생성/수정은 계속 검사한다. 이 경계는 6개 실패 재현 후 수정했다.

설명형 숏폼은 플러그인 식별자가 분명하므로 과거 문자열 오류에도 shortform_explainer 문맥을 사용한다. 알 수 없는 플러그인이나 요금제를 임의로 추측하지 않는다.

## 검증

- 웹 API: 전체 484 스위트, 5,324 테스트와 5 스냅샷 통과. 기존 16 스위트/174 테스트 skip.
- 로컬 서버: 전체 5,401 테스트 통과. 테스트용 CLIPPER_AUTH_MODE=local 및 제한된 동시 실행으로 개발 .env.local JWT 설정의 영향을 격리했다. 환경 파일은 수정하지 않았다.
- 웹 클라이언트: 전체 661 테스트 통과.
- 앱 UI: 최종 변경 관련 362 테스트, 스타일 검사 21개, 타입 검사 및 기본 packaged 빌드 통과. 마지막 P2 수정 후 전체 10,769/10,769 테스트가 통과했다.
- 네 저장소 빌드 및 diff 공백 검사 통과.
- 격리된 실제 Chrome 화면에서 방문자/Free/Basic 유료/연간/프로모션/계정 조회 실패를 가짜 API로 검증했다. Basic의 Pro 상향 선택은 기존 /my 명시 동의창으로 연결되며 동의 전 결제 요청이 없다. 동의 후 가짜 변경 응답을 주면 변경 API가 정확히 한 번 호출되고 Pro 카드가 “현재 이용 중”으로 갱신된다.
- 앱 전체 검사에서 TemplateBuilderEditorComponent tiny PNG 업로드 계열과 StoreComponent 3px 레이아웃 단언이 간헐 실패했다. 변경 없는 분리 실행은 각각 195/195, 81/81 통과했다. 수정 중 한 전체 실행에서는 TemplateBuilderEditorComponent의 “배경 추가가 서버 쪽 실패면 서버 에러번호를 그대로 싣는다”(spec.ts:1651, calls.mostRecent undefined) 1건 실패/10,759 통과였다. 마지막 P2 수정 후 단 한 번 실행한 최종 전체 검사는 10,769개 모두 통과했다. 앞선 간헐 실패가 사라졌다고 보장하거나 기준 대비 원인을 단정하지 않는다. 관련 없는 소스/테스트는 수정하지 않았다. 상세 실행별 실패는 구현자 보고서에 보존한다.

## 제한과 상태

실제 회원의 PG 결제, 외부 생성 제공자 호출, 실제 구매 권한 E2E는 수행하지 않았다. 웹 빌드는 성공하지만 initial bundle이 500 kB 예산보다 12.08 kB 큰 경고가 있다(최종 512.08 kB, 기준 브랜치와 경고 차이는 별도로 측정하지 않았다).

네 코드 저장소 모두 feat/plugin-execution-upgrade 브랜치에 미커밋 변경으로 보존했다. 커밋·push·merge 및 배포는 하지 않았다. 관리자 설정과 Electron 셸의 제품 코드는 변경하지 않았다.

## 구현·검사 후 새 별도 세션 검증

사용자의 추가 요청에 따라 구현과 검사 결과를 확정한 뒤 새 읽기 전용 채팅 “플러그인 요금제 제한 구현 후 최종 독립 검증”(01a1a3bd-9925-77f1-bf27-84e696320c74)을 생성했다. 최종 미커밋 diff와 신규 파일, 요구사항 및 모든 실패/통과 기록을 전달했다. 이 세션이 실패한 변화 그림만 남은 무료 전환의 P2를 실제 서버 경로로 재현했고, 주 세션에서 해당 store와 spec 두 파일만 최소 수정했다. 권한 거부/잔액 부족의 무료 직접·자동 전환과 유료 대조를 포함한 9개 회귀는 RED 4건 후 GREEN으로 검증했다. 같은 별도 세션의 수정 재검증에서 P2 해결을 확인했으며 추가 확정 결함을 발견하지 못했다. 이후에도 사용자 지시 없이 커밋·push·merge하지 않는다.

## 최종 독립 재검증 결과

최초 독립 실행 API155/로컬194/복구30/앱496/웹148 통과. 수정 후에는 별도 세션이 store282개를 독립 실행하고 기존 자연 실패 재현과 실제 서버 판정 18조합을 대조해 모두 통과했다. 이전 P2 미해결 판정은 최신 재검증으로 대체됐다. [독립 검증 원문과 수정 재검증](04-execution-upgrade-final-independent-review.md)에 판단 근거와 한계를 보존한다.

최종 전체 실행 테스트는 총 22,155개 통과(웹 API5,324 + 로컬5,401 + 웹661 + 앱10,769); API 기존174 skip은 별도다. 앱 수정 대상362 및 스타일21, 네 저장소 빌드/diff 검사도 통과했다. 실제 PG/운영 회원/외부 생성 종단 간 실행은 하지 않았다.

최종 상태: 네 코드 저장소 모두 feat/plugin-execution-upgrade 미커밋 변경 보존. 구현 전 별도 검증 → 구현·검사 → 구현 후 새 별도 검증 → 발견 P2 최소 수정·검사 → 같은 세션 독립 재검증까지 완료. 사용자 지시가 없으므로 dev 병합·커밋·push는 하지 않았다.

## 사용자 지시에 따른 dev 병합 완료

2026-11-04 사용자의 “데브 병합 해” 지시에 따라 최종 검증 코드를 네 저장소에서 커밋·dev 병합하고 원격 origin/dev에 반영했다. 실제 원격 커밋과 로컬 dev 일치를 확인했다. 병합본 검사 결과와 앱 전체 실행의 간헐 실패 및 분리 실행 내역은 [dev 병합 기록](04-execution-upgrade-dev-merge.md)에 보존한다.
