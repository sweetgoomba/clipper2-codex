# 종료일 미정 ↔ 날짜 지정 · 수정 회귀 검증

2026-11-02 KST. 사용자 질문에 따라 앞선 생성/활성 검증에 빠져 있던 양방향 수정의 실제 저장·재조회 검증을 보강했다. 제품 구현은 변경하지 않았다. 기존 `feat/signup-credit-promotion-free-20261102` API/Admin 테스트만 추가했고 커밋·푸시 없음.

## 검증 범위

| 기존 종료일 | 수정 | 참여 이력 없음 | 참여 이력 있음 |
| --- | --- | --- | --- |
| 미정(null) | 미래 날짜 지정 | 통과 | 통과 |
| 미래 날짜 | 미정(null)으로 삭제 | 통과 | 통과 |

위 네 조합을 크레딧형/이용권형 각각에 실행했다(실제 DB8개). 실제 `PromotionsService.updateCampaign` 트랜잭션으로 수정한 뒤 반환값·DB 원본·상세 조회·목록 조회에 같은 nullable 종료일이 남는 것을 확인했다. 수정 전후 기존 회원의 크레딧 지급량·잔량·지급일·만료일과 이용권 기간/상태를 비교해 동일함을 확인했다. 새 회원의 코드 등록·혜택 지급도 통과했다. 날짜 지정 후 해당 시각에 만료 sweep하면 비활성화되고, 미정으로 변경하면2099년 sweep에도 활성 상태를 유지했다.

추가 실제 DB2개:

- 비활성 캠페인에서 null→날짜→null로 수정해도 비활성 상태 유지.
- 이미 종료된 캠페인의 종료일을 미정으로 바꿔도 비활성 유지. 운영자가 명시적으로 재활성화한 뒤 등록·가입400+프로모션200=600 지급 가능.

관리자4개: 참여 이력0/2건 × 두 방향. 실제 component drawer input에 날짜 입력/빈 값으로 변경하는 이벤트를 전달하고, 변경 전 저장 비활성→변경 후 활성→기존 캠페인ID로 update 요청을 확인했다. 빈 값은null, 날짜는 선택일 전체가 포함되는 다음날0시의 exclusive timestamp로 전송된다. 크레딧 지급량/유효기간과 잠긴 시작일을 유지한다.

## 결과와 증거

- 실제 PostgreSQL 통합 전체33개 통과(기존23+추가10).
- 관리자 프로모션 component55개 통과(기존51+추가4).
- 두 테스트 파일 `git diff --check` 통과.
- 추가 테스트만 변경했으므로 제품 rebuild/서버 재시작/전체 회귀 반복은 하지 않았다. 직전 제품 전체 검증 결과는 [앞선 구현 기록](02-open-ended-campaign-implementation-and-verification.md)에 보존한다.
- 로그: `/tmp/open-ended-edit-integration-final.log`, `/tmp/open-ended-edit-admin.log`.
- 최초 새 DB 시험은 검증용 snapshot 쿼리에 실제 테이블명 `user_access_grants` 대신 `access_grants`를 쓴 오타로4개 실패했다. 테스트 쿼리만 수정하고 검증용 DB를 새로 준비한 후33개 통과했다. 제품 결함이나 수정으로 오인하지 않는다. 기존 pg9 deprecation 경고는 유지된다.
