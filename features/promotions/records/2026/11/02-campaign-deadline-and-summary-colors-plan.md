# 캠페인 종료일 단축 허용 · 확인창 열 배경 구분

사용자 피드백: 참여 이력이 있어도 긴 캠페인의 등록 종료일을 앞당길 수 있어야 한다. 등록 기한과 지급 혜택 만료는 별개다. 인원 제한은 기존값 증감/무제한 해제·추가를 모두 허용하되 각 코드의 이미 등록한 인원 아래로는 줄이지 않는다. 확인창은 양쪽 글자색을 같게 하고 열 배경만 은은하게 다르게 한다.

- [x] RED: 종료일 단축 API·관리자 date min·동일 글자색/다른 배경을 재현한다. 5명 등록일 때100→90/5/무제한, 무제한→90 허용·4거절을 확인한다.
- [x] GREEN: API의 참여 이력 잠금에서 등록 종료일 비교만 제거한다. 시작일 이후의 정상 날짜/null 검증, 다른 지급/참여 조건 잠금, 비활성·자동 만료 규칙은 유지한다. 관리자 min은 시작일로 바꾸고 거짓 단축 금지 안내를 제거한다.
- [x] 기존 공통 확인창 columns variant에만 열 배경/동일 글자색을 적용한다. 디자인 토큰 재사용, 다른 페이지 기본 확인창 유지.
- [x] 크레딧형/이용권형의 미래·과거 종료일 단축을 일회용 PostgreSQL15439에서 검증한다. 기존 크레딧/이용권 만료·잔량 보존과 신규 등록 제어, 실제5명 cap 변경/추가를 검사한다. 사용자DB15438은 변경하지 않는다.
- [x] API/Admin 전체 테스트·build·색상 검사·diff 검사 후 이 세션API4340만 재시작하고 관리자4242 사본을 갱신한다. 클라이언트/앱/다른 작업 서버·DB는 유지한다.
- [x] .codex의 이전 단축 금지 설명을 새 정책으로 정정·인계하고 결과를 사용자에게 설명한다. 커밋·푸시 없음.
