# 캠페인 생성 전 설정 확인 · 구현 계획

사용자 요청: 저장 시 입력·선택값을 다시 요약하고 확인 후 생성한다. 이미 회원이 참여한 캠페인의 수정 제한 정책은 유지하며, 모호한 ‘지급 조건’ 안내를 시작일/혜택/참여 대상/추가 조건/종료일 단축으로 명확히 설명한다.

기존 `feat/signup-credit-promotion-free-20261102` 격리 작업을 이어간다. 정책/DB/API 계약 변경이나 사용자DB 초기화, 앱/다른 작업 서버 재시작, 커밋·푸시는 하지 않는다. 전용 관리자4242만 최신 번들로 갱신한다.

선택한 구현: 기존 `ConfirmDialogService`/공통 Material 확인창 재사용. 새로운 모달 컴포넌트나 step UI를 만들지 않는다. 새 캠페인 생성에만 확인창을 추가하고 기존 수정 저장 흐름은 유지한다. 사용자 요구가 명확하므로 추가 선택/승인을 요구하지 않는다.

- [x] 기존 공통 확인창·캠페인 수정 API와 HTML 잠금 범위를 확인한다.
- [x] RED: 확인 전/취소 시 생성 요청 없음, 확인 중 재전송 차단, 입력 보존, 크레딧형/이용권형 요약과 전송값 일치, 명확한 잠금 오류를 검증한다. 기존 생성 시험도 비동기 확인에 맞춘다.
- [x] GREEN: 검증된 요청 snapshot으로 확인창 facts 생성. 이름/시작/종료(미정 포함)/혜택 종류·수량 또는 등급·기간/크레딧 사용기한/참여 대상/추가 조건/코드별 상한/초기 비활성을 표시한다. 취소는 drawer 입력을 보존하고 confirmed인 경우에만 생성한다.
- [x] HTML subtitle와 오류의 지급 조건 표현을 구체화한다. 잠금/상한/기간/이력 보호 정책은 변경하지 않는다.
- [x] 관련 및 관리자 전체 테스트, build, check:colors, git diff --check를 실행한다.
- [x] 실행 중인4242 번들만 갱신하고 실제 공통 확인창·취소 후 입력 보존을 브라우저에서 확인한다. 사용자가 만든 캠페인·참여 기록은 변경하지 않는다.
- [x] 실제 수정 가능/불가 표와 증거를 .codex/WORKBOARD/NEXT에 기록하고 사용자에게 설명한다.
