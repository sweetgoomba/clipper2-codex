# Clipper 요금제·크레딧·결제 정책 논의안

- 회의 대상: 경영진, 전략, 기획, 운영, 개발
- 작성일: 2026-08-19
- 회의 목적: 지금까지 준비한 상품안을 공유하고, 출시 전에 함께 정해야 할 정책을 논의함.

> 현재 문서에 적힌 가격과 크레딧은 논의를 시작하기 위한 안임. 실제 서비스 비용과 고객 가치를 분석한 뒤 가격, 제공 크레딧, 작업별 차감 크레딧을 함께 다시 정해야 함.

## 1. 한눈에 보는 요약

### 지금까지 준비한 방향

- 개인 사용자를 위한 Basic과 Pro 두 요금제를 준비하고 있음.
- 두 요금제 모두 월간과 연간 구독을 제공하는 방향임.
- 연간 구독도 크레딧은 한꺼번에 주지 않고 매월 나누어 제공함.
- 요금제 등급에 따라 사용할 수 있는 플러그인의 범위를 다르게 두는 방식을 검토하고 있음.
- 베리에이션 영상 생성만 Pro에서 제공하는 구분은 별도 정책 검토 없이 임시로 넣은 예시임.
- 구독 크레딧이 부족하면 추가 크레딧을 별도로 구매할 수 있도록 준비하고 있음.
- 구독은 카드 자동결제를 이용하고, 추가 크레딧은 카드·간편결제·계좌이체·가상계좌를 이용할 수 있도록 준비하고 있음.
- 다음 결제를 취소해도 이미 결제한 기간은 끝까지 이용하는 방향임.
- 결제 실패 시 바로 이용을 중단하지 않고 일정 기간 재결제 기회를 주는 방향임.

### 이번 회의에서 중요한 것

1. 가격과 크레딧 숫자를 바로 결정하는 것이 아니라, 별도 비용 분석의 범위와 담당자·일정을 정함.
2. Basic·Pro 두 단계로 충분한지, 세 단계 이상이 필요한지 논의함.
3. 요금제별 플러그인 사용 제한이 적절한지와 각 등급의 차이를 논의함.
4. 무료 체험, 크레딧 이월, 추가 크레딧, 연간 할인 방향을 논의함.
5. 환불 요청을 어떻게 받고 어떤 기준으로 처리할지 정함.
6. 결제 실패·해지·환불 상황에서 고객에게 어떤 안내를 할지 정함.

### 가장 중요한 전제

- 현재 참고하고 있는 작업별 크레딧 숫자는 실제 비용과 상품 정책을 반영하지 않은 임시값임.
- 이 숫자로 Basic은 몇 건, Pro는 몇 건을 만들 수 있다고 계산하면 안 됨.
- GPT를 비롯한 외부 서비스 비용, 이미지·음성·영상 생성 비용, 렌더링, 저장, 실패와 재시도 비용을 먼저 계산해야 함.
- 그 결과를 바탕으로 요금제 가격, 제공 크레딧, 작업별 차감 크레딧, 추가 크레딧 상품을 함께 정함.

## 2. 현재 준비된 상품안

### 2.1 요금제 구조와 구독 기간

새 결제·구독 구조를 준비하기 전에는 ‘Pro 1개월’, ‘Pro 3개월’, ‘Pro 1년’을 각각 하나의 요금제로 구분했음. 이 방식은 요금제의 등급과 이용 기간이 분리되지 않아, 고객이 상품 간 차이를 이해하기 어렵고 같은 등급에 여러 결제 기간을 일관되게 적용하기도 어려웠음.

이를 개선하기 위해 요금제 등급과 결제 기간을 분리했음. 먼저 Basic과 Pro라는 등급을 두고, 각 등급에서 월간·연간 등의 결제 기간을 선택할 수 있는 구조임. 향후 새로운 등급이나 결제 기간이 필요해지더라도 같은 원칙으로 확장할 수 있음.

현재 Basic과 Pro 두 단계로 구성한 이유는 다음과 같음.

- 초기에는 고객이 두 요금제의 차이를 쉽게 이해할 수 있도록 선택지를 단순하게 제시하려는 목적임.
- 아직 요금제별 가격, 제공 크레딧, 플러그인 범위가 정해지지 않아 세 단계 이상으로 나누면 각 단계의 차이가 불분명해질 수 있음.
- 먼저 두 단계로 고객 반응과 실제 사용 양상을 확인한 뒤, 뚜렷한 고객군과 추가 가치가 확인되면 중간 또는 상위 등급을 추가할 수 있음.

다만 두 단계 구성이 최종안은 아님. Basic·Pro만으로 고객군과 사용 목적을 충분히 구분할 수 있는지, 또는 입문·일반·전문 사용자처럼 세 단계 이상으로 세분화할 필요가 있는지 논의해야 함.

| 요금제 | 결제 주기 | 현재 준비된 가격안 | 현재 준비된 월 크레딧안 |
| --- | --- | ---: | ---: |
| Basic | 월간 | 19,900원 | 400 |
| Basic | 연간 | 190,900원 | 매월 400 |
| Pro | 월간 | 39,900원 | 1,000 |
| Pro | 연간 | 382,900원 | 매월 1,000 |

현재 연간 가격안은 월간 결제를 12번 하는 것보다 약 20% 저렴함.

이 숫자들은 실제 비용을 반영해 정한 최종 상품값이 아님. 별도 비용 분석 후 네 가지 상품을 모두 다시 비교해야 함.

함께 논의할 질문:

- Basic과 Pro의 두 단계만으로 충분한가?
- 세 단계 이상으로 나눈다면 각 등급은 어떤 고객과 이용 목적을 위한 것인가?
- 등급을 추가할 만큼 분명한 가격·사용량·플러그인 차이를 만들 수 있는가?
- 처음에는 두 단계로 시작하고 고객 반응을 본 뒤 세분화하는 방식이 적절한가?

### 2.2 요금제 등급별 플러그인 이용 범위

현재는 요금제 등급에 따라 사용할 수 있는 플러그인의 범위를 다르게 두는 방식을 준비했음. 낮은 등급에서는 일부 플러그인의 사용을 제한하고, 상위 등급으로 변경하면 이전 등급에서 사용할 수 없었던 플러그인이 열리는 구조임.

베리에이션 영상 생성만 Pro에서 제공하도록 구분한 것은 이 구조를 구체화하기 위해 임의로 넣은 예시이며, 확정된 상품 정책이 아님. 각 플러그인의 실제 비용, 고객 수요, 상품 차별화 효과를 비교하지 않은 분류이므로 이를 기준으로 요금제를 확정하면 안 됨.

회의에서는 개별 기능 목록을 하나씩 확정하기보다, 요금제에 따라 플러그인 사용 범위를 제한하는 방식 자체가 적절한지를 먼저 논의할 필요가 있음. 이 방향을 선택한다면 비용 분석과 고객 조사를 바탕으로 각 등급에서 제공할 플러그인을 별도로 정해야 함.

함께 논의할 질문:

- 요금제 등급별로 사용할 수 있는 플러그인을 제한하는 방식이 고객에게 납득 가능한가?
- 모든 요금제에서 같은 플러그인을 제공하고 사용량만 다르게 하는 방식이 더 적절한가?
- 플러그인을 구분한다면 어떤 기준으로 각 등급에 배치할 것인가?
- 상위 등급은 하위 등급에서 사용할 수 있는 모든 플러그인을 포함해야 하는가?
- Basic만으로도 고객이 서비스의 핵심 가치를 충분히 경험할 수 있는가?

현재 생각한 이용 방식:

- 구독이 활성화되어 있으면 남은 크레딧이 있어도 미리 구매할 수 있음.
- 추가 크레딧만 구매한다고 해서 이용기간이나 새로운 기능이 생기지는 않음.
- 구독이 끝나면 남은 추가 크레딧은 보관하지만 다시 구독하기 전까지 사용할 수 없음.
- 다시 구독했을 때 유효기간이 남아 있으면 이어서 사용할 수 있음.

- 구독 없이 추가 크레딧만 사용하는 상품도 나중에 필요한가?

## 3. 현재 준비된 구독 이용 방식

### 3.1 연간 구독과 월별 크레딧

- 연간 구독료는 한 번에 결제함.
- 포함 크레딧은 12개월치를 한꺼번에 주지 않고 매월 제공함.
- 매월 제공된 구독 크레딧은 다음 달 제공일에 만료하고 이월하지 않는 방향으로 준비했음.

함께 논의할 질문:

- 매월 사용량이 고르지 않은 영상 제작 서비스에서 무이월 정책이 적절한가?
- 한 달만 이월하거나, 월 제공량만큼만 이월하는 방식이 더 나은가?
- 무이월이라면 결제 전에 어느 정도로 눈에 띄게 알려야 하는가?

### 3.2 다음 결제 취소

- 사용자가 다음 자동결제를 취소해도 이미 결제한 기간은 끝까지 이용함.
- 남은 기간의 기능과 예정된 월별 크레딧도 유지함.
- 결제기간이 끝나기 전에는 다음 자동결제를 다시 켤 수 있도록 준비했음.
- 다음 결제 취소는 즉시 해지나 환불과는 다른 행동으로 봄.

이 방향은 고객이 이해하기 쉽고, 이미 결제한 기간을 보장한다는 장점이 있음.

### 3.3 요금제 변경

현재 준비한 방향:

- Basic에서 Pro로 바꾸면 남은 기간의 차액을 결제하고 바로 Pro를 이용함.
- Pro에서 Basic으로 바꾸면 다음 결제일부터 적용함.
- 월간과 연간 사이의 변경도 다음 결제일부터 적용함.
- 다음 결제 전에 예약한 변경을 취소하거나 다른 상품으로 바꿀 수 있음.

함께 논의할 질문:

- 즉시 Pro로 변경할 때 고객에게 차액과 추가 크레딧을 어떻게 설명할 것인가?
- 연간 구독 중간에 변경할 때도 같은 원칙을 적용할 것인가?
- 가격이 변경된 뒤 예약된 상품에는 신청 당시 가격을 적용할 것인가, 변경된 가격을 적용할 것인가?

### 3.4 결제 실패

현재 준비한 흐름:

| 시점 | 고객 상태 |
| --- | --- |
| 첫 결제 실패 | 이용을 바로 중단하지 않고 결제 실패 안내 |
| 1일 후 | 자동 재결제 시도 |
| 2일 후 | 마지막 자동 재결제 시도 |
| 3일 후 | 결제가 계속 실패하면 유료 기능 이용 중단 |

유예기간 동안에는 이미 가지고 있던 기능과 만료되지 않은 크레딧을 사용할 수 있도록 준비했음. 결제가 실패한 새 이용기간의 크레딧은 제공하지 않음.

함께 논의할 질문:

- 3일이 충분한가?
- 자동 재결제를 두 번 하는 것이 적절한가?
- 실패 직후, 마지막 재결제 전, 이용 중단 전에 각각 어떤 안내를 해야 하는가?
- 이메일, 알림톡, 앱 알림 중 어떤 방법을 사용할 것인가?

## 4. 가격과 크레딧은 별도 분석이 필요하다

### 현재 숫자를 그대로 판단 기준으로 쓰면 안 되는 이유

- 작업마다 사용하는 외부 서비스와 처리 시간이 다름.
- 같은 기능도 영상 길이, 해상도, 생성 개수, 선택한 모델에 따라 비용이 달라질 수 있음.
- 실패한 작업도 외부 서비스 비용이나 렌더링 비용이 이미 발생했을 수 있음.
- 고객은 여러 기능을 섞어 사용하므로 한 가지 작업만 기준으로 계산하면 실제 사용과 달라짐.
- 크레딧 숫자가 너무 크거나 작으면 고객이 실제 사용량을 이해하기 어려움.

### 별도 분석에서 확인해야 할 비용

- GPT 등 글·분석 관련 외부 서비스 비용
- 음성 생성과 음성 인식 비용
- 이미지 생성 비용
- 영상 생성 비용
- 영상 렌더링과 처리 비용
- 파일 저장과 전송 비용
- 실패, 재시도, 복구 과정에서 발생하는 비용
- 결제 수수료와 세금
- 고객 문의와 운영에 드는 비용

### 별도 분석에서 나와야 할 결과

1. 각 작업의 평균 비용과 비용이 많이 드는 경우의 상한
2. 작업 길이·해상도·생성 개수에 따른 비용 변화
3. 고객이 이해하기 쉬운 작업별 크레딧 차감 방식
4. Basic과 Pro의 가격 후보
5. 각 요금제의 월 제공 크레딧 후보
6. 추가 크레딧 상품의 수량과 가격 후보
7. 월간·연간 상품별 예상 수익과 비용
8. 사용량이 예상보다 많거나 적을 때의 영향

### 이번 회의에서 정할 것

- 이 분석을 누가 맡을지
- 어떤 서비스와 비용까지 조사할지
- 언제까지 첫 결과를 만들지
- 결과를 어떤 기준으로 비교할지

가격과 크레딧의 최종 숫자는 이 분석 결과를 보고 별도 회의에서 정하는 것이 안전함.

- 연간 구독에는 월간 대비 할인을 제공하는 경우가 많음.

## 7. 환불·크레딧 반환·고객지원

### 7.1 돈 환불

현재는 고객이 직접 환불을 요청하고 진행 상황을 확인하는 흐름이나, 운영자가 환불을 검토하고 처리하는 흐름이 아직 준비되지 않았음.

그 이유는 다음 정책이 먼저 정해져야 하기 때문임.

- 어떤 경우에 환불을 받을 수 있는가?
- 결제 후 며칠까지 요청할 수 있는가?
- 전액 환불과 일부 환불을 어떻게 구분할 것인가?
- 이미 지난 이용기간은 어떻게 계산할 것인가?
- 이미 사용한 크레딧은 어떻게 반영할 것인가?
- 연간 구독을 중간에 종료하면 얼마를 돌려줄 것인가?
- 환불 여부를 누가 확인하고 최종 결정할 것인가?
- 고객에게 처리 결과를 언제, 어떤 방법으로 알려줄 것인가?
- 결제·사용·안내·결정 기록을 얼마나 보관할 것인가?

먼저 필요한 일:

1. 국내 전자상거래와 디지털 콘텐츠 관련 기준을 검토함.
2. 서비스 이용약관과 환불 기준을 만듦.
3. 환불 요청을 받을 방법을 정함.
4. 담당자가 확인할 정보와 처리 순서를 정함.
5. 고객에게 보여줄 예상 환불금액과 안내 문구를 정함.
6. 반복 요청이나 중복 환불을 막을 확인 절차를 정함.

### 7.2 크레딧 반환

크레딧 반환은 돈 환불과 다름.

- 고객이 작업을 시작할 때 서비스 크레딧이 차감됨.
- 작업이 실패하면 차감한 크레딧을 원래 크레딧 묶음으로 돌려줌.
- 이것은 결제한 돈을 돌려주는 것이 아니라, 완료되지 않은 작업에 사용된 서비스 크레딧을 복구하는 것임.
- 고객 화면에서도 “환불”이 아니라 “크레딧 반환” 또는 “크레딧 복구”로 표현함.

함께 정할 내용:

- 어떤 상태를 작업 실패로 인정할 것인가?
- 결과는 만들어졌지만 품질이 만족스럽지 않은 경우도 반환 대상인가?
- 오래 걸리는 작업은 언제 실패로 판단할 것인가?
- 이미 유효기간이 지난 크레딧을 돌려줄 때 다시 사용할 수 있게 할 것인가?
- 자동 반환이 되지 않았을 때 고객이 어디에 문의할 것인가?

### 7.3 고객지원

유료 서비스를 시작하기 전 최소한 다음은 정해져야 함.

- 고객이 문의할 곳: 이메일, 채팅, 문의 페이지 중 무엇을 사용할지
- 결제 실패, 해지, 환불, 크레딧 반환 문의를 어떻게 구분할지
- 누가 문의를 확인하고 답변할지
- 고객에게 보통 언제까지 답변할지
- 결제 실패나 환불 요청에 사용할 기본 안내 문구
- 운영시간 밖에 들어온 긴급 결제 문의를 어떻게 처리할지

처음부터 큰 고객센터를 만들 필요는 없지만, 고객이 어디에 문의해야 하는지와 누가 답변하는지는 유료 서비스 시작 전에 분명해야 함.
