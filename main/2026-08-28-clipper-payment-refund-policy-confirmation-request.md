# Clipper 결제·구독·환불 운영정책 확인 요청

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-08-28 |
| 목적 | 결제·구독·환불 기능을 만들기 전에 회사가 정하거나 외부 전문가에게 확인해야 할 사항을 한 번에 정리 |
| 회신 방법 | 각 질문 아래의 회신란과 마지막 회신표에 답변을 기재 |

## 1. 이 문서를 작성하는 이유

정기구독, 무료 체험, 추가 구매 크레딧과 환불은 서로 영향을 준다. 예를 들어 정기구독 결제금을 환불하면 이용권을 언제 종료할지, 해당 결제로 지급한 크레딧을 어떻게 회수할지 함께 정해야 한다. 정기구독이 끝난 뒤에도 추가 구매 크레딧을 사용할 수 있게 하려면 어떤 기능까지 허용할지도 정해야 한다.

이 문서에는 다음 내용을 모두 포함한다.

- 회사가 사업적으로 결정할 사항
- 법률 전문가에게 확인할 사항
- 세무·회계 전문가에게 확인할 사항
- 실제 고객 문의와 환불을 처리하기 위해 정할 사항

별도의 부서가 있다고 가정하지 않는다. 회사에서 직접 결정하기 어려운 질문은 외부 전문가에게 확인한 뒤 같은 문서에 답을 기록하면 된다.

답을 바로 정하기 어려운 항목은 `미결`로 표시해 주기 바란다. 답이 없는 항목을 개발자가 임의로 정하지 않는다.

## 4. 추가 구매 크레딧

### 4.1 정기구독 종료 후 남은 추가 구매 크레딧

확인 성격: `회사 결정 필요`

추가 구매 크레딧은 정기구독 결제와 별도로 돈을 받고 판매한 상품이다. 따라서 정기구독이 끝났다는 이유만으로 남은 추가 구매 크레딧을 자동으로 삭제할지, 계속 보유하게 할지, 환불할지 정해야 한다.

다음 중 원하는 방식을 선택해 주기 바란다.

#### 선택 1 — 남겨 두지만 새 유료 정기구독을 시작할 때까지 사용하지 못하게 함

- 남은 추가 구매 크레딧은 삭제하지 않음
- 새 유료 정기구독을 시작하면 다시 사용 가능
- 사용할 수 없는 동안에도 유효기간을 계속 계산할지, 일시 중지할지 추가 결정 필요

#### 선택 2 — 정기구독이 끝나도 유효기간 안에는 계속 사용할 수 있게 함

- 고객은 이미 구매한 크레딧을 계속 사용할 수 있음
- 그러나 추가 구매 크레딧 자체에는 베이직·프로·비즈니스 같은 이용권 등급이 없음
- 따라서 정기구독 없이 다음 중 어떤 기능을 허용할지 반드시 정해야 함
  - 마지막으로 이용한 정기구독 등급의 기능
  - 모든 등급에 공통으로 제공하는 일부 기능
  - 추가 구매 크레딧 전용으로 따로 정한 기능

이 기능 범위를 정하지 않으면 크레딧은 남아 있지만 사용할 기능이 없거나, 반대로 정기구독 없이 유료 정기구독 기능을 계속 사용할 수 있는 문제가 생긴다.

#### 선택 3 — 정기구독이 끝날 때 남은 추가 구매 크레딧을 함께 정산함

- 자동으로 환불하거나 고객이 환불을 선택할 수 있게 함
- 일부 사용한 크레딧의 금액 계산과 부분 결제 취소가 필요함
- 법률과 세무·회계 확인이 필요함

회신:

### 6.2 환불 승인 방식

확인 성격: `회사 결정 필요` + `회사 운영 방식 확인 필요`

다음 중 초기 운영 방식을 선택해 주기 바란다.

#### 선택 1 — 모든 환불을 담당자가 확인하고 승인

- 정책을 처음 운영할 때 잘못된 환불을 줄이기 쉬움
- 처리시간과 담당자의 업무가 늘어남

#### 선택 2 — 명확한 경우만 자동 처리하고 나머지는 담당자가 승인

- 예: 중복 결제가 명확히 확인된 경우, 정해진 기간 안에 요청한 완전 미사용 결제
- 자동 처리할 조건을 구체적으로 정해야 함

#### 선택 3 — 정해진 기준에 맞는 모든 일반 환불을 자동 처리

- 처리가 빠름
- 계정 도용, 잘못된 기준, 환불 요청 중 추가 사용을 막기 위한 통제가 더 필요함

확인할 사항:

1. 초기 운영 방식으로 어느 선택지를 사용할 것인가?
2. 환불을 최종 승인할 사람은 누구인가?
3. 승인자가 자리를 비웠을 때 대신 확인할 사람은 누구인가?
4. 담당자별로 승인할 수 있는 최대 금액을 둘 것인가?
5. 일정 금액 이상이면 두 사람이 확인하게 할 것인가?
6. 일반 기준과 다른 예외 금액을 담당자가 직접 입력할 수 있게 할 것인가?
7. 예외 금액 입력을 허용한다면 어떤 증빙과 추가 승인이 필요한가?

권장 방향:

초기에는 모든 환불을 담당자가 확인하되, 환불 가능 여부와 금액 자체는 시스템이 계산하는 방식을 권장한다. 운영 결과가 쌓이면 명확한 경우부터 자동 처리 범위를 넓힐 수 있다.

## 10. 회신이 없는 항목의 처리

- 답을 받지 못한 정책을 개발자가 임의로 정하지 않는다.
- 전액 환불 또는 부분 환불을 임시 기본값으로 사용하지 않는다.
- 추가 구매 크레딧의 유효기간과 정기구독 종료 후 처리도 임의로 확정하지 않는다.
- 법률과 세무·회계 확인이 필요한 내용은 회사의 사업 결정만으로 확정하지 않는다.
- 답변과 필요한 외부 확인이 완료된 항목만 실제 운영 기준과 개발 설계에 반영한다.
