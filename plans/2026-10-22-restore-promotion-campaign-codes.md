# 캠페인별 복수 프로모션 코드 복구 계획

> **당시 구현 계획.** 이후 캠페인 생성 시 첫 코드 필수 조건을 없애고, 등록 상한을 코드마다 적용하며, 회원 표에 과거 등록 이력을 추가했다. 현재 규칙과 검증은 [2026-10-23 현재 설계](../design/2026-10-23-promotion-campaign-current-state.md)와 [병합 기록](../implementation/2026-10-23-promotion-campaign-dev-merge.md)을 우선한다.

**목표:** 관리자에게 캠페인과 코드를 다시 분리해 보여주고, 캠페인 하나에 하나 이상의 코드를 발급해 코드별 추천인 성과를 조회한다.

**기준 설계:** `.codex/design/2026-10-19-promotion-referral-design.md`. 캠페인은 지급 혜택, 등록 기간, 총 상한, 이력 제한과 회원당 1회 규칙을 공유한다. 코드는 문자열, 추천인, 개별 활성 상태를 갖는다. 캠페인과 코드가 모두 활성이고 기간·상한·자격을 충족할 때만 등록된다. 중지는 이미 지급한 혜택을 회수하지 않는다.

**저장소:** 구현은 `web/clipper_web_api`, `web/clipper_web_admin`, `web/clipper_web_client`; 설계 문서는 `.codex`에 둔다. 현재 dev의 미커밋 변경을 보존한다.

## 1. API와 저장 구조

- [x] 적용된 단일 코드 마이그레이션을 고치지 않고 후속 마이그레이션에서 캠페인별 고유 인덱스를 제거하고 코드별 `is_active`를 복구한다.
- [x] 캠페인 목록은 캠페인당 한 행과 코드 수/첫 코드 미리보기를 반환한다. 상세 API는 모든 코드와 각 코드의 누적 성공 등록 건수를 반환한다.
- [x] 코드 발급과 개별 중지/재개 API를 추가한다. 전역 문자열 중복, 캠페인당 최소 1코드, 캠페인 삭제와 등록 경합을 검사한다.
- [x] 캠페인 수정은 공유 설정만 변경한다. 등록된 코드/추천인 기록은 캠페인 수정에 의해 바뀌지 않는다.
- [x] 등록 시 캠페인과 코드 양쪽 상태를 검사하고, 등록 내역에 실제 코드를 반환한다.
- [x] 성과 조회와 XLSX 내보내기에 코드 필터를 연결한다. 캠페인 합계는 각 등록을 한 번만 센다.

## 2. 관리자 화면

- [x] 목록을 캠페인 단위로 표기하고 등록 상한과 첫 코드·`외 N건`을 보여준다. 캠페인 상세의 코드별 행에서 추천인·누적 성공 등록·상태를 표시하고 카드 오른쪽 위에서 코드를 발급한다.
- [x] 목록에 첫 코드만 표시해도 검색은 그 캠페인의 모든 코드와 추천인을 대상으로 한다.
- [x] 캠페인 생성에는 첫 코드가 필수다. 이후 상세에서 코드를 추가한다. 캠페인 수정 패널에는 공유 설정만 보여준다.
- [x] 등록·회수 표에 실제 등록 코드를 표시한다. 성과 조회와 XLSX에 전체/코드별 필터를 제공한다.
- [x] 코드 상태와 캠페인 상태의 관계를 명확히 안내하고 작업 기록에 변경 방향을 남긴다.

## 3. 회원 화면과 검증

- [x] 활성 프로모션 이용권 표에 추천인 컬럼을 추가한다. 현재 `/promotions/mine`은 활성 1건만 반환하므로 다중 행/과거 이력 조회는 별도 범위다.
- [x] 코드 상태별 등록 거절, 같은 캠페인 다른 코드 중복 등록, 상한 공유, 코드별 성과 조회, 마이그레이션, 관리자 화면 테스트를 통과한다.
- [x] API/관리자/회원 빌드, `git diff --check`, 실행 중 API 스모크를 확인한다.

**기존 데이터:** 단일 코드 전환 때 여러 행으로 분리된 옛 캠페인은 식별 근거 없이 자동 병합하지 않는다. 각 행은 코드 하나를 가진 캠페인으로 남고 운영자가 새 캠페인에 추가 코드를 발급할 수 있다.

**검증:** API 전체 392개 스위트/3,968개 테스트, 관리자 전체 2,355개 테스트, 회원 관련 32개 테스트 통과. 최종 문구 수정 후 관련 관리자 45개 테스트 통과. 세 앱 빌드와 OpenAPI YAML 파싱, 로컬 DB 마이그레이션 및 두 번째 코드 삽입 트랜잭션 스모크, 로컬 API `/health` 응답을 확인했다.

## 4. 후속 결정: 회원 표에 과거 이력 표시

회원은 과거 등록을 포함해 캠페인마다 받은 이용권을 여러 행으로 본다. 등록일 내림차순으로 표시하고 각 행에 코드, 추천인, 이용권, 이용 기간, 등록일, 종료일, `이용 중/종료/회수` 상태를 표시한다. 내부 캠페인 이름은 회원에게 보여주지 않는다. 활성 이용권만 반환하는 `/promotions/mine`은 유료 전환 흐름에서 계속 사용한다. 활성 이용권이 없으면 과거 이력이 있어도 코드 등록 화면을 보여준다.

- [x] 회원 등록 이력 API와 저장소 조회를 추가해 기간 종료 및 회수 기록을 포함한다.
- [x] 회원 표를 이력 목록으로 바꾸고, 유료 전환은 현재 활성 이용권이 있을 때만 보여준다.
- [x] 다중 행, 종료·회수 상태, 과거 이력이 있을 때의 새 코드 등록 흐름을 검증한다.

이력 조회 실패 시에도 현재 활성 이용권 조회 결과로 회원 표와 유료 전환을 보여준다. 회수된 이용권은 원래 예정 종료일 대신 실제 회수 시각을 표시한다. 회원별 등록일 정렬 조회를 위한 인덱스를 추가해 로컬 admin DB에 적용했다. API 전체 392개 스위트/3,969개 테스트, 회원 클라이언트 전체 496개 테스트, 두 앱 빌드, OpenAPI YAML 파싱과 로컬 API 인증 경로를 확인했다.

## 5. 후속 결정: 캠페인 목록과 코드별 지표 구분

캠페인 목록에는 공유 설정인 등록 상한을 표시하고 성공 등록 건수·추천인 컬럼을 두지 않는다. 코드는 첫 번째 하나만 표시하고 남은 수를 `외 N건`으로 표시한다. 캠페인 상세의 코드 표에는 각 코드의 추천인과 누적 성공 등록 건수를 표시한다. 회수된 등록도 이미 성공한 기록으로 계산한다. 코드 발급 버튼은 공통 카드의 우측 상단 작업 영역에 둔다. 성과 안내 문구에서는 등록·결제 성과와 크레딧 사용 내역을 구분한다.

API 전체 392개 스위트/3,970개 테스트와 관리자 전체 2,355개 테스트, 두 앱 빌드, OpenAPI 파싱, 로컬 DB에서 코드별 집계 SQL과 재시작된 API 응답을 확인했다.
