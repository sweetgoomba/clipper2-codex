# 독립 검토 7건 수정 계획 (2026-10-20)

작업 위치는 `promotion-referral-20261019`의 Web API, 관리자 웹, 회원 웹 작업 트리다. 각 원인을 기존 코드와 재현 테스트로 확인한 뒤 변경한다. 설계·검증 기록은 `.codex`에만 둔다.

1. **첫 결제 결과 불명 자동 복구**: 일반 첫 결제와 예약 첫 결제의 due 선별·실행 조건을 대조한다. 일반 구독에서 응답 불명 상태를 자동 재조정하는 실패 테스트를 만들고 최소 수정한다.
2. **성과 보고 일관성**: 동시 등록 중 offset 경계가 움직이는 실패 테스트를 만든다. 보고 요청의 행 목록과 합계를 일관되게 읽도록 수정하고 XLSX 고유 등록 ID·합계를 검증한다.
3. **회원 동의**: 프로모션 조회 전 동의를 체크했다가 첫 결제일이 바뀌는 재현을 테스트한다. 날짜가 확정되기 전 동의할 수 없게 하고 변동 시 이전 동의를 무효화한다.
4. **만료 경계 등록**: 날짜상 만료됐지만 상태가 열린 이용권이 있는 계정의 등록 실패를 재현한다. 지급 전 만료 정산을 동일 잠금·거래 안에서 수행한다.
5. **관리자 조회 권한**: `members.read`만 있는 역할에서 목록·성과가 보이는지 테스트한다. 카탈로그 권한 실패가 조회 전체를 막지 않도록 조정한다.
6. **캠페인 전환 경합**: 코드 발급 응답이 늦게 도착해도 현재 캠페인 목록에 섞이지 않도록 테스트·수정한다.
7. **감사 기록 경합**: 상태 변경의 이전 값을 동일 거래에서 잠그고 읽도록 테스트·수정하여 동시 재활성화 기록을 보존한다.

마지막으로 관련 테스트를 재실행하고 세 저장소 빌드·전체 테스트·`git diff --check`를 확인한다. PostgreSQL에서 검증 가능한 경합과 마이그레이션을 확인하고, 외부 Toss 실결제의 미검증 범위는 명시한다. 커밋·푸시는 하지 않는다.
